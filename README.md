> **两轮"减法"（2026-09-14）**：
> 1. **手写美化整层删除**（`src/InkEngine.Optimize`：1€ 滤波、RDP 抽稀、贝塞尔拟合、
>    速度→粗细、渐细、笔锋预设）。
> 2. **我们自己拼的笔迹轮廓整层删除**（等宽带子、半圆端帽、外侧圆弧、内角补角、
>    压感→宽度映射），**笔迹改由 Direct2D 原生描边渲染**（`DrawGeometry` +
>    圆头圆角样式）：宽度、端帽、拐角全交给 D2D。
>
> 理由：用户实测后认为 D2D 的观感更好；而且这层自己算的几何是"小 bug 最多"的地方
> （折角被削、自交挖洞、起笔毛边）。代价是**压感不再影响粗细**（一条笔画一个宽度），
> 采样点上仍然记着压力值，存档与将来要用都拿得到。
> 老存档仍能打开（格式 v3，读 v1/v2 时会跳过那个已废弃的预设字节）。

## 发布 / 打包（拿给别人用）

一条命令（绿色版和安装包一起出）：

```powershell
.\publish.ps1              # 目录 + zip + 安装包 Setup.exe
.\publish.ps1 -NoSetup     # 只出绿色版（机器上没装 Inno Setup 时也会自动跳过）
.\publish.ps1 -SingleFile  # 单文件版（就一个 exe，方便拷，启动稍慢）
```

产物落在 `dist\`：`InkTeach-<版本>-win-x64\`（目录）、同名 `.zip`（绿色版）、
`InkTeach-Setup-<版本>.exe`（安装包）。脚本会自己核对"发布出来的 exe 是 GUI 子系统"
（= 双击不弹黑框），不合就报错。

**安装版 vs 绿色版**（两个都发，看对象给）：

| | 安装包 `Setup.exe`（发给别人，推荐） | 绿色版 zip |
|---|---|---|
| 装 | 双击 → 下一步 → 完事，**不弹 UAC** | 解压就能用 |
| 快捷方式 | **桌面 + 开始菜单自动建** | 自己建 |
| 卸载 | 设置 → 应用 → 卸载（目录、快捷方式一起清） | 直接删目录 |
| 装到哪 | `%LOCALAPPDATA%\Programs\InkTeach`（**只给当前用户**，不需要管理员） | 你放哪就哪 |
| 自动更新 | **一样能用**（见「自动更新」：下载 → 换壳 → 重启） | 同 |
| 什么时候用 | 发给不认识的老师、要开始菜单入口和卸载 | 自己拷 U 盘、临时用、免安装 |

**为什么装"只给当前用户"**：① 教室机器多半没有管理员权限，不弹 UAC 就能装；
② **自动更新要能写自己的目录**——装到 `Program Files` 就得每次更新弹 UAC
（或者干脆失败）。装到用户目录就有写权限，更新全程无感。代价是"每台机器每个用户
各装一份"，对教室场景无所谓。

**安装包怎么做的**（`installer\InkTeach.iss`，Inno Setup 6）：

- 编译器是 Inno Setup 6（本机已装在 `%LOCALAPPDATA%\Programs\Inno Setup 6`，用
  `ISCC.exe` 编译）。**只有开发机需要它**，用户机不用；
- 中文界面用社区翻译 `installer\ChineseSimplified.isl`（MIT，出处见
  `src/InkEngine/THIRD-PARTY-NOTICES.md`）；
- 装之前会 `taskkill` 掉正在运行的 InkTeach（常驻覆盖层，礼貌关窗口未必管用）；
- 卸载按"整目录删"，所以**换壳更新进来的新文件也能卸干净**；
- 教室批量部署可以静默安装（不弹界面、装完也不自动启动）：
  ```powershell
  .\InkTeach-Setup-8.0.0.exe /VERYSILENT /SUPPRESSMSGBOXES /NORESTART
  ```

- **双击不弹黑框**：开发时工程是控制台程序（自检的输出要被管道抓住，必须是控制台子系统），
  **发布时**由脚本传 `PublishAsWinExe=true` 切成 GUI 子系统。两条路各管一边，见 csproj 里那段注释。

  **"界面上的重启"那条路**：新进程抢不到互斥体时先等 2 秒（老进程随后才退），
  并且**必须接住 `AbandonedMutexException`**——老进程退出时还攥着互斥体，内核把它标成
  "被放弃（abandoned）"，此时 `WaitOne` 是**抛异常**而不是返回 `false`
  （异常抛出时所有权已经转过来，按 MSDN 应视为"抢到了"）。
  2026-09-28 修：没接这个异常时，异常一路冒到 `Main` 外面（当时单实例判断写在 try 之外），
  表现就是"点了重启，老窗口关了、新窗口再也不出来"。
- **启动崩了看得见**：GUI 版没有控制台，崩溃会写到
  `%LOCALAPPDATA%\InkTeach\last-crash.txt` 并弹一句提示。
- **GUI 版里别随便碰 `Console.OutputEncoding`**（2026-09-27 踩过，双击发布版启动失败）：
  无控制台时它的 setter 会抛 `IOException“句柄无效”`，把启动流程整个打断。
  `Engine.Run` 里那一句已经包了 try；**以后新增控制台相关设置（改编码、改窗口大小、
  设光标可见性等）也要照样包**——`Console.WriteLine` 本身无控制台时是空操作、不会炸，
  只有"设置类"的调用会。命令行（带参数自检）那条路会先 `AttachConsole`，所以两种启动方式都要各测一遍。

**拷给别人前提醒两件事**：

1. **只拷软件目录**，别把开发机上的 `%APPDATA%\InkTeach`（设置 / 图库）和
   `%LOCALAPPDATA%\InkTeach`（自动存档 / PPT 批注）一起带过去。
2. 没签名的 exe 从网上/U 盘拷过去时可能弹"Windows 已保护你的电脑"
   （内网共享一般没有这个标记）。另外**PPT 联动需要那台机器装了 PowerPoint 或 WPS**。

已知还差的两条（记账）：**多屏混合 DPI**（全机按主屏缩放算，副屏上尺寸/落点可能偏）、
以及**多屏时"贴底"只认主屏工作区**。

### 自动更新（2026-09-29 起；2026-10-02 改并行探测）

**只在用户点击时才检查**（不联网偷看、不弹窗骚扰）：「更多」面板（设置页）里那一行
"检查更新"→点一下→"检查中…"→"已是最新" / "有新版本 8.0.1"，
**再点一下**才开始下载（下载完校验 sha256 → 自动重启换成新版本；不到"下载"这一步不写盘）。

**更新源是一串候选、六条同时问（并行探测）、先到先得**（`src/InkEngine/Update.cs` 的
`FetchBest`）：谁先报"有新版"就用谁（通常 1~2 秒，其余不等）；只有全都说"已是最新"
才算数（要等最慢的一条，单条超时 8 秒，所以最坏也就 8 秒左右）。**下载优先走响应快的
国内加速站**，失败或卡住（30 秒没数据）自动换下一条候选，不用用户重新点。

> 为什么改（2026-10-02，用户反馈"有时检查失败、有时等很久"）：原来是按顺序试、
> 每条 15 秒，六条全挂最坏要 90 秒才报失败，而挂掉的源恰恰最耗时；现在同时发出，
> 六条全挂的"检查失败"也是 8 秒内出结果。

| 顺序 | 源 | 说明 |
|---|---|---|
| 1–5 | 国内 GitHub 加速站：`gh-proxy.com` / `ghfast.top` / `gh.jasonzeng.dev` / `gh.llkk.cc` / `ghproxy.net` | 教室机连不上 GitHub，靠它们过去。清单和 33 MB 的 zip 都实测能过（zip 走 `gh-proxy.com` 实测 **32.9 MB / 3 秒**，sha256 与清单一致） |
| 6 | GitHub 直连 | 能上的机器走它最省事（但这台开发机的直连时好时坏，实测过 21 秒超时，所以放最后） |
| 覆盖 | `settings.json` 的 `update.url`（**非空就只用它**） | 教室/校内：指到局域网共享最稳（见下） |

三条实测结论（2026-09-29，动手选源前先看）：

1. **大学镜像站这条路走不通**：清华 / 南大 / 北外 / 中科大 / CERNET 的
   `github-release` 连 `cli/cli` 都是 404——那是**白名单制**，不覆盖任意仓库；
2. **加速站会生老病死**：同批测的 `mirror.ghproxy.com`、`hub.gitmirror.com`、
   `github.moeyy.xyz`、`ghproxy.cc`、`ghps.cc`、`gitdl.cn`、`kkgithub` 当时已挂/超时，
   `bgithub` 只收 raw 文件、不收 zip。所以**要多列几条，让活着、快的那条顶上来**（并行探测正好用上）；
   内容安全不靠它们——**sha256 对不上直接拒绝安装**（来路不明的东西绝不落盘）；
3. 走加速站时，App 会把清单里的 **zip 地址自动套上同一个前缀**
   （只重写 `github.com` 直链；局域网 / Gitee / 已带前缀的地址一律不动）——
   不这么做就会出现"查得到新版、下不动包"。

**换源不用改 App**，两种办法：
`publish.ps1` 顶部的 `$updateBase`（改的是清单里 zip 的落点）；
或者用户机器上 `%APPDATA%\InkTeach\settings.json`：

```json
{ "update": { "url": "\\\\教室服务器\\InkTeach\\update.json" } }
```

（局域网共享里放 `update.json` + zip 即可；这一条**最稳**，教室里推荐它。）

**装过安装包的机器也一样更新**：换壳会把新版文件铺回安装目录（桌面 / 开始菜单快捷方式
指向的路径没变，照常能用），而且换壳时会**把卸载程序 `unins000.*` 从旧目录带过去**——
不然"设置 → 应用"里的卸载按钮会指向一个不存在的文件（2026-09-29 加安装包时发现并修了，
`--updatetest` 里有一条沙箱测试专门盯着它）。一个已知小瑕疵：**卸载列表里显示的版本号
是"安装时"记的**，换壳更新后不会跟着变（不影响功能——卸载按"整目录删"走，能删干净）。

**拿 GitHub 当源**（本项目现在就是这么配的，仓库 <https://github.com/XueRenYi0/InkTeach>）：

1. `publish.ps1` 顶部填 zip 的落点前缀：
   ```powershell
   $updateBase = "https://github.com/<账号>/<仓库>/releases/latest/download"
   ```
2. 跑 `publish.ps1`：它会写**两份一样的清单**——
   `dist\update.json`（跟 zip 一起当 release 附件）和**仓库根目录的 `update.json`**；
3. **发新版三步**（`publish.ps1` 跑完会把这行提醒再打一遍）：
   ```powershell
   git add update.json && git commit -m "发布 vX.Y.Z" && git push
   gh release create vX.Y.Z dist\InkTeach-X.Y.Z-win-x64.zip dist\update.json `
                           dist\InkTeach-Setup-X.Y.Z.exe
   ```
   （zip 是给自动更新用的；安装包 `Setup.exe` 挂上去是给人手动下载的。
   Release 页面上建议把**安装包写在最前面**——老师要的就是"双击下一步"。）

**⚠ 版本号只有一处真源：`src/InkTeach/InkTeach.csproj` 的 `<Version>`**（2026-10-02）：
`publish.ps1` 用它命名 zip / 写清单；App 自报版本读的也是它（信息版本，`+提交号` 会去掉）。
**别单独钉 `AssemblyVersion` / `FileVersion`**——8.5.1 那次把它们钉在 8.5.1，之后 `<Version>`
升到 8.6.0 而它们没动，结果是**装了 8.6.0 的机器仍自报"当前 8.5.1"、永远提示"有新版本
8.6.0"**（已改成读信息版本，并把 csproj 里钉的那两行删了，SDK 默认让它们跟着 `<Version>` 走。
已发出去的 8.6.0 包带着旧毛病——下次发布（8.6.1）装上去就好了）。

**为什么清单放"仓库 raw 文件"、zip 放 release 附件**（2026-09-29 实测踩出来的）：

| | 结论 |
|---|---|
| release 附件 | 走 CDN。**刚发新版时"附件 digest 已经换了、取回来还是旧内容"**（实测：附件换了，`releases/…/update.json` 取回来还是上一版） |
| 清单 | 所以放**仓库文件**，App 从 `raw.githubusercontent.com/<账号>/<仓库>/main/update.json` 取，而且 `UpdateFeed.Fetch` 每次会**带一个查询串**击穿缓存（清单只有几百字节，不值得省这次请求） |
| zip | 继续放 release 附件：大文件、**版本固定**（URL 里带 tag），缓存是好事 |

**发布后别急着验证，等约 2~5 分钟**（2026-09-29 实测三遍）：raw 清单本身也在 CDN 上，
刚 `git push` 完的那一两分钟，**六条源全都在送旧清单**（连 GitHub 直连都是）。
App 的规矩是"**任一源报新版就采纳，所有源都说已是最新才算数**"，所以：

- 只要有一面镜像先刷新，用户点「检查更新」立刻就能查到（实测第三次升级就是
  `gh-proxy.com` 还旧、`ghfast.top` 已新，靠这条规则才升上去的）；
- 全都没刷新时，点了会显示"已是最新"——**过几分钟再点一次即可**，不是坏了。

所以发完新版请**隔几分钟**再在机器上验证；要"发布即生效"就得换掉 raw 这条路
（比如自己的对象存储 / Gitee），`settings.json` 的 `update.url` 可以随时覆盖。

为什么不用 GitHub API：那个 API 匿名限流 **60 次/小时**，几十台教室机一起点就废了；
`releases/latest/download/…` 那个恒定重定向也**不能用**——它 302 到不带查询串的附件地址，
照样命中 CDN 缓存（实测）。以后要换成局域网共享，只改 `settings.json` 里的 `update.url`。

**⚠ 网络现实（2026-09-29 实测，动手前先看这一条）**：本机**连不上 github.com**——
`Invoke-WebRequest -Head https://github.com` 直接超时、`git ls-remote` 21 秒后失败、
没有任何代理配置；同一时刻 `gitee.com` 是 200。教室里那些机器多半是同一个网络环境，
**所以拿 GitHub Releases 当更新源很可能"开发机能发、教室里装不上"**。
三条更靠谱的路，**都对代码零改动，只换 `$updateBase`**：

| 放哪 | `$updateBase` 长什么样 | 说明 |
|---|---|---|
| **Gitee（码云）** | `https://gitee.com/<账号>/<仓库>/raw/<分支>` | 国内直连。**清单放仓库根目录**（raw 地址恒定不变），zip 挂「发行版」附件、把附件地址写进清单的 `url` |
| **局域网共享** | `\\教室服务器\InkTeach` | 最省事最稳（不过外网）。清单和 zip 都放共享里；**支持裸路径**，sha256 照样校验 |
| **对象存储** | `https://<桶>.oss-cn-….aliyuncs.com` | 要 HTTPS + 快就选它，几块钱一个月 |

（GitHub 那套步骤保留在上面：哪天有稳定代理了，把 `$updateBase` 换回去即可，
App 端一行都不用动——**这正是"更新源只是一个字符串"的意义**。）

**清单格式**（`update.json`，扁平一层，故意不用 JSON 库——和 `Settings.cs` 同一个理由）：

```json
{
  "version": "8.0.1",
  "url":     "https://…/InkTeach-8.0.1-win-x64.zip",
  "sha256":  "…64 位十六进制…",
  "notes":   "一句话说明（会进日志，也可以空着）",
  "minVersion": ""
}
```

**更新是怎么装上去的**（绿色版的好处就在这儿）：下载到
`%LOCALAPPDATA%\InkTeach\update\<版本>\` → 校验 sha256（**对不上就把包删掉，不装**）
→ 拉起一个 PowerShell 换壳脚本 → 我们自己退出 → 脚本等我们退干净 → 把旧目录改名成
`<目录>.old-<时间戳>`（**留着可回滚**，下次更新时清）→ 解压新的 → 重启。
用户数据在 `%APPDATA%` / `%LOCALAPPDATA%`，更新完全不碰。

**验收**：`--updatetest`（离线自检 38 条：版本比较 / 清单解析 / sha256 / 本地取清单 /
镜像前缀重写 / 下载候选 / 换壳脚本沙箱真跑）。真下真装那一步要人工验一次
（找个旧版本、点一下「检查更新」）。

**还没做的**：安装包（Inno Setup）。做的时候原则是"绿色版是唯一的负载，
安装包只是把它包一层"——`PrivilegesRequired=lowest` 装到 `%LOCALAPPDATA%\Programs`，
**不要管理员权限**（教室机上要管理员等于装不上）。

## 快捷键

**完整清单在 [快捷键总表.md](快捷键总表.md)**（含每个功能的所有键、修饰键、
修改记录、本机实测的注册冲突）。那份文件是快捷键的唯一权威：改键必须同步改它，
`--keytest` 会自动核对"代码里的每一条绑定都能在文档里查到"。
下面两张表是摘要。

键位**是一张可配置的表**，不是写死的字符串。启动时会打印整张表；
改过的键位与**工具尺寸**存在 `%APPDATA%\InkTeach\settings.json`：


**只写"和默认不一样"的项**（删掉某一项 = 恢复默认；以后默认值改了，
老配置不会把新默认顶掉）。写坏了照样启动，只是逐条打警告并用人能看懂的
默认值——**坏配置不许让程序起不来**。

`ui` 段是界面自己的偏好（深色主题、贴边隐藏、档位、钉住、白板底纹……），
引擎只存不解释。其中一条值得单独说：

> **`restoreInk`（启动接上上次的板书）默认关**（用户 2026-09-17："退出以后再打开
> 不用恢复墨迹……我觉得默认不恢复墨迹"）。教室机器是公用的，一开机就铺满上一节课
> 的板书不合理。**它同时管写**：不读的东西不必写，所以关着的时候连自动存档文件都不产生。
> 以后在"更多"抽屉里给一行开关就能改（现在改配置文件即可）。

还有一条是**引擎自己解释**的（`ui.exportFormat`）：导出时默认选中第几条格式。
导出成功后写进去，下次接着用——常用 JPG 的老师不用每次都去下拉里找。

**为什么全局只剩 2 条**（用户 2026-09-19："除了最最最常用的功能需要全局热键以外，
其他的通通换成应用内快捷键就行了"）：全局热键是**抢别的程序的键**，注册多了还会撞车
（微信 / QQ / 输入法都抢 `Ctrl+Alt+…`，`Ctrl+Alt+H` 就被占过）。降级之后用起来没差别——
批注键盘模式默认开着，键盘本来就在批注层手里。**放映 PPT/WPS 时**，
`Ctrl+P/I/L/E/Z/Q` 与 `←→↑↓` 会临时注册成全局热键（退出放映立刻注销；穿透期间整体让路）。
**图形一个键都没有**（用户同一天定："图形不需要加快捷键，通通取消掉"），
换种类只走主条「图形」那一格的上带。

## 选中与旋转

拖动选中框上边外侧的旋转手柄时：

- 手柄外侧浮出一个**度数标签**（如 `90°`），显示相对按下那一刻转了多少度。
  **符号按高中数学那套：逆时针为正、顺时针为负**（`-45°`、`+90°` 写成 `90°`），
  **不设上限**——转两圈就是 `720°`，倒着转回去就是负数，不会在 ±180° 处绕回
  （用户 2026-09-15 定）。翻转过的对象也一样：读数是**眼睛看到的方向**；
- 松手前靠近 90° 的整数倍（±3°）会**吸附**，标签变强调色——用户能分清"我转到的"和"它吸到的"；
- 按住 `Shift` ＝ 硬网格 15°（覆盖任意角度，含精确 90°）；按住 `Alt` ＝ 完全自由；
- 一次拖拽 = **一步撤销**，松手提交，拖动中的预览不进撤销栈。

自检：`--rotatetest`（读数/三种吸附模式/矩阵自洽/标签真的上屏 + 撤销回原位）。
摆样看外观：`--rotateshow 90`、`--rotateshow 43`（挂住不动，人工截图）。

## 自动化测试

**功能测试和性能测试是分开的两套**（这就是两条命令，别混着跑）：

```powershell
# 功能：每个用例都给红绿，回答"这个功能好不好、有没有 bug"
pwsh -File tools/bench/Run-FuncSuite.ps1

# 性能：只看数字（耗时 / 内存 / 帧率），不判红绿
pwsh -File tools/bench/Run-PerfSuite.ps1
```

分开的理由是踩出来的：原来一套脚本混着跑，用 `PASS/FAIL/DATA` 区分，
而 `DATA`（跑完了但没判据）既是"基准模式"又是"自检少写了判据"。于是一条
**判据写错、永远红的用例**会被当成正常数字埋在中间——实测折角自检红了好几轮
没人发现。现在功能套件会把"没有判据"的用例单独点出来要求补，
有 FAIL 时退出码是 1（可以接 CI）。两套的原始输出分别落在
`reports/func*/`、`reports/perf*/`；`Run-StressSuite.ps1` 只是"两套都跑"的入口。

### 出图（离屏，给"只能看图"的事用）

排版好不好看、字有没有居中这类事**自检判不了**（几何全对也一样难看），所以单开一组出图命令。
它们**不截屏**：让界面 / 浮动层渲染到自己的位图上，锁屏、远程、没人看着的时候照样出图，

**笔迹只有一条画法**（2026-09-14 起）：**中心线 + D2D 原生描边**
（`DrawGeometry` + 圆头圆角样式）。宽度 = 笔宽（等宽），端帽与拐角由 D2D 算。
单点笔迹特殊处理：几何直接建成一个圆（零长度的线描边画不出东西）。
没有平滑、没有抽稀、没有拟合、没有笔锋、没有自己拼的轮廓——指针报什么坐标就画什么。

> 实测依据：自绘轮廓与 D2D 原生描边在 20 组折角对照里逐像素等价
> （[调研-折角掉色.md](调研-折角掉色.md) 第十节）；而**自交/折返处的露底**
> 两边都有（第十一节），D2D 有的情况还更大。既然几何等价、观感用户更喜欢 D2D，
> 就把我们那层删掉。

## 框选：框到的就选中

框选（`Ctrl+5`）有**两种起手**：

1. **点选**（2026-09-15 加）：在一条墨迹上按一下就直接选中它——**点住就能拖**，
   和 PowerPoint 一样；多条叠在一起时取**最上面**那条。`Shift` 点＝加选（再点一下移出）、
   `Alt` 点＝减选，加/减选时不进入拖动，方便连着点几条攒出一个选择。
   按在**已选中的对象**上、松手时没移动过，会把多选**收窄成只选它**（PPT/Figma 的行为）。
   命中判据和橡皮同源：细笔给 4 逻辑像素容差；**被像素橡皮擦掉的那段不算墨**
   （点缺口不会误命中）。
2. **拖框**：**碰到笔身就算选中那一条**，不要求整条都落在框里。

**选中什么时候消失**（2026-09-15 定，与 InkClass / PPT / Figma 一致）：**"选中是临时上下文"**——
换到别的工具（笔 / 荧光笔 / 激光 / 橡皮 / 像素橡皮 / 截图）就收起选区；否则选区遮罩会把
接下来的第一笔吃掉（"点完工具画不出来"）。**操作条按钮 / 手柄 / 框内拖动 / 键盘编辑键不算换上下文**；
**滚动也不算**（滚动是"看"，不是"操作对象"）。另外，对象一旦从文档里消失（被擦掉、被删掉、
撤销一次新增），会自动从选中集合里去掉，不会留一个"看得见摸不着"的选中框。

**操作条的复制按钮 = 复制拖拽模式**（参考 InkClass 的成熟交互）：点一下进入模式（图标高亮），
之后**按住选中内容拖动就拖出一份副本**（原件不动），可以连着拖第二份、第三份；
再点一次按钮 / 点空白 / 换工具退出。**"插入副本 + 位移"算一步撤销**，拖错了按一次就全回去。
（想"原地复制一份"仍可用 `Ctrl+D`。）

这条语义是被实测逼出来的：按"整条都在框里"，屏幕上永远选不全——笔迹只要有一头
在屏幕外（框拖不到那儿），或者粗笔的笔身压出框外一点点，那条就永远选不上，
用户看到的就是"我明明全框住了，却没全选中"。代价是框边碰到一条很长的笔迹会把
它整条选进来，这和 OneNote 的框选一致，也是更需要的那个方向（选多了点一下空白
重来；选少了会以为软件坏了）。自检：`--seltest`（29 项：框选、点选、加选减选、
"点选已选中的一条收窄成单选"、操作条贴着屏幕四边也点得到）。

**操作条十格**（2026-09-16 从 4 格扩到 9 格、2026-09-22 补上「图库」成 10 格，顺序即语义）：
**收起 / 颜色 / 锁定 / 层级 / 导出 / 图库 / 复制 / 左右翻转 / 上下翻转 / 删除**。
永远贴在选中框下方 14 逻辑像素；选区靠近屏幕下边时，条会在**离屏幕下边 12 像素**处停住
（**不翻到上方**——翻上去会盖住选区上方的板书），横向也夹在可见区域内，贴着屏幕四边都点得到。
三条规矩：**危险动作（删除）在最右**、开关类在左、**没有"旋转 90°"**（旋转手柄 + Shift 的
15° 已经覆盖，用户明确不要）。

### 套索（框选下**再按一次 `Ctrl+M`** 切）

框选工具下拖空白处有两种方式，再按一次 `Ctrl+M`（或点面板上「选择」那一格）切换，
面板上跟着"工具"显示当前是哪种：

| 方式 | 判据 | 像谁 |
|---|---|---|
| 矩形框（默认） | **碰到墨就算选中**那一条 | OneNote |
| 自由套索 | 对象的**代表点 80% 落在圈里**才算 | WPF / 绝大多数白板 |

两种判据**故意不一样**：拖矩形是"我框住这一片"，画一圈是"我把这一条圈起来了"。
80 这个数取自微软 WPF 的 `_percentIntersectForInk = 80`（代表点 = 笔迹的采样点 /
图形的轮廓折线 / 图像的四个角；**被像素橡皮擦掉的那一段不算墨**）。

套索还有一条关键规则：**圈到屏幕边＝当作无限延伸**（贴边的顶点推到屏幕外 10 万像素）。
没有它，一条横跨屏幕的长笔迹永远选不全——框选当初就是为同一个问题才改成"碰到就选"的。
`Shift` 加选、`Alt` 减选，和点选同一套。自检：`--lassotest`（17 项）。

**拖框是"锚点 ↔ 指针"，不是"扫过的最大范围"**（2026-09-15 修）：按住起点拖动，
四个方向都能拉，指针往回走框跟着缩回去；截图取景框用的是同一套算法（以前是累积
min/max，框只会越拉越大，手感"不跟手"）。套索的线头也咬着指针走——路径点为了判据
便宜抽稀到 3 逻辑像素，但预览会把线画到指针此刻的位置。

**选中框按"墨迹范围"算，不是按中心线算**（2026-09-14 修）。宽笔尤其明显：
64 像素宽的荧光笔在屏幕上是一条 64 像素宽的带子，如果框按中心线画，四条边全压在
墨里面，看着就是错的。现在每个采样点按自己的半宽往外扩（`Stroke.InkBounds`），
框刚好贴着墨的外沿，粗笔细笔都不会虚胖。自检见 `--seltest` 的"宽笔选中框把墨圈住 /
不虚胖"两项。

**框一律轴对齐**（2026-09-16 用户定，改掉了原来"单选跟对象转"那一档）：选一条也好、
选十条也好，框都是**屏幕上那个正矩形**（每个对象墨迹包围盒的并集），8 个手柄永远在
上/下/左/右，旋转柄永远在框的正上方。好处是斜着的对象也一眼能读出手柄语义；代价是
三条，都是这个决定的直接后果：斜着的对象框会**虚胖**（45° 的长条圈成一个大正方形）、
旋转中框**每帧重新贴合**（会"呼吸"）、缩放与翻转按**屏幕轴**走（不再沿对象自己的轴）。
自检：`--seltest` 的"单选一个转过的对象：框是正矩形、旋转柄在正上方"与
"旋转中：框仍正着，并每帧重新贴合当前内容"两条。

- **动态橡皮（8.3.4 起；8.3.6 重调参数）**：**面积擦**的尺寸跟着**移动速度**走，形状照隔壁 Inkeys「笔速橡皮」定（他们有**下限 25px / 上限 200px** + 线性斜坡）：**静止/慢速（≤ 0.8 px/ms）= 基准的 1.0 倍**（**死区**：常规擦字速度全落在里头，尺寸纹丝不动）→ 中间线性涨 `1.0 + (速度−0.8)×1.0`（1.5 px/ms ≈ 1.7 倍）→ **快扫（≥ 2.3 px/ms）封顶 2.5 倍**，另带**回差**（0.8 开始涨 / 0.6 才回落，门槛附近不来回切）；**整笔擦不受影响**（它的"大小"是命中半径，动态会让"点到哪条"变得不可预期）；**不分设备**——笔 / 鼠标 / **手指**走同一段擦除代码，触摸屏上用指头抹面积擦照样有；后门 `--eraserfixed` 关掉动态（不进界面）；**看见的框 = 擦的范围**（8.3.5 修：框和擦读**同一份**尺寸，拖动中框跟着速度一起变、悬停回基准 = 按下去第一下的那一块；切口正好停在框边，量出来**缝 = 0.0px**）；**8.3.6/8.3.7 一步步治好了"忽大忽小"**：速度不再用"单次 dist÷dt"（被小 dt 放大），改成**按时间攒满 100ms（或 40px）的窗口**（逐次估法在 1.33/0.22 之间跳，窗口稳在 0.50）；门槛从 0.35 提到 **0.8**（门槛低于"常规速度"就会"一擦就变尺寸"）；平滑按**时间常数**（涨 220ms / 收 450ms + 最少步长 0.01，与 Inkeys"每步走差距 1/50、至少 0.1px"同源）。**门槛不用猜**：`--eraserhud` 开左下角读数（速度 / 目标 / 当前系数 / 尺寸），真机上擦几下就能读出常规速度。自检 **`--dynerasertest`**（11 项：曲线（含死区）/ 后门 / 慢速与常规速不抖 / 窗口抗抖 / 慢扫 vs 快扫（逻辑版 + 真拖版）/ 框跟速度 / 严丝合缝 / 整笔擦半径不随速度变）；**8.3.8**：下限从 0.7 提到 **1.0**——"**你调的滑条值就是默认大小**"：**点击后按住不动、慢慢抹都不缩**（按住不动时手指/鼠标的微抖会被算成速度，8.3.7 之前会慢慢滑到 0.7 倍；现在这条也是自检判据）
- **上屏脏区像素对齐（8.4.2，用户实测确认）**：修"**面积橡皮左侧跟着一根黑线 / 一条条细密竖线**"和"**悬浮栏收起展开残留黑竖线**"。根因：脏区矩形的边界**带小数**（画布/逻辑坐标换算：DPI 2.0、相机亚像素偏移、奇数尺寸），而重画那一块用的是"裁剪框 + Copy 填充"——边界落在半个像素上时**最左/最上一列像素擦不掉**，于是**每个脏区矩形在左边漏一条竖线**（一帧好几个矩形 → "细密"；整窗重画后只剩一个 → 只剩一根；只在左侧、时有时无，都对得上）。修法：每个脏区矩形往外取整（左/上 `floor`、右/下 `ceil`）。配套修的两个真 bug：落点框并进上屏脏区（8.3.9）、并进"最近三帧"集合（8.4.0，双缓冲里躺的是两帧前的画面）；**8.4.3 撤掉排查期那记"整窗重画"保险**（用户实测：撤掉后两种竖线都不再出现；真根因既然在像素对齐，就不该为一个显示残留付"每帧整窗重画"的钱——那在弱机上是 20~40ms/帧的顿感；分块内存不受影响 = 可见块数 + 32 × 256KB，与笔迹多少无关）；自检 `--cursortest` 86 / `--pixelerasetest` 37 / `--dynerasertest` 11 全过。

- **压感 → 粗细**（2026-09-20；用户："现在有设备了，弄一个和人家一样、手感正常的"）：
  口径**对齐 WPF / Windows Ink**，而且是**从用户的两张真机对照图反推**出来的：
  `宽度 = 档位宽度 × clamp(2.0 × 压力, 0.10, 2.0)`（线性）。
  关键锚点是第二张图里**鼠标画的那条线**：WPF 官方文档写明无压感设备的
  `StylusPoint.PressureFactor` **默认 0.5**，所以它是"一半压力"的参照物，不是满压——
  于是实测（横线，逐像素量）：**鼠标 18.0 px**、笔·轻描 6.0 px（**0.33×**）、
  笔·重压 31.0 px（**1.72×**）、满压外推 **2.00×**。
  由此定下两个特征点：**p = 0.5 → 1.0 倍 = 档位宽度**（所以**档位语义没变**：
  档位就是你用鼠标画出来的粗细）、**p = 1 → 2 倍**（比鼠标那条粗一倍）。
  渲染走 **D2D 原生墨迹 `ID2D1Ink`**（每个采样点自带半径 → 变宽；官方对这套图元的说法是
  "比应用自己用一串椭圆和四边形去管墨迹**更快也更漂亮**"），**没有把自己拼轮廓那层加回来**。
  配套三条：① **湿墨同源**（委托墨迹轨迹的点本来就有逐点半径，不然抬手那一下粗细会跳）；
  ② 紧框 / 命中 / 两种橡皮按**最粗那一处**算（否则重压的地方看得见、点不着）；
  ③ **三个回退**——设备不报压感、虚线/点线（墨迹不吃 dash 图案）、被像素橡皮擦断
  → 一律走回等宽描边。**荧光笔不吃压感**（官方示例 `IgnorePressure = true` 同款：
  平头马克笔的粗细不该随手劲变，何况满压是 2 倍宽）。
  **存档 v10** 多一位"这一笔有没有压感"（不存的话"存盘重开就变等宽了"）。
  两个调手感的开关：`--nopressure`（对照）、`--pressrange min,max[,gamma]`
  （嫌重压太粗就降 max，嫌轻描太淡就抬 min）。
  自检 `--pressuretest`（**28 项**：映射 / 上屏墨量随压力单调 /
  **半压=鼠标 1.00×、轻描 0.33×、重压 1.72×、满压 2.00×（对着那张图逐项比）** /
  回退 / 荧光笔不吃压感 / 离屏与导出那条路 / 存档往返 + 真·v9 老文件）

  操作条贴到屏幕下边会停在原地（`BarRect` 的"给下限、不翻面"），而 8 个手柄与操作条

  度数标签；缩放手势不变——拖手柄时别的柄是有用的参照）。更实的一步在底下：拖动期间
  **模型一个字都不改**，被拖的那一批从内容层摘出去、改画在浮动层上——于是
  ① 它自己"浮"起来（不用去压暗周围），② 内容层**一帧都不重画**（实测 0 块/帧；
  一万条画面的每帧记录从 51.7ms 的修补掉到 2.7ms），③ 松开那一下像素级对得上
  （同一段墨量 1600 vs 1600）。代价：拖动中这批暂时压在最上层（松手回归）；
  起手那一下要一次性重画它们压过的块（一屏量级十几毫秒；一万条的极端画面约 0.1 秒）。见
  [调研-选中框-移动与旋转.md](调研-选中框-移动与旋转.md)，自检 `--seltest` 44 项
- **落点反馈**：鼠标悬停/书写时自绘（笔＝双层圆环、荧光笔＝直径 = 笔宽的圆盘、激光笔＝实心点、
  橡皮＝圆环、像素橡皮＝竖着的黄金比例矩形），手写笔落笔后不画（笔尖本身就是落点），触摸一律不画；
  笔环是"内圈＝真实笔宽 + 外圈＝最小可见尺寸"，所以 1.5 像素的细笔也看得见落点又不会误判粗细
- **笔迹两端是圆头、拐角是圆角**：由 D2D 的描边样式（`Gfx.Round`）保证；
  单击一下是一个圆点、宽笔拖出来是两头半圆的香肠
- **旋转度数显示与吸附**：拖动中浮出度数标签，90° 软吸附（±3°，可 Alt 关），
  Shift 是 15° 硬网格，一次拖拽一步撤销
- **键位可配置**：全局 / 批注内两档作用域 + 冲突检测 + 注册失败可见 + 落盘
- 穿透模式，三种实现方式都做了对照
- 内容层缓存 + 增量更新（结束一笔只重画那一小块）
- 内置性能面板（帧率、耗时、内存、CPU）和一万笔压力测试

### 性能面板（Ctrl+I 开关，2026-09-19 从全局降到应用内）

面板按 **DPI** 生成字号（以前字号写死 15 物理像素，200% 缩放的屏上只有
7.5 逻辑像素高——投影上看不清，这是"看不清"的根因，不是框不够大）。
整个面板画进一张**缓存位图**，只有数字变了（4 Hz）才重排一次：
每帧代价从 **4.3 ms 降到 0.05 ms**，所以框放大到 700×258 逻辑像素也不心疼。

内存那一行是三个口径并列，**并且标出在任务管理器里叫哪一列**：

| 面板显示 | 任务管理器里 |
|---|---|
| 内存 x MB（专用工作集） | 「内存」列 |
| 已提交 x MB | 「提交大小」列 |
| 工作集 x MB（含共享） | 详细信息里的「工作集」 |
| 共享提交 x MB | 解释"工作集为什么比专用大" |

取数走 `GetProcessMemoryInfo(PROCESS_MEMORY_COUNTERS_EX2)`（Windows 11 起），
实测与 `\Process\Working Set - Private`、`NtQuerySystemInformation` 的
`WorkingSetPrivateSize` 三者一致；比原来的 `Process.Refresh()` 便宜两个数量级
（统计那一栏 3~4 ms → 0.03 ms）。

> 自检/基准模式下面板默认**关**（除非 `--hud`）：它是个大黑框，压在屏幕左上角，
> 而很多自检的判据正是"数屏幕上的墨"，面板一盖就会假失败。
- 引擎与界面已拆分：引擎可独立编译，界面只通过 `IOverlayUi` 接入，
  输入优先给界面、界面画在自己的矩形里（代价约 0.4 ms/帧）
  粗细点开是档位表（一步到位）、穿透后给提示并让出点击
- 笔迹两端是**圆头**：单击＝圆点、短拖＝两头半圆的胶囊、宽笔＝香肠形。
- **折角不掉色**：外侧补半径 = 半宽的圆弧（≡ D2D 的 round join），内侧补到两条
  内边的交点（上限 3 倍半宽）。原先"偏移点只摆到半宽"的写法会把外角切掉一块、
  内角也缺一口，宽笔上肉眼可见。自检：`--captest` 15 项 + `--cornertest` 9 项
  （含"拐角不超出脏区"这条残影防线）。来龙去脉见 [调研-折角掉色.md](调研-折角掉色.md)

## 还没做 / 没验证的

- **穿透模式下真实点击是否落到下层程序**：自动化的命中测试已经通过，但还需要人工点一下确认
- **`--uitest` 里"穿透·面板外交下层 / 面板外不落墨"这两条是偶发失败**（2026-09-18 记）：
  归档的报告里 **12 份全绿、8 份全红**，同一份代码两种结果，而且红的时候签名一模一样
  （下层窗口收到 0 次点击、笔画 1 → 0）——是**时序/前景窗口**那一类问题，不是功能坏了。
  待查方向：点了下层窗口之后，**前景窗口有没有还回来**。**单开一轮查**，别和别的改动混在一起
- **面板展开态的每帧代价超了红线**（+2.54 ms，红线 1.5）：其中约 0.46 ms 是浅色投影
  从 2 层加到 5 层付的，其余是这台机器的噪声（同轮归因里"不算色片细节"反而变慢）。
  解法不是砍层数，而是 [reports/性能-面板每帧代价.md](reports/性能-面板每帧代价.md)
  §三那条：**引擎先开"绘制前准备"的口子，再上静态底缓存**——投影与这 1.5～2.5 ms 是一起归零的
- **手写笔的真实延迟手感**：分段延时的量化已经做完（见[延时-实测与优化.md](延时-实测与优化.md)），
  但"真笔端到端主观手感"和"委托墨迹轨迹到底画不画得出来"需要真笔确认一次
  （`--penlive 30`，手写笔在屏幕上写 30 秒即可）
- **压感这条线的三件收尾**（2026-09-20 记）：
  ① **主观手感还没在真机上定过**——`2.0 / 0.10` 是从用户那两张图上反推的，
     四个锚点（半压/轻描/重压/满压 = 1.00 / 0.33 / 1.72 / 2.00）逐项对得上，
     但"顺不顺手"要真人拿笔写才知道：真机上用 `--pressrange min,max[,gamma]` 现调
     （嫌重压太粗就降 max 到 1.6~1.8，嫌轻描太淡就抬 min）；
  ② **一万条压感笔迹的每帧代价没量过**：变宽那条路每次重画要现建 ink 对象
     （按点数抽稀到 ≤120 段），正常写字时只有一笔脏、代价可忽略，但"一屏压感笔迹
     整层重铺"必须用性能套件量一次（`Run-PerfSuite.ps1`）；
  ③ **倾角 / 旋转还没用上**（`PenSample` 里已经有了、存档里没存）——侧锋那种笔刷的前提
- 委托墨迹轨迹的**预测点**已经在用了（`AddTrailPointsWithPrediction` + 自写的
  `InkPredictor`，见 `--predicttest` / `--wetinktest`）；还能抢的是"预测点也带压力"
  （微软的预测器会连压力一起推，我们自己写的那套目前只推位置）
- **预测尾（2026-09-22）**：鼠标 / 触摸现在也吃预测了。以前预测只喂真笔的委托轨迹，
  而"手写板没开 Windows Ink（以鼠标上报）"和"触摸屏"这两条路**没有任何低延时通道**，
  墨的末端永远落在上一帧。现在把预测段接进**正在写的那一笔的几何里**
  （`Stroke.RenderTail`，同一个 figure，所以半透明荧光笔不会在接缝处变深），
  末端就回到"现在"。四条前提：预测开着、这一笔没交给系统合成器画、自由笔迹+笔/荧光笔+实线、
  预测器真的出了点（慢写与急转弯它会主动不给）。**2026-09-29 起预测默认关**（用户拍板：
  真笔那条 DWM 不画我们喂的预测点、鼠标那条自绘尾会让末端"突突突往外跳"，而开与关手感分不出来）——
  `--predict` 打开做对照，`--predictms` 调地平线、`--predictlead` 调前带量上限；自检 `--predicttailtest`
  （它自己会把开关拨来拨去，不依赖默认值）。
  ⚠ **真笔 + 委托轨迹时这条尾是"让给系统"的**（见 `Engine.ActiveStrokeOnTrail`）：
  那一笔的湿墨由系统合成器画，我们只把预测点交给 `AddTrailPointsWithPrediction`。
  所以调 `--predictms / --predictlead` 在**真笔上几乎看不出效果**——2026-09-22 用户实测
  原话："用鼠标写的时候确实很难受……用手写板没有感觉"。要看它到底有多大效果，先把委托
  轨迹关掉：`InkTeach.exe --noinktrail --predictms 100 --predictlead 100`，鼠标上那一长段
  在真笔上照样会出现。
  另一个副作用要在真机上定：笔工具下系统光标是藏起来的（落点圆环由我们画），
  所以墨会比圆环略微超前一点——嫌多就把 `--predictlead` 调小。
  ⚠ **渲染有两路，尾必须两处都接**（2026-09-22 用户实测抓到的坑）：无压感笔迹走等宽描边
  （几何出自 `BuildCenterline`，那里带尾）、**有压感笔迹走 `ID2D1Ink` 变宽那条
  （`DrawPressureInk`）**。只接了前者，表现就是"鼠标甩得出来、手写板毫无反应"——
  而真笔**必然**报压感、走的正是 ink 那条，等于这个功能对主力设备一直是没生效的。
  `--predicttailtest` 的 ③ 专门盯这一条（先断言走了 `PressureInkDraws`，再数末点之外的红像素）。
  顺带把 `POINTER_INFO` 的合并点也读了（`--penlive` 打印的 `[笔画] … 合并(N 条消息 → M 个采样点)` 那一行现在鼠标/触摸也有数）
- **同一时刻只跟一条指针（2026-09-22）**：`OnPointerDown` 以前没有"已经有指针在手"的守卫，
  而**只有触摸踩得到**——鼠标和笔一次只有一个指针。触摸屏上写字时蹭到的第二根手指
  （或者落屏的掌根）会把 `_activePointer` 抢走、`ActiveStroke` 换成新的一笔，
  而**正在写的那一笔还没进文档，于是"写一半的字凭空消失"**。现在 `_drawing` 为真时
  后来的按下直接忽略（顺带把"拖滚动条/擦除中第二根手指插进来起一笔"也堵住了）。
  自检 `--touchguardtest`。**这还不是完整的掌心抑制**：掌根**先**落屏时它仍然占住指针，
  真正的掌拒要按"笔在接触时忽略触摸"那条策略做（见对标文档里 P0 那一条）
- 触摸这条路上仍然空着的：**落点反馈不画**（`CursorKind.Hidden` + `ToolCursorShape.None`）、
  多指手势（两指缩放/平移）没有、触摸面板的合并点在真机上能拿到多少还没量过
  （触摸屏上跑 `--penlive 20`，看"非笔指针（鼠标/触摸）"那一行）
- **书写期间的 GC 低延迟档 + 分配/GC 仪表（2026-09-22，低配机第一批）**：
  · [GcLatency.cs](src/InkEngine/GcLatency.cs)：书写期间进 `SustainedLowLatency`——
    它抑制的是**前台第 2 代回收**，而那正是"笔突然卡一下"的元凶（要扫整个堆、可能压缩内存，
    一次几十毫秒）；停手满 5 秒退回。⚠ 两件文档里写明的事：它**依赖后台 GC**（所以设完要
    读回来确认，不是"设了就当生效"）、而且**系统发低内存通知时会打断它**——低配上光开这一条
    不够，还得同时管住内存占用。`--nogclatency` 关（做对照）、`--gchold N` 调保持毫秒
  · **写一笔的分配 / GC 次数**进了 `[笔画]` 那一行（例：`分配 27.5 KB/GC 0/0/0`）和 `--penlive`
    汇总；第 2 代回收**出现在书写期间**会单独告警。这是后面所有低配优化的**验收依据**——
    先有数字再改，不然动错地方就是白干
  · 启动横幅顺带打印**系统笔设置**（`HKCU\Software\Microsoft\Wisp\Pen\SysEventParameters` 的
    HoldMode / WaitTime / HoldTime）：**"长按当右键"在板书停顿多的场景容易添乱**。
    值只**如实打印**、不解释哪个取值代表开还是关（没有可靠出处，不猜）
  · 自检当场抓到一个设计 bug：保持窗口一开始只在"按下"那一刻刷新，**一笔写得比窗口长就会在
    笔画中途退出低延迟档**——越写越容易卡，正好和目的相反。现在手势进行期间一直保持
  · **没做：缓存几何实现（`ID2D1GeometryRealization`）**。它省的是**全页重画**（滚动/翻页），
    不是写字延迟；而且"缓存对象能不能跨窗口 context 用"（同一台 D2D 设备、每个窗口一个
    context，见 `Overlay.cs`）要先查清 D2D 的规则，属"先测再改"那一类
- **"重启"的两种语义分开了（2026-09-22 用户定）**：界面上那个「重启软件」现在**等于电脑重启**——
  真拉新进程、自己退出（内存全还给系统），**板书不接回来**，新进程起来是一块干净白板。
  为了误点不致命，**盘上留一份自动存档**：写 `Recovery.SaveAuto`（不受"下次打开要不要接上"
  那个偏好影响），并把会话暂存**主动删掉**（`Recovery.DiscardSession`——光"不写"不够，
  上次崩溃抢救的残留会被新进程读回去，那就成了"重启还带出旧板书"）。
  ⚠ 而"界面崩了自动重建"那条路**照旧不丢板书**（写会话暂存、启动读回）：那种情况是 App
  自己决定重启、老师没要求，丢了是事故。**两处判据正好相反，别一起改**——
  `--paneltest` 与 `--uitest` 各钉一边（会话暂存必须"不存在" / 必须"读得回来"）。
- 冻结截图模式、多显示器跨屏、HDR 色彩
- 界面自身还差几条（见 [计划-底层对接界面.md](计划-底层对接界面.md) §10.1 的表）：
  极简档只给 4 色、色带开合的热键、贴边隐藏首次开启的一次性提示、**光标按工具区分**
  （截图与七种图形现在共用一个十字）、键位编辑界面
