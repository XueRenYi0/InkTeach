# 手写体替换 · 方案与决策（2026-11-05）

> 目标：识别板书后，**在原位置**把字换成“像手写、但每个学生都认识”的字体。
> 不覆盖原板书，结果可撤销。

---

## 1. 已定的决策

| 项 | 结论 | 依据 |
|---|---|---|
| 中文手写字体 | **志莽行书（Zhi Mang Xing）** | OFL 授权，可商用、可随软件分发；用户看效果认可 |
| 拉丁字母 | 手写拉丁字体（演示用 Ink Free，上线换 OFL 拉丁手写体） | 用户确认“英文也跟手写” |

## 2. 混排规则

```
一行文字 = [中文段][公式段][中文段]…
  中文段 → 志莽行书，按原行高定字号
  公式段 → KaTeX 渲染成矢量，按正文 x-height 缩放、基线对齐
  英文段 → 手写拉丁字体（或随中文）
```

- 行框来源：**用自己的笔画数据算**（投影切行 + 列范围），不用 OCR 的 bbox。
- 宽度不够时**缩字号重排**，不横向拉伸（拉伸会让字距变宽、笔画变细）。
- 颜色取该行原墨迹的中位色（红/蓝分开处理）。

## 3. 交互（2026-11-05 用户改定）

**入口：选中操作条末尾接一条「彩色 AI 条」**，点开是下拉菜单，里面放各类 AI 动作：

```
选中对象 → [操作条：删除 复制 置顶 …][AI ▾]
                                      └─ 手写优化
                                         识别文字
                                         转公式
                                         生成图像
                                         （以后再加）
```

- **就地替换**：直接改原对象，**不生成新页**。
- **一步撤销**：`Ctrl+Z` 回到替换前；不要求“左右对照预览”。
- 只处理选中的文字行；图形/箭头/圈注原地不动。
- 公式默认保留原笔迹（二期再谈是否换印刷体）。

### AI 格的视觉（2026-11-05 用户定）

- **跟着操作条一起出现**，在「全选 / 复制 / 粘贴」后面。
- **彩色、丰富、梦幻**：青 → 紫 → 粉 的横向渐变（`#22D3EE → #A855F7 → #F472B6`），
  白色 `AI` 字 + 右下小三角 `▾`；hover 时渐变提亮并加一层柔光。
- **下拉只放已做好的项**（用户选 A）：当前只有「手写优化」，
  以后加「识别文字 / 转公式 / 生成图像」时再逐条出现，不展示灰项。

和 1A 那个「AI 出题」面板的关系：
- 出题是**居中弹窗**（输入要求 → 生成题卡）；
- 手写优化是**即时动作**，不需要输入，点完就做，所以放在下拉里而不是弹窗。

## 4. 明确不做

- **不做“美化原笔迹”作为主打**：实测平滑 + 笔宽统一后，肉眼几乎看不出差别
  （见 `调研/AI-板书识别-基准-2026-11-05.md` 与 `--inkbeautify` 的实现）。
  代码保留为隐藏项，不做宣传。
- **不做整页自动排版**：会破坏老师原有的版面结构。
- **不覆盖原笔迹**。

## 5.1 填充方案（2026-11-06 调研，用户指定）

### 外面怎么做的（调研结论）

- **显卡/2D 库的通用做法**：字形是「轮廓 + 填充规则」。
  Direct2D 的 `ID2D1PathGeometry` + `FillGeometry`，填充规则 `D2D1_FILL_MODE_ALTERNATE`
  就是 even-odd——外轮廓与内孔交替，孔自动空出来（Microsoft Docs）。
- **矢量软件（Illustrator / Inkscape / Figma）**：同一个字形是一条「复合路径」，
  用 even-odd 或 nonzero 决定哪里填、哪里挖孔；导出 TrueType/Android 时只能 nonzero，
  所以才需要手动反转方向。
- **绘画软件的「正填充/反填充」**：本质是 even-odd vs nonzero 两套规则，
  不是两种算法。

### 我们的做法

新增一种对象 `StrokeKind.Glyph`：

| 项 | 设计 |
|---|---|
| 存什么 | 若干闭合轮廓（三次贝塞尔 + 折线），`FillMode = Alternate` |
| 从哪来 | SkiaSharp `SKPath` 取字形轮廓（`GetTextPath`），逐条 verb 存下来 |
| 渲染 | 建 `ID2D1PathGeometry` → `FillGeometry`，孔自动空 |
| 缩放 | 纯矢量，**任意大小一模一样**，没有锯齿 |
| 命中 | `ID2D1Geometry.FillContainsPoint` |
| **局部擦除** | `ID2D1Geometry.CombineWithGeometry(..., EXCLUDE, 橡皮圆)` → **布尔减**，擦掉一点是可行的 |
| 存档 | 加一种 kind；老文件不受影响 |
| 导出 | 复用现有离屏渲染 |

### 和中心线方案对比

| | 中心线墨迹 | Glyph 填充 |
|---|---|---|
| 还原度 | ~85%，有毛刺/多余点 | **100%** |
| 缩放 | 平滑但会变细 | **完美** |
| 局部擦 | 天然支持 | 需要布尔减（D2D 支持） |
| 工作量 | 小 | 中（新对象类型） |

> 结论：**改用 Glyph 填充**。中心线版留作后备（代码在 `GlyphInk.cs`）。

### 实测发现的识别问题（2026-11-06）

用真实 b1 板书跑 DeepSeek `deepseek-flash`，12 行里仍有 2 处数学识别错误：

| 位置 | 识别 | 正确 | 后果 |
|---|---|---|---|
| 第 8 行 | `AB 与 DD₁ 异面` | `AB 与 D₁C₁ 异面` | 线段改了，整题例子变了 |
| 第 9 行 | `后两者都叫 ∉` | `后两者都叫 ⊄` | 集合符号错误 |
| 第 3 行 | `点在面上 A ∈` | `点在面上：A ∈` | 少冒号，属格式问题 |
| 第 7 行 | `二、1` | `二、1.` | 少点号，属格式问题 |

> 结论：**公式行不能盲替换**。所以默认「保留公式」；「含公式」只给明确知道风险的用户。
> 另外模型偶尔会把立方体顶点 `D`、括号批注 `（包含）/（答对）` 单独认成一行，
> 已在 `OcrText.FilterLines` 里过滤，切行也改成只信几何（不再按 OCR 行数硬补）。

### 识别服务怎么配（测试期）

只设环境变量即可，**密钥不进 git / 安装包**：

```powershell
$env:DEEPSEEK_API_KEY = "sk-..."          # 官方 DeepSeek：base/model 自动填
# 或任意 OpenAI 兼容中转：
$env:INKTEACH_AI_BASEURL = "https://xxx/v1"
$env:INKTEACH_AI_KEY     = "sk-..."
$env:INKTEACH_AI_MODEL   = "deepseek-flash"
$env:INKTEACH_AI_THINKING = "auto"        # auto / disabled / low / none
```

也可以写 `%APPDATA%\InkTeach\ai.json`：

```json
{ "baseUrl": "https://api.deepseek.com", "key": "sk-...", "model": "deepseek-flash", "thinking": "auto" }
```

### 复杂排版算法（2026-11-06 设计）

> 详细方案见 `调研/AI-手写体替换-复杂排版-算法.md`：
> RLSA → 递归 XY-cut → 块级 OCR → 字格 DTW。
