## 零、先给结论（三句话）

1. **"小 bug 多"这个判断是对的，而且能指到具体出处**：残影、接缝、坐标错位、
   拐角掉色、起笔毛边——全部来自下面 A/B 两张表里**我们自己加的加工**，
   没有一条来自 Windows 或 Direct2D。
2. **但"延迟是它们造成的"这个判断不成立**（有实测）：笔尖动→像素亮共五段，
   我们**自己画一帧只占 2 ms 量级**，延迟的大头是"等垂直同步/等合成"
   （13.4 ms → 修好后 0.31 ms）。把渲染算法再优化也救不了手感。
3. **所以"统统删除"要分开看**：
   - **形状加工（A 表）**：删了不影响延迟，但会退回"平头、拐角缺块、单击不是圆点"。
     真正该做的是**把参数写死、把分支收敛**，而不是删功能。
   - **管线加工（B 表）**：**不能删**。删了以后一万笔每帧要重画 **154 ms**
     （实测），那才是真的卡。它们的代价是复杂度，收益是 30 倍。
   - **真正能删干净的是 C 表：实验开关与多档实现**——一个行为只留一条路，
     代码里不再有"可能走错的那条分支"。这是立刻能减少 bug 面、又不动性能的动作。

## 一、A 表：对"墨迹形状"的加工（改变它长什么样）

| # | 处理 | 在哪 | 为什么加 | 代价 | 历史 bug | 删掉的后果 | 建议 |
|---|---|---|---|---|---|---|---|
| A1 | 压感→宽度映射 `w × (0.6 + 0.8P)` | `Model.HalfWidthAt` | 手写笔有压感，粗细跟手 | 一处乘法 | 无 | 全笔等宽（压感白采） | 留 |
| A2 | 两端**半圆端帽**（分段数按半径自适应 6~32 段） | `Model.BuildRibbonFromPoints` | 你要的：单击＝圆点、宽笔＝香肠不是长条 | 每端最多 31 个点 | 平头→你反馈"长条" | 已删：改由 D2D 描边的圆头端帽（观感实测更好） | **已删** |
| A3 | 拐角处理：外侧**圆弧** + 内侧补到两条内边交点（上限 3 倍半宽） | 同上 | 修"尖角外侧少一块" | 每拐角最多 ~32 点；脏区外扩系数 1.4→4.2 | ①旧写法外角削 0.41r、内角缺一口；②曾被"补圆弧"的反向绕向挖出洞 | 已删：20 组对照证明与 D2D 逐像素等价 | **已删** |
| A4 | 方向取"前后**不一样**的点"（跳过重合坐标） | 同上 | 鼠标按下瞬间连报相同坐标会把方向摊成水平 | 两次 while | 起笔毛边 | 起笔处一个尖角/毛刺 | 留（20 行） |
| A5 | 所有点重合 → 画一个圆 | 同上 | 退化数据别画成 1 像素细丝 | 4 行 | 无 | 极端数据下一条细丝 | 留 |
| A6 | 单圈轮廓 + **Winding** 填充 | 同上 | 自交不被挖空；半透明荧光笔不叠深 | 1 行 | 若用默认 ALTERNATE：内角挖洞 | 内角出洞、荧光笔自交处变深 | 留（1 行） |
| A7 | 荧光笔半透明（α=0.32） | `Ui.InkPalette.ToHighlighter` | 荧光笔语义 | 0 | 无 | 变成实心粗笔 | 留 |

| A10 | 橡皮沿路径插值擦除 | `Engine.EraseAlongPath` | 快速划过不漏 | 每段最多 48 步 | 早期"橡皮没反应" | 快划漏擦 | 留 |

## 二、B 表：管线加工（为了性能/延迟，不改变墨迹形状）

| # | 处理 | 在哪 | 实测收益 | 删掉的后果（有数字） | 历史 bug | 建议 |
|---|---|---|---|---|---|---|
| B1 | 画布坐标 + 相机（滚动只动一个数） | `Engine.ScreenToCanvas`、`Overlay.CanvasToWindow` | 滚动不重写点数据（一万笔滚一格重写十万点 = InkClass 的坑） | 滚动要重算全部点 | **踩过 4 次**：脏区/裁剪漏相机、滚动后写不了字 | 留 |
| B2 | 脏矩形集合（合并 + 上限 32 + 最小面积并法） | `Model.DirtyRegion` | 只重画变化的区域 | 每帧全屏重画 | 漏标脏 → 残影（多次） | 留 |
| B3 | 内容层**分块缓存**（脏/补画/淘汰/预算 + 子矩形合成） | `CanvasTiles.cs`（333 行） | 滚动 82 ms → **3.6 ms**；密集页光栅 3.40 → **1.35 ms** | 一万笔每帧重画 **154 ms**（核显不可用） | 接缝、块内变换写反、空间索引只索引中心线、浮动层混用坐标 | 留 |
| B4 | 几何**细分缓存**（realization）+ 保留策略/预算/淘汰 | `Model.GetRealization`、`RetentionMode` | 每帧记录 1.3~1.9 ms（与内容量无关） | 单笔重建 3.4 µs × 每帧可见笔数 | 内存棘轮（全留 393 MB） | **已删**：它只服务"填充几何"；笔迹改成描边后没有用户，顺带拿回 100 MB 量级的常驻内存 |
| B5 | 空间索引（网格，只查邻近） | `SpatialGrid.cs` | 命中从 O(笔画数) 降下来（实测快 32 倍） | 橡皮/框选每帧遍历全部 | 只索引中心线 → 块边界缺一块 | 留 |
| B6 | 委托墨迹轨迹（湿墨交系统画） | `Overlay.BeginInkTrail` 等 + `Native` + DComp | 接口已接；**真笔实测：本机系统不渲染**（2026-10-05，判据修正后）——当前收益＝0，作换机备用 | （若真渲染则）真笔手感不受我们渲染节奏影响 | 判据两次被干墨累积假阳性骗过（已修） | **留但保持可关**（`--noinktrail`）；`--syswet` 勿用 |
| B7 | 呈现配速（`DwmFlush` → 抽消息 → `Present(0)`） | `Overlay.Present` | Present 阻塞 13.4 → **0.31 ms**；"返回→变色" 58.3 → **16.3 ms** | 回到 Present(1)：每帧多等 13 ms、消息排队 | 无 | 留（这是延迟正解） |
| B8 | HUD 缓存位图（4 Hz 重排）+ 各类计数器 | `Overlay.PrepareHud` | HUD 每帧 4.3 → 0.05 ms | 面板文字每帧重排 | 无 | 留（默认关） |
| B9 | 滚动条自动隐藏 + 淡出动画 | `Overlay.DrawScrollBar` | 观感 | 动画期间每帧标脏（很小） | 无 | 可简化（去掉淡出，省掉动画脏区） |
| B10 | 截图时先藏覆盖层 | `ScreenCapture.HiddenOverlay` | 截图不把自己拍进去 | 截图会带上批注 | 无 | 留 |
| B11 | 只在脏区/可视范围内绘制（裁剪） | `Overlay.RenderFrame` | 每帧只动脏区 | 每帧全屏 5.2M 像素 | 无 | 留 |

**B 表的账**：这些"聪明处理"就是延迟和内存数字的来源。
**删 B2/B3/B4 任一项，都会把每帧代价从 1.3~1.9 ms 拉回几十上百 ms。**
它们确实也带来了最多的小 bug——**这正是取舍本身**：用复杂度换性能。
能改进的方向不是删，而是"**一个行为只留一条路**"（见 C）。

## 三、C 表：实验开关与多档实现（**建议统统删**）

这些不影响功能，只让代码里多出一条"可能走错的路"。当前命令行开关 **63 个**，
其中相当一部分是这类：

| 类别 | 具体 | 处理建议 |
|---|---|---|
| 呈现方式多档 | `--nopace`、`--vblankpace`、`--latencywait`、`--bufcount`、`--framestats` | 只留默认（配速）+ `--nopace` 一个逃生口；其余删 |
| 内存 A/B | `--memab`、`--norealize`、`Stroke.KeepGeometry` 静态开关、`RetentionMode` 三档 | 只留实测最好的一档（画完丢路径几何、留少量细分缓存），删掉另外两档与开关 |
| 渲染 A/B | `NoContentCache` 整条"每帧全量重画"路径、`CenterlineRendering`、`MultithreadedRaster`、`LaserAdditive` 开关 | 删（提性能数据时用一次就够，不必常驻代码） |
| 调试 | `--laggy`（人为延时）、`--mtraster`、`--nohist`、`--nosettings`、`--activate` | 删 |
| 参数化 | `--tilesize 256/512`、`ScrollBackBytes`、`MaxRealizations`、`RealizationPointsBudget` | 默认值已经实测选好，**写死**；旋钮删掉（少一类"参数不一致"的 bug） |

**这一批删完，行为一条都不会变**（因为留下的都是实测最优那一条路），
但代码里"走得通的分支数"会下降一大截——这才是你要的"统统删除"。

## 四、如果真要"统统删掉"会变成什么样

最小墨迹管线（把 A、B 表的加工全去掉）只剩：

```
指针坐标 → 点列表 → 每帧把可见笔画用等宽带子（平头）重画一遍
```

代价（都是有数字的）：

| 失去 | 后果 |
|---|---|
| A2/A3 | 平头长条、拐角缺块（你之前反馈过两次） |
| A5/A4 | 单击变扁条、起笔毛刺 |
| B2/B3/B4 | 一万笔每帧 **154 ms**（≈6 fps），滚动 82 ms/格 |
| B7 | 每帧多等 13 ms，笔尖拖影回来 |
| A11/A12 | 宽笔选中框压在墨上、框选永远选不全 |

所以"统统删除"更准确的版本是：**功能与形状照旧，把 C 表那批开关和第二条实现删掉。**

## 五、我建议的动作（等你点头就做）

**第一批（零风险，行为不变）**：删除 C 表里"实验开关 + 多档实现"：
