# 调研：拍照美化、PDF 切题、OCR 重排版

- 日期：2026-10-25
- 状态：**只调研，不改代码**
- 背景：用户明确三件最想要的事——
  1. 学生手拍的题目，怎么美化成像扫描件/正规黑白卷；
  2. PDF 上很多题，怎么一道一道切开，像 PPT 一样在白板里讲；
  3. 拍晃了/拍糊了，能不能识别后重新排版成好看的。
- 关联：`调研-图片与PDF处理.md`、`调研-图片与PDF-AI优先重评估.md`、`调研-AI助手与大模型语音接入.md`

---

## 0. 结论速览

1. **拍照美化：最确定、最快能上，建议第一个做。**
   纯本地算法就能做到“扫描全能王”八九成效果：去阴影、去灰底、白平衡、对比度、锐化、自适应黑白。
   一张 600 万像素的图，全流程约 **100~300ms**，不需要联网、不需要大模型。
2. **PDF 切题：价值最高，但要分两条路。**
   - **数字版 PDF**：PDFium 自带文字层和字符坐标，切题主要靠规则，**一页 <200ms**，又准又便宜，AI 只是兜底。
   - **扫描版 PDF / 照片**：必须先 OCR 拿到“文字行 + 坐标”，再切；一页约 **2~6 秒**，要后台跑、预取下一页。
3. **“切开一道一道像 PPT”不用另造一套系统。**
   现有文档页 `DocPages` 已经是“一叠页 + 底部页码条 + 翻页 + 每页批注”，
   只要让每一页的配方变成“源 PDF 的某个矩形”，就得到题目集；**能复用 70%~80%**。
4. **OCR 重新排版：不建议第一版做。**
   “美化”不等于“重排”。重排要处理公式、图形、表格、分栏、断行，任何一处错都比如实拍更难看；
   而且渲染 LaTeX 要额外依赖。第一版用“增强 + 黑白 + 可复制文字”就够，重排放 beta。
5. **DeepSeek V4.1 Flash 确实适合当“大脑”，但不适合当“眼睛”。**
   它原生多模态、便宜、快，但**每张图最多 1024 token、会缩到约 1300×1300 总像素**；
   整页小字会糊，公式更不可靠。正确分工：
   - **眼睛**：`qwen3.5-ocr` / `qwen-vl-ocr`（带行框、公式、表格），或本地 PaddleOCR；
   - **大脑**：DeepSeek Flash 做“哪一行是第几题”“怎么归类/讲解”，只吃文字，快且准。
6. **速度可控**：数字 PDF 规则切题几乎瞬时；OCR 切题 2~6 秒/页，后台 + 预取 + 可取消；
   老师翻到下一页时，下一页的题已经切好了。
7. **推荐顺序**：拍照美化（2~3 周）→ 数字 PDF 切题（4~6 周）→ 扫描件 OCR 切题（3~4 周）→ 重排版/AI 解题（可选）。
   若 AI 基础设施（BYOK、任务队列）还没做，前面再加 3~4 周。

## 1. 三个功能，翻译成产品语言

### 1.1 拍照美化 = 三档，不是一档

| 档位 | 效果 | 技术 | 建议 |
|---|---|---|---|
| **增强** | 原图还是原图，但阴影没了、底变白、字更清楚、颜色正常 | 背景估计 + 白平衡 + 对比度 + 锐化 | **默认**，最安全 |
| **黑白** | 像印刷试卷：纯白底、黑字、没有灰雾 | 自适应二值化（Sauvola）+ 去噪 | 老师最爱，但会丢彩色标注 |
| **重排版** | 识别文字后重新排版成“电子版” | OCR + 版面重建 + 公式渲染 | 最后做，风险最高 |

> 关键认知：**“看起来正规”主要来自“白底 + 黑字 + 平整”，不是来自“重新打字”。**
> 增强和黑白就能解决 80% 的“拍得丑”。

### 1.2 PDF 切题 = 两种输出

- **A. 题目集（推荐）**：每道题 = 一页，底部页码条 1/20、上一页/下一页，笔迹批注按页保存。就是“像 PPT 一样一道一道讲”。
- **B. 贴到白板**：把每道题裁成图片对象，摆到白板的某一页上，自由排列。适合“拼几道题一起讲”。

A 复用现有文档模式最多，B 复用现有图片对象最多。第一版建议先做 A。

### 1.3 “拍晃了” = 先判断，再决定救不救

- 轻微模糊：锐化 + 适度放大，能改善观感，但**不会凭空造出细节**。
- 明显运动模糊：数学上需要知道模糊方向和核，普通锐化救不回来；AI 去模糊可能“编字”，对题目是灾难。
- **正确产品策略**：检测清晰度 → 提示“这张糊了，建议重拍” → 提供“仍然使用/增强试试”。
  不要承诺“糊了也能变清晰”。

### 1.4 AI 解题 = 锦上添花

- 选中题目裁图/文字 → 侧栏流式输出讲解，不改板书、不自动写答案。
- 用 DeepSeek Flash（文字）或视觉模型（单题裁图）即可，成本约 0.01 元/题。
- 需要 Markdown + 公式显示；这是独立的小工程，不要和“切题”绑在一起。

## 2. 拍照美化：具体怎么做

### 2.1 处理流水线（全部本地 CPU）

| 步骤 | 做法 | 作用 | 6MP 耗时 |
|---|---|---|---|
| 1. 解码/EXIF 转正 | 已有 `DocImageSource` | 手机竖拍不横着 | 解码另计 |
| 2. 找纸边 | 自动（Otsu + 最大连通域 + 四边形）或手动四点 | 去掉桌面/手指 | 30~80ms |
| 3. 透视校正 | 单应矩阵 + 双线性重采样 | 拍斜了变正 | 50~150ms |
| 4. 去阴影/底灰 | 缩小估背景 → 相除归一化 | 阴影、光照不匀 | 30~60ms |
| 5. 白平衡 | 按背景 RGB 均值归一 | 去黄光/蓝光 | 10~20ms |
| 6. 对比度 | 1%/99% 分位拉伸 或 S 曲线 | 字更黑、底更白 | 10~20ms |
| 7. 锐化 | 非锐化掩模（半径 1px，强度 0.5~0.8） | 手机软焦变利 | 20~40ms |
| 8. 黑白（可选） | Sauvola 局部阈值 + 去孤立点 | 正规试卷感 | 40~100ms |
| 9. 输出 | 长边 2000~2400，PNG/JPEG | 够清、不过大 | 20~50ms |

> 总计约 **150~400ms**（6MP，后台线程）。预览用 1000px 缩图，约 **20~50ms**，滑杆可以接近实时。

### 2.2 去阴影是“黑白好看”的前提

很多“黑白”做出来一团黑，是因为直接全局阈值。正确顺序：

1. **估背景**：把图缩小到 1/8，灰度，做一次大半径模糊（半径约短边的 1/20），再放大。
2. **归一化**：`out = clamp(src × (245 / bg))`。
   白纸处 bg≈200、阴影处 bg≈120，都会被拉回 245；字仍然是黑的。
3. **再二值化**：Sauvola（窗口 31~51，k≈0.2~0.3），比 Otsu 更抗光照不均。
4. **去噪**：去掉面积 < 3~5 像素的孤立黑点；不要用中值滤波大核，会把细笔画磨掉。

### 2.3 预设参数（建议直接给老师四个按钮）

| 预设 | 处理 | 适用 |
|---|---|---|
| 原图 | 只转正/裁边 | 对照 |
| 清晰 | 去阴影 + 白平衡 + 对比 + 轻锐化 | 默认 |
| 试卷 | 清晰 + Sauvola 黑白 + 去噪 | 打印/投影 |
| 护眼 | 清晰 + 暖白底（245,242,232） | 长时间看 |

另外给“重置”和“前后对比（按住看原图）”，这是信任的关键。

### 2.4 自动找纸边：先做便宜版

- **便宜版（推荐第一版）**：缩到 800px → 灰度 → Otsu → 最大连通域 → 凸包 → 最小外接四边形。
  白纸放在深色桌面上很稳；白桌面上会失败，失败就自动转手动四点。
- **AI 版**：视觉模型给四个角点。坐标精度一般（±2%~5%），只能当“建议”，仍要手动微调；
  为这点体验多一次网络请求不划算，**不建议第一版**。
- **OpenCV 版**：Canny + Hough + 轮廓筛选，稳但要带 38MB 原生包，第一版不引。

### 2.5 非破坏性

- 文档页：只存“编辑配方”（裁切/透视/预设），原图不动；重开按配方重新生成。
- 画布图片对象：处理后的 BGRA 写进 `.inkb`；撤销栈保留旧像素引用，不复制。
- 已经有批注的页改几何 → 批注会错位。第一版：**有批注的页禁止改裁切/透视**，或提示“另存为新页”。

## 3. PDF 切题：这是重点

### 3.1 两条来源，两条路

| 来源 | 拿文字/坐标 | 切题依据 | 一页耗时 |
|---|---|---|---|
| **数字版 PDF** | PDFium 文字层：`FPDFText_LoadPage` / `GetText` / `GetCharBox` / `GetFontSize` | 题号正则 + 字号 + 行距 + 分栏 | 规则 <200ms；LLM 兜底 +1~3s |
| **扫描 PDF / 照片** | OCR 行框：`qwen3.5-ocr` 高精识别（`rotate_rect`），或本地 PaddleOCR | 行框 + 同样规则；LLM 选“起始行号” | OCR 2~5s + 规则/LLM |

> 数字 PDF **不要**先 OCR：文字层是精确的，OCR 反而引入错误和延迟。这是性价比最高的一条。

### 3.2 切题规则（数字 PDF）

1. **字符 → 行**：按基线 y 聚类，x 相邻的字符合并成行。
2. **行 → 块**：行距明显大于正文行距、或缩进变化，切成段。
3. **分栏检测**：统计 x 方向空白，出现贯穿整页的宽空白就分栏；每栏独立处理，避免左右串题。
4. **题号候选**（行首）：
   - `1.` `1、` `1．` `(1)` `（1）` `第1题`
   - `一、` `二、`（大题）
   - `例1` `练习1` `【例1】`
   - 字号大于正文 / 加粗 / 段前空白大
5. **打分**：题号模式 3 分 + 字号 1 分 + 段前空白 1 分 + 栏首 1 分；超过阈值才算新题。
6. **切点**：题目起始行的上沿，向上留 4~8px 余量；不要把上一题的图切走。
7. **图/表归属**：PDF 里的图片对象有 bbox（`FPDFPage_CountObjects` + `FPDFPageObj_GetBounds`），
   按 y 归到包含它的题目区间；公式若已转曲线，也会以图片对象出现，同样处理。
8. **跨页**：上一页最后一题明显没写完（末尾无空白、句子未完），允许与下一页开头合并。

### 3.3 LLM 怎么用：只选“行号”，不要它给坐标

视觉模型直接返回 bbox 的通病是**坐标偏**，偏 2% 就可能切掉半个字。稳的做法：

1. OCR/文字层先得到有序行：`[0] 1. 已知函数...`、`[1] ...`。
2. 把**纯文字 + 行号**发给 DeepSeek Flash：
   > “下面是一页试卷按阅读顺序排列的文字行。请返回每道题的起始行号、题号和标题；不要返回坐标，不要改写原文。”
3. 本地按行号找到真实 bbox，切点由几何决定。
4. 若某行 OCR 缺失（公式/图），用相邻行 + 图片对象补。

好处：LLM 的语义能力用在它擅长的地方，坐标永远由本地精确数据决定；输出也只是几十个整数，快、便宜、可校验。

### 3.4 人工校正 UI（必须有）

自动切题不可能 100% 正确，老师必须能 30 秒内改完：

- 页面上画横向切分线，拖动即可；点“+”加一刀、“−”删一刀。
- 右侧题目列表：缩略图 + 题号 + 首行文字，可拖拽排序、合并、拆分、排除。
- “全选/只选前 N 题”“排除答案页/页眉页脚”。
- “预览题目集” → 直接翻页看效果，满意再生成。
- 记住这套 PDF 的切法（按文件 hash），下次打开直接命中。

### 3.5 输出：题目集就是“另一种 DocPages”

现有 `DocPages` 的一页由 `Spec` 描述（`src/InkEngine/Doc/DocPages.cs:34`）：

- `Kind`：0 图片切片 / 1 PDF 页
- `Source` + `SourceIndex`：源文件 + 页号
- `SrcX/SrcY/SrcW/SrcH`：**目前只有图片用**，PDF 没用
- `OutW/OutH`：输出位图尺寸

要做的改动很小：

1. 给 PDF 也启用 `SrcX/Y/W/H`（单位：PDF 点，或 0~1 归一化）。
2. `Pdfium.Render` 现在整页渲染（`src/InkEngine/Doc/Pdfium.cs:239`）；
   增加 `FPDF_RenderPageBitmapWithMatrix`，把“源页的矩形”映射到输出位图，只渲染这一块。
   > 不要“整页渲染再裁”：题目只占页面 1/4 时，整页要按 4 倍宽度渲染，内存会炸。
3. 新增“打开题目集”入口：读 `questions.json` → 生成 `Spec` 列表 → 走现有 `DocPages`。
4. 底部页码条、翻页、每页批注、导出当前页，**全部原样复用**。
5. 文档槽位：`DocStore.KeyOf` 用题目集 id 的 hash；批注自然按页保存。

题目集文件（建议）：

```json
{
  "version": 1,
  "source": "D:/试卷/2026月考.pdf",
  "sourceHash": "sha256:...",
  "title": "2026 月考 数学",
  "items": [
    { "id": "q1", "page": 2, "rect": [0.08, 0.12, 0.92, 0.31], "number": "1", "text": "已知函数..." },
    { "id": "q2", "page": 2, "rect": [0.08, 0.33, 0.92, 0.55], "number": "2" }
  ]
}
```

- `rect` 用 0~1 归一化，换分辨率不跑偏。
- 源文件移动/改名：按 hash 提示“重新定位”，不要静默失效。
- 重新切题后题目 id 变化 → 旧批注会错位。规则：**已经写过批注的题目集，改切法前提示“批注将按题号迁移，可能错位”**，或复制成新题目集。

### 3.6 跨页题、分栏、答案页

| 情况 | 处理 |
|---|---|
| 题目跨页 | 第一版：允许手动“与下一页合并”，生成一个上下拼接的虚拟页；自动判断后置 |
| 两栏/三栏 | 先分栏再切；UI 显示栏界线，允许手动调 |
| 图表题 | 图片对象按 bbox 归属；切点默认在题号上方，图在题号下方 |
| 答案页 | 识别“参考答案/答案与解析”标题，默认排除；可手动勾回 |
| 页眉页脚 | 按 y 位置 + 重复文本过滤，切题时排除 |

## 4. OCR 重新排版：为什么建议后置

### 4.1 三个层级，不要混为一谈

| 层级 | 做什么 | 视觉变化 | 难度 | 建议 |
|---|---|---|---|---|
| **L1 增强** | 去阴影、黑白、锐化 | 变干净，但仍是原图 | 低 | **第一版** |
| **L2 可复制** | OCR 出文字，侧栏可复制/搜索/给 AI | 不改图 | 中 | **第一版可带** |
| **L3 重排** | 识别后重新排版成“电子版” | 完全变样 | 高 | beta，后置 |

### 4.2 L3 难在哪

- **公式**：分式、根号、上下标、矩阵；普通 OCR 会打散，需要公式识别（qwen3.5-ocr 支持公式，但仍有错）。
- **图形/表格**：必须从原图裁出来再插回去，否则题目缺图；表格结构识别也会错。
- **断行/分栏**：重排后每行宽度变了，断行、标点、缩进都要重新算。
- **字体**：中文数学字体、希腊字母、特殊符号；缺字会变成方框。
- **渲染**：LaTeX 要渲染器。C# 可选 CSharpMath（MIT，依赖 SkiaSharp），或 WebView2 + KaTeX；
  两者都增加包体和兼容风险。
- **校对成本**：只要错一个字/一个符号，老师就要通读一遍，可能比直接看增强图更慢。

> 结论：**“重排”不是美化的升级版，是另一条产品线。**
> 第一版做 L1+L2，L3 只在“纯文字、无图、无公式”的题目上做 beta，并且必须并排预览。

### 4.3 如果一定要做 L3，建议路线

1. OCR 返回“块 + 行 + 文字 + 字体大小 + 坐标”。
2. 保留图片/表格块，按原位置裁图。
3. 文字块用本地排版（不是 HTML）：行宽、字号、行距按原比例；公式用 CSharpMath 渲染成小图。
4. 生成一张新的 BGRA 页，作为“重排版结果”，**不覆盖原图**；可一键切回。
5. 只对“单栏、纯文字、无公式”的题默认开启；其余提示“这题含图/公式，建议用增强”。

## 5. 模型与速度：DeepSeek Flash 到底适合干什么

### 5.1 已核实的事实（官方文档，2026-10）

| 项目 | DeepSeek V4.1 Flash |
|---|---|
| 模型名 | `deepseek-flash` |
| 多模态 | 原生支持图片（JPEG/PNG/GIF/WebP） |
| 图片处理 | 自动缩放到约 **1300×1300 总像素**；每张图**最多 1024 token** |
| `detail` | `low` = 512×512；`high/original` = 原图（但仍受上面的缩放上限） |
| 上下文 | 1M；输出最大 384K |
| JSON 输出 | 支持 |
| 思考模式 | **默认开启，effort=high**；可 `{"thinking":{"type":"disabled"}}` 关闭 |
| 价格（每百万 token） | 输入 $0.15（闲时）/ $0.30（峰时）；输出 $0.6 / $1.2 |

**两个直接影响：**

1. **必须关思考**。做“切题/分类/改写”这类任务，默认 high 思考会多等好几秒；课堂场景应显式关闭。
2. **它看图是“低分辨率”的**。整页 A4 缩到约 1050×1590，小五号字和上下标会糊；
   但**单题裁图**（比如 1000×600）不缩放，识别大字/题干是够的。

### 5.2 所以分工应该是

| 任务 | 用什么 | 为什么 |
|---|---|---|
| 数字 PDF 切题 | 本地文字层 + 规则；DeepSeek Flash 兜底 | 文字层精确；LLM 只吃文字，快 |
| 扫描件切题 | `qwen3.5-ocr` 行框 + DeepSeek Flash 选行号 | OCR 负责“看清”，LLM 负责“理解哪行是题” |
| 公式识别 | `qwen3.5-ocr` / `qwen-vl-ocr`（内置公式任务） | 专用 OCR 比通用视觉稳 |
| 题目讲解 | DeepSeek Flash（文字/单题图） | 便宜、快、文科长项 |
| 图片美化 | 本地 | AI 又慢又贵，还可能改字 |
| 自动找纸角 | 本地经典 CV；AI 可选 | 坐标精度要求高 |

> 一句话：**DeepSeek 当大脑，OCR 当眼睛。** 不要让大脑去干眼睛的活。

### 5.3 其他可选模型（2026-10 价格，元/百万 token）

| 模型 | 输入 | 输出 | 特点 |
|---|---|---|---|
| `qwen3.5-ocr` | 0.5 | 2.0 | 文档解析、行框、公式、表格；支持 PDF 输入 |
| `qwen-vl-ocr` | 0.3 | 0.5 | 最便宜的专用 OCR；高精识别带行框 |
| `qwen3-vl-flash` | 0.15 起（≤32K） | 见控制台 | 小尺寸视觉，2D 定位，响应快 |
| 豆包 `Seed-2.1-lite` | 0.8 | 2.7 | 图片 token 有上限，便宜 |
| PaddleOCR-VL 1.6（本地） | 0 | 0 | 0.9B，OmniDocBench 96.3；但要 GPU/Python，包体 +1.9GB 模型 |
| DeepSeek Flash | ≈1.1（闲时） | ≈4.3 | 文本/推理强，视觉分辨率低 |

> 百炼一个 Key 同时有 `qwen3.5-ocr` 和 `deepseek-v4.1-flash`，对 BYOK 用户最省事：
> 只填一个 Key，就能同时用“眼睛”和“大脑”。建议做成首选预设。

### 5.4 延迟预算（目标，不是承诺）

| 操作 | 目标 | 做法 |
|---|---|---|
| 拍照增强预览 | <100ms | 1000px 缩图，本地 |
| 增强/黑白应用 | <500ms | 后台线程，6MP |
| 数字 PDF 规则切题 | <200ms/页 | 纯本地 |
| 数字 PDF + LLM 兜底 | 1~3s/页 | 后台、只发文字 |
| 扫描件 OCR + 切题 | 2~6s/页 | 后台、预取下 2 页、可取消 |
| 生成题目集首页 | <300ms | 按需渲染，不预生成全部 |
| AI 讲解首字 | 1~2s | 流式 |

**课堂纪律**：任何 AI 任务都不能挡住写字/翻页；按钮旁显示“识别中 2s”，不要全屏转圈。

### 5.5 必须做的实测（上线前）

拿 30 页真实材料（数字 PDF、扫描 PDF、手机照片、两栏、公式、图表各若干），量：

- 切题边界 F1：干净数字 PDF ≥0.92；两栏 ≥0.80；扫描件 ≥0.85；复杂版面 ≥0.70。
- 端到端 p50/p95：目标 p95 ≤6s/页。
- 单页成本：目标 ≤0.02 元。
- OCR 字准：印刷体 ≥98%（不含公式）；公式单独统计，不承诺。
- 4GB 内存机器：峰值内存、是否卡顿。

## 7. 工作量与分期（建议）

> 口径：一名熟悉本仓库的开发者，含自检/真机；不含长期调参。

### 阶段 1：拍照美化（2~3 周）

- 自动/手动纸边 + 透视（手动优先，自动兜底）
- 去阴影、白平衡、对比、锐化
- 四个预设 + 前后对比 + 重置
- 文档页“编辑配方”、画布图片“替换像素 + 撤销”
- 清晰度检测与重拍提示
- 自检：合成阴影图、斜拍图、低对比图

**产出**：学生拍的照片，30 秒内变成能投影的干净卷面。

### 阶段 2：数字 PDF 切题 + 题目集（4~6 周）

- PDFium 文字层 P/Invoke（`FPDFText_*`）
- 行/块/分栏 + 题号规则
- 图片对象归属 + 跨页手动合并
- 切分线 UI + 题目列表 + 合并/拆分/排序
- 题目集文件 + 打开/保存 + 页码条复用 + 批注
- 自检：10 份不同排版的数字 PDF

**产出**：数字 PDF 一键切题，像 PPT 一样一道一道讲。

### 阶段 3：扫描件 OCR 切题（3~4 周）

- OCR 供应商抽象（`qwen3.5-ocr` / `qwen-vl-ocr` / 未来本地）
- 行框 → 行/块/分栏 → 规则 + LLM 选行号
- 预取、缓存、取消、失败降级
- 隐私同意（图片上传单独开关）
- 自检：扫描 PDF、手机照片、两栏、公式

**产出**：拍的/扫描的卷子也能切。

### 阶段 4（可选）：重排版 / AI 解题（4~8 周）

- L2 可复制文字（1 周）
- L3 重排 beta（3~6 周，公式/图形风险高）
- AI 讲解侧栏（1~2 周，依赖 AI 基础设施）

### 如果 AI 基础设施还没做

BYOK、Key 加密、任务队列、超时/重试/取消、缓存、设置页：**3~4 周**。
可以和阶段 1 并行。

## 8. 风险

1. **切题误判**：题号不规律、跨页、两栏、图表题；必须有人工校正，不能“全自动生成后不让改”。
2. **批注错位**：改切法/改页面几何会让已有批注错位；要锁定或提示迁移。
3. **OCR 分辨率**：整页 OCR 要 2000px 以上；不要用 DeepSeek 的 1024 token 图做整页 OCR。
4. **公式/手写**：准确率显著低于印刷体；产品上标“需校对”，不要直接当标准答案。
5. **重排版翻车**：丢图、丢公式、错字；必须并排预览、可一键回原图。
6. **PDF 坐标**：旋转页、CropBox、UserUnit 都会影响换算；要用 PDFium 的页尺寸和矩阵，别自己猜。
7. **包体/内存**：本地 OCR 会让 9MB 变几十 MB；第一版走云 OCR，本地 OCR 后置。
8. **隐私**：题目图片可能含学生姓名/答案；必须单独同意、能离线、不写日志。
9. **网络**：学校断网时，切题/OCR 要能降级到“手动框选 + 本地增强”。

---

## 9. 需要拍板

1. **切题输出**：先做“题目集（PPT 式）”，还是“贴到白板”？建议先题目集。
2. **第一版范围**：是否只做“数字 PDF 切题 + 拍照美化”，扫描件 OCR 放第二阶段？
3. **OCR 放哪**：云端（快、准、要上传）还是本地（离线、包大、要 GPU）？建议第一版云端 + 手动兜底。
4. **Key 怎么给**：DeepSeek 直连，还是走百炼（一个 Key 同时有 OCR + DeepSeek）？建议百炼做首选预设，DeepSeek 直连做备选。
5. **重排版**：第一版是否明确不做，只做“增强 + 可复制文字”？
6. **默认预设**：拍照后默认“清晰”还是“试卷黑白”？（建议清晰，黑白一键切换）
