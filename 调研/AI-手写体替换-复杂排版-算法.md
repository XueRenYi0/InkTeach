# 复杂排版下的手写替换 · 算法方案（2026-11-06）

> 目标：解决 b2（图文混排）、b3（双栏 + 公式碎片）这类整板替换错位的问题。
> 用户思路（2026-11-06）：**一块一块替换**，每个字 / 每个公式块保持原来的大小，
> 不再整行统一缩字号。本文先把成熟算法找齐，再落到 InkTeach 的矢量笔迹上。

---

## 1. 结论

采用 **「RLSA → 递归 XY-cut → 块级 OCR → 字格 DTW 对齐」** 四段式：

```
矢量笔迹
  → ① 栅格化墨迹 + RLSA 横向/纵向膨胀（把字粘成行、行粘成块）
  → ② 递归 XY-cut（先切列，再切行；切不开时用 Docstrum 兜底）
  → ③ 每个块单独 OCR（块内单栏，行数能对上；公式块单独走 LaTeX）
  → ④ 行内按字格切分 + DTW 对齐（每个字按原字格大小放，不再整行缩放）
```

**不采用**端到端版面检测模型（DocLayout-YOLO / PP-Structure）作为主路径：
我们的输入是**矢量笔迹**，不是扫描页；这些模型训练在印刷文档上，且要带模型/GPU。
但**照搬它们的“块优先 + 阅读顺序”思想**，以及 PP-Structure 的块分类口径。

## 2. 成熟参考（先找再做）

| 参考 | 来源 / 版本 | 我们照搬什么 | 不照搬什么 |
|---|---|---|---|
| **递归 XY-cut** | Nagy & Seth, *Hierarchical representation of optically scanned documents*, ICPR 1984；PdfPig 的 `RecursiveXYCut`（MIT） | 投影切分：先找竖向空白切列，再在每列里找横向空白切行；递归到块 | 不照搬 PdfPig 的 PDF 文字对象模型，我们切的是墨迹像素 |
| **RLSA（Run-Length Smearing）** | Wong, Casey & Wahl, *Document analysis system*, IBM J. Res. Dev. 1982；`rlsa_python`（MIT） | 横向 / 纵向 run-length 膨胀，把同一行的字、同一段的字粘成连通块 | 不照搬固定阈值；阈值按当前行高中位数自适应 |
| **Docstrum** | O'Gorman, *The document spectrum for page layout analysis*, IEEE TPAMI 1993；PdfPig `DocstrumBoundingBoxes` | 底向上：按最近邻距离/角度聚类连通块；XY-cut 切不开时兜底 | 不照搬倾斜页校正；我们的白板默认水平 |
| **PP-Structure / PP-DocLayout** | PaddleOCR 3.x / PP-StructureV3，2025–2026 | 块分类口径：正文 / 标题 / 图 / 表 / 公式；阅读顺序先列后行 | 不引入预训练检测模型；不依赖 GPU |
| **DocLayout-YOLO** | arXiv:2410.12628, 2024 | “先检测块，再块内识别”的流水线；块级置信度门槛 | 不引入 YOLO 权重；训练分布是印刷文档，不是手写板书 |
| **UniMERNet** | arXiv:2404.15254（公式识别） | 公式作为独立块处理；公式 bbox 与正文分离；识别失败保留原笔迹 | 不打包公式识别模型；我们仍用云端 VLM 出 LaTeX + CSharpMath 渲染 |
| **DTW 序列对齐** | Sakoe & Chiba, IEEE TASSP 1978；词图匹配（Rath & Manmatha） | 把 OCR 字符序列与原字格序列做动态规划对齐，允许 1 格 ↔ 多字 / 多格 ↔ 1 字 | 不拿 DTW 做识别，只做“字放哪个格”的对齐 |
| **Tesseract 版面分析** | Tesseract `textord` 的列查找 / 投影分析 | 列优先、行次之的切分顺序；空白阈值用页内统计量 | 不用 Tesseract 的识别器 |

> 结论：**主路径用经典版面分析（快、可解释、无模型），块分类和公式处理借 PP-Structure /
> UniMERNet 的口径，字格对齐用 DTW。** 这符合“先找成熟参考，再按场景改”的原则。

## 3. 算法细节

### 3.1 第一步：墨迹栅格化 + RLSA

输入是 `Stroke` 列表，不是图片；先按 2–4 px/单位栅格化成二值墨迹图（只画文字候选笔迹）：

- 过滤：`Kind != Freehand`、`Highlighter`、`Image`、`Shape`、`Locked` 不参与；
- 过滤长直线：`bbox.Width > 400` 或 `Width > 220 && Points.Count < Width*0.12` 视为图形；
- 过滤超高：`bbox.Height > 区域高度 * 0.18`；
- 得到 `textMask`。

RLSA 口径（照搬 Wong 1982，阈值自适应）：

```
hGap = 0.55 * medianLineHeight   // 横向：字与字之间
vGap = 0.90 * medianLineHeight   // 纵向：行与行之间
maskH = 横向 run-length <= hGap 的空白填满
maskV = 纵向 run-length <= vGap 的空白填满
blockMask = maskH ∪ maskV
```

效果：同一行的字粘成一条，同一段的行粘成一块；公式里的分式横线、上下标也会被粘进同一块。
**不把公式和正文强行分开**——公式块由后面的块分类决定。

### 3.2 第二步：递归 XY-cut（主切分）

在 `blockMask` 上做投影：

```
cutVertical(mask, region):
  proj[x] = 该列墨迹像素数
  找连续 0（或 < 阈值）的竖向空白带
  若空白宽度 >= max(1.2*medianLineHeight, 40px)
     且左右两侧墨迹都 >= 8%
     → 在空白带中心切一刀，递归左右
cutHorizontal(mask, region):
  同样的投影，找横向空白带
  若空白高度 >= 0.8*medianLineHeight
     → 切上下，递归
```

递归顺序（照搬 XY-cut / Tesseract 列优先）：

1. 先竖向切列（b3 的双栏、b2 的图旁文字）；
2. 每列内再横向切行 / 切段；
3. 直到块高度 < 3 倍行高，或切不出空白。

**自适应阈值**：

- `medianLineHeight` = 当前区域行高投影的中位数；
- 双栏空白带要求 `>= 1.2 * lineHeight`；
- 行间空白要求 `>= 0.8 * lineHeight`；
- 两侧墨迹占比 < 8% 的切法丢弃（防止把公式里的空隙切成两栏）。

**兜底（Docstrum）**：如果 XY-cut 切不开（斜写、圈注跨行、公式横线连通两栏），
改用连通块最近邻聚类：

- 每个连通块的中心 / 外接框；
- 按最近邻距离和角度聚类，形成文本行 / 块；
- 只在 XY-cut 失败的区域启用，避免全局变慢。

### 3.3 第三步：块分类（只做轻量规则）

对每个块算：

| 特征 | 用途 |
|---|---|
| 墨迹像素密度 | 图 / 公式 / 正文区分 |
| 块宽高比 | 双栏、长公式 |
| 长直线笔迹数量 | 图形 / 表格 / 分式横线 |
| 块内行数 / 行高方差 | 正文 vs 公式堆叠 |
| OCR 返回的 LaTeX / 符号比例 | 公式块 |

规则（先照搬 PP-Structure 的块类型，不做模型）：

```
if 密度低 && 长直线多 && 宽高比极端 → 图形块（保留原笔迹）
else if 含 $...$ / LaTeX / 数学符号比例高 → 公式块
else → 正文块（可替换）
```

图形块**永远不替换**；公式块走 3.5；正文块走 3.4。

### 3.4 第四步：块级 OCR（解决“行数对不上”）

**不再整板一次 OCR**，每个正文块单独裁剪、单独识别：

- 把块内笔迹渲染成白底 PNG（保留原行距）；
- 提示词要求 **逐行输出 JSON**：

```json
[
  {"text":"点在线上：A∈直线AD", "x0":0.02, "y0":0.12, "x1":0.98, "y1":0.18},
  {"text":"...", "x0":0.02, "y0":0.22, "x1":0.99, "y1":0.28}
]
```

- `x0/x1/y0/y1` 是相对块图的归一化坐标；
- 若模型不返回 bbox，则退回 **按行裁切**：用 3.2 的行投影把块切成行条，
  每条单独 OCR（可 3–5 条拼一张图，按分隔线切回）。

**行数校验**：

```
if OCR 行数 != 几何行数:
    如果 OCR 有 bbox：按 bbox 的 y 中心匹配几何行；匹配不上的行跳过
    否则：整块跳过，保留原笔迹
```

这样 b2 的 20 几何行 / 13 OCR 行不会再整页错位，最多跳过这一块。

### 3.5 第五步：公式块

公式块不参与字格 DTW，单独处理：

1. 块级 OCR 返回 LaTeX（`$...$` / `\(...\)`）；
2. 用 CSharpMath 渲染成透明 PNG；
3. **按公式块原来的 bbox 缩放**：高度 = 原公式块高度 × 0.95，宽度按比例；
   不再按整行高度缩放；
4. 公式块内的中文批注（“答对 / 包含”）作为独立小文本块，跟随公式块位置；
5. LaTeX 渲染失败 / 括号不配对 → 整块保留原笔迹。

> 这一条对应 UniMERNet 的“公式是独立块”口径；我们不做公式识别模型，
> 只做公式 bbox + LaTeX 渲染。

### 3.6 第六步：字格切分 + DTW 对齐（用户要的“每个字大小差不多”）

对每个正文行：

1. 在行内做 **横向投影**，找字间空白（RLSA 的 hGap 同一口径）；
2. 切出字格 `cell[i] = (x0,x1,y0,y1)`；连笔切不开时，允许一个格包含多个字；
3. OCR 文本切成字符序列 `ch[j]`（英文按单词/字母，中文按字）；
4. 用 DTW 对齐 `ch` ↔ `cell`：

```
cost(i,j) = |cell[i].Width - expectedWidth(ch[j])| / lineHeight
          + 0.2 * |cell[i].Height - lineHeight| / lineHeight
          + gapPenalty（跳过一个格 / 一个字符）
DTW 允许：
  1 格 ↔ 1 字
  1 格 ↔ 多字（英文单词 / 连笔）
  多格 ↔ 1 字（宽字 / 圈注）
```

5. 每个字按它的 `cell` 高度 × 0.95 定字号，水平居中放进 cell；
   **不再按整行宽度缩字号**；字距由 cell 位置决定，原字大就大、原字小就小。
6. 对齐置信度低（DTW 代价 > 阈值 / 跳字过多）→ 整行退回“行级排版”，
   但行级排版也不再无限缩字号：最小字号 = 原行高 × 0.75，宁可轻微溢出。

### 3.7 替换与撤销

- 每个块 = 一个 `CompoundAction`：删块内原笔迹 + 加 Glyph / 公式图；
- 整个选区 = 一个外层 `CompoundAction`（块级 action 按顺序），Ctrl+Z 一次回退；
- 图形块不动，只作为背景保留；
- 块级状态：`已优化 N 块 / 跳过 M 块（行数对不上 / 公式渲染失败）`。

## 4. 和当前实现的差异

| 项 | 当前（2026-11-06 第一版） | 新方案 |
|---|---|---|
| 切分 | 整板按 y 投影切行 | RLSA + 递归 XY-cut 切块 |
| OCR | 整板一次 | 每块单独，块内行数校验 |
| 双栏 | 不支持，整板拒绝 | 先切列，左右栏各自 OCR |
| 字号 | 整行统一，宽度不够就缩 | 按字格 / 公式块各自大小 |
| 公式 | 行内 LaTeX 图，按行高缩放 | 公式块独立 bbox，按块缩放 |
| 失败 | 整板拒绝 | 块级跳过，其余块继续 |
| 图形 | y 投影可能混入 | 长直线 / 高对象先过滤，图形块保留 |

## 5. 实施顺序（建议）

1. **layout-analyzer**：`RLSA + XY-cut`，只输出块矩形 / 行矩形，接 `--handblocks` 自检；
   先在 b1 / b2 / b3 上把块数和列数调对。
2. **block-ocr**：每块裁剪、OCR、行数校验；块级替换，先不做字格 DTW。
   验证 b2 的上下两块、b3 的左右两栏。
3. **formula-block**：公式块 bbox + CSharpMath；验证 b3 的分数 / 根式。
4. **cell-dtw**：行内字格切分 + DTW；验证“每个字大小差不多”。
5. **quality gates**：块级置信度 / 行数 / 公式渲染失败 → 跳过而不是硬替换。
6. **回归**：b1 / b2 / b3 / n1 / n2，记录每块的替换率、错位率、耗时、撤销。

---

## 6. 验收标准

- **列不串**：b3 左右栏文字不得跨到另一栏；
- **行不串**：每块 OCR 行数与几何行数一致才替换；
- **字大小**：单字高度与原地字格高度误差 ≤ 20%；
- **公式大小**：公式 bbox 高度与原地公式块高度误差 ≤ 15%；
- **图形不动**：图形块像素级保留；
- **可撤销**：整个选区一次 Ctrl+Z 回到替换前；
- **失败可见**：跳过的块在状态里写清原因，不静默。

---

## 7. 风险

- **手写连笔切字**：字格可能粘连；DTW 允许“1 格多字”，切不开就退回行级。
- **公式块与正文粘连**：RLSA 可能把公式和中文粘成一块；块分类用 LaTeX / 符号比例拆。
- **双栏空白被圈注跨过**：XY-cut 切不开时用 Docstrum 兜底，仍失败则整块跳过。
- **云端 OCR bbox 不稳定**：优先每块裁剪 + 行数校验；bbox 只作辅助，不硬依赖。
- **性能**：块数一般 2–8；每块一次 OCR，整页 4–12 秒，可接受；可在块级并行。

## 8. 初测结果（2026-11-06）

用 RLSA + 递归 XY-cut 的 C# 原型跑三张真实板书：

| 板书 | 结果 | 说明 |
|---|---|---|
| b1（单栏） | 11 块，块内 1–3 行 | 可用；块边界基本落在行/段上 |
| b2（图文混排） | 1 块，20 行 | 横向没有切出段落；图旁文字和正文粘成一块 |
| b3（双栏 + 公式） | 3 个横向大块（13/8/10 行） | **没有切出左右栏** |

关键发现：

- b3 的红色竖分隔线**不在 `Stroke` 列表里**（很可能是页面背景/截图元素），
  所以“所有 x 都有墨”，只靠笔迹投影切不出左右栏；
- b2 的正文行距 < 0.9×行高，RLSA 纵向膨胀把整段粘成一块，XY-cut 没有段落级空白；
- 原型在 b1 上耗时约 18–20ms，性能不是问题。

结论：

1. **块级 OCR 可以先做**：b1 的 11 块、b2 的 1 大块都能跑，但 b2 仍需块内行数校验；
2. **b3 的列切分不能只靠笔迹投影**：要么拿到背景图中的分隔线，要么让 OCR 返回 bbox，
   要么在行级按 x 空隙聚成左右两列；
3. 原型先不接产品，避免把未验证的切块逻辑带进正式路径。
