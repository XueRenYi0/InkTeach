# 识别到文本框 · 优化与难关（2026-11-06）

> 目标：识别结果不只是“能读”，还要**像原板书**——字体可换、行距可调、同一框内保留红蓝、
> 整体大小贴近原选区。本文记录参考产品、本轮已做、以及第二版（原位替换）前必须攻克的难关。

---

## 1. 参考产品与照搬范围

| 参考 | 版本 / 来源 | 照搬什么 | 不搬什么 / 原因 |
|---|---|---|---|
| Microsoft OneNote「Ink to Text」 | Microsoft 365，2024–2026 | 框选墨迹 → 转文字；保留原墨迹的先后顺序和大致版面；转换结果仍可编辑 | 不搬它的云端手写模型（我们 BYOK，识别走 DeepSeek） |
| ClassIn 文本框选中条 | 2026-11 线上版 | 选中文字后只给“字号 / 颜色 / 锁定 / 层级 / 复制 / 删除”这类高频项，条不撑长 | 不搬它的图标和配色；我们沿用现有 7 格条 |
| Microsoft Word「字体」对话框 / 段落行距 | Word 2021+ | 字体、字号、行距三件事放同一处；行距用 1.0 / 1.2 / 1.5 / 1.8 / 2.0 档 | 不做完整字体列表、不做首行缩进/段前段后（板书场景用不上） |
| Excalidraw text element | 2025–2026，MIT | 文字对象的 `fontFamily` / `fontSize` / `strokeColor` 存在元素自身；换字号/字体后元素重新排版 | 不搬它的 Hand/Code/Normal 三档字体（我们要中文四档） |
| tldraw / ProseMirror rich text | tldraw 3.x；ProseMirror 1.x | 富文本用“run + marks”存颜色/粗体，而不是给整框一个颜色 | 第一版不做完整富文本编辑器；先做**逐行色**，第二版再上 run |
| Mathpix / MyScript | 2025–2026 商业 API | 公式识别返回行/词级 bbox；公式按 bbox 定位 | 不接它们的 API（成本和离线要求）；只借 bbox 思路 |
| RLSA + XY-cut | 经典版面分析（OpenCV / Tesseract 预处理） | 先横向/纵向投影切块，再按块 OCR；处理双栏和公式块 | 不直接上整页自动排版（用户明确不要破坏原版面） |

**没有成熟参考、由我们自己定的一点**：从 **OCR 行 bbox 反查该行原墨迹颜色**（红/蓝/其它三桶）。
OneNote/Excalidraw 只存“对象颜色”，不存“同一框内逐行颜色”；这块按我们自己的板书场景实现。

## 2. 本轮已做（2026-11-06）

### 2.1 先修“红字里夹黑字”

原因不是配色表，而是**排版顺序**：

1. `CreatePlainTextBox` 先按默认墨色排版，公式图（CSharpMath 位图）已经烘成深色；
2. 之后才把 `Stroke.Color` / `TextBoxData.Ink` 改成原墨迹主色；
3. 文字是绘制时取 `s.Color`，所以变红；公式是位图，仍是黑 → 同一框里红黑混排。

修法：新增 `CreatePlainTextBoxAt`，**先设墨色、字体、行距、逐行色，再 `FitToContent` 排版**。
`--handtextbox` 实测 b1/b3 渲染像素：`dark=0`，不再有黑字。

### 2.2 逐行颜色

- `TextBoxData.LineColors`：按硬换行行号存 `Color4`；
- OCR bbox 命中哪一行，就用该行框内的笔迹点算主色（红/蓝/其它三桶）；
- 行内公式也按该行色烘；不同行可以红、蓝、黑混排；
- 存档 v29 保存 `FontFace / LineSpacing / LineColors`，v30 再追加逐字 `ColorSpans`；老 v28 文件按默认值迁移。

### 2.3 字体 / 行距面板

文字选中条「A」下拉从 3×2 字号格扩成三行：

```
字体：雅黑 / 楷体 / 宋体 / 黑体
字号：10 / 14 / 18 / 24 / 48 / 64
行距：1.0 / 1.2 / 1.5 / 1.8 / 2.0
```

- 字体档存在文本框自身（不是全局设置），所以一页里可以有两种字体；
- 改字体/行距走 `TextBoxStyleAction`，一步撤销；
- 面板命中、绘制、脏区共用同一份几何（`FontPanel*Rect`）。

### 2.4 结果贴近原选区

- 框宽 = 原选区宽 + 左右内边距；位置从原选区左上角开始；
- 字号由“贴近墨迹的几何行”中位高反推（不用 OCR bbox 的整行高，避免偏大）；
- 行距由几何行中心距反推，夹在 1.0–2.2；
- 整页/多栏导致高度超过目标 1.25 倍时，自动缩字号再排（最多两轮）。
  b3 整页：高 9691 → 3950（原页 3698），不再是一条“几米长的纸”。

### 2.5 编辑中改色：选中改一段，没选中改整框

- **有选中**：只改 RichEdit 里选中的字（`EM_SETCHARFORMAT / SCF_SELECTION`），
  同时记成 `TextBoxData.ColorSpans`；画布排版按 span 切成彩色 run，公式按所在段色烘。
- **没选中**：改整框主色，清空逐行/逐字色（`LineColors` + `ColorSpans`）。
- 文字色带、自定义取色板、选中条颜色按钮三条入口都走同一判定
  （`SetTextBoxEditColorFromUi`）。
- 退出编辑时从 RichEdit 逐字抓回颜色，重建 span；文字增删后颜色仍跟着字走。
- 存档 v30 保存 span；`Ctrl+Z` 能撤销“选中改色”。

**实测**（`--textcolor`）：两行文本，选中第二行改蓝 → 第一行保持黑、第二行蓝；
撤销恢复；不选中改红 → 整框红且逐字色清空；存盘往返 OK。

## 3. 第二版前必须攻克的难关

按“影响大小 × 现在能不能做”排序。

### 难关 1：双栏 / 多栏的可靠切分（最高）

- 现状：用 OCR bbox 的 x 中心找最大空隙，并加“左右范围不重叠”保护。
  b3 是“宽左栏 + 右批注”，两栏横向交叠，保护生效后仍合成一个长框。
- 为什么难：红色竖分隔线不在矢量笔迹里；只靠笔迹投影切不开；OCR bbox 的 x0
  会被跨栏公式拉低。
- 下一步：三路证据投票
  1. 背景图/截屏里的竖线检测（Hough / 列暗度）；
  2. 笔迹的纵向空白带（RLSA，允许 1–2 个字宽的噪声）；
  3. OCR bbox 的 x 中心聚类。
  三者一致才切；不一致就保持一个框并提示“建议分栏框选”。

### 难关 2：逐字 / 逐词位置与颜色（第二版核心）

- 现状：逐行颜色；行内文字仍按文本框自动换行，不贴原字位。
- 下一步：
  1. OCR 返回词级 bbox（DeepSeek 目前行级；可让模型多给 word 数组）；
  2. 笔迹按 bbox 聚类成“字格”，用字格宽高 / 间距做 DTW 对齐；
  3. 每个字格取自己的墨色，渲染时按字格中心放 Glyph/公式图。
- 风险：OCR 行数与字格数不一致；公式、下标、圈注会破坏字格。需要“置信度低就整行退回”。

### 难关 3：系统字体与手写字的度量差

- 现状：用几何行高中位值 × 0.76 估字号，再按目标高度缩一次。
- 问题：CJK 字面高约 0.88 em，英文 x-height 约 0.52 em；同一字号下视觉大小差很多。
- 下一步：按字体读 ` ascent/descent/x-height`（DirectWrite `IDWriteFontFace`），
  用“原行墨迹的 x-height”反推字号，而不是统一乘系数。

### 难关 4：换行与原始硬换行

- 现状：保留 OCR 的硬换行；文本框宽度不够时再自动换行。
- 问题：自动换行会把“一行”拆成多行，行色还按硬行号走，颜色对得上；
  但“贴近原位置”会整体错位。
- 下一步：第二版用“硬行 + 词级 bbox”直接定位，不再依赖自动换行；
  第一版保留硬换行，宽度贴近选区，减少二次换行。

### 难关 5：富文本 run 模型

- 现状：已有 `ColorSpans`（字符区间 + 颜色）和逐行色，能保留“同一行里一段红、一段蓝”；
  但没有粗体/斜体/字号混合的完整 run 模型。
- 下一步：照 ProseMirror marks 把 `Text` 升级成 `TextRun { text, color, bold, italic, math }`；
  存档再做 v31 迁移。
- 不做的理由（本轮）：完整富文本编辑器 + 光标映射成本高；先解决颜色这一条最高频需求。

### 难关 6：编辑后颜色/位置映射失效

- 现状：用户改字后，`LineColors` 仍按旧行号；插入/删除行会串色。
- 下一步：编辑时按“行首/行尾 diff”迁移颜色；或直接清空逐行色回到主色。
  第二版上 run 模型后这个问题自然消失。

### 难关 7：公式的基线与宽度

- 现状：CSharpMath 出位图，按行内 ascent/descent 对齐；宽度超行宽时等比缩小。
- 问题：分式/根式比文字高，行高会被撑大；同一行里公式和文字的视觉基线仍有 1–2px 差。
- 下一步：用 `MathRenderer` 返回的 baseline 偏移统一校准；公式按行内 x-height 缩放，
  不按整行高。

### 难关 8：性能

- b3 47 行 8.2s：其中 bbox JSON 让 max_tokens 到 4096，模型输出变长；公式图逐行烘。
- 下一步：
  - 按块并发 OCR（左栏/右栏各一次）；
  - 公式图缓存 key 已含颜色/字号，复用没问题；排版缓存要确保换色只失效一次；
  - 大页先分块，避免一次 4k 图。

### 难关 9：旋转 / 选区变换

- 文本框目前不支持旋转；选区旋转后识别结果仍按轴对齐框放。
- 第二版做原位替换时，必须把 OCR bbox 通过选区矩阵变换回画布坐标。

---

## 4. 结论

- 第一版（一个框、行级颜色、字体/行距可调、大小贴近选区）**已达到可用**；
- 第二版（原位、按字/公式保持原大小）先攻 **多栏切分 + 词级 bbox + 字格 DTW**，
  不要先做完整富文本编辑器；
- 逐行色是低成本的中间态，等 run 模型上了再替换。
