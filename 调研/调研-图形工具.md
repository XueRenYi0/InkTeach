## 〇、结论速览

1. **图形的"机器"早就装好了，缺的是"画它的开关"**：`Line/Rectangle/Ellipse/Arrow`
   四种对象能存、能画、能命中、能存档、能被框选和撤销（自检 `--shapetest` 一直在跑），
   **但没有热键、没有按钮**——今天就算切到"直线"工具，按下拖动画出来的也是一条自由笔迹。
2. **建议：手柄按"图形的定义元素"给，不按通用包围盒给。** 直线 = 两个端点、
   三角形 = 三个顶点、圆 = 圆心 + 半径点、矩形 = 四个角、椭圆 = 两条半轴端点。
   拉伸那 8 个手柄**对图形不需要**（理由见第二节），多选时再退回通用框。
3. **角度是两套数，别混**：直线的**倾斜角** α ∈ [0°,180°)（数学上本来就该这样），
   和上一版刚定的**旋转读数**（逆时针为正、不设上限，可以 -400°、720°）是两件事。
   建议界面上分清楚：线上显示 α，转的时候显示 Δ。
4. **图形和墨迹：存储层不区分、行为层按种类分流、编辑层才分开。**
   这不是折中——**你自己那版 InkClass 就是这么做的**（一切皆笔迹 + 一个组标签），
   我们只比它多走一步：**参数化顶点编辑**（InkClass 没有这个）。
5. **橡皮碰到图形怎么办**要重新定：InkClass 是"**整组删**"，我们现在是"**熔成笔迹再擦一半**"。
   两者都说得通，但和"顶点可拖"放在一起，前者更自洽（第三节末尾）。

## 二、问题一：数学/图形实际使用中，它应该怎么操作？

### 2.1 先看每个图形在数学上"由什么定义"

这一列决定手柄给哪几个点——**图形的控制点不是 UI 细节，它就是它的定义**：

| 图形 | 数学上的定义元素 | 拖动它等于 |
|---|---|---|
| 直线 | **两个点**（两点确定一条直线） | 换端点 → 长度和倾斜角都变 |
| 三角形 | **三个顶点**（三点确定一个三角形） | 换顶点 → 形状、三个内角都变 |
| 矩形 | 两条对角顶点（或四条边） | 拖角 → 边长变，**四个直角必须保持** |
| 椭圆 | 中心 + 两个半轴 | 拖轴端 → 半轴变长变短 |
| 圆 | **圆心 + 半径** | 拖圆周点 → 半径变；圆心不动 |

### 2.2 同行怎么让人操作这些定义元素

**① GeoGebra（数学教学的事实标准）——"对象由点定义，之后拖点"**

| 对象 | 官方文档原文（可自查） |
|---|---|
| 线段 | "select **two existing points** or click/tap two distinct positions in the Graphics View to create the line segment **bounded by these end points**" —— [Segment Tool](https://geogebra.github.io/docs/manual/en/tools/Segment/) |
| 多边形（含三角形） | "select consecutively **at least three existing points** … which will be the **vertices** of the polygon. Click the first vertex again to close" —— [Polygon Tool](https://geogebra.github.io/docs/manual/en/tools/Polygon/) |
| 圆 | "select an existing point … that will be the **center** … **Drag to create the circle, and set its radius by** … clicking in the Graphics View" —— [Circle with Center through Point](https://geogebra.github.io/docs/manual/en/tools/Circle_with_Center_through_Point/) |

同一份文档里还有一条**顺手的旁证**：多边形工具按住 `Alt` 建下一个顶点时，
"the side between these two points makes with the preceding side an angle that is
a **multiple of 15°**"——**15° 这个吸附粒度，和我们旋转手柄的 `Shift` 硬网格是同一个数**。

GeoGebra 里没有"拉伸手柄"这回事：**要改形状就拖定义点**。它的"角度"也是独立对象：
`Angle(<Vector>)` = 与 x 轴的夹角；`Angle(<Polygon>)` 一次给出所有内角，且
"in mathematically **positive orientation (counter clockwise)**"（逆时针为正）
——和我们上一版刚定的旋转符号完全一致。

**② 你自己那版 InkClass（同一批用户、同一批习惯）——"一切都是笔迹，图形只是带了标签"**

源码原文（`D:\文件集中\code\画布测试\Ink-Canvas-Dev\Ink Canvas\MW_GraphStrokes.cs` 文件头）：

> "背景：画布上'**一切都是笔迹**'，但有三类内容其实是'图形'：…… **方案：不改变存储模型**
> （仍是普通笔迹，翻页 / 撤销 / 保存零改动），只给图形笔迹附加一个**'组 ID'** 属性。"

它给人的操作是（同上文件，`InsertGraphStrokes`）：

> "图形插入的统一入口：**打标签 → 设笔模式 → 自动选中 → 显示选区控制条**"，
> 于是"拖动 / 缩放 / 旋转立即可用"。

也就是说 **InkClass 的图形画完就是"固定形状的墨"**：能整体拖、整体缩放、整体旋转，
**没有顶点编辑**。三角形在那边只有一条来路——手写识别（`InkRecognizeHelper`）：
识别成三角形之后生成一串点，从此它也是普通笔迹。

顺带一条**画直线时的角度吸附**（`MW_SimulatePressure.cs:756`）：

> `private const double LineAssistSnapDeg = 4.0;     // 定型时角度吸附：接近水平/垂直吸正（画坐标轴刚需）`

**③ PowerPoint / OneNote / Figma / Excalidraw（业界常识，我没引到官方原文，建议你开 PPT 验一下）**

| 对象 | 选中后给什么手柄 |
|---|---|
| 直线 / 连接线 | **只有两个端点**（能拖端点改长短和角度）+ 旋转柄；**没有**左右/上下拉伸 |
| 矩形 / 椭圆 / 三角形 | 8 个缩放手柄（四角 + 四边中点）+ 旋转柄；拖角**保持**它是矩形/椭圆 |
| 文本框 / 图片 | 同上 8 个 |

规律很清楚：**"这个形状有几个自由度，就给它几个手柄"**。
直线只有"两个端点"这一个自由度 → 只给两个端点；矩形有"宽 + 高"两个 → 给一圈缩放；
三角形如果"只能用包围盒缩放"，那三个顶点的自由度就浪费了。

### 2.3 直线的角度怎么算（你说的 0~180）

数学上这叫**倾斜角**：x 轴正向与直线所成的角，范围 **[0°, 180°)**。
可核对的等式是 `m = tan θ`（[Slope, Wikipedia](https://en.wikipedia.org/wiki/Slope)）：
原文举的例子是"45° **上升**的线斜率为 +1、45° **下降**的线斜率为 −1"——
下降线只能是钝角，所以 θ 跑不出 0~180。

落到我们的坐标（屏幕 y 轴朝下）：`α = atan2(-(y₁-y₀), x₁-x₀)`，再折到 [0,180)。

| 这条线 | 读数 |
|---|---|
| 水平 | `0°` |
| 右上斜（上升） | `0°~90°` |
| 竖直 | `90°` |
| 右下斜（下降） | `90°~180°`（例：斜率 -1 → `135°`） |

**注意别和上一版刚定的旋转读数混了**：

| 数 | 是什么 | 范围 | 什么时候出现 |
|---|---|---|---|
| **倾斜角 α** | 这条线**本身**的姿态 | `[0°,180°)`，永远非负 | 画线时、拖端点时 |
| **旋转量 Δ** | 我这一次**转了多少** | 逆时针为正、**不设上限**（`-400°`、`720°` 都可能） | 拖旋转柄时 |

两个数同时挂在一条直线上是对的（"这条线现在是 135°，我刚才把它转了 -20°"），
但**必须分开显示**，否则用户会以为软件自相矛盾。

### 2.4 问题一的答案（建议）

**手柄 = 图形的定义元素 + 一个旋转柄。**

| 图形 | 控制点手柄 | 拖动语义 |
|---|---|---|
| 直线 / 箭头 | 2 个端点 | 改端点（长度、倾斜角跟着变） |
| 矩形 | 4 个角 | 拖角**保持矩形**（同时改两条边），不让它变成任意四边形 |
| 圆 | 圆心 + 圆周点 | 拖圆心 = 平移圆；拖圆周点 = 改半径（**永远是圆**） |
| 椭圆 | 两条半轴的端点（4 个） | 改半轴（**永远是椭圆**，不会变成"歪了"的东西） |
| 三角形 | 3 个顶点 | 任意三角形 |
| **多选（含混选）** | 退回现在的**通用 8 手柄框** | 整组缩放/旋转——"把这几样一起放大"是另一件事 |

**旋转柄一律保留**（形状是"参数"，旋转是"姿态"，两码事）。

**拉伸那 8 个手柄对单选图形不需要**，理由具体到我们的代码：
现在的"左右拉伸"是在框坐标里做 `CreateScale(sx, sy)`。对一条
`(0,0)→(100,50)` 的直线，左右拉伸 2 倍会变成 `(0,0)→(200,50)`：

| | 拉伸前 | 左右拉伸 2 倍后 |
|---|---|---|
| 倾斜角 | `atan2(50,100) = 26.57°` | `atan2(50,200) = 14.04°` |

**用户只是"想把它变长"，线的角度却变了**——这不是他按下去时预期的那个操作。
换成"拖端点"就没有这个歧义：拖哪个点，哪个点动，角度是我自己拖出来的。

## 三、问题二：图形和墨迹要不要区分开？

分三层回答，**结论是"底层不区分、上层按种类分流"**：

| 层 | 要不要分开 | 为什么 |
|---|---|---|
| **存储层**（对象模型 / 存档 / 撤销 / 剪贴板） | **不分开**（图形就是 `Stroke` 的一种） | ① 我们已经是这样了，白拿选中/变换/撤销/存档/剪贴板/套索全套能力；② **InkClass 也是"一切皆笔迹 + 一个组标签"**，它的注释把理由写得很清楚："不改变存储模型（翻页/撤销/保存零改动）"；③ 分成两套对象，等于把上面每一条能力都实现两遍 |
| **行为层**（渲染 / 命中 / 橡皮 / 手柄） | **分开**（按 `Kind` 分流） | 这些**本来就该不一样**：图形命中走描边（中间是空的）、矩形不能被橡皮"擦出缺口"、手柄按定义元素给。我们现在已经按 `Kind` 分流了三处，这一轮再加手柄和角度 |
| **编辑层**（能不能改形状参数） | **这就是这一轮的新东西** | InkClass **没有**顶点编辑（图形画完就固定了）。你想要的"拖两个端点控制直线"是**比它多一步**的能力，得新建一套编辑动作（改的是几何，不是 `Transform`，几何缓存要重建） |

### 3.1 一个必须一起定的取舍：橡皮碰到图形怎么办

两条路都有先例，但**选哪条会反过来影响手柄设计**：

| | A. 整条删（InkClass 的做法） | B. 熔成笔迹再擦一半（我们现在的做法） |
|---|---|---|
| 依据 | InkClass `MW_GraphStrokes.cs`：「擦除拦截：橡皮碰到"图形组"里的任意一条笔迹时，取消默认的"只擦这一条"，**改为把同组笔迹一次性全部移除**」——而且它**只在"按笔迹擦除"模式下拦**，"点擦除"模式故意不拦（保留"精细雕刻"语义） | 你 09-15 定的"擦断要分开算"，当时给图形加了 `MeltToFreehand()` |
| 用户得到 | 图形永远保持是"图形"（顶点点得到、角度显示得出来） | 能擦掉三角形的一条边——**但那之后它就不是三角形了**：没有顶点、没有角度，跟手写的一团墨一样 |
| 代价 | 想"擦掉一条边"做不到，只能删了重画 | "我刚才那个三角形的顶点呢？"——这是最难解释的一类**静默变质** |
| 我的建议 | **选 A**：整笔橡皮 / 像素橡皮碰到图形 = **整条删**（一步撤销）；想擦一半，用**显式动作**"打散成笔迹"（像已经有的 `Ctrl+Alt+8` 那样，动作名写清楚"打散"） | |

理由：**参数化图形和"擦一半"本来是互相矛盾的**——你要么让它保持数学定义（那就不该被切开），
要么承认它变成墨（那就别怪顶点没了）。把一个隐含副作用（擦一下 → 静默降级）换成显式动作，
用户至少知道自己做了什么。

### 3.2 顺带：新建图形之后要不要"自动选中"

InkClass 是**自动选中**的（`InsertGraphStrokes`：打标签 → 自动选中 → 控件条立即可用），
我们截图之后也是自动选中。建议**图形画完也自动选中**，理由一样：画完最可能的下一件事
是挪它/改它。（代价：画完立刻再落笔要先点一下空白——InkClass 为这件事专门写了
`EndOneShotSelectionNow`，说明它在真实课堂上真的会咬人。我们已经有了"切工具收起选区"，
但"画完自动选中"之后用户接着画第一笔仍会被遮罩吃掉——**这条要连着做**。）

## 四、如果按上面做，施工大概是什么样（等你点头才动）

| 步骤 | 改哪里 | 代价 | 怎么验 |
|---|---|---|---|
| 1. 接线画图入口 | `KeyBindings`（新键）+ `Engine` 按下/移动/抬起（拖动 → 两个端点 → `Kind` 设置 + `SetEnd`） | 小 | 新 `--shapetooltest`：拖出来的对象 `Kind` 对、端点在按下的点和松手的点上 |
| 2. 加 `Triangle` / `Circle` 两种 Kind | `Model.cs`：`BuildTriangle` / `BuildCircle`、`ShapeOutline` 两个分支、`StrokeKind` 两个枚举值（**存档要升版本或复用一个空闲值**） | 中 | 存档往返 + 命中 + 轮廓折线 |
| 3. 控制点手柄 | `Selection.cs`：`ControlPoints(stroke)` 按 Kind 返回点集；`HitTest/Position` 走它；`Engine` 拖控制点 → 新动作 `VertexEditAction`（**几何重建，缓存失效**，和"改变换"是两条路） | **大**（这一轮最大的一块） | 拖端点的自检：角度/长度按预期变、**一步撤销**、几何版本号变了（缓存真的失效了） |
| 4. 直线倾斜角显示 | 复用旋转度数标签那套（浮出、按文案量宽、进脏区） | 小 | 0/26.57/90/135/179 五个角度的读数 |
| 5. 橡皮改"整条删" + 显式"打散" | `EraseAt` / `EraseRectAt` 的图形分支 + 一个新动作 | 小 | 两种橡皮都不把图形切开；"打散"之后变成笔迹 |
| 6. 画图时的吸附 | 默认软吸附 0/90（±3°，和旋转一致）、`Shift` 15° 网格、`Alt` 自由 | 小 | 和旋转吸附同一套判据，自检直接复用量角 |

**明确不做**（除非你改主意）：图形识别（手写一笔变图形）、多边形/五角星等更多形状、
角度标注对象（画一个角并标出度数）、图形之间的约束（垂直/相切/交点）。

| 5 | 橡皮碰到图形：**整条删**（对齐你现在的 InkClass）还是**熔成笔迹**（现状）？ | **整条删** + 一个显式的"打散成笔迹"动作 | 小 |
| 6 | 角度显示：只做**直线倾斜角**，还是三角形三个内角也做？ | **先只做直线**（三角形的内角是"角度标注"小功能，单独一轮） | 小 / 中 |
| 7 | 键位：直线 `Ctrl+Alt+L`、矩形 `Ctrl+Alt+R`、椭圆 `Ctrl+Alt+E`、圆 `Ctrl+Alt+O`、三角形 `Ctrl+Alt+T` | 先按这套排（真机注册会报冲突，`--keytest` 会盯住） | 小 |
| 8 | 画完自动选中 + **紧接着落笔不被遮罩吃掉** | 要做（InkClass 为这件事专门打过补丁） | 小 |

## 六、一页纸的对照表（先看这个就够）

|---|---|---|---|---|---|
