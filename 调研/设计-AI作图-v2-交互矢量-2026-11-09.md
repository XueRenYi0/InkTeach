## 2. 实现

### 2.1 对象与存档

- `StrokeKind.Figure = 33`（追加，不动旧值）；
- `Stroke.Figure : PlotSpec`；
- `Points[0]/[1]` = 图卡局部左上/右下（1100×760）；`Transform` 负责放置/缩放；
- `InkSerializer.FormatVersion = 34`：仅 `Kind == Figure` 时在对象末尾追加 PlotSpec JSON；
- `PlotSpecJson` 与 AI 解析共用同一套 JSON 读写，避免"模型一套、存档一套"。

### 2.2 渲染

- `Overlay.DrawStrokeCore` 最前面分流 `Kind == Figure`；
- `DrawFigure`：白卡、坐标轴、网格、刻度、曲线、焦点/准线/渐近线、图例、标题、参数行；
- 曲线用 `ID2D1PathGeometry` 一次构建，`DrawGeometry` 描边；
- 文字用现有 DirectWrite（`AiTextFormat`），不引新依赖；
- 缩放时文字/线宽一起缩放（像图片），但边缘保持矢量清晰；
- 采样与 v1 静态图共用 `PlotSampling`（同一份 y 范围/等比例/断段规则）。

### 2.3 参数滑杆

- 单选 Figure 时，在选中框上方浮出参数条（overlay，不进内容层/导出）；
- 含参函数：a/b/c；圆锥：a/b/h/k；
- 拖动范围 = 按下值 ± max(2, |v|)；圆锥 a/b 夹在 0.1–50；
- 一次拖动 = 一步 Undo；参数写回 `PlotSpec.Params` / `PlotConic.A/B`；
- **关键坑（已修）**：只改 `Stroke.Revision` 不会让 `CanvasTileCache` 重烘；
  必须同时 `Doc.Version++` + `StructureChangedSinceRender = true` + `Dirty.Add(PaddedBounds)`；
- 参数条本身必须加进 `ComputeTransientBounds` 的脏区，否则曲线变了、滑杆仍停在旧值。

### 2.4 AI 插入

- 函数/圆锥：后台只解析，不再生成 3.2MB 位图；主线程插 Figure；
- 平面/立体：仍生成 Image（现有 `FigureRenderer` 快照）；
- 旧 Image 文档照常打开；`Image` 路径完整保留。

### 2.5 选中「识别作图」

入口：选中对象 → 操作条 `AI ▾` → 第二项「📈 识别作图」。

| 选中内容 | 路径 |
|---|---|
| 手写题目 | OCR 成文字 → 同一套 `AiPlotClient` 解析 → Figure |
| 文本框/题卡 | 直接取 `Text` + 所有题干 → Figure（不重复 OCR） |
| 单张题目图片 | 图片转 PNG → 模型直接看图反推函数/圆锥/几何（`ParseImageAsync`） |
| 已经是 Figure | 提示“直接拖参数滑杆即可”，不重复生成 |

- 图片路径用 `image_url` 发原图，不做本地 OCR，避免“图里的函数/图线被 OCR 丢字”；
- 模型返回同一套 JSON（functions/conic/plane/solid），函数/圆锥插矢量，平面/立体插本地 Image；
- 菜单两行：`识别文本`、`识别作图`；`BarAiMenuRows=2`。

### 2.6 生题带图

现有 `AiQuestionClient` + `FigureSpec`/`FigureRenderer` 已经把 AI 生成的结构化题图
转成本地 Image 后贴进题卡；本轮不改这条链路。若原题来自截图/图片，用
「识别作图」把图里的函数/几何转成本地 Figure/Image，不再依赖模型直接产图。

### 2.8 识别文本收尾（2026-11-09）

- **原墨迹删除**：识别成功后 `RemoveStrokesAction` + `AddStrokesAction` 用
  `CommitCompound` 合成**一步撤销**；Undo 同时恢复手写、移除文本框。
  之前只加框不删墨，98% 白纸底下会透出原笔迹（“鬼影”）。
- **背景默认**：第一次用 **白纸**（不是透明）；之后沿用设置里**上一次调整**的
  `textBg` 档（透明/白纸/板色/浅色），并持久化到 UI 偏好。
- **空结果**：模型回 `[]` / `{}` / `null` 时不建空文本框。
- **AOT**：`OcrClient` 原来用 `JsonSerializer.Serialize(匿名对象)`，AOT 下报
  “Reflection-based serialization has been disabled”；已改成手写 JSON，AOT 识别恢复。
- 测试：真实手写 220 笔、9 行数学推导，OCR 2.4–3.3s；9 行全部返回，
  分段函数/分式/上下标结构保留；识别后 Undo 恢复 220 笔、文本框 0；AOT 通过。

### 2.7 平面/立体是否转矢量（评估）

**结论：本轮不做，保持 Image。**

| 方案 | 难度 | 性价比 |
|---|---|---|
| 平面/立体静态 D2D 线框（不可编辑） | 中（投影/缩放/标签已有，补 FigureSpec JSON + D2D 线） | 中：省 1–2MB/张、放大清晰 |
| 平面/立体可拖顶点 | 高（新对象/手柄/约束/选中条/存档/回归） | 低：课堂主要是“出图”，不是反复改图 |
| 函数/圆锥矢量 | 已完成 | 高：参数可调、内存几 KB |

老 4GB 机器：函数/圆锥已从 3.2MB/张降到几 KB；平面/立体 Image 默认 820×600
约 1.9MB/张，10 张约 19MB，可接受。真正要防的是“一页几十张大图”，不是几张题图。
所以优先级：**先保证函数/圆锥矢量和识别入口，不急着做平面/立体顶点编辑**。


### 2.9 分段函数（2026-11-09）

- `PlotSeries.Pieces`：每段 `expr + min/max + 开闭`；不再把 `x≥0` 当成表达式条件。
- `PlotSampling`：逐段采样、段间插 `NaN` 断线，共用同一 y 范围；
- `PlotSpecJson`：存档/AI 都写 `pieces` 数组；
- `AiPlotClient` 提示词增加 pieces 模板，真实模型实测返回 2 段；
- 文字识别显示：`--mathtest` 51 张中 50 张成功，`cases` PASS；
  所以分段函数“显示不出来”不是 CSharpMath 的问题，先看 OCR 返回的 LaTeX 是否完整。

截图：`reports/aiplot-piecewise-ai.png`（真实模型返回 2^x / x^2 分段，本地画两支）。
