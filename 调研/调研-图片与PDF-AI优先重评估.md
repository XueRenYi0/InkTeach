# 调研：图片 / PDF 功能——AI 优先重评估

- 日期：2026-10-25
- 状态：**只调研，不改代码**
- 背景：用户新方向——**技术难关优先接大模型 API**，功能不一定要自己写；后期可做付费，支持用户自备 Key 或官方接入赚差价/手续费
- 前置：`调研-图片与PDF处理.md`（代码事实、依赖、包体/内存账仍有效；本文覆盖其“LLM 可选”的结论）

---

## 0. 新结论

1. **AI 优先是对的，但不是“所有功能都交给大模型”。**
   - **该交给 AI 的**：公式/手写识别、复杂版面理解、题目切分、题目讲解/分类/生成、题目文字清洗。
   - **仍应本地/经典做的**：裁切、旋转、透视纠正、美化、数字 PDF 文字层提取、印刷体快速 OCR、精确像素级裁图。
   - 原因：像素操作 AI 更慢、更贵、还不准；AI 的强项是“语义”和“难识别”，不是“抠像素”。
2. **速度是这条路的生命线。**
   - 课堂即时操作（裁切/透视/美化/显示）必须 **<300ms 级**，不能等 AI。
   - AI 识题/公式：目标 **2~5 秒**出结果，最长不超过 8~10 秒；**必须后台跑、不挡写字**，结果好了再提示。
   - AI 讲解：流式输出，首字 **1~2 秒**；不要等整段生成完。
3. **建议“快路径 + AI 深度路径”双层**：
   - 快路径：本地/经典算法 + 本地 OCR/PDF 文字层，解决 80% 的印刷体、数字 PDF、几何处理。
   - AI 路径：只把“本地搞不定”的题目裁图/文字发给大模型；结果缓存、可预取、可取消。
   - 这样既满足“AI 优先”，又不会让老师上课等。
4. **商业模式建议分两期**：
   - 一期 **BYOK**：用户自己填 API Key，软件免费；我们不做后端、不碰账单、不承担模型合规。
   - 二期 **官方托管**：我们做代理/额度/支付，按次或按点数收费，赚服务费/差价；需要后端、账号、支付、限流、合规。
   - 客户端必须同一套“AI 提供方”抽象；BYOK 和托管只是 endpoint/key 不同，不能写两套功能。
5. **AI 能实现功能，但不能保证“全自动正确”。**
   - 题目框坐标、公式转写、题目边界都可能出错；必须给预览/手动修正，不能直接改板书。
   - 公式/手写识别准确率显著低于印刷体；产品上要标“AI 识别，需校对”。
6. **工作量重估**：
   - AI 功能 MVP（BYOK + 识题/公式 + 预览）：**4~6 周**。
   - 加本地快路径（裁切/透视/美化/PDF 文字层）：**+3~5 周**（可与 AI 并行）。
   - 官方托管付费（账号/额度/支付/代理/合规）：**+6~10 周**，且是长期运维。
   - 只做 BYOK、不做托管：**4~8 周**可出可用版本。

## 1. 功能重新分配：哪些给 AI，哪些不给

| 功能 | 首选实现 | AI 的角色 | 理由 |
|---|---|---|---|
| 旋转 / 裁切 | 本地像素/矩阵 | 不用 | 精确、即时、免费 |
| 手动四点透视 | 本地单应 + 重采样 | 不用 | 精确、可控；AI 反而慢 |
| 自动找纸张四角 | 经典 CV / 小模型 / AI 视觉 | 可选 | AI 可做，但坐标不如经典稳；不是第一优先 |
| 美化（对比/去阴影/黑白） | Direct2D/CPU | 不用 | 像素处理 AI 又慢又贵 |
| 数字 PDF 抽文字 | PDFium 文字层 | 可选：AI 清洗/切题 | 文字层是精确的，AI 只做语义 |
| 印刷体 OCR | 本地 OCR 优先 | 可选：低置信度时 AI 复核 | 本地快、便宜、离线 |
| 公式 OCR | **AI 视觉/公式 API** | **主力** | 普通 OCR 做不了 |
| 手写识别 | **AI 视觉** | **主力** | 本地 OCR 准确率低 |
| 题目切分（数字 PDF） | PDFium 文字 + 规则 | 可选：AI 处理不规则题号 | 规则快且准 |
| 题目切分（扫描/复杂版面） | **AI 视觉** + 手动修正 | **主力** | 规则难以覆盖 |
| 题目讲解/分类/变式 | **LLM** | **主力** | 纯语义任务 |
| 题目导出/裁图 | 本地 | 不用 | 像素操作 |

> 一句话：**AI 负责“看不懂/说不清”的部分，本地负责“算得准/等不起”的部分。**

## 2. 延迟账：上课到底能不能等

### 2.1 课堂场景分两类

| 场景 | 老师能等多久 | 结论 |
|---|---|---|
| 写板书、裁一题、翻一页、美化一下 | **0.3 秒内** | 必须本地，不能走 AI |
| 点“AI 识题 / 公式转写” | **2~5 秒**可接受，但**不能挡写字** | 后台任务 + 进度 + 结果提示 |
| 点“AI 讲解” | 首字 1~2 秒，整段 3~10 秒 | 流式输出，边生成边显示 |
| 课前批量整理一整套试卷 | 几十秒~几分钟 | 后台队列/批量，不要求即时 |

**最忌讳**：点一下按钮，整个界面转圈 10 秒，老师不能写字、不能翻页。这比“没有 AI”更糟。

### 2.2 一次 AI 识题的端到端时间

| 环节 | 大约耗时 | 优化 |
|---|---|---|
| 本地裁图/压缩 | 10~100ms | 只发题目区域，长边 1600~2000px，JPEG 80% |
| 上传 | 0.2~2s | 国内 endpoint；别发整页 8MB |
| 排队/冷启动 | 0~2s | 预热、连接复用、避开冷门模型 |
| 视觉推理 | 1~5s | 快速模型优先；“精准”再升级 |
| 结构化 JSON/解析 | 0.1~0.5s | JSON schema；失败重试一次 |
| 本地渲染/预览 | <100ms | 不阻塞主线程 |
| **合计** | **约 2~8s** | 目标 ≤5s；超过 8s 改后台/提示 |

> 这是“一页/一题”的量级；实际取决于网络、模型、图片大小。必须实测，不能拍脑袋承诺。

### 2.3 提速手段（按性价比）

1. **只发题目裁图，不发整页 PDF**；长边压到 1600~2000px，JPEG/WebP。
2. **能用文字就不发图**：数字 PDF 先抽文字层，把“文字 + 行框”发给文本模型做切题/清洗；比视觉模型快、便宜。
3. **一次请求处理整页**，不要一题一次请求；让模型返回题目数组。
4. **缓存**：按“图片 hash + prompt 版本 + 模型”缓存结果；同一页第二次打开直接命中。
5. **预取**：打开页面/翻到下一页时，后台先跑识题；老师要讲时结果已到。
6. **快慢两档模型**：默认快速视觉模型；用户点“精准识别”再走大模型。
7. **并发上限 2~3**：别把一页拆成 20 个请求；限流、重试、超时、取消。
8. **流式**：讲解用 SSE 流式；识题要 JSON，不能流式半截，但可以先显示“正在识别第 N 题”。
9. **失败降级**：超时/断网 → 本地 OCR/规则/手动框选，不要卡死。

### 2.4 课堂可接受的目标（建议写进验收）

- 裁切/透视/美化：**<300ms**，无网络依赖。
- 数字 PDF 抽文字/切题：**<500ms/页**。
- 本地印刷体 OCR：**<2s/页**（i5 级、2000px）。
- AI 单题识别：**p50 ≤3s，p95 ≤8s**；超过 8s 不阻塞，转后台并提示。
- AI 讲解：首字 **≤2s**，整段 **≤10s**。
- 任何 AI 任务：**可取消**，取消后 1 秒内释放 UI。

## 3. AI 优先的功能设计

### 3.1 图片美化 / 透视：AI 不做主力

- 这些是像素级、确定性操作，本地更快更准。
- AI 可以以后做“自动找角/自动判断哪块是题目”，但第一版不做。
- 老师拍照后的流程：
  1. 本地自动 EXIF 转正；
  2. 手动四点透视（或自动找角，第二版）；
  3. 本地美化预览；
  4. 需要识题时再把处理后的裁图发给 AI。
- **不要**把整张 4000×3000 原图直接发视觉模型：慢、贵、还可能被降采样。

### 3.2 OCR：本地快路径 + AI 深度路径

**快路径（默认）**

- 数字 PDF：PDFium 文字层，零 OCR。
- 图片/扫描件印刷体：本地 OCR（RapidOcrNet/Tesseract），1~2 秒，离线。
- 结果直接可复制/搜索；低置信度标黄。

**AI 深度路径（按钮触发/自动建议）**

- 公式、手写、复杂版面、低置信度 → 把**题目裁图**发给视觉模型。
- 返回：文字、LaTeX、题目边界（近似）、置信度/说明。
- 结果必须预览/校正；不要直接覆盖原图或自动写板书。
- 如果只是“给 AI 讲解”，可以**跳过 OCR**，直接把题目裁图发给视觉模型；更准，也少一步。

### 3.3 题目切分：规则优先，AI 兜底

| 来源 | 首选 | AI 何时上 |
|---|---|---|
| 数字 PDF、题号规范 | PDFium 文字 + 题号/间距规则 | 题号乱、分栏、跨页时 |
| 扫描件/照片、印刷体 | 本地 OCR 行框 + 规则 | 版面复杂、公式多、规则切不准 |
| 手写/混合 | AI 视觉 | 默认就走 AI |
| 需要“题目语义”（题型/知识点/难度） | AI 文本/视觉 | 总是 |

**AI 返回结构建议**（示例，不是代码）：

```json
{
  "questions": [
    {
      "number": "12",
      "bbox": [0.08, 0.22, 0.92, 0.41],
      "text": "已知函数 ...",
      "latex": "f(x)=...",
      "confidence": 0.86
    }
  ]
}
```

- `bbox` 用 0~1 归一化坐标；本地裁图仍然用精确像素框，AI 框只做“建议”。
- 坐标可能偏；必须允许拖动/合并/拆分。
- 一次请求整页，返回数组；不要一题一请求。

### 3.4 题目讲解 / 分类 / 变式：纯 AI

- 选中题目裁图/文字 → 流式讲解、知识点、难度、同类题。
- 这是付费功能的最佳切入点：按次/按点数，用户感知价值直接。
- 结果只显示在侧栏/浮层，不自动改板书；可复制/插入文本。

### 3.5 输出形态

- **题目裁图**：本地按最终框裁，不依赖 AI 坐标精度。
- **题目卡片**：AI 文本/公式/标签 + 本地裁图；存为对象或题目库（后续）。
- **导出**：先图片；PDF 导出后置（PDFsharp）。

## 4. 技术架构：一套 AI 抽象，BYOK/托管都能用

### 4.1 客户端抽象

- 统一走 **OpenAI 兼容协议**（`/chat/completions`，支持 `image_url`/base64、JSON schema、SSE 流式）。
- 配置项：`base_url`、`api_key`、`model`、`timeout`、`max_tokens`、`temperature`、`response_format`。
- 预设：通义千问（DashScope 兼容模式）、豆包（火山 Ark）、GLM、DeepSeek（文本）、OpenAI；用户也可自定义。
- 模型分两档：
  - `fast`：视觉小模型/文本模型，默认识题、切题；
  - `accurate`：大视觉模型，公式/复杂版面/用户点“精准”。
- 密钥安全：BYOK 用 **DPAPI** 加密存本机；不写日志；不放进 URL；不上传我们服务器（除非托管模式）。

### 4.2 两种运行模式

| 模式 | 客户端请求 | 谁付模型费 | 我们的成本 | 适合 |
|---|---|---|---|---|
| **BYOK** | 直接到厂商 endpoint | 用户 | 0 | 一期，验证需求 |
| **官方托管** | 到我们的代理 `/ai/...` | 用户买点数/会员 | 服务器、支付、合规、运维 | 二期，赚服务费/差价 |

**托管模式的最小后端**：

- 账号/登录（或设备码 + 订单）；
- 预付费点数/订阅；
- 代理转发（服务端持有厂商 Key，绝不下发）；
- 计量/扣点/失败退款/重试；
- 限流、防滥用、成本上限；
- 支付（微信/支付宝）、发票/对账；
- 内容安全/未成年人保护；
- 日志脱敏（不存图片/题目内容）。

**不要**把厂商 Key 硬编码进客户端；客户端 token 只能访问我们的代理，且有额度/过期。

### 4.3 任务队列 / 缓存 / 预取

- 所有 AI 调用走**后台任务队列**；主线程只发任务、收结果。
- 任务 key：`图片hash + prompt版本 + 模型 + 任务类型`；命中缓存直接返回。
- 页面打开/翻页时预取“识题”；老师点按钮时大概率已好。
- 并发上限 2~3；超时 10~15 秒；取消即丢弃；失败降级本地。
- 结果存内存 LRU（可选磁盘缓存），不把题目图片长期落盘。
- UI：按钮旁显示“识别中 2s / 已缓存 / 失败（重试）”；不转全屏圈。

### 4.4 预处理（决定速度和成本）

- 只裁题目区域；长边 1600~2000px；JPEG 80% 或 WebP。
- 先本地透视/去阴影/增强，再发；识别率更高、图更小。
- 数字 PDF：先抽文字，文本模型优先；只有公式/图表才发图。
- 多题一页：一次请求返回数组；不要拆成 N 次。
- 公式题：裁到公式附近，减少无关文字；返回 LaTeX 并预览。

## 5. 商业模式：BYOK 与托管怎么组合

### 5.1 一期：BYOK（推荐先做）

- 软件免费；用户自己开厂商 API Key，填进设置。
- 我们不做服务器、不收款、不承担模型账单；不涉及生成式 AI 备案（模型由用户自己开通；仍建议法务确认）。
- 优点：上线快、成本低、验证“老师到底用不用”。
- 缺点：配置门槛；用户可能觉得“还要自己买 Key”；网络/限流问题会被当成软件 bug。
- 缓解：内置三家预设 + “测试连接” + 用量估算 + 错误提示。

### 5.2 二期：官方托管（付费）

- 用户不用 Key，买点数/会员；我们代理调用，赚服务费/差价。
- 定价单位建议：**按“识题/讲解/公式”次数**，不要按 token 展示给老师（太技术）。
- 成本要算全：模型费 + 支付手续费 + 服务器 + 失败重试 + 客服 + 税费；毛利建议 ≥30~50% 再上。
- 需要：
  - 账号/订单/点数；
  - 支付与退款；
  - 限流/防刷/成本封顶；
  - 模型多路切换/降级；
  - 隐私政策/用户协议/未成年人保护；
  - 生成式 AI 相关合规（若面向公众提供生成服务，按现行规定评估备案/安全评估）。
- **不要**在没有后端/合规之前，把官方 Key 放进客户端“先跑起来”。

### 5.3 混合（最终形态）

- 免费版：BYOK，功能完整；
- 付费版：官方通道 + 赠送额度 + 更快/更好的模型 + 题目库/批量整理；
- 同一套客户端抽象，切 endpoint/key 即可。

## 6. 工作量与分期（AI 优先版）

> 口径：一名熟悉仓库的开发者，含自检/真机；不含长期模型调参和法务。

### 阶段 A：AI 基础设施 + BYOK（3~5 周）

1. AI 提供方抽象（OpenAI 兼容、预设、Key 加密、连接测试）。
2. 后台任务队列、超时/重试/取消、缓存、进度 UI。
3. 单题“AI 识题/公式”最小闭环：裁图 → 视觉模型 → JSON/文本 → 预览。
4. 隐私同意：单独开关；不沿用设备统计同意。
5. 真机延迟/成本实测。

**产出**：老师可以选中一题，2~5 秒看到 AI 转写的文字/公式；不挡写字。

### 阶段 B：快路径 + 题目切分（3~5 周，可与 A 并行）

1. 图片/PDF 页：旋转、裁切、手动四点透视、美化预设。
2. 数字 PDF 文字层 + 规则切题。
3. 手动框选题目 → 插入画布/导出。
4. 本地印刷体 OCR 可选（RapidOcrNet/Tesseract）作为 AI 的快路径/降级。

**产出**：没有 AI 也能顺畅裁题/讲题；AI 只处理难题。

### 阶段 C：官方托管付费（6~10 周）

1. 后端代理、账号、点数、支付、限流、计量。
2. 多模型路由/降级、成本控制。
3. 隐私/合规/协议。
4. 运营后台（用量、退款、告警）。

**产出**：用户不用 Key，买点数直接用；我们赚服务费/差价。

### 阶段 D：自动切题/题目库/批量（后续）

- AI 自动切题 + 人工修正；
- 题目库、标签、搜索、组卷；
- 批量识别/导出；
- 这是长期产品，不是第一版。

## 7. 速度/成本/准确率的现实边界

| 指标 | 现实预期 | 应对 |
|---|---|---|
| 视觉模型识一题 | 2~8s | 后台 + 预取 + 快速模型 |
| 文本模型切一页 | 1~3s | 数字 PDF 文字层优先 |
| 公式转写 | 2~8s，可能错 | 预览/校对；只裁公式 |
| 手写识别 | 3~10s，准确率低 | 标 beta；不承诺全对 |
| 单题成本 | 几分钱到几毛钱（看模型/图大小） | 裁图、压缩、缓存、快速模型 |
| 4GB 学校机器 | 本地 OCR 可能吃内存 | 本地 OCR 可选/云端；一次一页 |
| 网络差/断网 | AI 不可用 | 本地快路径/手动兜底 |

> 价格和延迟随厂商/模型/地区变化，**以实测账单为准**；不要在代码里写死价格。

### 7.1 价格锚点（2026-10 查询，人民币/百万 token）

| 模型 | 输入 | 输出 | 备注 |
|---|---|---|---|
| 阿里云 `qwen-vl-ocr` | 0.3 元 | 0.5 元 | 专做文字/文档识别，最便宜的 OCR 档 |
| 阿里云 `qwen-vl-plus` | 0.8 元 | 3.2 元 | 通用视觉，识题/切题够用 |
| 火山 `Doubao-Seed-2.1-lite` | 0.8 元 | 2.7 元 | 支持图片；图片 token 有上限 |
| 火山 `Doubao-Seed-2.1-turbo` | 3 元 | 15 元 | 更快/更强 |
| 火山 `Doubao-Seed-2.1-pro` | 6 元 | 30 元 | 复杂版面/公式再上 |

**一题到底多少钱（估算）：**

- 阿里视觉模型：每 token 对应 32×32 像素 → 一张 1600×2000 的题目裁图 ≈ **3100 token** ≈ **0.0025 元**输入。
- 豆包视觉：图片 token 按 `min(宽×高/784, 1312)` 计 → 同样一张图**封顶 1312 token**，输入更便宜。
- 输出按 300~800 token 估 ≈ **0.001~0.02 元**。
- **合计：一题约 0.005~0.03 元**（快速档），旗舰档约 0.05~0.15 元；整页一次返回多题时更省。

### 7.2 托管定价的算法（举例，不是定价决定）

- 成本 = 模型费 + 支付手续费（约 0.6%）+ 服务器/带宽 + 失败重试 + 客服。
- 若一题成本 0.02 元、卖 0.1 元/次，毛利约 80%；卖 0.05 元/次，毛利约 60%。
- 更稳的做法是**点数包**：如 10 元 = 150 点，识题 1 点、讲解 3 点；成本波动时调点数，不改价目表。
- 必须设**单用户日限额/成本封顶**，否则被刷或模型涨价会直接亏。
- 免费额度（如 100 点）比“无限免费”安全，也方便转付费。

> 结论：单次成本是**分/厘级**，做差价有空间；真正吃利润的是失败重试、整页大图、旗舰模型滥用和支付/客服，不是模型单价本身。

## 8. 隐私与合规（AI 版）

- 题目图片可能含学生姓名、班级、答案、批改痕迹；属于个人信息/未成年人信息。
- **设备统计同意不能覆盖 AI 上传**；必须单独、明确、可撤回。
- BYOK 也可能上传到厂商云；不是“本地”。
- 托管模式我们是数据处理者/服务提供者，责任更重；需要隐私政策、数据保留、删除机制、未成年人保护。
- 不把题目图片/OCR 文本写日志；不上传整页 if 裁图够用；不长期存图。
- 学校可能禁外网；必须保留离线快路径。

## 9. 风险

1. **速度不达标**：视觉模型 5~10s，课堂等不了；必须后台/预取/快速模型，不能做同步阻塞。
2. **准确率/幻觉**：公式、手写、题目边界可能错；必须人工确认。
3. **成本失控**：整页大图、反复重试、N 题 N 请求；需要裁图/缓存/限额。
4. **网络/厂商不稳定**：限流、断网、区域限制；需要多厂商/降级。
5. **BYOK 门槛**：老师不会配 Key；需要预设和测试连接。
6. **托管合规/支付/运维**：不是写个代理就完事；需要长期投入。
7. **隐私**：学生图片上传；同意、脱敏、留存都要设计。
8. **包体**：本地 OCR/模型会让安装包变大；AI 模式本身不增加包体，但需要网络。

## 10. 建议与需要拍板

### 建议

- **AI 优先，但只优先“语义/难识别”**；像素操作仍本地。
- **一期只做 BYOK**，不做托管；先验证老师是否愿意用、愿意配 Key。
- **AI 功能从“单题识题/公式”切入**，不要一上来做全自动整卷切题。
- **所有 AI 调用后台化 + 缓存 + 预取**；课堂主线程永不等待。
- **数字 PDF 先抽文字**，文本模型切题；扫描件/公式再走视觉。
- **托管付费放二期**；先把模型抽象、计量、隐私同意做对，再接支付。

### 需要拍板

1. 一期是否 **只做 BYOK**，官方托管放二期？
2. 第一个 AI 功能选哪个：**单题识题/公式**，还是 **整页自动切题**？（建议单题）
3. 课堂可接受的 AI 延迟上限：**5 秒 / 8 秒 / 10 秒**？
4. 公式/手写识别是否第一版就上？还是先只做印刷体 + 单题裁图？
5. 托管付费的定价单位：**按次（识题/讲解）** 还是 **点数包/会员**？
6. 是否接受“AI 结果必须预览/校对，不自动改板书”这条产品纪律？
