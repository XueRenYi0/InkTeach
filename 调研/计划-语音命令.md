## 一、目标形态（用户视角）

| 用户说 / 打 | 发生什么 |
|---|---|
| 画三角形 / 来个圆 / 画条抛物线 | 当前视图中心按默认尺寸画好，**画完自动选中**（手柄直接可拖） |

| 激光笔 / 橡皮 / 截图 | 切工具 |

1. **全部走 `IEngineCommands`**（`src/InkEngine/Ui.cs:191`）——撤销栈、脏区、空间索引

3. **不常驻、不落盘**：按键才录音，说完即释放，音频默认不留存。

## 四、词表与解析规则

**词表按"意图"分组，不按"词"分组**（一个意图可挂多个说法）：

| 组 | 示例（说法 → 意图） |
|---|---|
| 图形 | 三角形/三角/三角行 → `shape(Triangle)`；圆/圆形/缘 → `shape(Circle)`；抛物线/抱物线 → `shape(Parabola)`；波浪/正弦/正弦曲线 → `shape(Wave/Sine)`…… |
| 工具 | 笔/画笔、橡皮、激光笔、截图、框选、白板、鼠标/穿透 |
| 颜色 | 红/红色/大红、黑、蓝、白、绿、黄 → `color(…)` |
| 动作 | 撤销/退一步/返回、重做、清空/清屏、删除、翻页/下一页/上一页 |
| 属性 | 粗一点/细一点、大一点/小一点 |
| 数字 | "半径三"、"三十度" → 3 / 30（中文数字 + 阿拉伯数字都认） |

**容错三层**（从便宜到贵，命中即止）：

1. **别名表**（手写，几十条）：错字（三角行）、同义（圆形/圆）、口语（来个/帮我画）；
2. **归一化**：全角↔半角、中文数字→阿拉伯数字、去掉"请/帮我/一下/来个"等填充词；
3. **编辑距离 ≤1**（在词表内部算，不引拼音库）；到这一层还没命中 →
   **不猜**，显示"听到：xxx"并给示例（三期才考虑交给大模型）。

**默认几何原则**（写死在表里，实现时调具体值）：

- 位置 = **当前视图中心**（引擎有现成的窗口↔画布换算）；
- 尺寸 = 视图短边的 ~35%（每种图形允许有自己的宽高比，比如抛物线默认开口向上）；
- 画完**自动选中**；"大一点/小一点"作用于当前选中或刚画的对象。

## 五、语音链路技术选型（一期）

| 项 | 选择 | 理由 |
|---|---|---|
| 采集 | NAudio WASAPI，16k / 16bit / 单声道 | MIT、成熟、格式正好是识别接口要的 |

| 识别（备选） | 讯飞 IAT | 中文最强、有方言；但要 appid+key+secret 三个字段 |
| 网络 | `ClientWebSocket` / `HttpClient`，超时 + 一次重试 | 无新依赖 |
| 隐私 | 音频只在内存里，识别完即弃；日志默认不记文本 | 课堂录音很敏感 |
| 成本 | 每天 10 分钟命令 ≈ ¥0.05/天 | 需要写进用户说明 |

## 附：语音的价值评估（2026-10-01 讨论，去留待定）

### 一、语音真正独有的优势（几乎没有替代品）

1. **手被占用时的"内容型"输入**：老师写字、指屏、拿教具时，快捷键要腾手、打字不可能；
   语音是唯一"不脱手就能输入内容（要画什么）"的通道。
2. **"讲解即操作"的潜力**：教学本来就靠说话——"这里我们画一个圆"本来就是讲解的一部分，
   操作可以零额外动作。这条潜力最大，但也最难做对（要区分讲课内容与命令，避免误触发）。
3. **远离键鼠时**：站在大屏/投影前，手上没有鼠标键盘。

### 二、有替代品、语音并不占优的

| 需求 | 更便宜/更稳的替代 |
|---|---|
| 切工具、撤销、翻页 | 快捷键、按钮带、**翻页笔**（多数是 PageUp/PageDown，你们已经能用）、脚踏开关 |
| 打字/输入内容 | 键盘、触摸 |
| 精确、零误识别 | 任何物理按键都比语音稳 |

**所以要害在于**：语音的独特价值高度集中在"内容型/组合型"命令上——而这类命令的价值
主要来自 **AI 命令层**；语音只是把"打字"换成"说话"。

### 三、代价（不便宜）

- 工程：录音 / VAD / 识别 / 错误处理 / 设置 / 权限 / 自检，阶段 1～2 约 2～4 周；
- 使用：麦克风权限、教室噪声、误识别、当着学生说话的心理成本、断网即失效；
- 维护：Key、费用、供应商变化；
- 机会成本：同样的时间可以补日志 / 首启引导 / 多屏 DPI / 手掌抑制——这些影响**所有**用户。

### 四、什么条件下值得重启（建议先不做）

1. 有 **≥3 个真实用户**明确提"想要语音"（不是开发者觉得酷）；
2. AI 命令层上线后，出现"打字太麻烦 / 腾不出手"的抱怨；
3. 录课/直播用户占比明显上升（语音在录课场景比课堂更自然）；
4. 或自己做一次课堂观察：数一数"因为腾不出手而打断书写去点按钮"的真实次数。

### 五、最便宜的验证方式（一行识别代码都不用写）

先做**文字命令面板**（阶段 1，它本身是 AI 命令层的前提），然后接**系统听写（Win+H）**：

- 老师真用、觉得爽 → 再接真语音；
- 没人用命令面板 → 语音先别做，AI 面板也要重新评估。

> **结论（2026-10-01 用户拍板）：语音与 AI 画图整体搁置——"先放起来"。**
> 命令层（文字命令）作为将来 AI 的前提，方案保留在本文（含词表、命令、自检步骤）；
> 重启时先做最便宜的验证（文字命令面板 + Win+H），再决定接不接真语音。
