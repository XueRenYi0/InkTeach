# AI 出题 · 底部上滑面板与语音输入调研

日期：2026-11-02  
状态：调研完成，待拍板；**AI 出题已按用户决定暂停，入口置灰显示“开发中”**，本文保留供以后恢复时使用  
范围：AI 出题面板的入口、底部上滑、文字/语音输入、生成参数、加载/失败、题目预览与插入白板

---

## 0. 先看结论

1. **推荐方案 B：三段式底部抽屉**。  
   - 第一段（Peek，约 240 逻辑高）：微信式按住说话。  
   - 第二段（Half，约 460）：转写结果 + 可点的年级/学科/题量/难度。  
   - 第三段（Full，约 80% 屏高）：题目列表，逐题编辑/换题/删除，最后一键插入白板。
2. **“默认语音”建议定义成：默认选中语音模式，但按住才录，不打开就常听。**  
   这既符合微信的 PTT，也符合 Wispr Flow / Cursor 的桌面听写；Gemini Live 那种常开麦在教室场景会收进学生说话、投影回声和无关对话。
3. **转写后必须让老师看一眼再生成，不学微信“松手直接发送”。**  
   出题要求里年级、题量、难度、答案要求都不能错；ChatGPT 官方也把“录一段 → 审核/编辑 → 再发”单独定义为 Dictation，而不是 Voice 对话。
4. **参数不要摆成大表单。**  
   用“一句话 + 可点的 chips”：老师说完“给初二出三道二次函数题，中等难度，带答案”，下面自动出现 `初二 / 数学 / 二次函数 / 3 道 / 中等 / 带答案`，点哪个改哪个。这样既有语音的轻，也有出题产品的可控。
5. **结果建议合成一张 AI 题卡（内含 N 道题）插入白板，而不是 N 张卡。**  
   和现有 `AiCard` 的数据结构一致；审核时用列表，插入后仍是一张可折叠答案、可拖动、可改宽的题卡。
6. **ClassIn / 希沃的公开资料只到“功能层”，没有可照搬的面板 UI。**  
   公开报道能确认它们有“按教学目标/知识点生成不同难度和题型”的能力，但没有官方截图/录屏。要真正做到“全量照搬 ClassIn 的 AI 出题面板”，还需要你提供一段 ClassIn 6.0 的录屏或截图；否则这一块只能按通用出题产品 + 微信输入栏来设计。

## 2. 产品拆解

### 2.1 微信：底部输入栏 + 按住说话

**结构（经典版）**

```
┌──────────────────────────────────────────────┐
│  🎙/⌨   [ 按住 说话 ]              😊  ＋   │
└──────────────────────────────────────────────┘
```

- 左侧是**语音/键盘切换**，中间是按住说话，右侧是表情和更多。
- 文字模式下，中间变成输入框；有文字时右侧出现“发送”。
- 语音模式不是“点一下就一直录”，而是**按住才录、松手结束**。

**按住说话的完整状态机**

| 阶段 | 界面 | 行为 |
|---|---|---|
| 按下 | 弹出录音浮层，波形 + 计时 | 开始录音 |
| 按住说话 | 波形随音量动，显示 `00:03` | 继续录 |
| 上滑 | 浮层出现“松开取消” | 进入取消预备 |
| 松手（未上滑） | 浮层消失，语音消息发出 | 发送 |
| 松手（已上滑） | 浮层消失，不发送 | 取消 |
| 太短 | 提示“说话时间太短” | 不发送 |
| 到上限 | 自动结束 | 发送或转文字 |

**2026 年的变化（微信灰度“可按住 转文字”）**

- 输入框本身变成一条灰字“可按住 转文字”，长按输入框直接说话，松手后自动转文字并发送；部分版本把右侧麦克风图标去掉了。
- 官方客服回应：iOS 小范围灰度，安卓/鸿蒙还在做；收到更新的用户**不能手动关闭提示**。
- 用户反馈两极：
  - 好：不用来回切语音/键盘，少点一步；
  - 不好：老用户找不到麦克风、误触、灰色提示打扰、不能关。

**对我们的直接结论**

- 照搬：按住说话的状态机、波形 + 计时、上滑取消、太短提示、60 秒上限。
- 不照搬：**不要删掉文字入口**，也不要把提示做成不能关的常驻灰字。老师上课时可能必须打字（教室吵、麦克风被占、要精确输入公式/符号）。
- 微信是“松手直接发”，我们改成“松手 → 转写文字进输入框 → 老师确认 → 生成”。这是聊天和出题的关键差异。

来源：凤凰网《微信灰度测试“按住转文字”新功能》、澎湃《微信为了让你用语音输入，快“魔怔”了》、财联社相关报道（2026-08）。

### 2.2 ChatGPT Voice：语音和文字在同一个输入栏

**结构**

```
┌──────────────────────────────────────────────┐
│  输入框…                            🎙  ➤   │
└──────────────────────────────────────────────┘
```

- 语音入口是输入框右侧的波形图标；点开后按钮变蓝，进入语音。
- 语音对话**发生在当前聊天里**，不是另开一个全屏页面；可以说话、看文字回答、翻前面的消息。
- 语音进行中，可以点麦克风静音/取消静音，点退出结束。
- 官方设置里有 `Start with Voice`：打开新对话时自动进入语音。
- 官方帮助明确区分：
  - **Voice**：实时来回对话；
  - **Dictation**：录一段 → 审核/编辑转写 → 当文字发出去。

**对我们的直接结论**

- 照搬：**语音和文字共用一个输入栏**，语音不是另一个页面；转写结果要可见、可编辑；不能说话时随时能打字。
- 照搬：`Start with Voice` 这种“默认语音”的开关思路——默认语音可以是设置，不是硬编码。
- 不照搬：实时语音对话。我们只需要“ dictation（听写）”，不需要 AI 跟老师来回聊，至少第一版不需要。

来源：OpenAI Help Center《ChatGPT Voice》（2026 更新）、PCMag/OpenAI 关于语音合并进聊天的报道（2025-11）。

### 2.3 Gemini Live：常开麦 + 全屏，不适合教室

- 默认是持续监听的双向对话；界面像通话，麦克风可静音、可暂停、可打断。
- 2026-07 的拆包显示，Google 正在加**按住说话（PTT）**模式：只在按住麦克风时听，用来应对嘈杂环境，避免把旁边人的话收进去。
- 交互是全屏沉浸式，会盖住白板/课件。

**对我们的直接结论**

- 不照搬：常开麦、全屏。
- 照搬：PTT 的动机——“在嘈杂环境里，只在我按住时听”。
- 教室就是典型嘈杂环境：学生说话、投影回声、走廊声音。**默认语音必须默认 PTT，不能默认常听。**

来源：Android Authority（2026-07-06，APK teardown）、Google Gemini Live 帮助页。

### 2.4 桌面听写：Wispr Flow / Cursor

这两个是“在桌面软件里按住说话、松手出文字”的成熟参考，比手机微信更接近我们的场景。

**Wispr Flow**

- 按住快捷键（Mac 默认 `Fn`，Windows 默认 `Ctrl + Win`）说话，松开后把整理好的文字插入当前光标位置。
- 有 hands-free（免按住）模式；有历史、词典、片段、风格设置。
- 官方明确：插入后**先读一遍再发送/分享**；转写失败时提供粘贴兜底。

**Cursor 3.1 语音输入**

- `Ctrl + M` 开始说话；录音时显示**波形、计时器、取消、确认**。
- 语音处理期间，提示按钮保持原位，不跳。

**对我们的直接结论**

- 照搬：按住说话 + 波形 + 计时 + 取消/确认；松手后先出文字，再让用户确认。
- 照搬：处理中保持布局稳定，按钮不跳。
- 可借鉴：免按住作为高级选项，不放进第一版主路径。
- 注意：桌面鼠标按住 20 秒会累；如果老师要口述长题，最好同时支持“点一下开始、再点一下结束”，但默认仍显示“按住说话”。

来源：Wispr Flow 官方文档《What is Wispr Flow?》、Cursor 3.1 更新日志（2026-04-13）。

### 2.5 AI 出题产品：表单 → 生成 → 审核 → 发布/导出

这一组是“出题”本身的流程参考。它们几乎都不是语音优先，但生成参数、审核和插入方式很成熟。

| 产品 | 入口 | 输入 | 参数 | 生成后 | 输出 |
|---|---|---|---|---|---|
| Wayground（原 Quizizz） | Create → Assessment → Generate with AI | 文档 / 提示词 / 网页 / YouTube / 课程 | 题量、学科、年级、语言、标准、DOK；提示词路径还会选子主题 | 逐题编辑；可继续和 AI 对话改；也可手动改 | Publish 发布 |
| Khanmigo | Teacher Tools → Question Generator | 文本/主题，最多 4500 词 | 年级、题量（最多 10） | 直接编辑题目和答案，不用重新提示 | 导出 Google Forms / Blooket |
| MagicSchool | Tools → Multiple Choice Quiz | 主题/文本/附件 | 年级、选择题数量、开放题数量、难度、标准 | 生成后调整难度/题量/重点 | 复制/导出/课堂使用 |
| ClassIn 6.0 | 测验 → AI 出题 | 教学目标/知识点 | 难度、题型 | 公开资料未给 UI | 测验/作业 |
| 希沃 | AI 教学空间 / AI 备课 | 教学目标/课文 | 公开资料未给 UI | 公开资料未给 UI | 课件/课堂活动 |

**共性**

1. 先给“来源”或“主题”，再给参数；
2. 参数是显式的：年级、题量、题型、难度、是否带答案；
3. 生成后一定有**审核层**：逐题编辑、换题、删题、重新生成；
4. 最后是“发布/导出/插入”，不是生成完就结束。

**对我们的直接结论**

- 照搬：生成参数、逐题审核、换题/删题、重新生成、最后插入。
- 不照搬：一整页的大表单。我们是底部抽屉，参数必须压缩成 chips / 一行。
- 机会点：这些产品都没有“老师按住说一句话就出题”。语音是我们的差异，但**审核层不能省**，否则老师不敢把题投到白板上。

来源：Wayground 官方帮助（2026-03-24 更新）、Khanmigo 官方 Question Generator 页、MagicSchool 官方 Multiple Choice Quiz 页。

### 2.7 底部面板的通用规则（NN/g + Apple HIG）

**NN/g《Bottom Sheets》**

- 底部面板适合**短时、上下文相关**的操作，能让用户继续看到背后的内容。
- 必须给明确的关闭方式（X），不能只靠下滑把手；要支持 Back/Esc。
- 不要叠多个底部面板；不要用底部面板承载需要长时间阅读/编辑的长内容。

**Apple HIG**

- Sheet 用 detent（中/大）定义停留高度；可以从中等高度拉到大高度。
- 中高度适合“看一眼/做一步”，大高度适合更多内容。

**对我们的直接结论**

- 用**多段高度**，不要一个固定高度：说话时矮，确认时中，审题时高。
- 说话/确认是短交互，适合底部；审题是长内容，所以第三段要接近全屏，并且有独立滚动区，不能硬塞在 300 高的小面板里。
- 关闭按钮始终在；Esc 逐层退；点空白在矮态关闭、在高态先收一层，避免误丢已经生成的题。

来源：NN/g《Bottom Sheets: Definition and UX Guidelines》（2023-06-11）、Apple HIG《Sheets》。

## 3. 跨产品对照：我们到底该抄哪一段

| 我们要的 | 最成熟参考 | 照搬什么 | 不照搬什么 |
|---|---|---|---|
| 底部输入栏 | 微信 | 左语音/键盘切换、中间按住说话、右侧更多/发送 | 删掉文字入口、常驻灰字提示、松手直接发 |
| 语音转文字 | ChatGPT Dictation / Wispr Flow | 录 → 转写 → 可编辑 → 再确认 | 实时语音对话、全屏语音页 |
| 桌面按住说话 | Wispr Flow / Cursor | 波形、计时、取消、确认、处理中不跳 | 全局快捷键（第一版不做） |
| 出题参数 | Wayground / Khanmigo / MagicSchool | 年级、题量、题型、难度、答案；可改 | 大表单、先选来源再选一堆设置 |
| 生成后审核 | Wayground / Khanmigo | 逐题编辑、换题、删题、重新生成 | 发布到 LMS 的整套流程 |
| 底部抽屉 | Apple HIG / NN/g | 多段高度、抓手、X、Esc、不叠层 | 用底部抽屉承载长表单 |
| 插入白板 | 我们自己的 AI 题卡 | 一张卡内含 N 题、可折叠答案、可拖动/改宽 | 拆成 N 张卡、插入后关不掉 |

## 4. 三套方案

### 方案 A：微信单条（最轻）

**布局**

```
┌──────────────────────────────────────────────┐
│                  ───                         │
│  AI 出题                               ✕     │
│  ┌────┐ ┌──────────────────────────┐  ＋     │
│  │ 🎙 │ │  按住 说出题目要求        │         │
│  └────┘ └──────────────────────────┘         │
│  [初二] [数学] [二次函数] [3道] [中等]       │
│  最近：二次函数 / 一元二次方程 / 勾股定理     │
└──────────────────────────────────────────────┘
```

- 只有一段高度（约 240）。
- 语音默认；松手转写后，文字直接替换“按住说话”条，右侧出现“生成”。
- 生成后，面板内容换成一张题卡预览（最多 3 题），底部“插入白板”。
- 适合：课堂上临时补一道题、快速出 1–3 题。

**优点**：最像微信，学习成本最低；实现量最小；不挡白板。  
**缺点**：题目一多就要在很矮的区域里滚动；参数多了放不下；审核体验弱。  
**风险**：做到后面一定会想加高，最后还是变成方案 B，等于绕一圈。

### 方案 B：三段式底部抽屉（推荐）

**布局**

第一段 · 说话（Peek，约 240）

```
┌──────────────────────────────────────────────┐
│                  ───                         │
│  AI 出题                               ✕     │
│  ┌────┐ ┌──────────────────────────┐  ＋     │
│  │ 🎙 │ │  按住 说出题目要求        │         │
│  └────┘ └──────────────────────────┘         │
│  [初二] [数学] [二次函数] [3道] [中等]  ⚙   │
└──────────────────────────────────────────────┘
```

第二段 · 确认（Half，约 460）

```
┌──────────────────────────────────────────────┐
│  AI 出题                               ✕     │
│  ┌────────────────────────────────────────┐  │
│  │ 给初二出三道二次函数题，中等难度，带答案│  │
│  └────────────────────────────────────────┘  │
│  [重说]  [清空]                              │
│  年级 [初二▾]  学科 [数学▾]  题型 [选择题▾] │
│  数量 [3▾]     难度 [中等▾]  答案 [开]       │
│                              [生成题卡 →]    │
└──────────────────────────────────────────────┘
```

第三段 · 审题（Full，约 80% 屏高）

```
┌──────────────────────────────────────────────┐
│  AI 出题 · 3 道 · 初二数学     [重新生成] ✕  │
│  ┌────────────────────────────────────────┐  │
│  │ 1. 已知二次函数 …                      │  │
│  │ A. …  B. …  C. …  D. …                 │  │
│  │ [编辑] [换一题] [删除]                 │  │
│  ├────────────────────────────────────────┤  │
│  │ 2. …                                   │  │
│  └────────────────────────────────────────┘  │
│  [全部插入白板]        [插入选中 1 道]       │
└──────────────────────────────────────────────┘
```

- 三段用同一个抽屉，向上拉或点“生成”进入下一段；向下拉退一段。
- 第一段就是微信；第二段是“出题确认”；第三段是“题目审核”。
- 第三段底部可以再加一条“继续调整”小输入栏，支持“第三题简单点”这种对话式微调（可选，第二版）。

**优点**：说话轻、确认稳、审题不挤；符合 NN/g 对底部面板“短交互”的定位；和出题产品的审核流程对齐。  
**缺点**：状态多，动画和命中要做细；实现量比 A 大。  
**适合**：我们这种“课堂上要快速出题，又要保证题能直接投白板”的场景。

---

### 方案 C：对话式（ChatGPT / 豆包）

**布局**

```
┌──────────────────────────────────────────────┐
│  你：给初二出三道二次函数题，中等，带答案      │
│  AI：好的，这是 3 道题……（题卡预览）          │
│  你：第三题再简单点                            │
│  AI：已调整……                                 │
│  ┌────────────────────────────────────────┐  │
│  │ 输入…                            🎙 ➤  │  │
│  └────────────────────────────────────────┘  │
└──────────────────────────────────────────────┘
```

- 生成结果以聊天气泡出现，靠说话/打字继续改。
- 最后“插入白板”。

**优点**：改题自然，适合“越改越准”；语音和文字完全同栏。  
**缺点**：题目是结构化内容，聊天里逐题编辑不如列表；对话一长，白板被挡；老师不容易确认“到底会插入哪几题”。  
**适合**：作为方案 B 第三段的“继续调整”增强，不建议作为第一版主界面。

## 5. 推荐方案 B 的详细设计

### 5.1 几何与层级

按当前 1260×840 逻辑工作区估算（实际以 `_work` 为准）：

| 段 | 高度 | 用途 | 背后白板 |
|---|---|---|---|
| Peek | 约 240 | 按住说话 + 快捷 chips | 基本可见，不压主工具条 |
| Half | 约 460 | 转写确认 + 参数 | 上半屏可见 |
| Full | `_work` 高 - 120，最大 720 | 题目列表 + 底部动作 | 顶部露一条，可感知位置 |

- 宽度：`min(880, _work 宽 - 48)`，底部居中；不跟主工具条长短缩。
- 圆角：顶部 22；底部贴屏幕边不圆。
- 抓手：顶部中间 36×4；拖动可换段。
- 遮罩：Peek 不加暗遮罩；Half 加很轻的遮罩；Full 加标准遮罩。这样“说话”时白板仍然是主角，“审题”时注意力回到面板。
- 位置：贴在主工具条上方；主工具条被拖到上面时，面板跟着换到下方（和现有面板的“朝屏幕中心长”规则一致）。

### 5.2 状态机

```
关闭
  │ 点 AI / 快捷键
  ▼
Peek（语音待机）
  │ 按住说话
  ▼
Listening（录音）
  │ 松手                 │ 上滑松手
  ▼                      ▼
Transcribing（转写）     Peek（取消，无文字）
  │ 成功                 │ 失败
  ▼                      ▼
Half（转写确认）         Half（错误条 + 重试/改用文字）
  │ 生成
  ▼
Generating（加载）
  │ 成功                 │ 失败
  ▼                      ▼
Full（审题）             Full（错误态 + 重试/改要求）
  │ 插入
  ▼
关闭 / Peek（toast：已插入 3 道 · 撤销）
```

Esc 逐层退：

- Listening / Transcribing：取消，回 Peek；
- Half：回 Peek（保留转写文字）；
- Full：回 Half（保留题目，不丢）；
- Peek：关闭。

点空白：

- Peek：关闭；
- Half / Full：先收一段，不直接关（防止误丢已经生成的题）。

### 5.3 第一段：微信式输入栏

```
┌────┐ ┌──────────────────────────────┐ ┌────┐ ┌──────┐
│ 🎙 │ │  按住 说出题目要求            │ │ ＋ │ │ 生成 │
└────┘ └──────────────────────────────┘ └────┘ └──────┘
  48              自适应                    44      88
```

- 左：语音/键盘切换。默认语音；点一下切文字，图标变成键盘，中间变成可编辑输入框。
- 中：语音模式是 PTT 面；文字模式是单行输入框（可长到 3 行，不内部滚动）。
- 右：`＋` 打开“最近要求 / 模板 / 从选中内容出题”；第一版可以只做“最近要求”。
- 最右：`生成`。语音模式未转写时置灰；转写后变主按钮。
- 下方 chips：`年级 / 学科 / 知识点 / 题量 / 难度`。chips 是从这句话里解析出来的，点一下弹出小菜单改；不打开新面板（避免叠层）。
-  chips 高度 36，点击热区 44；最多一行，放不下横向滚动；再多收进 `⚙`。

**录音态**

```
┌──────────────────────────────────────────────┐
│  上滑取消                          00:04     │
│      ▁▃▅▇▅▃▁▃▅▇▅▃▁                          │
│      正在听… 松开 转文字                     │
└──────────────────────────────────────────────┘
```

- 波形 + 计时 + 状态文字，三者同时有；不能只靠颜色。
- 上滑超过 48 逻辑像素进入“松开取消”；松手回 Peek，不产生文字。
- 60 秒自动结束并转写；最后 5 秒数字变强调色。
- 录音时**不**显示“生成”，避免误触。

**转写态**

- 显示“正在转文字…” + 细进度条；可取消。
- 超过 8 秒仍无结果，加一句“网络有点慢，仍在转…”。
- 失败：在输入栏位置显示错误条，不弹系统对话框；按钮 `重试` / `改用文字`。

### 5.4 第二段：确认与参数

- 转写文字进入一个可编辑的多行框；第一行就是老师说的话。
- 下面参数 chips 默认从文字解析：
  - 年级：`初二`
  - 学科：`数学`
  - 知识点：`二次函数`
  - 题量：`3 道`
  - 难度：`中等`
  - 答案：`开`
- 解析不出来的项显示“未指定”，点开让老师选；不阻塞生成。
- `重说`：回到 Peek 并清空当前转写（二次确认？第一版可以直接清空，因为还没生成）。
- `清空`：清空文字和参数。
- `生成题卡`：主按钮；点后进入 Generating。
- 右侧 `⚙`：题型（选择题/填空/判断/解答/混合）、是否带解析、分值/考试时长等低频项；收进 `⚙`，不占主行。

### 5.5 第三段：审题与插入

- 顶部：`AI 出题 · 3 道 · 初二数学`；右侧 `重新生成` 和 `✕`。
- 中间：题目列表，每题一张卡：
  - 题干；
  - 选项（如果有）；
  - 答案/解析默认折叠；
  - 行内动作：`编辑` / `换一题` / `删除` / `上移下移`（后者可收进 `⋯`）。
- 底部固定动作条：
  - 主：`全部插入白板`；
  - 次：`插入选中 N 道`（有勾选时才出现）；
  - 左：`继续调整`（可选，打开一条小输入栏，说“第三题简单点”）。
- 插入行为：
  - 合成一张 AI 题卡，插入当前视口中心偏上，避免被面板挡住；
  - 面板收成 Peek，toast：`已插入 3 道题 · 撤销`；
  - 撤销只撤这一次插入，不影响生成记录。
- 如果题很多（>10），列表滚动，顶部显示总数；不缩卡片、不分页到看不见。

### 5.6 加载 / 空 / 错 / 权限

| 状态 | 界面 | 动作 |
|---|---|---|
| 生成中 | 3 张骨架卡 + “正在理解要求 / 正在出题 / 正在排版” | 可取消；取消保留要求 |
| 生成空 | “这次没抓到合适的题” + 3 个示例要求 | 改要求 / 重试 |
| 生成失败 | 错误条 + 原因 + `重试` / `改要求` | 不丢转写 |
| 无麦克风 | 输入栏下方一条提示“未找到麦克风” | `改用文字` / `重试检测` |
| 权限拒绝 | 提示“麦克风权限被系统关闭” | `打开设置` / `改用文字` |
| 转写失败 | “没听清，再说一次” | `重试` / `改用文字` |
| 说话太短 | “说话时间太短，再按住说一次” | 回 Peek |
| 网络慢 | 8 秒后加提示，不自动失败 | 继续等 / 取消 |

原则：**任何失败都不能丢掉老师已经说的话**；能重试就重试，不能重试就保留文字让老师改。

### 5.7 默认语音的规则（建议）

- 打开面板：默认语音模式，PTT 待机，**不自动开麦**。
- 设置里提供 `默认语音输入` 开关，默认开；关掉则默认文字。
- 本次会话内手动切到文字：关闭再开，仍按设置回到语音（满足“默认语音”）；如果老师连续三次切文字，可以弹一次“以后默认文字？”——第一版可不做。
- 提供“免按住”作为 `⚙` 里的高级选项，默认关；打开后点一下开始、再点一下结束，适合长题。
- 全局快捷键第一版不做，避免和现有热键冲突；如果做，建议 `Ctrl+Alt+Space`，且只在面板打开时生效。

### 5.8 键盘 / 触摸 / 无障碍

- 所有点击目标 ≥ 48 逻辑像素；语音主按钮 56。
- `Esc`：逐层退 / 取消录音。
- `空格`：面板聚焦时，按住说话 / 松开结束；输入框内不拦截空格。
- `Tab`：语音/文字切换 → 输入栏 → chips → 生成；焦点环可见。
- 录音态有文字“正在听”，不只靠红色/波形。
- 波形动画尊重“减少动态效果”设置；可退化成静态电平条。

### 5.9 草稿与记忆

- 关闭面板时保留：转写文字、参数、最近一次生成结果（本次运行内）。
- 跨重启保留：最近 5 条要求（不含音频）；默认参数（年级/学科/题量/难度）。
- 音频：转写完成即删；失败时最多保留到本次面板关闭，不做长期缓存。
- 不默认把老师的要求上传到云端历史；如果以后做，需要单独开关。

### 5.10 入口与“图标由少到多”

- 入口保持现状：`更多 → 课堂 → AI`；不新增第二个主工具条图标，避免重复入口。
- 面板不跟主工具条长短缩：极简 5 格时仍是自己的宽度。
- 0 题：空态 + 示例要求 + “按住说话”。
- 1 题：卡片不拉伸、不居中到奇怪位置；动作条仍然贴底。
- 很多题：列表滚动，顶部有总数；不缩点击目标。
- 溢出：参数 chips 放不下时横向滚动；再多收进 `⚙`；题型/解析/分值都在 `⚙`。
- 界面档 0.8 / 1.0 / 1.3：面板宽度、圆角、字号按 `UiUnit` 缩放；点击目标不低于 44。
- 短条 / 中条 / 长条：面板宽度独立，不因主条短而缩成一条。

## 6. 需要你拍板的关键点

1. **默认语音是“按住才录”还是“打开就常听”？**  
   我建议按住才录。常听在教室会收进学生说话和投影回声，且老师会有隐私顾虑。
2. **转写后直接生成，还是先确认？**  
   我建议先确认。出题要求错一个年级/题量，后面全错；确认只多一步，但能省一次重生成。
3. **结果是一张题卡还是多张？**  
   我建议一张 AI 题卡内含 N 道题，和现有 `AiCard` 一致；审核时用列表，插入后是一张卡。
4. **面板要三段还是两段？**  
   我建议三段（说话 / 确认 / 审题）。如果第一版想省事，可以先做“Peek + Full”两段，确认层并进 Full 的顶部。
5. **参数用“智能解析 + chips”还是完整表单？**  
   我建议 chips。语音说一句话就带出大部分参数；解析不出的再点选，不逼老师填表。
6. **关闭面板要不要保留草稿？**  
   我建议保留（本次运行内），并在下次打开时恢复；避免老师说到一半点空白就白说。
7. **要不要“免按住”和全局快捷键？**  
   我建议第一版都不做；先把按住说话做稳。免按住放 `⚙`，快捷键以后再说。
8. **ClassIn 的 AI 出题面板要不要作为硬参考？**  
   如果你有录屏/截图，我可以按帧拆解后再定稿；没有的话，这一版按“微信 + ChatGPT Dictation + Wayground 审核流”来做，ClassIn 只作为方向确认。

## 7. 建议的实施顺序（拍板后）

**第一步：Peek + 语音链路**

- 底部抽屉、抓手、Peek 高度；
- 语音/文字切换；
- 按住说话、波形、计时、上滑取消、60 秒、太短提示；
- 转写结果进入可编辑输入框；
- 失败/权限/无麦克风状态。

**第二步：确认 + 参数**

- 从文字解析年级/学科/知识点/题量/难度/答案；
- chips 点选；
- `⚙` 低频参数；
- 生成按钮与加载态。

**第三步：审题 + 插入**

- 题目列表、逐题编辑/换题/删除；
- 全部插入 / 插入选中；
- 插入后收 Peek + 撤销；
- 生成失败/空态。

**第四步：增强**

- “继续调整”对话式微调；
- 免按住；
- 最近要求/模板；
- 从选中内容出题（白板上的文本/图片）；
- 真实 ASR / 模型接入。
