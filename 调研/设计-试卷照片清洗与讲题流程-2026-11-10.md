## 0. 先说结论

**这不是一条流水线，而是两条出口，前端共用一次"清洗"。**

```
学生照片 → ① 拉正（透视/旋转）→ ② 去黄去阴影 → ③ 去彩笔（可选）
                                        ├─ A. 识别成题（只抄印刷体）→ 可编辑题卡 → 作图/讲解   ← 讲题主推
                                        └─ B. 保留清洗后的原图 → 当背景批注 / 直接识别作图      ← 有图有表时用
```

四条硬结论：

1. **"发黄 + 阴影"是一个算法**：逐通道背景除法，一次解决，不用单独做白平衡。
2. **"扭曲"分两种**：平纸拍歪（透视）用四点校正，**纯 C# 几十行就够**；书页弯曲才需要 ML（UVDoc，Apache-2.0，32MB），放到 V2。
3. **手写批注不要指望本地自动去除**：彩色笔可以（色度掩码），**黑笔/铅笔不行**。开源里唯一纯经典实现（MIT）自己在 README 里写"达不到实用精度"；能用的都是 ML + 非商用权重，**或者按页买云 API**（腾讯云 0.18 元/页、夸克开放平台有免费试用）。
4. **讲题场景优先走 A（识别成题）**：模型"只抄印刷体、忽略手写"比"把黑笔从像素里抠掉"可靠得多，而且结果可编辑、可改错、可存档。
5. **云 API 是"还原空白卷"的兜底，不是默认**：本地能做的（切边、去黄、去阴影、去彩笔）全部本地；只有"去黑笔/弯页"才需要它。
6. **现在有一个必须先修的硬缺口**：`InsertAiPlotFromImageFromUi` 发图前**不缩放**，12MP 照片会变成 20–33MB 的请求体，多数接口直接失败（见 §4.2）。

## 1. 场景与约束

| 项 | 现实情况 |
|---|---|
| 来源 | 微信/QQ 转存的手机照片，常见 3000×4000、JPEG |
| 几何 | 轻度旋转 + 透视；少数是书本弯页 |
| 颜色 | 白纸发黄、台灯偏暖、半边阴影 |
| 手写 | 学生答案：蓝笔/黑笔/铅笔；老师红笔批改；圈画、打勾、划线 |
| 内容 | 印刷体题干 + 公式 + 几何图/表格 + 手写答案混在一起 |
| 目标 | 讲这道题：要么变成可编辑题目，要么在原图上写 |

## 2. 两条路线对比

| | **A. 识别成题（OCR → 文本卡）** | **B. 处理原图** |
|---|---|---|
| 适合 | 讲题、要作图、要改数字、要存档检索 | 原题上有几何图/表格；要在原卷上批注 |
| 手写干扰 | 模型层忽略 + 结果可编辑 | 彩色笔可去，黑笔去不掉 |
| 版式/图形 | **丢失**（几何图、表格要另说） | 完整保留 |
| 失败表现 | 抄错公式/漏行 → 老师改两个字 | 去不干净 → 老师手动擦 |
| 依赖 | 现有云端 VLM（已在用） | 纯本地算法 |
| 隐私 | 图片会上传（和现在"识别作图"一样） | 不出本机 |

**建议：A 做默认主路径，B 做保底。** 因为改文字比抠像素可靠，而且题目文字一旦成卡，后面"识别作图/讲解/存档"全都通了。几何图题走 B（或者 A 拿到题干 + B 保留图）。

## 3. 调研：每一段用什么

### 3.1 拉正（透视/旋转）

| 参考 | 许可证 | 结论 |
|---|---|---|
| **DocScanner** 四角检测（Canny + 凸包 + `ApproxPolyDP` + `WarpPerspective`） | 未声明 | 只借流程；我们要用纯 C# 重写，简化为"亮纸最大连通域 + 四极点" |
| **page_dewarp**（mzucker，2016，cubic sheet 模型） | **MIT** | 弯页去扭曲的经典做法：先找文本行，再拟合三次曲面。**V2 参考**，C# 重写成本高（要解非线性最小二乘） |
| **page-dewarp**（lmmx，Python3 重写，PyPI） | **MIT** | 同上，工程化更好；仍然依赖 SciPy/OpenCV |
| **UVDoc**（SIGGRAPH Asia 2023，PaddleOCR 收录） | **Apache-2.0** | **最合适的 ML 方案**：8M 参数，ONNX ~32MB，输入整图输出拉平图；官方有 ONNX 导出。AOT 兼容性需 spike |
| **DvD**（SIGGRAPH Asia 2025，扩散模型） | AGPL-3.0 | 不采用 |

**V1 只做透视（homography）**：学生发来的绝大多数是"平纸拍歪"，四点透视就能拉正，不需要 ML。
**V2 再评估 UVDoc**：弯页/书本才用得上，代价是 +45MB 左右安装包 + ONNX Runtime 的 AOT 风险。

### 3.2 去黄 / 去阴影 / 美白

沿用 DocScanner 的**逐通道背景除法**（详见配套文档 §1.2）：

```
r  = max(15, (max(w,h)/25)|1)          // 奇数
bg = GaussianBlur(Dilate(channel, r), r)
out = channel / max(1,bg) * 255
```

- **发黄**：黄色是 R/G 高、B 低，逐通道除法会把三个通道的纸面都拉到 255，黄调自然消失；
- **阴影**：局部背景被估出来除掉，半边暗也拉平；
- 不需要单独的"白平衡"步骤；如果纸质本身是米黄，除法后会变成"干净的白"。

保底：若除法后仍有整体偏色，再补一次**按通道 99 分位缩放到 255**。

### 3.3 去手写

| 类型 | 方案 | 可靠性 |
|---|---|---|
| 红笔 / 蓝笔 / 绿笔 | 色度掩码 `S>0.32 && V<0.90`，填背景色 | 高（90%+） |
| 荧光笔 | 同上（高明度彩色） | 高 |
| 黑笔 / 铅笔 | **不做自动** | — |
| 任意笔（手动） | 擦除笔刷：拖过 → 填背景 | 100%（靠人） |

为什么黑笔不做：

- `hyorimitsu/handwritten-remover`（MIT，纯经典算法）README 原话：*"it is not possible to remove the handwritten contents with practical accuracy"*，实测"黑色印刷内容也一起被删"；
- 学术侧（ICDAR 2024 **HPSegNet**）用 Transformer 做像素级"手写/印刷"分割，能处理重叠，但**没有公开代码/权重**；
- 商业侧（OmniPage RecAPI `kRecLocateHandwriting`）有现成能力，但是商业 SDK；
- ML 开源侧（`handwritingRemover`：YOLOv8 + LaMa）是 **AGPL + 非商用权重**，体积/内存/AOT 都不合适。

**真正能买到"去黑笔"的，是云 API，不是开源模型**（见 §3.5）。

### 3.4 OCR / 识别成题

- 现有通道：`OcrClient` → 云端 VLM（deepseek-flash / GLM-4.5V 等），**已经能看图**；
- 基准：Qwen2.5-VL 系列在中文文档/手写 OCR 上属第一梯队（OmniDocBench 中文 edit 0.324；OmniHandwritingOCR 里 Qwen 系中文手写 CER 最低一档）；
- 关键不是模型，是**提示词**：明确"只抄印刷体、忽略一切手写/圈画/打勾、不要解答、公式用 LaTeX"。

### 3.5 成熟云 API：本地做不了的那一段，可以直接买

| 服务 | 能力 | 价格（2026-10 刊例） | 免费额度 | 对应我们哪一步 |
|---|---|---|---|---|
| **腾讯云 · 试卷手写擦除** | 去手写/批改痕迹，输出空白卷 | 180 元 / 1000 次 ≈ **0.18 元/页**（促销 0.15 起） | 文档智能类共享额度，以控制台为准 | 黑笔/铅笔自动去除 |
| **腾讯云 · 图像切边增强** | 切边 + 透视 + 阴影 + 摩尔纹 + 弯曲矫正 | 180 元 / 1000 次 ≈ 0.18 元/页 | 同上 | 拍歪/弯页兜底 |
| **腾讯云 · 试卷切题** | 整页切题 + 每题坐标 + 文本 | 200 元 / 1000 次 ≈ 0.20 元/页 | 1000 次/用户（1 年） | 一页多题自动切 |
| **夸克扫描王开放平台 · 图像去手写** | 去手写/划痕，保留印刷体 | 需申请，**有 API 免费试用** | 有 | 同上 |
| **百度 OCR · 文档去手写 / 文档矫正增强** | 同 | 按量计费 | 有免费额度 | 同上 |

成本感受：一个老师一天处理 20 页 ≈ **3–4 元/天**；一学期按 100 天算 ≈ 300–400 元。
对比自研 ML：模型 + 推理 + 标注 + 长期维护，成本高一个量级，效果还不一定追得上。

**结论**：

- 本地做"切边/去黄/去阴影/去彩笔"（免费、即时、隐私）；
- **"去黑笔 / 弯页矫正"这种本地做不了的，给一个可选的云开关**，用户自己填 key 或学校统一配；
- 不要把云 API 设成默认：一是有网才有，二是图片要出本机，三是会产生费用。

## 4. 推荐流水线

### 4.1 清洗（一次点击，全部本地）

```
图片 → 缩到 ≤2400 → 自动找纸面四角
     → 找到：透视拉正；找不到/不准：跳过（可手动拖四角）
     → 自动旋转（文字行角度，±15° 内）
     → 去黄去阴影（逐通道背景除法）
     → 可选：去彩笔 / 黑白
     → 输出（≤2400，约 17MB）
```

- 自动检测失败**不是错误**：不拉正，照常清洗；
- 每一步都可撤销（一步 Undo），失败点一次撤销；
- 手动四角：4 个可拖的角点 + 实时预览，松手才应用。

### 4.2 出口 A：识别成题

```
清洗图（或框选一道题）→ 模型"只抄印刷体" → 题卡（可编辑）
   → 题卡上：识别作图 / 讲解 / 复制
```

- 入口：图片 AI 菜单加一项 **「识别文本」**（当前图片只有"识别作图"，要改回两项）；
- 多题一页：用**截图工具框选一道题**再识别（现有截图流程，不用新做框选）；
- 题卡是现有 OCR 文本卡，支持公式渲染、可编辑、可一步撤销。

**⚠ 现状缺口（必须先修，否则试卷照片走不通）**

`InsertAiPlotFromImageFromUi` 现在把**原分辨率**图片编码成 PNG 再 base64 发给模型，中间没有缩放：

- 3024×4032 的手机照片 → PNG 约 15–25MB → base64 后 **20–33MB** 请求体；
- 多数视觉接口请求体上限 10–20MB，会直接 413/超时；
- 就算能发，图像 token 费用和耗时也会翻几倍。

建议发送前统一：**长边 ≤ 2048 + JPEG q85**（照片约 300–600KB；线条图仍用 PNG）。试卷小字在 2048 长边下仍可读，这是速度/成本/清晰度的平衡点。

### 4.3 出口 B：处理原图

```
清洗图 → 去彩笔 →（可选）手动擦 → 变成一张干净的"答题纸"
   → 直接识别作图（几何图题）
   → 或当背景，老师在上面写
```

黑色笔迹去不掉时，给两个阶梯：

1. **手动擦**（默认，离线、可控）；
2. **云去手写**（可选开关）：把当前图发给腾讯云「试卷手写擦除」/夸克「图像去手写」，拿回空白卷；一次约 0.15–0.2 元，需要用户自己的 key。

## 5. 入口与交互

| 位置 | 现在 | 改成 |
|---|---|---|
| 图片选中条 | 7 格：收起/保存/复制/美化/AI/删除/⋯ | 不变（美化面板扩成"处理"面板） |
| 图片 AI 菜单 | 1 行：识别作图 | **2 行：识别文本 / 识别作图** |
| 处理面板 | 4 个预设 | 预设行 + 动作行：`校正` `旋转` `去彩笔` |
| 截图调整条 | 美化/AI/取消/完成 | 不变 |

处理面板（两行，高 34 + 34）：

```
┌────────────────────────────────────────────┐
│  原图    增强    黑白    去彩笔        ✓ ✕ │
│  四角校正   旋转 90°   自动拉正              │
└────────────────────────────────────────────┘
```

- `四角校正` 进入拖角模式，四个角可拖，`✓` 应用 `✕` 退出；
- `自动拉正` = 重新跑一次检测（检测失败时手动点）；
- 所有动作都只改**副本**，`✓` 才落一步撤销。

图标预算（AGENTS §1–§7）：不新增主条图标，不新增格子；面板内动作不占主条预算，不存在"图标多到放不下"。

### 5.1 一个现实缺口：现在没有"插入图片文件"

- 现有路径：**剪贴板粘贴**（微信里右键复制 → Ctrl+V）、或"收藏 → 导入图片"再插入；
- **没有**拖拽文件、也没有"插入图片…"菜单；
- 微信 PC 版右键"复制"再 Ctrl+V 可用，但多一张图就多三步。

建议顺带补一个 **拖拽图片文件到画布**（`WM_DROPFILES`，约 30 行），这和"学生发试卷"的场景是天然搭配。
按 AGENTS 规则它不占主条图标，不涉及迁移。

## 6. 实现拆解（纯 C#，零新增原生库）

| 模块 | 内容 | 量级 |
|---|---|---|
| `ImageClean.cs` | 背景除法、CLAHE、自适应阈值、去彩笔、白平衡兜底 | ~400 行 |

| `SetImagePixelsAction` | 一步撤销 | ~60 行 |
| OCR 入口 | 图片 AI 菜单加"识别文本" + 提示词 | ~40 行 |
| `ImageSend.cs` | 发送前缩放（≤2048）+ JPEG/PNG 选择 + 体积上限 | ~60 行 |

内存：处理峰值 ≈ 原图 + 45MB（瞬时），输出 ≤2400 长边。

## 7. 不做 / 风险

| 不做 | 理由 |
|---|---|
| 本地自动去黑笔 | 无可靠轻量方案（见 §3.3），改用手动擦或云 API |
| V1 上 UVDoc / ONNX | +45MB + AOT 风险；同类能力云 API 更便宜 |
| 通用图像编辑模型去手写 | 会把印刷体一起改掉，不可控；专用 API 才稳 |
| 自动判断"哪道题" | 一页多题，交给老师框选最准 |
| 批量处理整本 | 课堂不需要 |

| 风险 | 处理 |
|---|---|
| 四角检测错 → 拉歪 | 预览可见 + 一步撤销 + 手动四角 |
| 去彩笔把彩色插图洗掉 | 预览 + 撤销 + 提示语 |
| 黑笔去不掉，老师失望 | 文案写清"彩色笔可去，黑笔请用橡皮" |
| OCR 抄错公式 | 题卡可编辑；错误率高的题走 B |
| 12MP 照片直发 → 413/超时 | P0 缩放（≤2048 + JPEG），自检第 9 条兜住 |
| 照片上传隐私 | 与现有 AI 作图同一条通道，设置里已有说明 |

## 8. 自检（≤10 项，一条命令 `--paperphoto`）

用 3 张合成图（平拍/斜拍/黄底阴影）测：

1. 斜拍图拉正后，四角接近矩形（角度误差 < 2°）；
2. 黄底图清洗后纸面均值 ≥ 245；
3. 半边阴影图清洗后左右亮度差 < 10；
4. 去彩笔后红像素 < 1%，黑字保留 > 90%；
5. 检测失败时不报错、不拉歪（跳过）；
6. 输出 ≤ 2400、预览 ≤ 1200；
7. ✓ 后一步 Undo 回原图；
8. ✕ 后引用不变；
9. 发送前缩放：12MP 输入，编码后 ≤ 1.5MB，长边 ≤ 2048；
10. 耗时打印（目标：清洗 ≤ 200ms / 拉正 ≤ 120ms）。

## 9. 分阶段建议

| 阶段 | 内容 | 价值 |
|---|---|---|
| **P0（先做）** | ① 发送前缩放（≤2048/JPEG）② 图片 AI 菜单加「识别文本」+ 只抄印刷体的提示词 | 1 天，立刻能讲题（也是现在大图必挂的修复） |
| **P1** | 清洗（去黄/去阴影/黑白/去彩笔）+ 预览面板 | 1–2 天，照片可用 |
| **P2** | 自动四角 + 透视拉正 + 手动拖角 | 2–3 天，解决"扭曲" |
| **P3** | 手动擦除笔刷（黑笔兜底） | 1 天 |
| **P4（可选）** | 云去手写开关（腾讯云/夸克，用户自带 key） | 1 天，一键还原空白卷 |
| **P5（可选）** | UVDoc ONNX（弯页，纯本地）+ AOT spike | 3–5 天，先验证再决定 |

**建议先 P0 + P1**：这两步就能覆盖"学生发黄照片、手写乱"的讲题主流程；扭曲（P2）再补。
**P4 优先于 P5**：同样解决"去黑笔 + 弯页"，云 API 一天能接完，UVDoc 要先解决 ONNX 与 AOT。
