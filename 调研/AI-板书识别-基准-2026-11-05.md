# 手写板书识别 · 线上大模型基准（2026-11-05）

> 目的：判断「手写板书 → 可编辑文本」这条路能不能做，以及选哪个模型、多少钱、多快。
> 样本：学校真实备份里的 3 张板书（`InkTeach备份-20261105-1048.zip` → `.inkb` → PNG）。
> 结论先给：**能做，但要按“选区识别 + 可编辑预览”做；整板识别太慢，且公式里有致命的下标错误。**

---

## 1. 方法与口径

### 1.1 样本

| 编号 | 文件 | 内容 | 尺寸 | 特点 |
|---|---|---|---|---|
| b1 | 板书-20261105-100213 | 点线面位置关系 | 1840×1235 | 字迹工整，符号密集，含一个立体图 |
| b2 | 板书-20261103-173142 | 斜二测画法 | 1831×2354 | 长段落文字 + 两个坐标系图 |
| b3 | 板书-20261023-105034 | 数列（累加法/累乘法） | 1796×3610 | 纯公式推导，分数/下标/上下标极多 |

`.inkb → PNG` 用的是仓库里的开发模式（见 `src/InkTeach/SelfTests/InkPng.cs`）：

```
InkTeach.exe --inkboardpng <in.inkb> <out.png>
```

### 1.2 提示词

通用 VLM 用同一套结构化提示（逐行、Unicode 数学符号、复杂公式用 LaTeX、不解释、认不出写 ？）。
**专用 OCR 模型（PaddleOCR-VL / DeepSeek-OCR）另有自己惯用的短提示**——硬套通用提示会让它们退化成复读机（实测两种都崩）。这一点在报告里单列。

### 1.3 指标

- **CER（字符错误率）**：Levenshtein 距离 ÷ 标准答案字数，先做归一化（去空白/标点、LaTeX 转 Unicode、下标统一）。越低越好。
- **行准确率**：每条标准行找最相似的识别行，相似度 ≥ 0.90 记对（对合并/拆行鲁棒）。
- **公式行准确率**：只统计含数学符号的行，相似度 ≥ 0.95 记对。
- **标准答案**：人工逐行转录。b2 有 2 处一开始抄错（“建双轴”“将图变为”），已复核修正；即便如此，b2 的 CER 仍有 ±2~3% 的人工误差。

### 2.2 b1 逐行对照（Qwen3-VL-32B）

12 行里 11 行完全正确，**只有 1 行是真错**：

- 标准：`面面相交：面ABCD∩面AA₁D₁D=AD`
- 识别：`面面相交：面ABCD∩面A₁B₁C₁D₁=AD`

其余差异全是格式噪声（`A1` vs `A₁`、空格、`⊄` 写成 `∉`）。

### 2.3 b3（纯公式板）到底行不行

Qwen3-VL-32B / 32B-Thinking / qwen3-vl-plus 三家**关键公式全对**：

| 考点 | 正确答案 | 是否识别对 |
|---|---|---|
| 累加法通项 | `aₙ = (n²−n+2)/2` | ✅ |
| 等比累加 | `aₙ = 2ⁿ−1` | ✅ |
| 累乘法条件 | `aₙ₊₁/aₙ = f(n)` | ✅ |
| 累乘结果 | `aₙ/a₁ = 2·(3/2)···(n/(n−1)) = n` | ✅ |

但有**一类致命错误**反复出现：

> 原文 `aₙ = aₙ₋₁ + n` → 被识别成 `aₙ = aₙ₊₁ + n`（GLM-4.5V、qwen3-vl-plus 都犯过）

**下标差一位，整道题就错了。** 这类错误肉眼扫一遍文本很难发现，所以产品上必须：

1. 公式用 **LaTeX 渲染出来**给老师看，不能只给纯文本；
2. 原图与识别结果**并排对照**，点一行高亮原图对应位置；
3. 允许“保留原图 / 用识别结果”二选一，绝不自动覆盖。

### 2.4 关键发现：慢的不是截图，是“思考”

同一张图、同一个模型（V4.1-Flash），只改一个参数：

| 调用方式 | 耗时 | 输出 token | 结果 |
|---|---|---|---|
| 默认（thinking 开） | **10.4s** | 2000（被截断） | 全是推理，正文为空 |
| `reasoning_effort: low` | 7.8s | 1394 | 推理仍占 2287 字 |
| **`thinking: {"type":"disabled"}`** | **1.1s** | **72** | 直接出结果，且正确 |

整张板书关掉思考后：**b1 2.4s / b2 2.5s / b3 4.8s**——这就是 DeepSeek 官方客户端“截图秒出”的原因。

反过来，同一个模型走**硅基流动**时没有这个开关，默认带思考：
b1 24s、b2 62s、b3 105s，输出 1221 / 4516 / **6305** token。

**结论：之前统计的“慢”主要是思考 token，不是图片。** 产品里必须显式关掉（或设最低档）。

各家关思考的写法不一样，接的时候要按表来：

| 厂商 / 模型 | 正确写法 | 备注 |
|---|---|---|
| DeepSeek 官方 `deepseek-flash` | `thinking: {"type":"disabled"}` | 实测 10.4s → 1.1s |
| 智谱 `glm-4.5v` / `glm-4v` 系列 | `thinking: {"type":"disabled"}` | 有效 |
| 智谱 `glm-5.3-flash` / `flashx` | **`reasoning_effort: "low"`** | 用 `thinking` 会直接 400；`effort:"low"` 无效 |
| 硅基流动 `DeepSeek-V4.1-Flash` | 无 | 关不掉，别用 |
| 阿里百炼 `qwen3-vl-plus` | 本身不思考 | — |
| 阿里百炼 `deepseek-v4.1-flash` | **`reasoning_effort: "none"`** | 局部图 5.0s → 1.3s |
| 阿里百炼 `deepseek-v4-flash-0731` | 只有 low/medium/high/xhigh/max | 没有 none，且不支持图片 |

另外两个次要因素也验证了：
- **图越小越快**：同一模型裁到 1020×360 的局部只要 1.1s（DeepSeek-OCR 也是，整图 36s、局部 1.1s）。
- **输出越长越慢**：这是自回归解码的固有代价，只能靠流式缓解。

### 2.5 快速模型横评（全部关掉思考）

用户要“快且不思考”，这是专表（b3 列是纯公式板，只做定性）：

| 模型 | 平台 | b1 CER | b1 行准 | b2 CER | b2 行准 | 耗时 b1/b2/b3 |
|---|---|---|---|---|---|---|
| **DeepSeek-V4.1-Flash（关思考）** | DeepSeek 官方 | **2.6%** | **100%** | 7.4% | 69% | **2.4 / 2.5 / 4.8s** |
| **GLM-4V** | 智谱 | 3.7% | 92% | **6.7%** | **85%** | 4.3 / 6.4 / 13.0s |
| **qwen3.5-omni-flash** | 阿里百炼 | 5.9% | 83% | 8.2% | 77% | **2.1 / 1.7 / 4.5s** |
| **GLM-5.3-FlashX** | 智谱 | 6.7% | 83% | **5.9%** | **85%** | 5.0 / 3.5 / 8.7s |
| GLM-4.5V | 智谱 | 5.9% | 83% | 9.7% | 62% | 5.7 / 8.2 / 14.5s |
| GLM-5.3-Flash | 智谱 | 5.2% | 92% | 16.4% | 85% | 12.8 / 8.6 / 21.7s |
| qwen3-vl-plus | 阿里百炼 | 4.8% | 83% | 6.3% | 77% | 11.6 / 9.2 / 29.1s |
| GLM-4V-Flash | 智谱 | 10.7% | 58% | 16.0% | 38% | 8.1 / 6.6 / 25.4s |
| GLM-4V-Plus | 智谱 | 10.7% | 50% | 26.4% | 15% | 10.1 / 5.4 / 20.8s |
| qwen3-omni-flash | 阿里百炼 | 11.1% | 67% | 25.7% | 54% | 4.0 / 4.5 / 12.3s |

三个反直觉的结论：

1. **GLM-4V（最老、最便宜那个）比 GLM-4.5V 和 4V-Plus 都准**，b2 行准 85% 是全场最高。
   它是 OCR 向的老模型，反而更贴合“照抄原文”这个任务；4.5V 是通用推理模型，会“理解后改写”。
2. **qwen3.5-omni-flash 是速度冠军**：整板 1.7–2.1 秒，比 DeepSeek 还快，准确率只差 3 个点。
3. **GLM-4.6 / 4.7 / 5.3（不带 flash）不支持图片**，报 `content.type 取值 ['text']`。
4. **GLM-5.3 系列能关思考，但参数是 `reasoning_effort: "low"`**，不是 `thinking:{"type":"disabled"}`
   （后者会直接报错）。实测这样调 `reasoning_tokens=0`，局部图 2.0s 出结果。
   `effort: "low"` 无效（仍产生 455 个推理 token）——两个字段名很容易搞混。

b3（纯公式）复核：DeepSeek 官方、qwen3.5-omni-flash、GLM-4V、GLM-4.5V、qwen3-vl-plus
都正确给出了 `aₙ=(n²−n+2)/2`、`aₙ=2ⁿ−1`、`aₙ=n`。

### 2.6 专用 OCR 模型为什么反而不行

| 模型 | 表现 |
|---|---|
| qwen-vl-ocr | 输出 HTML 结构，符号丢失（⊂→∈、⊄→∉），b2 直接崩到 89.6% |
| PaddleOCR-VL-1.5 | 换个提示就陷入 `1. 1. 1. …` 复读；b3 也复读。免费但不可靠 |
| DeepSeek-OCR | 整板输出到 max_tokens 后开始复读，CER 超 1000% |

原因：它们是**印刷文档** OCR（论文、扫描件、票据），手写连笔 + 数学版式不在训练分布里。
**结论：不要因为“专用”“免费”就选它们。**

## 3. 延迟与成本

### 3.1 延迟（这才是产品体验的瓶颈）

| 场景 | 尺寸 | Qwen3-VL-32B | GLM-4.5V | qwen3-vl-plus |
|---|---|---|---|---|
| 选区·标题块 | 1220×430 | 4.3s | 13.8s | **3.5s** |
| 选区·单行公式 | 1630×190 | 8.9s | 7.5s | **1.9s** |
| 选区·解题块 | 970×380 | 7.7s | 24.7s | **4.1s** |
| 整板（原图） | 1840×1235 | 33s | 12s | 12s |
| 整板（缩到 60%） | 1104×741 | 35s | 13s | — |
| 整板（缩到 40%） | 736×494 | 32s | 16s | — |

三条结论：

1. **关掉思考后整板只要 2.4–4.8 秒**（DeepSeek 官方）；不关思考则 24–105 秒。这一条比换模型重要得多。
2. **选区识别 1–9 秒**；`qwen3-vl-plus` 的选区是 1.9–4.1s。
3. **缩图不省时间还掉准确率**（40% 时“后两者”→“后者”、“点用”→“改用”）。**别缩图**——但对专门的 OCR 小模型例外，它们对尺寸敏感（裁到局部 1.1s，整图 36s）。
4. 同样输入不同时刻能差 3 倍（硅基流动 32B 排过 120s），**必须做超时重试 + 备用通道**。

### 3.2 成本

按公开价（未公开的按同类上限估）：

- 整张板书（约 2400 in / 400 out）：**≈ ¥0.008（0.8 分钱）**
- 一个选区（约 500 in / 100 out）：**≈ ¥0.002（0.2 分钱）**
- 本次全部约 40 次调用（10 模型 × 3 板 + 12 次选区/缩图）：**≈ ¥0.40**

**100 元 ≈ 1.2 万张整板识别。** 成本完全不是问题，瓶颈只在准确率和延迟。

## 4. 结论与建议

### 4.1 能不能做

**能做，且效果远超预期。** 但要做对三件事：

0. **必须关掉模型的“思考”**：DeepSeek 官方 `thinking: {"type":"disabled"}`，其他家找等价开关（`reasoning_effort` / `enable_thinking`）。这一项把 30 秒变成 2.4 秒。
1. **只在“选中”上做**：选中一块 → 识别 → 可编辑预览。不做整板自动识别。
2. **公式必须渲染**：LaTeX 渲染 + 原图对照，否则下标错误没人看得出来。
3. **绝不自动覆盖原板书**：识别结果落到新的一页/新的文字对象，原墨迹保留。

### 4.2 选型

| 用途 | 推荐 | 理由 |
|---|---|---|
| **主力** | DeepSeek 官方 `deepseek-flash` + **关思考** | 2.4–4.8s，b1 CER 2.6% / 行准 100%，目前唯一“又准又快” |
| **备用（同模型）** | 阿里百炼 `deepseek-v4.1-flash` + `reasoning_effort: none` | 4.3/4.0/6.6s，CER 3.3%/8.9%，主站挂了切它 |
| **速度冠军** | 阿里百炼 `qwen3.5-omni-flash` | 1.7–2.1s，CER 5.9%/8.2%，最省时间 |
| **精度档** | 智谱 `GLM-4V` | 3.7%/6.7%，b2 行准 85% 全场第一，13s 跑完公式板 |
| 慢但稳 | `qwen3-vl-plus` / `Qwen3-VL-32B` | 9–62s，b2 6.3–8.6% |
| **不要用** | qwen-vl-ocr / PaddleOCR-VL / DeepSeek-OCR | 手写+公式会崩 |
| **不要用（慢）** | 硅基流动版 `DeepSeek-V4.1-Flash` | 关不掉思考，24–105s；要用就走官方 API |
| **不要用（误导）** | GLM-4V-Flash / GLM-4V-Plus / qwen3-omni-flash | 快但错得多（CER 10–26%） |
| **断网兜底** | 不做本地 OCR | 本地 36–45% 不可用；提示“需要联网”更诚实 |

### 4.3 架构要求（避免踩坑）

- 接口统一走 **OpenAI 兼容协议**，`baseURL + model + key + 关思考参数` 四个都可配，换平台不改代码；
- **关思考参数必须按厂商分支**（见 2.4 的表），写死一个字段名会导致某家静默变慢；
- **密钥不进客户端**（现在日志上传那个 token 已经是个教训）：测试期用环境变量，上线走自建中转；
- 每次请求带 `max_tokens` 上限 + **复读检测**（连续重复行 > 3 就判失败重试）；
- 记录 `usage`，便于算钱和限流。

### 4.4 下一步

1. 把样本从 3 张扩到 **20–30 张**（不同老师、不同学科、不同字迹），再确认 CER 是否稳定在 5–10%；
2. 先做「选中 → 识别 → 可编辑预览」的最小闭环，**不做自动整理整页**；
3. 「美化原笔迹」并行推进（不需要 OCR，风险最低，效果老师立刻能感知）；
4. 等识别闭环跑通后，再考虑「识别结果 → 手写字体 + 笔顺回放」（二期）。

## 5. 复现方式

脚本在 `tools/ai-bench/`（密钥只从环境变量读）：

```powershell
$env:SILICONFLOW_API_KEY = "..."
$env:DASHSCOPE_API_KEY   = "..."
python tools/ai-bench/bench.py --boards b1,b2,b3      # 跑原始结果，落盘 raw/
python tools/ai-bench/score.py                        # 出 CER 总表
python tools/ai-bench/score.py --detail qwen3-vl-32b b1   # 逐行对照
```

原始返回全部落盘（`raw/*.json`），**重算指标不花钱**。
