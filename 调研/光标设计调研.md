# 光标（鼠标指针）设计调研

> **后续（2026-09-26）**：设备 × 工具矩阵、'斜笔'（IDC_PEN）选型、"十字↔箭头反复跳"的
> 治理与"光标可配置"路线，见 **[调研-光标方案.md](调研-光标方案.md)**。
> 注意：本文 9.1 那张"生效规则"表已被之后的迭代覆盖（画笔在鼠标下已改成自绘双层环、
> 激光落点改成实心点），**当下现状以新文档第二节为准**。

面向：屏幕批注层（Win32 覆盖窗口 + 手写板/鼠标/触摸）。
目的：先解释"为什么现在一直转圈"，再给出每个场景该显示什么光标的建议，最后给一份可落地的实现顺序。

---

## 一、结论先行

1. **"一直转圈"是 bug，不是设计取舍。**
   覆盖窗口的窗口类没有指定 `hCursor`，程序里也没有任何 `WM_SETCURSOR` 处理，全工程找不到一次 `SetCursor`
   —— 等于从没告诉过 Windows "指针在我窗口上该长什么样"，系统就给了个默认的等待类光标。

   本机实测（2880×1800 @200%）：

   | 时刻 | 指针下窗口 | 当前光标 |
   |---|---|---|
   | 程序未运行，指针在桌面 | 桌面 | `IDC_ARROW`（普通箭头） |
   | 程序运行中，指针在覆盖层上 | `InkTeachOverlay_…` | **`IDC_WAIT`（转圈/忙）** |
   | 程序退出后 | 桌面 | `IDC_ARROW`（恢复正常） |

2. **修法很小。** 窗口类给一个兜底光标 + 在 `WM_SETCURSOR` 里按状态指定光标并返回 `TRUE`，
   大约几十行，转圈立刻消失，之后所有光标设计都挂在这个状态机上。

3. **分工要定清楚：语义用真光标，落点用自绘。**
   - 语义类（箭头 / 十字 / 移动 / 四向缩放 / 旋转）：用系统光标或自绘 `HCURSOR`。
   - 落点类（笔尖环、荧光笔宽度、橡皮圆环）：继续画在浮动层上（橡皮已经这么做了，效果对）。
   - **两者不能同时出现。** 现在如果只修类光标而不藏系统光标，会出现"转圈箭头 + 橡皮圆环"叠在一起。

4. **输入设备要先分叉**：触摸一律不要光标；笔在范围内显示工具光标、落笔即隐藏；鼠标走完整语义。

5. **滚动条那一条要换个顺序问**：现在滚动条还**不能拖**（只有滚轮会滚、会把它唤出来，
   没有任何命中判定）。所以先让它能拖，再谈光标；而且按微软规范，滑块不该用"手型"。

## 二、根因：为什么永远是转圈

### 2.1 代码事实

| 位置 | 现状 |
|---|---|
| `src/InkEngine/Engine.cs` `RegisterWindowClass()` | `WNDCLASSEX` 只赋了 `cbSize / style / lpfnWndProc / hInstance / lpszClassName`，`hCursor` 保持 NULL |
| `src/InkEngine/Engine.cs` `WndProc()` | 有 `WM_NCHITTEST / WM_POINTER* / WM_TIMER` 等分支，**没有 `WM_SETCURSOR`** |
| 全工程 | 没有 `SetCursor` / `LoadCursor` / 自定义光标（`CountCursor` 是截图里数像素的，无关） |

### 2.2 文档依据

- `WNDCLASSEX.hCursor`：*"If this member is NULL, an application must explicitly set the cursor shape
  whenever the mouse moves into the application's window."*
  —— 设成 NULL 就等于放弃这块窗口的光标定义权，系统用自己的默认值兜底，我们看到的就是忙光标。
- `WM_SETCURSOR`：系统在"鼠标移动且输入未被捕获"时发给指针所在窗口；
  `DefWindowProc` 的处理是"客户区用窗口类光标、非客户区用箭头"，应用自己处理时应当返回 `TRUE` 阻止后续处理。

### 2.3 为什么不只是"难看"

- 用户看到转圈会以为程序卡了 —— 一个全屏覆盖层顶着忙光标，第一印象就是"这软件在加载"。
- 光标是**动手前**唯一的"这里能干什么"提示，放弃它等于把交互可发现性丢掉一大半。
- 后面接触摸/手写笔时，转圈会和笔尖反馈打架。

## 三、平台既定语义（微软的规矩，不参考也得知道）

来源：Windows 的指针形状（Pointer shapes）与系统光标常量表。

| 系统光标 | 名称 | 用途 |
|---|---|---|
| `IDC_ARROW` | Normal select | 绝大多数对象 |
| `IDC_IBEAM` | Text select | 文本插入点 |
| `IDC_CROSS` | Precision select | 图形 / 二维精确取点 |
| `IDC_HAND` | Link select | **只能表示链接** |
| `IDC_SIZEALL` | Move | 任意方向移动（拖窗口那种） |
| `IDC_SIZEWE` / `IDC_SIZENS` | Horizontal / Vertical resize | 单轴缩放 |
| `IDC_SIZENWSE` / `IDC_SIZENESW` | Diagonal resize 1 / 2 | 对角缩放 |
| `IDC_NO` | Unavailable | 此处不接受拖放 |
| `IDC_WAIT` | Busy | 用户必须等（真阻塞） |
| `IDC_APPSTARTING` | Working in background | 后台还在忙，但用户可以先干别的 |
| `IDC_UPARROW` / `IDC_HELP` / `IDC_PIN` / `IDC_PERSON` | Alternate / Help / Location / Person | 特殊场景 |

几条硬规则：

1. **手型只能是链接。** 微软的措辞是"imperative not to use the hand pointer for other purposes"。
   按钮、滑块、手柄都不要用手型。
2. **忙/等待光标只在真等待时出现。** 我们的目标状态是"这个程序永远不出现转圈"。
3. **光标要在"按下之前"给提示。** 悬停就该变，按下去才变等于没提示。
4. **光标不是唯一的反馈通道。** 控件自己的 hover / active 视觉（滑块变宽、手柄放大、按钮变色）
   和光标一起用才清楚；光靠光标变化容易被忽略。

## 四、一次决策的优先级模型

不要在每个分支里各写一套判断，先把"谁说了算"定下来，后面只是填表：

```
1. 拖拽中（已 SetCapture）      → 按下那一刻定下的光标，一直保持到松手
2. 悬停在交互控件 / 手柄上       → 手柄 > 操作条 > 滚动条 > 画布内容
3. 悬停在画布上                 → 当前工具决定（笔 / 荧光笔 / 激光 / 橡皮 / 框选）
4. 穿透模式                     → 什么都不做，让下层窗口决定（现在 HTTRANSPARENT 已经是对的）
5. 需要隐藏的情况               → 笔在范围内或接触、触摸、激光/橡皮的自绘反馈
```

第 1 条特别重要：`WM_SETCURSOR` 只在**输入未被捕获**时发送，所以"拖动中变光标"必须在
`OnPointerDown` 里 `SetCapture` 的同时设一次 —— 之后系统不会再问我们了。

## 五、逐场景建议

### 5.1 输入设备（第一个分叉）

| 设备 | 有没有悬停 | 建议 |
|---|---|---|
| 鼠标 | 有 | 走完整语义：工具光标 + 控件光标 + 手柄光标 |
| 手写笔 / 手写板 | 主动笔有（进范围即 hover）；被动笔没有 | hover 显示工具光标；**落笔后隐藏系统光标**，落点反馈交给我们自绘 |
| 触摸 | 没有（微软文档：触摸必须接触才触发进入事件） | **一律不显示光标**，也不要有残留的自绘环 |

实现上已经有现成条件：`EnableMouseInPointer(true)` + `WM_POINTER*` + `GetPointerInfo`，
`ReadPointer` 已经能区分 `PT_PEN / PT_TOUCH / PT_MOUSE`，直接拿来做分叉即可。

补充两点：

- 触摸时 Windows 自己会把鼠标指针收起来，但**只要鼠标一移动它就会回来**，
  所以我们窗口里的光标必须由我们自己显式指定，不能指望系统。
- 隐藏光标的正确做法不是 `ShowCursor(false)`（它是计数式的，容易配不平），
  而是准备一个 1×1 全透明光标，在 `WM_SETCURSOR` 里 `SetCursor` 它并返回 `TRUE`。

### 5.2 工具状态

| 工具 | 鼠标悬停 | 笔悬停 | 落笔 / 接触 | 说明 |
|---|---|---|---|---|
| 画笔 | `IDC_CROSS`（或系统箭头） | 自绘笔尖环（直径 = 当前笔宽） | 隐藏系统光标，只有笔迹 | 笔宽从 1 到几十像素，环能让"这一笔多粗"动手前就知道 |
| 荧光笔 | 自绘**圆盘**（直径 = 荧光笔宽） | 同左 | 隐藏 | 落笔处就是一个直径 = 笔宽的圆：单击留下的墨点、拖动时墨迹的截面都是它（旧版用横条，见 9.5） |
| 激光笔 | 小十字或小圆点 | 同左 | 隐藏，自绘激光点 + 轨迹 | 激光的语义就是"指针即标记"，再跟一个箭头会互相干扰 |
| 橡皮 · 面积擦 | 自绘圆环（**已有，保留**） | 同左 | 隐藏 | 现在的双色描边 + 四向刻度是对的，深浅背景都看得见 |
| 橡皮 · 点擦 / 整笔删 | 小圆环（半径 = 命中容差）或十字 | 同左 | 隐藏 | 让用户看得到"多细才算点中"，比换一个橡皮图标更有用 |
| 直线 / 矩形 / 椭圆 / 箭头（枚举里已有） | `IDC_CROSS` | 十字或自绘预览 | 隐藏 | 都是"两点定形"，十字是图形类工具的既有语义 |

一条最容易踩的坑：**自绘落点必须同时把系统光标藏起来**，否则就是箭头/转圈和圆环叠在一起。

### 5.3 交互控件

**滚动条**

- 现状：只有 `HandleWheel` 会刷新 `ScrollBarActiveAtMs`，滚动条本身没有命中判定，拖不动。
  建议顺序是：先实现"悬停浮现 + 按住拖动 + 拖动中反白"，再定光标。
- 光标建议：**轨道和滑块都用系统箭头**，不用手型，也不用 `IDC_SIZEALL / IDC_SIZENS`。
  - 手型：违反"手型只能是链接"的规范，而且用户会以为点一下会跳转。
  - `IDC_SIZENS` 的语义是"改变高度（缩放）"，用在"移动视口"上会让老用户误判。
  - 系统自己的滚动条、Figma、VS Code 都是箭头，"能拖"这件事由滑块自身的
    hover 变宽 / 加深 / 按下反白来表达 —— 你们的"样式 B：细线"设计稿正好就是这套。
- 唯一的例外：如果以后做成"拉伸内容高度"的滚动条（有些白板软件有），那才该用 `IDC_SIZENS`。

**悬浮操作条按钮**（复制 / 删除 / 翻转 / 旋转）：保持系统箭头。按钮本身有强 affordance，
微软明确说按钮不需要手型。

**穿透模式**：什么都不设。`WM_NCHITTEST` 已经返回 `HTTRANSPARENT`，光标自然归下层窗口，
这也是我们想要的行为（穿透时"光标要跟下面的软件一致"）。

### 5.4 选中操作（移动 / 左右 / 上下 / 对角）

选中框现在是 8 个缩放手柄 + 1 个旋转手柄，命中半径 14 逻辑像素，直接用 `SelectionHandles.HitTest`
的结果驱动光标即可：

| 指针位置 | 建议光标 | 备注 |
|---|---|---|
| 框内部（整体拖动） | `IDC_SIZEALL`（Move） | 和拖窗口、拖图标一致 |
| 左 / 右边中点 | `IDC_SIZEWE` | |
| 上 / 下边中点 | `IDC_SIZENS` | |
| 左上 / 右下角 | `IDC_SIZENWSE` | |
| 右上 / 左下角 | `IDC_SIZENESW` | |
| 旋转手柄 | 自绘旋转光标（见 5.5） | 系统没有旋转光标可用 |
| 框线但不是手柄 | 保持箭头 | 避免和手柄抢语义；也可以给"最近手柄"的光标，但要点在手柄判定上 |
| 悬停在未选中的笔迹上 | 保持箭头 | 现在是"点一下选中、拖一下框选"，用移动光标会误导 |

**斜框（旋转过的对象）** 是这里唯一的真正难点：框转了 30° 以后，系统那个水平的
`IDC_SIZEWE` 和实际拉伸方向对不上，用户会犹豫。

- 方案 A（省事）：照样用系统四向光标，接受"方向不跟随"。
- 方案 B（更好，也是 Figma / Adobe 现在的做法）：让缩放光标跟着框一起转 —— 用
  `CreateIconIndirect` 在运行时把矢量的双向箭头按当前角度画成位图当光标。
- 落地建议：**先 A 后 B**。A 是零成本，先让功能可用、转圈消失；等旋转真正用起来了再做 B。

### 5.5 旋转

- Windows 没有旋转系统光标（`IDC_*` 里没有这一项），必须自绘。
- 图形建议：**带箭头的圆弧**（顺时针），中心留一个点当轴心热点 —— 和 `design/旋转手柄-放大.png`
  里那颗圆图标同形，视觉语言和手柄一致。
- 热点定在旋转轴心，不是图形左上角。
- 框是斜的时候，箭头朝向跟着手柄方向走。
- 转到接近 0° / 90° / 180° 时可以叠加吸附提示，但那是另一件事，别塞进光标里。

### 5.6 自绘 vs 真光标：分工建议

| | 用什么 | 例子 | 好处 |
|---|---|---|---|
| 语义类 | 真光标（系统或自绘 HCURSOR） | 箭头、十字、移动、缩放、旋转 | 系统帮你处理 DPI、无障碍设置、热点 |
| 落点类 | 画在浮动层上 | 笔尖环、荧光笔宽度、橡皮圆环、激光点 | 位置永远和笔迹同源（不受光标热点误差影响），能随笔压/角度变、能做动画 |

自绘落点类已经是你们的成熟做法（橡皮环），参考即可；要注意的只有两件事：
把它算进每帧脏区（已有），以及**在笔/触摸/离开窗口时让它消失**。

## 六、实现要点与坑

### 6.1 `WM_SETCURSOR` 的正确写法

```
case WM_SETCURSOR:                                  // 0x0020
    if ((lParam & 0xFFFF) != HTCLIENT)              // 非客户区/边框交给系统
        return DefWindowProc(...);
    if (PassThrough) return DefWindowProc(...);     // 穿透时不插手
    SetCursor(CursorForCurrentState());             // 状态机：设备 × 工具 × 悬停目标 × 是否拖拽
    return TRUE;                                    // 关键：返回 TRUE，否则类光标会覆盖
```

- 窗口类里同时给个兜底：`hCursor = LoadCursor(NULL, IDC_ARROW)`。
  只做这一步就能让转圈消失，但光标永远是箭头 —— 状态机才是真正的活儿。
- 光标句柄缓存起来，别每次 `SetCursor` 时新建一个自绘光标（会漏 GDI 对象）。
- `WM_SETCURSOR` 只在没捕获时来，所以"按下后换光标"必须在 `OnPointerDown` 里主动设。

### 6.2 隐藏光标 / 恢复

- 隐藏：1×1 透明 `HCURSOR` + 返回 `TRUE`（比 `ShowCursor(false)` 稳）。
- 笔：`WM_POINTERUPDATE` 里 `POINTER_FLAG_INCONTACT` 为真 = 接触中 → 隐藏；
  只是 `INRANGE` = 悬停 → 显示工具光标。
- 触摸（`PT_TOUCH`）：永远隐藏，手指抬起后也不要留自绘环。
- 现在的 `WM_MOUSELEAVE` 只处理了恢复小圆钮那个窗口，覆盖层没有处理
  → 指针离开屏幕/切到别的窗口后，`PointerInside` 不复位，橡皮圆环可能残留。
  顺手补 `TrackMouseEvent` + `WM_MOUSELEAVE`。

### 6.3 尺寸 / DPI / 热点

- 光标位图是**物理像素**，尺寸跟着系统设置走。本机实测：
  `SM_CXCURSOR` = 32（100%）、48（150%）、**64（200%，也就是你这台机器）**。
  自绘光标要按当前 DPI 生成对应尺寸，不然在高分屏上会糊。
- 系统光标会自动适配用户的"指针大小/颜色"辅助功能设置，自绘的不会 ——
  所以自绘光标（尤其旋转这种必须自绘的）至少要把线宽和颜色写活，别写死 1px 单色。
- 深浅背景都要看得见：沿用橡皮环那套"白色外圈 + 深色内圈"的双描边经验。

### 6.4 要动的代码位置

| 文件 | 改动 |
|---|---|
| `src/InkEngine/Native.cs` | 补 `WM_SETCURSOR`、`IDC_*`、`SetCursor`、`LoadCursor`、`CreateIconIndirect/DestroyCursor`、`GetSystemMetrics(SM_CXCURSOR)` |
| `src/InkEngine/Engine.cs` `RegisterWindowClass()` | `hCursor` 兜底给 `IDC_ARROW` |
| `src/InkEngine/Engine.cs` `WndProc()` | 新增 `WM_SETCURSOR` 分支 + `WM_MOUSELEAVE` 复位 |
| `src/InkEngine/Engine.cs` `OnPointerMove()` | 现在 `!_drawing` 直接 return，**没有悬停路径**；悬停也要更新坐标、悬停目标和光标 |
| `src/InkEngine/Engine.cs` `OnPointerDown()` | 按下时按拖拽类型设一次光标（移动/缩放/旋转） |
| `src/InkEngine/Selection.cs` `HitTest()` | 直接复用为光标判定，不必再写一套 |
| `src/InkEngine/Overlay.cs` `DrawScrollBar()` | 需要补 hover / 滑块命中（目前完全没有） |
| `src/InkEngine/Overlay.cs` `DrawEraserCursor()` | 作为其他工具落点反馈的模板（笔尖环、荧光笔圆盘） |

### 6.5 建议的落地顺序

| 步 | 内容 | 成本 | 验证方式 |
|---|---|---|---|
| P0 | 类光标兜底 + `WM_SETCURSOR` 状态机：箭头 / 十字 / 移动 / 四向缩放 / 穿透不插手 / 触摸隐藏 / 拖拽锁定 | 半天 | 手工逐点确认；再加一个 `--cursortest` 自检模式把状态表打出来（和现有 `--erasertest` 一样，不靠人盯） |
| P1 | 自绘落点反馈：笔尖环、荧光笔圆盘、点擦小环、旋转光标；同时隐藏系统光标 | 1 天 | 鼠标 + 手写笔各过一遍；深浅背景各看一次 |
| P2 | 斜框跟随角度的缩放光标、光标随 DPI/辅助功能设置、淡出/呼吸等细节 | 按需 | 200% 缩放下的截图比对 |

`--cursortest` 这类自检建议保留：光标逻辑是"状态 × 场景"的表格，用打印表格的方式验证
比人工一个个悬停快得多，也和你们现有的自检风格一致。

## 七、需要你拍板的 4 件事

（已拍板：按下面每一条的建议执行，落地记录见第九节。）

1. **画笔悬停长什么样？** 我建议：鼠标用系统十字，笔用手写板时用自绘笔尖环（跟随笔宽）。
   备选是统一用箭头（最保守）或统一用环（最直观）。
2. **滚动条滑块要不要手型？** 我建议不要，靠滑块变宽/加深表达"可拖"。
3. **旋转框的光标现在做不做跟随？** 我建议 P0 先用系统四向光标顶住，P1/P2 再做跟随角度的自绘。
4. **触摸时是否完全无光标？** 我建议是（1×1 透明光标），并且触摸期间不要留任何自绘环。

行业惯例（通用做法，非逐条引用文档）：绘图类工具的"笔刷大小圆环 / 精确十字"切换（Photoshop 一脉）、

### 9.2 顺手修掉的两个真 bug

1. **滚动之后落点环会失效/退化**：临时图元的脏区用的是画布坐标，漏了相机换算。
   表现是滚动后橡皮环要么不在该在的位置，要么退化成大面积重绘。已按
   `CanvasRectToWindow` 修正（文件里本来就写着"来自文档的矩形必须先过这一步"，
   是橡皮光标这一处漏了）。
2. **指针离开窗口后不通知**：`WM_MOUSELEAVE` 只处理了恢复小圆钮那个窗口，
   覆盖层的 `PointerInside` 永远是 true——指针移开屏幕边缘后，落点环会留在屏幕上。
   已补 `TrackMouseEvent` + 两个离开消息。

### 9.5 修订（用户实测反馈）：荧光笔落点从"横条"改成"圆盘"

第一版给荧光笔画了一根**横着的胶囊**（高 = 笔宽、宽 = 1.7×笔宽），理由是
"荧光笔的笔尖是扁的，横条比圆圈更贴切"。用户上手后指出两件事：
横条不好看；而且它和真正画出来的墨迹对不上——看着别扭。

复核之后确认**用户说得对**，而且是底层几何决定的：

| 事实 | 在哪 |
|---|---|
| 荧光笔的墨迹是"中心线两侧各半个笔宽 + 两端圆帽" | 由 D2D 的描边样式给出（`Gfx.Round`：圆头端帽 + 圆角拐角） |
| 所以落笔处的墨迹是一个**直径 = 笔宽的圆**，单击一下留下的就是这个圆 | 同上 |
| 横条只在水平方向变宽，竖着画的那一刻和墨迹对不上 | `Overlay.cs`（旧版 `DrawHighlighterCapsule`） |

改法：`DrawHighlighterDisc` —— 一个实心圆盘，半径就是半个笔宽，填充用荧光笔
当前的颜色（半透明），描边沿用笔/橡皮那一套"白外圈 + 深内芯"。脏区半径也
跟着从"1.7×笔宽"改成"半径 + 12 像素"（`Engine.DrawnCursorRadius`）。

| 验证 | 结果 |
|---|---|
| `--cursortest` | **48 / 48 通过**，含"圆盘半径就是半个笔宽"（8 → 8px，32 → 32px）、"脏区盖得住圆盘" |
| 截图 | `reports/光标-荧光笔圆盘.bmp`（`--cursorshow hl 32 --board` + `--screenshot`；`--board` 让截出来的图只有我们自己的白板 + 落点，桌面上的窗口一概不进画面） |
