# 设置搜索 / AI 设置助手 · 可行性与难度（2026-11-14）

> 用户想法：设置项越来越多，能不能加搜索；再进一步，配好 API 后让用户“说一句话”由模型帮他把设置改好。
> 本文只做调查与方案，不改代码。

---

## 0. 结论

1. **教程/设置搜索：可行，难度 2/5。** 设置页已经是“行表 + 分类”的确定结构，加搜索框和“跳到那一行”大约 1–2 天。
2. **AI 建议设置（只找不改）：可行，难度 3/5。** 把“行表 + 别名 + 当前值”交给模型，模型只返回“建议哪几项”，用户点进去自己改；约 2–3 天。
3. **AI 直接改设置（确认后应用 + 撤销）：可行，难度 4/5。** 关键不在模型，而在**设置 schema 和 setter**——现在设置分散在设置页行表、工具色带、各面板里，要先收成一份可读可写的注册表；约 4–6 天。
4. **“展开 + 穿透”这个组合不建议做**：穿透会把整个覆盖层设成点击穿透，工具条也点不到；现在只有两种可用形态：
   - 展开 + 批注（手动启动）
   - 收起小球 + 穿透（开机自启 / 后台待命）
   真要做，只能做“手动启动也用后台待命形态”，不能做“展开但穿透”。

**推荐顺序**：搜索 →（设置项补全 + 注册表）→ AI 建议 → AI 确认后应用。

## 1. 成熟参考（先找再做）

| 参考 | 来源/版本 | 照搬什么 | 不照搬什么 |
|---|---|---|---|
| **Windows 11 设置搜索 + Settings Agent** | 微软官方（2025–2026，Copilot+ PC） | 搜索框里直接说需求；模型只**建议**设置，用户点 Apply 才改；改完可 Undo；模型没把握时**退回普通搜索结果** | 不引入本地小模型（Settings Mu）；不做系统级策略 |
| **VS Code 设置搜索** | VS Code 1.x | 设置 schema（id/类型/默认值/描述）+ 关键词搜索 + “在设置 UI 中显示” | 不做 JSON 设置文件给用户编辑 |
| **macOS 系统设置搜索** | macOS 13+ | 输入即过滤、结果高亮、分类路径可见 | 不做整页跳转动画 |

结论：**“搜索框 + schema + 建议/确认/撤销”是成熟做法**，Windows 11 的 Agent 已经把边界划得很清楚：AI 不自动改、必须用户确认、必须能撤销、没把握就退回搜索。

## 3. 设置搜索：怎么做、难度

### 3.1 结构
- 现有设置页已经是 `Rows[]` 表（18 行）+ 7 个分类，命中/绘制/执行同源；
- 搜索只需要：`label + hint + 别名` 建一张索引，输入即过滤，回车跳转；
- 跳转 = `ScrollSettingsToCategory(cat)` + 行高亮脉冲。

### 3.2 输入框
- 设置页是自绘 UI，没有现成文本框；但 API 设置页已经有 `WindowlessTextControl`（原生 EDIT + IME）可复用；
- 位置：设置页顶部，和分类同一条；宽度 ~280。

### 3.3 难度
- **2/5**：1–2 天（含自检：搜“笔宽/深色/翻页”能命中并跳转）。

## 4. AI 设置助手：怎么做、难度

### 4.1 两种形态
1. **AI 只建议**（安全）：输入“字太小了/想穿透时清屏”，模型返回 1–3 个设置项 + 理由，点结果跳到那一行；
2. **AI 确认后应用**（Windows 11 同款）：模型返回结构化动作（`{key, value}`），App 用 schema 校验，弹“将修改：A 3→5、B 开→关”，确认后应用，可撤销。

### 4.2 前提：设置注册表（唯一真源）
每一项要有：
```
id, 分类, 标签, 别名（“笔粗/线宽”）, 类型（bool/enum/int/float/action）,
范围/档位, 当前值 getter, 设置 setter, 是否需要重启, 风险级别
```
- 现在 `Rows[]` 只有标签/提示/开关，getter/setter 散在 `LegacyActivateRow` 和各面板；
- 需要先把 18 行收进注册表，再把新增的 8–10 项也写成注册表行；
- 工具默认值（颜色/粗细/字体）不在设置页，但也要进注册表，AI 才能改。

### 4.3 模型调用
- 输入：用户一句话 + 注册表（id/标签/别名/类型/范围/当前值，**不含密钥、不含文档内容**）；
- 输出：JSON 动作数组；`temperature=0`；
- 校验：类型/范围/白名单；不合法就丢弃并提示；
- 成本：deepseek-flash 1–2k token ≈ **0.001–0.003 元/次**，1–2 秒；离线/失败自动退回搜索。

### 4.4 难度
| 部分 | 难度 | 工作量 |
|---|---|---|
| 注册表（18 行 + 新 8 项） | 3/5 | 2–3 天 |
| AI 只建议 | 3/5 | 2–3 天 |
| 确认卡 + 应用 + 设置级撤销 | 4/5 | +2 天 |
| 只做 18 行、不动工具默认值 | 3/5 | 4–5 天 |
| 全量（含工具默认值/面板设置） | 5/5 | 8–12 天 |

### 4.5 风险
- **误改**：模型把“笔粗一点”理解成 20 → 必须范围校验 + 确认 + 撤销；
- **歧义**：一句话对应多个设置 → 列候选让用户选，不替用户猜；
- **重启项**：语言/自启动要提示“重启生效”；
- **危险动作**：备份恢复、清空数据、删除收藏 **永远不给 AI 执行**，最多跳到对应入口；
- **隐私**：只发设置键值，不发 API Key/文档/板书；首次使用给一句说明；
- **离线**：搜索必须独立可用，不能依赖 API。

## 5. 建议的分期

**P1（3 天）**
- 设置搜索框（含别名）+ 跳转高亮；
- 新增 4 行：启动形态（两种）、启动检查更新、截图隐藏批注、导出默认格式；
- 设置页顶部放「AI 服务」状态（已配置/未配置），AI 服务分类排第一。

**P2（4–5 天）**
- 设置注册表（18 行 + P1 新增）；
- AI「只建议」：一句话 → 推荐 1–3 项 → 跳转。

**P3（+3–4 天）**
- AI「确认后应用」：动作 JSON + 校验 + 差异确认卡 + 设置级撤销（一步）。

**P4（可选）**
- 工具默认值/面板设置进注册表，AI 可改颜色/粗细/字体等。
