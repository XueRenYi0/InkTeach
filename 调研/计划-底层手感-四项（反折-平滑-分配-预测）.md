## 〇、实测结论（为什么是这四项）

两轮真机数据（开 ink / 关 ink）：

| 指标（中位） | 开 ink（手写板） | 关 ink（手写板） |
|---|---|---|
| 笔尖采样 → 收到消息 | 3.33 ms | 0.10 ms ＊ |
| 笔尖采样 → Present 返回 | **4.32 ms** | 0.75 ms ＊ |
| Present 内部阻塞 | 0.17 ms | 0.15 ms |
| 超过 22.2 ms 的帧 | **0 / 1025** | **0 / 1196** |
| 每笔分配 / 书写期间 GC | 平均 26KB，无 | 平均 19.8KB，无 |
| 输入点率 | ~190–230 Hz（合并 1.5–1.8:1） | ~190+ Hz（raw 补点；消息 1:1 投递） |

＊ 关 ink 没有硬件时标，这一列只是"消息一进来就处理"的内部耗时，**不可与开 ink 直接比**。

结论：

1. **软件链路不是瓶颈**（4.3ms 中位、0 超帧、无 GC）——"不跟手"的可见来源 =
   **① 显示那一帧**（面板刷新周期，软件消不掉，只能预测遮）+ **② mean2 固定 ~6px 平滑滞后**（B2）
   + **③ 反折形状失真**（B1）；
2. 长笔分配 **10.8MB 级尖峰 + 一次 gen0 GC**（4.4 秒长笔实测；4G 校园机要防）→ B3；
3. **系统委托湿墨在手写板 Ink 开上不渲染**（用户两轮目视确认：开 ink 边写无墨、抬笔才出；
   `--syswet` 只是诊断开关）→ 触摸 / 关 ink / 开 ink 三条路都靠**自绘** →
   **显示那一帧只能靠自绘预测遮（B4）**。

## 一、B1 反折保真（"3"的中间）

### 现状（三处机制，各有代码位置）

1. **mean2 距离窗削平**：`StrokeMotion.BuildMean2`（`StrokeMotion.cs:367`，窗 `Mean2WindowPx=12` `:89`）
   输出 = 最近 12px **路径**的平均。反折处"来路 + 回程"的点落在同一扇窗里 →
   尖端位置被平均拉平（几何上等于把折角削圆）。
2. **角判据漏判**：`StrokeSmoothing.MarkCorners`（`StrokeSmoothing.cs:278`）的趋势门
   （`:320-324`）——`|单点转角 − 局部趋势| < 80°` 就 `continue`，**连 ③ 窗口判据一起跳过**。
   摊开在 3~4 个点上的反折，单点只有 40~70°，`|st−trend|` 可能 < 80° → 整段被判"光滑" → 无角点。
3. **控制点限幅**：`TravelOffset`（`:494`）里 CR 控制点最多 **0.5×弦长**（`MaxCtrlChordRatio`
   `:177`、夹取 `:508-513`）。没判成角时，曲线在反折处做不出"折"，会鼓成圆弧或塌陷。

> 现有自检**没有覆盖 180° 反折**（这是缺口，也是"3 怪"能潜伏至今的原因）。

### 方案（a→d 先小后大，做完 a-c 先看效果）

- **a. 折叠窗判据（新增，独立于趋势门）**
  ±2~3 点、两臂长均 ≤ `CornerWindowMaxPx`(24px)、两弦夹角 ≥ **`CornerFoldDeg`（初值 110°）** → 直接判角。
  与现有 ③ 的区别：**不经过趋势门**、阈值更高（110° 而非 80°）。参数 `--cornerfold N` 可调、`0` 关。
- **b. 趋势门语义修正**
  ⓪ 门只挡 ①（单点判据）；③（±2 点窗）与 a（折叠窗）**在门判"光滑"时仍运行**——
  理由：门是为了防"稀疏圆弧被单点判据切成折线"，而窗口类判据自带臂长护栏（>24px 直接跳过），
  不会在稀疏圆弧上误触发。
- **c. mean2 反折清窗**
  mean2 在**输入**（原始点）里检测近 180° 反折（前后两段方向夹角 ≥ `FoldResetDeg` 初值 120°）→
  当场清空距离窗、从反折点重新累计 → 尖端不进平均。**只影响建模输出**，不动存档点。
- **d. （备选，a~c 不够再上）角点段控制点**
  判成角的段现在取弦的 1/3（`:474-475`）；若"折得不够干脆"，在折叠窗点处放宽 0.5 弦长限幅
  或改沿切线取向（`--cornerctrl N` 对照）。

### 验收

- **新增自检**（如 `--foldtest`，并入 SelfTests）：
  - 合成 180° 反折（快/慢各一）+ 摊开反折（4 点摊 140°）：折尖位置误差 **≤1.5px**、
    输出在折点处两段夹角 **≥ 输入夹角 −15°**；
  - 圆弧/锯齿反例：不许被折叠窗误判。
- **回归**：`--smoothtest`、`--cornertest`（含"稀采样快画圆不变折线"）、`--motiontest` 全绿，
  重点盯"圆弧偏离"不退化。
- **用户样本**：`--recink` 录的"3"经 `--inkfile` 回放，出修前/修后对照图；
- **真机**：用户写"3 / 弯钩 / 折笔"验收。

### 分支 e（视用户回答）

若用户答"3 是**粗细**怪"：加"反折附近的宽度低通"（宽度沿曲率/速度做平滑）。
**先把形状修到位，再谈粗细**——两件事不同时动，否则分不清是谁的效果。

## 二、B2 速度自适应平滑

### 现状

mean2 窗固定 12px → 滞后 ≈ 窗长一半 ≈ **5.9px**（合成语料实测；不随速度增长，但也**不收缩**）。

### 方案

- **窗长随速度收缩**：慢速（<0.8px/ms）保持 12px 不动；中速线性降到 8px；快速（≥2.5px/ms）收到 **6px**
  → 快写滞后 ≈ 3px，慢写维持现在的平滑强度。
- **可选叠"末点混合"**：输出 = 平滑点 + (原始末点 − 平滑末点) × k(v)，k 从 0（慢）到 ~0.35（快）
  —— 快写时笔尖更贴手，慢写完全不动。
- 收笔追赶（`:400-410`）不动。

### 评估与验收

- 离线先行：`--motiontest` 加"自适应窗"列（合成语料 + 用户样本回放），看：快写滞后 / 慢写抖动 /
  圆弧偏离 / 直角偏离 / 末点误差。
- 验收目标：快写滞后 **≤3px**（现在 5.9）；慢写抖动 **≤0.09px**（现在 0.072，允许小幅回退）；
  直角/圆弧不退化；末点误差仍 ~0。
- 开关：`--mean2adapt`（**默认先关**，离线数字 + 真机 A/B 之后再定默认）；`--mean2win` 保持。

## 三、B3 分配复用与偶发低帧

### 数据

- 常态每笔分配 **20~26KB**（很好）；但 **4.4 秒长笔 10.8MB + 1 次 gen0**（4G 校园机的隐患）；
- 书写期间 fps 恒定 48.0 = **当时面板真在 48Hz**（用户自设，已核实；90Hz 下待复核 fps≈90）；
  模式切换（穿透/纸底/文档）时 1~2 帧低值。

### A) 分配

- **先定位**：活笔路径（`Overlay` 每帧重建 + `[笔画]` 分配列）找出 10.8MB 的构成；
  重点怀疑"活笔每帧重建几何的临时数组 / 每来一个点重走全量加工"。
- **复用**：活笔加工的缓冲池化（数组/列表容量只增不减、跨笔复用）；几何按"新增段"增量重建。
- **验收**：4 秒长笔分配 **≤200KB**（降两个数量级）、书写期间 0 GC、`--penlive` 分配列复核。

### B) 低帧 / 配速

- 先按 P0 复核：**90Hz 下 fps 应 ≈90**；若仍 ~48（面板确为 90Hz 时），才轮到"双重等待"排查——
  `DwmFlush`（`Engine.cs:3225`）+ 帧延迟等待对象（`Overlay.cs:6250-6251`）。
- fps 随面板 Hz 走 → 配速正确，本条只留观察（模式切换的一次性低值属整屏重建，**判定可接受**）。

### C) 探针小修（顺手，代码 2 行级）

- `--penlive` 结束写 `reports\latency-live.csv`：目录不存在 → **FATAL 崩溃**（已两次复现，
  两份数据的结尾堆栈一致）→ 写前 `CreateDirectory` + 失败不崩；
- 收尾 0ms 空笔的打印（"采样 0 Hz / 原始输入 14000 Hz"）加保护。

## 四、B4 有纪律的预测

### 前提事实

系统委托湿墨在手写板 Ink 开上**不渲染**（实测两轮）；触摸 / 关 ink 本来只有自绘 →
**显示那一帧只能靠自绘预测遮**。委托轨迹继续照喂（无害），B4 **不依赖**它。

### 纪律（写死，逐条验收）

1. **只画显示**：预测段永不进 `Stroke.Points` / 文档 / 存档 / 命中 / 撤销；
2. **混合重建**：每帧用"最后 2~3 个真实点 + 速度"重建尾；收到新点 / 抬笔**当场丢弃重建**，绝不累积；
3. **慢写不预测 + 反向不预测**：速度门（如 <0.8px/ms 不出尾）；反折/大转角处尾巴沿切线**衰减**（防甩墨）；
4. **开关**：起步 `--predict2`（命名待定）、**默认关**；验收合格后再定默认与设置项；
5. **先评测量化，达标才接线**。

### 评测（离线先行）

- A. `PredictEval`（`InkTeach/PredictEval.cs`，CLI 接线现为注释）接回 +
  数据集导出（`tools/datasets/Export-CharacterTrajectories.py`；UCI CharacterTrajectories，需下载一次）
  → 出 8/10/12/15ms 四个地平线的「吃到 / 超前」；
- B. 新离线回放：用户 `--recink`（带压感用 `--recinkp`）录 10+ 个"3"（快慢各半）→
  按 60Hz 帧仿真，量：显示墨尖端 vs 真实笔位的**滞后**、**越前**、**反折处过冲/甩尾**；
- 门槛（草案，沿用老口径）：吃到 ≥50%；越前 p99 ≤ 0.8×滞后；反折过冲 ≤2px；慢写段出尾长度 →0。

### 上屏验收

`--penlive` 前后对比 + 用户 A/B（"笔尖后面是否还拖着"）+ 复活 `--tailjumptest`
（防"突突跳"——当年被否就是这个症状；老自检注释保留在 `SelfTests/Touch.cs:714-1112`）。

### 分步

① 评测工具 + 数据集 → 出数 → ② 参数定稿（含反折衰减形状）→ ③ 接显示（默认关）→
④ 用户真机 A/B → ⑤ 定默认 / 进设置。

## 六、本方案不做什么（防跑偏）

- 不做"自造双线程湿墨"（B5，已砍：渲染实测 ~1ms，救不了"显示那一帧"）；
- 不再试整套照搬（WPF/WinUI3 均已否；系统栈已在用，湿墨已证不渲染）；
- 不动存档 / 命中 / 撤销 / 橡皮；不动默认档以外的手感行为；
- 白板盖 PDF、显示形态四档、放大+滚动条等 = 另行搁置，等用户重提。
