## 一、我们现在有什么（逐条对应代码）

| 能力 | 现状 | 在哪 |
|---|---|---|
| 框选工具 | `Ctrl+Alt+5`，拖框；**碰到就选中**（相交），小于 4 像素的拖动＝单击空白＝取消选中 | `Engine.ApplyMarquee`、`Model.ApplyMarquee` |
| 选区坐标系 | **一律画布轴对齐**（2026-09-16 改：单选原来跟对象转，现在和多选同一条公式——框永远正着、旋转柄永远在正上方） | `SelectionHandles.FrameOf` |
| 手柄 | 8 个缩放手柄 + 1 个旋转手柄（在上边中点外侧 30px，官方图标） | `Selection.cs`、`Overlay.DrawSelection` |
| 尺寸（按设计稿"方案 B 教室友好"实现） | 视觉 14×14、**命中区 28×28**、描边 2.5px + 6.5px 半透明光晕、白底蓝边 | `VisualSizeLogical / HitRadiusLogical` |
| 旋转 | 90° 软吸附（±3°）、`Shift` 15° 硬网格、`Alt` 完全自由；拖动中浮出度数标签，吸附住整块变强调色 | `Engine.UpdateSelDrag`、`Overlay.DrawSelection` |
| 拖动 | 每帧从"按下那一刻的变换"重算（不累积浮点误差）；**一次拖拽＝一步撤销**（拖动中不进撤销栈） | `Engine.UpdateSelDrag / EndSelDrag` |
| 操作条 | 框下方 14px，**4 个按钮**：复制 / 删除 / 左右翻转 / 上下翻转 | `Overlay.DrawSelectionBar`、`Engine.RunBarAction` |
| 键盘（批注键盘模式） | `Ctrl+A` 全选、`Ctrl+D` 复制一份、`Delete` 删除、`Esc` 取消、方向键 1px / `Shift`+方向键 10px | `KeyBindings.Default` |

| 性能边界（已有实测） | 一屏量级选中变换 **1.83 ms/帧**；散布全屏的 20 个对象 19 ms/帧（与架构无关，是重画面积） | `reports/性能边界-全量压力测试.md` |

## 二、和同行对照

### 2.1 你自己的 InkClass（最相关：同一批用户、同一批习惯）

| 能力 | InkClass | 我们 |
|---|---|---|
| 矩形框选 | ✓ **相交即选中**（`s.GetBounds().IntersectsWith(rect)`，注释写"PowerPoint/OneNote 同标准"） | ✓ 一样 |
| **点选墨迹** | ✓ 原生（点在墨迹上不启动框选；命中取**最上面**那条：`hitTestStrokes[^1]`） | **✗ 完全没有** |
| 套索（自由选择） | ✓ 选择面板里可切"矩形 / 自由" | ✗ |
| 选区操作条 | ✓ 复制（**复制拖拽模式**：点一下就进入"拖出副本"状态，可连续拖多份）/ 删除 / 水平翻转 / 垂直翻转 / 图片铺满宽度… | 4 个按钮，缺"旋转" |
| 剪贴板 | ✓ 复制时**同时写 ISF（墨迹，画板内粘回来仍是可编辑墨迹）+ PNG（外部应用能粘）** | ✗ 格式名定义了，**没接线** |
| 选中收回 | ✓ "选中是**临时上下文**：任何与选中无关的新操作（截图/激活笔/橡皮/图形工具）出现时旧选中立即清场——与 PPT/Figma 行业惯例一致" | ✗ 切工具后选区还挂着 |

### 2.2 微软官方墨迹控件（判据都能核实）

| 产品 | 框选/套索判据 | 证据 |
|---|---|---|
| **WPF `InkCanvas`** | 套索：**一个笔迹有 80% 的点落在套索里**才算选中（非墨迹元素 60%） | `LassoSelectionBehavior.cs`：`_percentIntersectForInk = 80; _percentIntersectForElements = 60;` |
| **UWP 墨迹 API** | `SelectWithPolyLine` = "contained entirely within"（全包含）；`SelectWithLine` = "intersected by"（相交） | 官方 API 文档原文（见 `调研-图形与选中框.md` 4.1） |

规律还是一样：**矩形框（粗手势）宽松——碰到就选；套索（精确手势）严格——80% 或全包含。**

## 三、缺口清单（按"老师会不会被卡住"排序）

### P0：现在就会让人卡住 / 点不到

**P0-1 没有"点选"**（最要紧的一条）

现在单击一条墨迹**不会**选中它——`TryBeginSelectionGesture` 只在"已有选区"时才接管，
否则一律起框选，而框选松手时小于 4 像素的拖动＝取消选中。想选单独一条必须拖一个小框。

> 顺带发现一处**文档与实现不一致**：`光标设计调研.md` 里写着"悬停在未选中的笔迹上保持箭头——
> **现在是"点一下选中、拖一下框选"**"。这句话描述的行为**代码里没有**。要么补上这个行为，要么改那句文档。

做法：按下时先做命中测试（网格粗筛 → 宽笔用 `PaddedBounds`、图形用 `HitTestExact`），
命中就**选中那一条并直接进入"整体拖动"手势**；没命中才起框选。多条叠在一起时取**最上面**那条。
代价：小（`TryBeginSelectionGesture` 加一个分支 + 复用现成的 `HitTestExact / DistanceToCanvas`）。
验收：`--seltest` 加三条——点一下选中那一条、点空白取消、点另一条换成另一条。

**P0-2 操作条会被屏幕底边切掉**

`SelectionHandles.BarRect` 无条件把操作条放在框下方（`y = sel.MaxY + 14`），**没有翻面**。
选区靠近屏幕底部时，操作条整个跑到屏幕外——看得见框、点不到按钮。
设计稿只考虑了"上方不留空"（框贴屏幕顶部时按钮不会被顶出屏幕），漏了下面这一半。

做法：下方放不下就翻到框**上方**（保持 14px 间距）；再不够就贴屏幕边。
代价：小（`BarRect` 里加一次夹取，但**渲染和命中必须用同一个函数**——它们现在同源，别写两遍）。
验收：新增自检——选区贴屏幕底边时，`BarRect` 落在屏幕内、`BarButtonAt` 能点中第一个按钮。

**P0-3 ~~操作条缺"旋转"按钮~~ —— 更正：是有意不做的（我上一轮看漏了）**

设计稿里画了 5 个图标（含旋转），但**代码里明确写了为什么不做**：
`SelectionHandles.BarButtonCount` 的注释——"**没有"旋转 90°"**：旋转手柄 + Shift 的 15°
吸附已经覆盖了任意角度（包括精确 90°），再放一个按钮是冗余，还占宽度、增加误点。"
用户 2026-09-15 也确认"旋转按钮不需要"。**这条从缺口清单里划掉。**

### P1：常用，缺了别扭

| 项 | 说明 | 代价 |
|---|---|---|
| **加选 / 减选** | `Shift` 点/框＝加选、`Alt`（或 `Ctrl`）＝减选。现在只能"全换一批" | 中 |
| **剪贴板对象通道** | `Ctrl+C` / `Ctrl+V` 复制墨迹，**跨页/跨程序粘回来仍是可编辑墨迹**（InkClass 用 ISF+PNG；我们序列化器和 `ClipboardFormatName` 已经写好了，只差接线） | 中 |
| **切工具时收起选区** | 现在切到笔之后选区还挂着（框还在、还能被误拖）。InkClass 的原则："选中是临时上下文" | 小 |
| **套索（自由选择）** | 圈"一行里的几个字"比矩形准；判据直接沿用微软的 **80%** | 中 |
| **复制拖拽** | `Alt`+拖动 = 拖出副本（PPT/Figma），或 InkClass 那种"复制模式"按钮 | 小 |

### P2：锦上添花

| 项 | 为什么值得 |
|---|---|
| 层级（置顶/置底/上移/下移） | 荧光笔压住字、或字被图盖住时的唯一解 |
| 锁定对象 | 把截图/已定稿板书锁住，防止误拖（老师最常见的事故） |
| 智能参考线 + 吸附对齐 | "把这两个字对齐"是真实需求；也是课件观感的关键 |
| 多选对齐/等距分布 | 对齐一堆零散的标注 |
| 持久分组（组/解组） | 一次把"图+圈注"整体搬走 |
| 操作条 hover 态（设计稿有：浅蓝底+图标加深）、悬停手柄放大 | 投影上"我点到了吗"的反馈 |
| 双击进入顶点编辑 | 已按你的决定回退，暂不做（要做得先讨论语义） |

## 四、建议分三批做

| 批次 | 内容 | 为什么这么排 |
|---|---|---|
| **第一批** | **点选 + 操作条翻面 + 旋转按钮**（三条都是 P0） | 都是"现在就会卡住/点不到"的；改动集中在 `TryBeginSelectionGesture` / `BarRect` / `BarButtonCount`，都能上自检 |
| **第二批** | 加选减选 + 剪贴板 + 切工具收起 + 套索 | 把"选"这件事做全；套索取自微软 80% 阈值 |
| **第三批** | 层级 + 锁定 + 参考线吸附 + 分组 | 属于"用久了才会提"的需求，等第一批手感确认后再排 |

## 五、需要你拍板的

1. **第一批就按上面三条做？** 还是你想换掉/加一条（比如先做套索）。
2. **点选的修饰键**：`Shift` 加选、`Alt` 减选，要不要**一起**做（在第一批里很便宜）。
3. **操作条第 5 个"旋转"按钮**：点一下**转 90°**（好按、好撤销），还是**进入旋转拖动模式**（像手柄那样跟着指针转）？
4. **套索**放第二批可以吗？（它能立刻改善"选一行里的几个字"这件事）
5. **切工具就收起选区**——按 InkClass/PPT/Figma 的惯例改，还是你想让选区留着（比如"选中后换笔在它旁边补两笔"）？
