## 一、现状：一条截图的链路（按发生顺序）

### 1. 入口
- `Ctrl+S`（批注内热键，`KeyBindings`：`ToolCapture`）或面板第 9 格；
- 第 9 格的上带是**三段**：`[直接截取] [隐藏界面] [粘贴图片]`（`FullUi.cs:3616`），
  前两段是**模式**（点一下切换、当前档高亮），第三段是**动作**（调 `Paste()`，从不点亮）。

### 2. 框选（`Engine.BeginCaptureAt / ExtendCaptureTo`）
和框选用**同一套锚点算法**：按下 = 锚点，拖出去 = 框，往回拖 = 框跟着缩。
坐标存**画布坐标**，松手换算回屏幕坐标（`screen = canvas + ViewOffsetY`；x 没有滚动）。

### 3. 光标（当前形态，`Overlay.DrawCaptureFrameCursor`）
- 截图工具**藏掉系统光标**（`ToolCursorKind → CursorKind.Hidden`），自绘一个
  **24×24 逻辑像素的取景框角括号 + 中心小十字**（琥珀色 + 白垫，见 `reports/截图光标.png`）；
- **一按下就完全不画**（`DrawnCursor`：`Tool.Capture → CaptureActive ? None : Frame`）——
  这是 2026-09-17 定的："框本身就是反馈，再留一个十字跟着手跑就是两个东西一起晃"；
- 没有全屏准线、没有放大镜、没有坐标/尺寸跟随读数（尺寸读数在框外，见下）。

### 4. 取景框与读数（`Overlay.DrawCaptureRect`）
- 1.6 逻辑像素**琥珀色矩形** + 四角角标（角标线画在框内侧）；
- 框**左下角外侧**跟一个深色胶囊 `宽 × 高`（**逻辑像素**，14 号白字）；
  贴屏幕底时自动改画到框内；框小于 24×16 逻辑像素时不画（"数字没意义"）；
- **没有全屏变暗**（没有遮罩）：屏幕原样，只有一圈细线。

### 5. 松手之后（`Engine.EndCapture`）
1. 框小于 4 物理像素 → 当没发生过（静默取消）；
2. 按模式抓屏：
   - **隐藏界面**（默认）：`ScreenCapture.HiddenOverlay` 把**所有覆盖层窗口**藏掉 →
     两次 `DwmFlush` + `Thread.Sleep(60)` → `GDI BitBlt` 抓合成结果；
   - **直接截取**：只把**取景框**收起来（`HiddenCaptureFrame`：重画一帧 + 等一拍），
     板书留在画面里一起拍；
3. 图**落到视口左上角 + 24 逻辑像素边距**（`CaptureMarginLogical`），按 DPI 折成画布尺寸；
4. `EnsureVisible`（图比视口大时把相机拉过去看全它）；
5. 自动选中 + **工具切成框选** + 同时写剪贴板（`ClipboardImage`）。

### 6. 自检与出图
- `--capturetest` **15 项**：生成对象、物理尺寸=框、DPI 折算、落点、自动选中、
  自己的批注不入镜（品红≈0）、剪贴板、拖动中读数上屏、截后无残影、
  直接截取的板书入镜 / 取景框不入镜；
- `--captureshow <图>`：离屏出"取景框+读数"的摆样图（本报告看图用的就是它）。

## 二、参考：同行与 InkClass 是怎么做的

### 2.1 InkClass（本仓库一直对照的实现，源码在磁盘上）

来源：`D:\文件集中\code\画布测试\Ink-Canvas-Dev\Ink Canvas\MW_Capture.cs`
＋同目录 `ScreenshotMaskWindow.xaml(.cs)`。它的做法（原文要点）：

| 维度 | InkClass | 我们 |
|---|---|---|
| 框选界面 | **独立的全屏遮罩窗口**：整屏 `#66000000`（40% 黑）铺满，选区用 `EvenOdd` **挖洞变亮**；顶部一行提示"拖动框选截图区域（Esc / 右键 取消）" | 没有遮罩；只有一圈细框 |
| 光标 | **系统十字**（`Cursor="Cross"`，窗口级），一直显示、零延迟 | 自绘角括号；**拖动中完全不画** |
| 尺寸角标 | 选区**右下角**，黑底白字，显示**物理像素**；贴底时翻到框内 | 左下角外侧，显示**逻辑像素**；贴底翻到框内 |
| 取消 | **Esc / 右键 / 单击没拖开（<10 逻辑像素）/ 窗口失焦** —— 四条路，都"关窗即恢复、无副作用" | 只有"框太小当没发生"；Esc/右键不处理 |
| 松手 | 松手 = 完成（够大就确认） | 同（松手即抓） |
| 抓屏时机 | 遮罩**先关**、再等两拍渲染、然后 `CopyFromScreen`；UI 的隐藏发生在"选区刚定、遮罩还盖着"时——**闪的一下被遮罩挡住** | 先藏窗口/框（60ms+两次 flush）再 `BitBlt`——**这一下用户看得见**（批注瞬间消失又出现） |
| 两种模式 | 快速截图（选的时候 UI 原样，选定瞬间才藏 UI）／隐藏界面截图（先藏 UI 再上遮罩） | 直接截取／隐藏界面（语义一样，只是没遮罩） |
| 松手之后 | **快速截图**：只进剪贴板 + **进入"粘贴模式"**（画布挂起、专用光标，点哪放哪；Esc 取消；翻页后再放也行——"截的图放到第二页"是它的核心诉求）；**隐藏界面截图**：自动插入当前页 + 剪贴板 | 一律自动插到**视口左上角** + 选中 + 切框选 + 剪贴板 |
| 粘贴光标 | 自绘"图片图标+右下加号徽章"的 32×32 光标，热点=图片中心 | 无（粘贴=Ctrl+V 直接落点） |

### 2.2 通用截图工具的惯例（Snipaste / 微信 / Windows 截图工具）

- **十字准线**：Snipaste 截图时在指针处画**全屏十字标线**（可在选项里常开，或按住 Alt 唤出）；
  微信/QQ 的框选也有细细的十字参考。作用是**对着屏幕上的边找齐**——这是"顺手"的关键。
- **放大镜**：Snipaste 按住 Alt 出放大镜（看像素级细节/取色）。我们做的话是 P2。
- **松手后还能调整**：微信/QQ 截图**松手后选区仍带 8 个手柄**，可以继续拖边缘、拖整体，
  拖到满意再点 ✓（Enter/双击 = 复制，Esc = 取消）；Snipaste 还能用方向键/WASD 做像素级微调。
  Windows 截图工具（Win+Shift+S）松手即出编辑器（画完才能存）。
- **全屏/窗口模式**：Windows 截图工具有矩形/任意形状/窗口/全屏四种；Snipaste 有 `Ctrl+A` 全屏。
- **落地**：Snipaste 把截图**贴在屏幕上原位**（贴图）；Windows 进编辑器；微信复制到剪贴板。

## 三、问题拆解（把"不顺手 / 不对"落到具体状态与像素）

### 3.1 光标不顺手（对应 "截图光标不顺手"）

1. **拖动中一个光标都没有**（`CaptureActive → None`）。框一旦拖起来，屏幕上看不到
   指针精确在哪个像素上——想对齐表格线/PPT 的边只能靠框边猜。这是"不顺手"最大的一条。
2. **没有全屏准线**。同行都有十字准线，对着屏幕边缘找齐时它是唯一的"尺子"。
3. **角括号是"面"不是"点"**：24×24 的括号 + 4 像素的小十字，中心点不锐利；
   框一出现它又消失，两个状态之间没有连续性。
4. **按下那一瞬间没有反馈**：press 时框是 0 尺寸（画出来就是一个点），
   而括号光标又在同一刻被藏掉——"我这一下按到了没有、锚点在哪"在头几帧是空的。

### 3.2 感觉不对（对应 "截图感觉也不对"）

1. **没有变暗（遮罩）**：屏幕上没有"我要截的这一块 vs 不要的"的明暗对比，
   细线在花哨的课件上很容易淹没；也没有"现在在截图模式里"的模态感。
2. **抓屏那一下看得见"闪"**：隐藏界面模式要把整个覆盖层藏 60ms（＋两次 DwmFlush）再抓，
   用户看到的是**批注整层消失又出现**；直接截取模式至少也会看到取景框消失一拍。
   （InkClass 把这 60ms 藏在遮罩下面，所以它不闪。）
3. **框的对比度不够**：1.6px 琥珀色在浅色底和深色底上都只是"够看"，
   没有白/黑双色垫底；四角角标和边框同色、画在框内侧，等于没有"角"。
4. **读数位置/口径**：逻辑像素是我们的口径（要保留），但它在**左下角**，
   而眼睛此刻在框的右下角（拖动的那个角）；贴底翻转的判据也只看屏幕底。

### 3.3 逻辑（对应 "截图逻辑"）

1. **松手即定局**：没有"确认/调整"阶段。框偏了一点只能删掉重来（或 Ctrl+Z 后再截一次）；
   拖框途中想反悔也没有出口（Esc 当前只清选区，右键不处理）。
2. **落点固定"视口左上角"**：截的是屏幕右下角的一块公式，它却出现在左上角，
   还得拖回去。同行都是**原位贴回**（Snipaste）或**点哪放哪**（InkClass 快速截图）。
   另外 `EnsureVisible` 在图比视口大时还会**挪相机**——视线被拉走。
3. **三段混着"模式"和"动作"**：`[直接截取][隐藏界面][粘贴图片]` 里第三段是动作，
   永远不会高亮，也不属于"截法"；前两段的名字"直接/隐藏界面"要靠记忆才分得清谁是谁。
4. **没有全屏/重截等快捷**：想截整屏只能手拖到四个边；截歪了没有"重截"入口。

## 四、建议（按"要不要动架构"分档）

### A 档：不改架构，这轮就能做（建议直接做，0.5～1 天）

| # | 改什么 | 怎么做 | 为什么 |
|---|---|---|---|
| A1 | **拖动中也给一个锐利的落点** | 按下后画"**细十字（1px）+ 全屏准线（细虚线，随指针到屏幕边）**"；角括号退到"还没按下"时才画（或缩到 16 逻辑像素） | 回答"指针精确在哪儿"；准线是线不是第二个形状，不会晃眼（推翻 2026-09-17 那条"拖框中不画"——当时怕的是两个形状打架） |
| A2 | **一条全屏遮罩** | 进截图模式就铺一层 40% 黑（`#66000000`），选区**挖洞**变亮；顶部一行小字"拖动框选 · Esc/右键取消" | 一眼看出"截哪儿"；截图有了模态感（InkClass / 所有同行都这么做）；顺带给提词器留了位置 |
| A3 | **框线加强对比** | 2 逻辑像素琥珀 + **白色外垫 1px**；四角改画**小方块**（4×4，压在角上） | 深浅底都立得住；"角"看得见 |
| A4 | **Esc / 右键 = 取消** | 拖框中按 Esc 或右键 → 直接当没发生过（不抓、不落图） | 同行的标配；成本极低（引擎里已经有按键/右键入口，加一个 capture 分支） |
| A5 | **读数挪到"正在拖的那个角"** | 贴右下角（框内/框外自适应，和 InkClass 一样）；口径保持**逻辑像素** | 眼睛此刻就在那个角上，数字不用跨半个屏去找 |
| A6 | **第三段拆出去** | `[直接截取][隐藏界面]` 只留两种截法；"粘贴图片"改成上带右端的**动作按钮**（和"清空/全选/关闭白板"同一套位置语言） | "动作"混进"模式"里，既不高亮也没法从名字看出来它是按钮 |

> A 档**不解决**"抓屏那一闪"——遮罩和覆盖层在同一个窗口里，藏窗口时一起没。
> 要解决它得看 B 档。

### B 档：要拍板才算数（1～2 天）

| # | 改什么 | 两种做法 | 取舍 |
|---|---|---|---|
| B1 | **抓屏不再闪** | ① 保持现架构，缩短等待（实测两次 DwmFlush 后能不能把 60ms 睡去掉）；② **按下时先抓整屏**（冻结），松手只做裁剪 | ①便宜但收益有限；②**一劳永逸**：抓一次整屏（~20MB 瞬态）之后松手不再藏任何窗口——不闪、还能支撑 B2/B3。代价是"拍到的画面 = 按下那一刻"（PPT 动画会停在按下时） |
| B2 | **松手后还能调整** | ① 松手即完成（现状）；② 松手后选区留 8 个手柄，可拖边/拖整体，Enter/✓ = 确认，Esc = 取消（微信/QQ/Snipaste 手感）；③ 双击直接确认 | ②最"正"、也最花时间（要一套选区编辑状态机 + 手柄几何 + 光标切换）。有了 B1 的冻结帧，确认时只是裁剪，不用二次抓屏 |
| B3 | **落地方式** | ① 视口左上角（现状）；② **原位落**：截图区域在屏幕上的位置换算成画布坐标，夹进视口；③ 粘贴模式：点哪放哪（InkClass 快速截图；适合"截了放到下一页"） | ②最直觉（"贴回原处"）、实现小；③给 PPT 翻页场景，但要一套粘贴模式状态机；①最安全但"感觉不对"多半就是它 |
| B4 | **模式命名** | `直接截取 / 隐藏界面` 改成 `连批注拍 / 只拍下层`（或保留原名但把提示写进 A2 的顶部小字） | 现在这两个名字要靠记忆；老师说出口的是"我要不要把批注拍进去" |

### C 档：大改（另开一轮，3 天+）

- **截图后进标注**：像 Windows 截图工具/Snipaste 那样，先把截图放进一个可标注的临时层
  （画箭头/框/文字再落成对象）。这和"图像对象"是两条路，值得单独立项。
- **冻结截屏批注模式**：计划里已有的方向（`计划-底层性能与功能.md` §12：先截一屏冻结成底图，
  再在图片坐标上批注）。B1 的"按下抓整屏"正好是它的地基。
- **多屏 / HDR**：记账里已有（`README` 的"还差的两条"），截图这块要按屏抓、按屏算 DPI。
