## 一、荧光笔那次改动：我到底动了什么，退回了什么

**结论：动过一处渲染代码（填充规则），已经退回默认；颜色/透明度/粗细/渲染方式一个字没改。**

`git diff b0aed4e -- src/InkEngine` 里和荧光笔有关的行**全部是同一行被移动位置**，
没有一处逻辑变化；`Overlay.cs`（真正画笔画的地方）**一行没动**。渲染路径上唯一的实质改动
是 `Stroke.BuildCenterline`：

| 改动 | 是否影响观感 | 现状 |
|---|---|---|
| 一条笔迹可以带**多个 figure**（擦断后剩下的每段一个） | 没擦过时只有一个 figure，与原来完全一致 | 保留（这是橡皮的实现基础） |
| 给中心线几何加了 `SetFillMode(FillMode.Winding)` | **可能影响自交处的填充** | **已退回**（删掉这一行，用默认） |

退回前后的实测（同一台机器，同一份代码其余部分）：

| 判据 | 改前（Winding） | 退回后（默认） |
|---|---|---|
| `--holetest` 找洞 | 3 通过 / 3 失败（170 / 1862 / 15813 像素） | **一字不差** |
| `--eraseselfcross` 自交叠色 | 切前差 0、切后差 0 | **一字不差** |
| `--selfcross` | 差 0 | 差 0 |

也就是说那条填充规则本来就是**空改动**，退回去零代价。

> 唯一"看起来像把荧光笔改了"的地方是：**擦断之后，段与段的交叠不再叠加变深**。
> 那不是新行为——它就是这条笔迹本来的画法（一条几何、一次 `DrawGeometry`）；
> 是"把笔迹拆成两个对象"那一版把它改坏了（离屏实测：交叠处差 0 → 56），
> 区间表这一版把它恢复回来。如果你要的"退回"是把这一条也退掉（即擦断之后两半各画各的、
> 交叠处变深），说一声，我把拆分改成默认行为——但那就等于把"对象数会一直涨"一起要回来。

## 二、图形是 D2D 自带的吗？

**渲染是 D2D 的，"图形"这个概念是我们自己的对象模型。**

| D2D 提供了什么 | 我们用了什么 |
|---|---|
| `ID2D1RenderTarget::DrawRectangle` / `DrawEllipse`（直接画形状） | **没用**（我们统一走几何 + 描边） |
| `ID2D1Factory::CreateRectangleGeometry` / `CreateEllipseGeometry` | 椭圆用了 `CreateEllipseGeometry`；矩形/直线/箭头是**我们自己建 path**（4 条线 / 2 点 / 3 段） |
| 描边（线宽、圆头端帽、圆角拐角）由 `ID2D1StrokeStyle` 决定 | **用了**：`Gfx.Round`（`StartCap/EndCap = Round`、`LineJoin = Round`） |

所以：**椭圆是 D2D 的几何，其余图形的几何是我们拼的；线宽/端帽/拐角全是 D2D 画的。**
但"图形"在我们这里的真正含义是**对象模型**：

```
Stroke { Kind = Line/Rectangle/Ellipse/Arrow, 只有两个端点, Transform }
```

它只知道两个端点 + 一个种类，矩形/椭圆/箭头都是"从两点推出来的"。
**橡皮怎么对它，取决于这个模型，不取决于 D2D。**

## 三、擦图形能不能像墨迹那样（擦掉一部分、剩下留着）？

**能。而且你自己那版 InkClass 天然就是这样的——因为那里的"图形"就是笔迹。**

InkClass 源码原话（`MW_GraphStrokes.cs` 文件头）：

> "**背景：画布上"一切都是笔迹"**，但有三类内容其实是"图形"：① 函数识别生成的图像
> ② 图形面板拖拽画的图形 ③ 手写识别成图形 / 自定义图库插入。……**方案：不改变存储模型
> （仍是普通笔迹，翻页 / 撤销 / 保存零改动）**，只给图形笔迹附加一个"组 ID"属性。"

图形 = `Stroke` → WPF 的橡皮（`EraseByPoint`）切它，就跟切手写字一样：擦掉哪段掉哪段、
剩下的留着，而且**切完就是两条独立笔迹**（所以能分开选中——这正是你问过的那件事）。

我们这版不是这样：图形是"两个端点的参数化对象"，所以像素橡皮只能用**整条删**（`EraseRectAt`
里对非自由笔迹的那条分支）。三种改法：

| 方案 | 做法 | 得到什么 | 代价 |
|---|---|---|---|
| A **保持现状** | 碰到轮廓整条删 | 图形永远是"可拖顶点的图形" | 擦一半做不到 |
| B **熔化**（推荐） | 第一次被橡皮碰到时，用轮廓折线把它**变成自由笔迹**（`ShapeOutline()` → 点列），然后走同一套区间逻辑 | 和 InkClass/OneNote 一样：弧、线段被切开留缺口，可分段选中；一步撤销 | 那一笔从此**不再是图形**（没有顶点手柄、不能改形状参数）。建议在动作名/提示里体现（"已转为笔迹"） |
| C 保留参数 + 擦除区间 | 图形定义不变，另存"轮廓上被擦掉的区间" | 形状语义与擦除状态并存 | 顶点一拖动，擦除区间就失去意义，规则说不清；实现也最绕 |

**要我做 B 的话**：`EraseRectAt` 里把"非自由笔迹 → 整条删"改成"先熔化再擦"，
加上一步撤销 + 自检（擦矩形的一条边，剩下三条边还在、且变成 4 条独立线段）。

## 四、选中框：碰到就选中，还是全包含才选中？

**我们现在是"碰到就选中"；你自己的 InkClass 也是这个标准。**

我们的代码（`Model.ApplyMarquee`）：

```csharp
foreach (var s in _queryScratch)
    if (s.PaddedBounds.Intersects(r)) Selected.Add(s);   // 笔身擦到框 → 选中
```

InkClass 的代码（`MW_SelectionMode.cs`，矩形框选松手那一段）：

```csharp
/// 结束拖选：矩形与墨迹/图片包围盒**相交即选中（PowerPoint/OneNote 框选同标准）**。
if (s.GetBounds().IntersectsWith(rect)) hits.Add(s);
if (b.IntersectsWith(rect)) hitImages.Add(img);
```

两边**判据完全一致**（相交 = 碰到）。而且我们这条还是你之前明确要的：
`清单-墨迹处理.md` 里记着「A12 框选语义"碰到就选中"…… **留（你明确要的）**」，
起因是"整条都在框里才选中"时你反馈"我明明全框住了，却没全选中"——屏幕上永远选不全：
笔迹只要有一头在屏幕外，或者粗笔的笔身压出框外一点点，那条就永远选不上。

顺带对照（InkClass 有的、我们没有的）：

| InkClass | 我们 | 差距 |
|---|---|---|
| 矩形框选 / **自由选择（套索）** 两种方式，面板里切 | 只有矩形框选 | 套索能贴着字圈，选"一行里的几个字"更准 |
| **点选墨迹**（点一下就选中那一条，在墨迹上按下不启动框选） | **没有点选**：只能拖框，且小于 4 像素的拖动 = 取消选中 | 想选单独一条得拖一个小框 |
| 面板里"全选" | 有（`Ctrl+A`，批注键盘模式下） | —— |

### 4.1 同行到底怎么定的（这一轮把源码翻出来了，四家三种规则）

| 产品 | 框选语义 | 证据（可自查） |
|---|---|---|
| **WPF `InkCanvas`**（微软自己的墨迹控件） | 套索：**一个笔迹有 80% 的点落在套索里**就算选中（非墨迹元素用 60%） | `LassoSelectionBehavior.cs`：`private const int _percentIntersectForInk = 80;` / `_percentIntersectForElements = 60;`，配合 `Strokes.GetIncrementalLassoHitTester(_percentIntersectForInk)` |
| **UWP 墨迹 API** | **两种都提供**：套索 `SelectWithPolyLine` = "**contained entirely within**"（完全包含）；`SelectWithLine` = "**intersected by**"（相交） | [SelectWithPolyLine](https://learn.microsoft.com/en-us/uwp/api/windows.ui.input.inking.inkstrokecontainer.selectwithpolyline) / [SelectWithLine](https://learn.microsoft.com/en-us/uwp/api/windows.ui.input.inking.inkstrokecontainer.selectwithline) 文档原文 |
| **Xournal++** | 矩形框选：**完全包含**——遍历这条笔迹的**每一个点**，有一个点不在框里就不选 | `Stroke::isInSelection(ShapeContainer*) const`："for (auto&& p : this->points) { if (!container->contains(px, py)) return false; } return true;" |
| **你自己的 InkClass** | 矩形框选：**相交（碰到就选）**，注释里写着"（PowerPoint/OneNote 框选同标准）" | `MW_SelectionMode.cs`：`if (s.GetBounds().IntersectsWith(rect)) hits.Add(s);` |
| **我们（本原型）** | 矩形框选：**相交（碰到就选）** | `Model.ApplyMarquee`：`if (s.PaddedBounds.Intersects(r))` |

### 4.2 规律：手势越精确，判据越严

- **套索（用手圈）**：用户是在"描出我要的那几笔"，所以判据严——**全包含**（UWP）或 **80% 覆盖**（WPF）。
  WPF 取 80% 而不是 100% 是在容忍手抖：圈得差一点点也算。
- **矩形框选（拖一个框）**：是"我说这一片"的粗手势，判据分化：
  **碰到就选**（PowerPoint / OneNote / InkClass / 我们）↔ **全包含**（Xournal++）。
- **按方向分流**（CAD 传统的"窗选/交叉选"）也有人用，但那条隐含规则对老师来说太隐晦。

### 4.3 结论与建议（待你拍板）

**建议保持现状：矩形框选 = 碰到就选。** 理由：

1. 这正是你自己那版 InkClass 的判据，也是当初你反馈"我明明全框住了、却没全选中"之后改成的；
2. 老师用框选通常是"把这一片都给我"——**选多了点空白处重来就行，选少了会以为软件坏了**（这条写在 `Model.ApplyMarquee` 的注释里）；
3. 真要解决"框边蹭到长笔迹就把整条带进来"，更对症的是**加"点选"**和**框选预览**（框里的先高亮、松手才定），而不是改判据。

**如果以后加套索（自由选择）**，套索那条就用**微软 WPF 的 80% 覆盖**：那是"精确手势用严格判据"的做法，同行里说得通，数值也直接沿用得到。

## 五、附带发现：两种橡皮对图像的行为不一致（实测）

探针 `--imageerase`（放一张 400×300 的图，橡皮落点打在图像正中）：

```
像素橡皮擦一下：受影响 0 条，图还在吗 在（对象数 1）
整笔橡皮擦一下：删掉 1 条，图还在吗 **没了**（对象数 0）
```

- **像素橡皮**：按设计不碰图像（代码里 `if (s.IsImage) continue`）——"擦掉半张截图不是任何人想要的"。
- **整笔橡皮**：走 `IsShape` 分支 → `HitTestExact` → **碰到就把整张图删了**。这是历史遗留：
  图像是后来加的对象种类，整笔橡皮那条分支没跟着改。

**已按你的决定统一成"都不碰"**（2026-09-15）：`EraseAt` 里加了 `if (s.IsImage) continue;`，
两种橡皮现在对图像的行为一致——图像只能框选 + `Delete` 删。
自检加了一条："图像：两种橡皮都不碰（要删它用框选 + Delete）"，`--pixelerasetest` 全过。

## 六、"擦除只是像素没了"——这条原则落到代码上是什么

你定的原则：**擦除前后，除了被擦掉的那一块，屏幕上别的东西必须一模一样。**
具体到代码，是这三条：

| 要求 | 实现 | 怎么验 |
|---|---|---|
| 擦完还是**同一条笔迹**（不变成两个对象） | 只往 `Stroke.Erased`（擦除区间表）里加区间，不新建对象 | `--pixelerasetest`："还是同一条笔迹（对象不拆）" |
| 剩下那截的**观感不能变**（半透明荧光笔在"两截互相穿过"的地方不能变深） | 剩下的段拼成**一条几何**、一次 `DrawGeometry` | `--eraseselfcross`：切前差 0、切后差 0 |
| **框选也不许改变墨的样子** | 框选只改选中集合；不再"框到就自动拆开"（曾经这么做过：拆成两个对象会让交叠处叠色变深，等于"什么都没擦、只是选了一下，墨却变了"） | `--pixelerasetest`："框选被擦断的笔迹：不会自动拆开" |

要单独搬动某一截时，用**显式动作** `Ctrl+Alt+8`（拆开擦断的笔迹）：先框选，再按键。
键位表已同步（`--keytest` 会核对文档与代码一致）。
