## 0. 结论

1. **截图的"去手写"已经有了**：`CaptureHideInk = true`（默认，Ctrl+Shift+A 切换）截图时不把自己的墨迹拍进去。**不要再做后处理去自己的手写**——那是把已经干净的东西再猜一遍。
2. 真正缺的是**图片本身的美化**（手机拍纸、展台拍纸、微信收到的题图）：做 4 个预设 `原图 / 增强 / 黑白 / 去彩笔`，点一下实时预览，✓ 应用，一步撤销。
3. 第一版**不引入 OpenCvSharp**：用已有的 SkiaSharp + 纯 C#，新增原生依赖 = 0，AOT 不受影响。
4. **黑色手写这一版不做自动去除**（与印刷体同色，没有轻量成熟算法）；给"手动擦除笔刷"兜底，ML 方案暂不引入。
5. 入口两处：图片选中条加第 4 格 `🪄 美化`；截图调整条加第 1 个按钮 `🪄 美化`（= 完成截图 + 打开美化面板）。

### 1.2 DocScanner 的原始参数（照录，供实现对照）

来自 `Services/ImageProcessingService.cs`：

- 背景估计：`kernel = max(15, (max(w,h)/25)|1)`，强制奇数；逐通道 `Dilate` → `GaussianBlur(kernel)`；
- 背景除法：`out = plane / bg * (255 * clamp(strength, 1.0, 1.25))`；`strength < 0.99` 时与原图按 `strength` 混合；
- 色彩增强：转 LAB，**只对 L 通道** `CLAHE(clipLimit=2.2, tileGridSize=8×8)`；
- 锐化：`unsharp: GaussianBlur(sigma=1.5)`，`alpha = 1+s, beta = -s`；
- 黑白：灰度 → 背景除法 → `AdaptiveThreshold(GaussianC, block = max(21, (min(w,h)/60)|1), C = 8)` → 2×2 开运算；
- 透视矫正：Canny + 凸包 + `ApproxPolyDP` + `WarpPerspective`。

### 1.3 哪些照搬 / 哪些不搬 / 我们的差异

**照搬（逻辑）**

- 背景估计 + 除法这条主链：去阴影、去黄、压平纸面；
- LAB 上**只动 L** 的 CLAHE：不动色相，印章/彩色图不串色；
- 自适应阈值的块大小"跟图幅走"的规则（不是写死 25）；
- hbot 的"预设而不是滑块"的产品形态。

**不搬（及理由）**

- **OpenCvSharp / OpenCV 原生库**：体积 + AOT + 4GB 机器内存，代价远大于收益；
- **四角检测 + 透视矫正**：截图/裁剪阶段已经解决；课堂 90% 是正拍；
- **PDF 批处理、多页队列**：不属于批注场景；
- **medianBlur**：C# 里代价高，用盒式模糊近似；
- **ML 阴影图**：专利 + 重依赖。

**我们的差异**

- 纯 C# + 已有 SkiaSharp，**零新增原生库**；
- 输出最长边上限 **2400px**（内存可控，见 §7）；
- 预览用 **1200px**，切预设实时出图；
- 一步 Undo 用"换 `Image` 引用"实现，**不复制像素**；
- 新增 **「去彩笔」** 预设（参考项目都没有）。

## 3. 入口与交互

### 3.1 入口

**图片选中条：6 格 → 7 格**

```
收起 / 保存 / 复制 / 🪄 美化 / AI / 删除 / ⋯
```

**截图调整条：3 键 → 4 键**

```
🪄 美化    ✨ AI 作图    ✕ 取消    ✓ 完成
```

- 点「🪄 美化」= 先走 `ConfirmCapture()` 落图并选中，再打开同一个美化面板；
- **不新增截图状态**，不复制逻辑，`✨ AI 作图` 已经是这个套路（`ConfirmCaptureAndPlot`）。

**图标预算（AGENTS §1–§7 逐条回答）**

- 主入口：图片条第 4 格；截图条第 1 键。
- 兜底入口：**不需要**。图片条不是可自定义主条，功能不会因"图标少"消失。
- 不在 `⋯` 重复：美化是图片专属高频动作，放核心格；`⋯` 保持 置顶/置底/翻转/锁定/图库。
- 0 / 1 / 多：美化面板没有"条目"概念，固定 4 个预设 + ✓/✕，不存在空态、分页、溢出。
- 旧入口迁移：全新功能，无老配置需要翻译。

### 3.2 面板

```
┌──────────────────────────────────────────┐
│  原图    增强    黑白    去彩笔     ✓   ✕ │
└──────────────────────────────────────────┘
```

- 贴在图片/操作条上方（放不下自动翻到下方），高 34 逻辑像素，圆角胶囊；
- 点预设 = **立刻在画布上换预览**（不落盘、不进撤销栈）；
- `✓` = 后台跑全分辨率 → 换图 → 记一步 Undo → 关面板；
- `✕` / `Esc` / 点画布空白 = 还原原图 → 关面板；
- 处理中当前格显示"处理中…"，禁止重复点。

### 3.3 状态机

```
Idle ──点「美化」──> Open(old = s.Image, mode = 原图)
Open ──点预设──> Preview：s.Image = preview[mode]
Preview ──✓──> 后台全分辨率 ──> s.Image = full + Commit(SetImagePixelsAction) ──> Idle
Preview ──✕/Esc──> s.Image = old ──> Idle
```

## 4. 算法设计（`ImageBeautify.cs`，纯 C#）

统一前置：

1. 像素本来就是预乘 BGRA 且 alpha=255（截图/粘贴已 `Normalize`），直接当 straight 用；
2. 超过 `MaxOut = 2400` 先按比例缩小（Skia `SKBitmap.Resize`，高质量）；
3. 灰度：`Y = (77R + 150G + 29B) >> 8`。

### 4.1 增强（美白）

```
bg  = GaussianBlur(Dilate(Y, r), r)          r = max(15, (max(w,h)/25)|1)，奇数
out = src / bg * 255                         逐通道，bg 取 max(1,bg)
L   = CLAHE(Lab.L, clip=2.2, tiles=8×8)      只动 L
out = src + 0.6 * (src - GaussianBlur(src, 1.5))   unsharp
```

效果：纸面压到接近纯白、阴影拉平、字口变锐、印章颜色不跑。

### 4.2 黑白

```
Y   = 灰度 → 背景除法（同上）
bw  = AdaptiveThreshold(GaussianC, block=max(21,(min(w,h)/60)|1), C=8)
bw  = Open(bw, 2×2)    // 去孤立噪点
```

输出只有 0/255，适合打印和 OCR。

### 4.3 去彩笔（我们的）

在**增强后的图**上做（纸已白，掩码更稳）：

```
S = (max(R,G,B) - min(R,G,B)) / max(1, max(R,G,B))
V = max(R,G,B) / 255
mask = (S > 0.32) && (V < 0.90)        // 彩色 + 不是高光
mask = Open(mask, 1px) → Close(mask, 1px)
过滤连通域：面积 < max(24, W*H/200000) 的丢掉   // JPEG 彩边
羽化 1px：对 mask 做 3×3 均值
被 mask 的像素 = bg（背景估计图，纸色）        // 没有 bg 时填 255
```

- 红 / 蓝 / 绿 / 紫笔迹去掉；
- 黑色印刷体 `S≈0`，不受影响；
- **彩色插图、红色标题会一起变淡** —— 面板提示语写明，靠预览 + 撤销兜底。

### 4.4 原图

直接返回原 `ImageData`，用于对比。

### 4.5 参数总表

| 项 | 值 | 来源 |
|---|---|---|
| 背景核 `r` | `max(15, (max(w,h)/25)|1)` | DocScanner |
| 除法缩放 | `255 × clamp(1.0..1.25)` | DocScanner |
| CLAHE | `clip=2.2, tile=8×8`，仅 L | DocScanner |
| Unsharp | `sigma=1.5, s=0.6` | DocScanner（s 取默认） |
| 黑白块 | `max(21, (min(w,h)/60)|1)`，`C=8` | DocScanner |
| 去彩笔 | `S>0.32, V<0.90`，面积门限 | 本文 |

## 5. 数据与撤销

- 新增 `SetImagePixelsAction : EditAction`：持有 `old` / `new` 两个 `ImageData` 引用；`Redo` 换新、`Undo` 换旧，`s.Release()` + 脏区 `PaddedBounds`。
- 预览 / 取消只改 `s.Image`，**不进撤销栈、不复制像素**。
- 存档、导出、AI 作图读的都是 `s.Image`，**自动跟随美化结果**（美化后再"识别作图"更准）。
- 失败（像素格式不对/超时）→ 保持原图 + 状态栏提示，不弹窗。

## 6. 性能与内存

| 对象 | 尺寸 | BGRA |
|---|---|---|
| 手机原图（12MP） | 3024×4032 | 48.8 MB（本来就在） |
| 输出上限 2400 长边 | 1800×2400 | 17.3 MB |
| 预览 1200 长边 | 900×1200 | 4.3 MB |
| 处理中间（灰度/背景/临时） | 同上 | ≈ 26 MB 瞬时 |

- 后台线程处理，完成后释放中间数组；
- 峰值 = 原图 + 输出 + 中间 ≈ 原图 + 45MB（瞬时，非长期）；
- 目标耗时：**预览 ≤ 40ms，全图 ≤ 150ms**（2400px），实测后回填；
- 不新增任何原生库 → AOT 体积不变。

## 7. 不做 / 为什么

| 不做 | 理由 |
|---|---|
| 黑色手写自动去除 | 与印刷体同色，没有轻量成熟算法；ML（YOLOv8+LaMa）体积/内存/许可证都不合适 |
| 透视矫正 / 自动裁边 | 截图与裁剪已经解决；再引入 Canny/轮廓会把"拍歪一点"变成"裁错" |
| 参数滑块 | 课堂不需要，增加学习成本和误触 |
| 自动美化 | 截 PPT 时无谓改变对比度；默认手动，一键可得 |
| 云端处理 | 隐私 + 网络 + 课堂断网 |
| 改存档格式 | `ImageData` 不变，像素换了而已 |

## 8. 风险与回退

| 风险 | 处理 |
|---|---|
| 彩色插图/印章被"去彩笔"洗掉 | 面板提示 + 只作用于副本 + 一步撤销 |
| 大图处理卡顿 | 后台线程 + 2400px 上限 + "处理中"忙状态 |
| AOT 裁剪/反射 | 只用数组运算 + Skia 尺寸变换，无反射；AOT 跑一遍自检 |
| 旧图占内存 | 只在撤销栈里多活一次，裁剪后自动释放 |
| 效果不达预期 | 删按钮即可回退；`ImageBeautify.cs` 零外部依赖，不碰存档格式 |

## 9. 自检（新增 `--beautifytest`，≤10 项，一条命令）

合成一张"灰底 + 斜阴影 + 红色手写 + 黑色印刷"的测试图：

1. 增强后纸面均值 ≥ 245；
2. 阴影角亮度提升 ≥ 40；
3. 黑白输出只有 0 / 255；
4. 去彩笔后红色像素占比 < 1%；
5. 去彩笔后黑色文字像素保留 ≥ 90%；
6. 预览最长边 ≤ 1200；
7. 应用后 `s.Image` 改变；
8. Undo 后 `s.Image` 回到原引用；
9. 取消后 `s.Image` 引用相等（没换过）；
10. 2400px 上限生效 + 打印耗时。

按最高原则：**只跑这一条**，不全量。
