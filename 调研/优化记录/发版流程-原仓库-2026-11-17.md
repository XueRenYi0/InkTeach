# 发版流程（2026-11-17 起：回到原仓库 + 一条命令）

> 替代 `2026-11-11` 那版"私有源 + 发布仓库"的做法（那份历史仍留在本文件末尾，仅作对照）。
> **结论**：源码公开、发版只在最早的 `XueRenYi0/InkTeach`、GitCode 继续做国内镜像、
> 老客户端用一条过渡清单接住。

## 一、三个仓库各干什么

| 仓库 | 可见性 | 放什么 |
| --- | --- | --- |
| `github.com/XueRenYi0/InkTeach` | Public | **源码、tag、Release 附件、`update.json`（唯一清单）** |
| `gitcode.com/XueRenYI0/InkTeach-Releases` | Public | 只放二进制附件（国内直连）；**不推源码** |
| `github.com/XueRenYi0/InkTeach-Releases` | Public | **只剩一条过渡 `update.json`**，给 9.7–9.9.2 老客户端 |

`InkTeach-Source`（私有）**不再参与发版**，保留只读即可。

## 二、每次发版：一条命令

```powershell
# 1) 先在 dist\release-notes-<版本>.md 写好发布说明
# 2) 改 src\InkTeach\InkTeach.csproj 的 <Version>（唯一版本源）
.\tools\release.ps1 -Notes dist\release-notes-9.9.3.md
```

它按固定顺序做，**失败就停在那一步**、重跑同一条命令即续上（幂等）：

1. `tools\sync-site.ps1` —— 官网 `docs\release.json`、JSON-LD、sitemap、首屏兜底跟上版本；
2. `publish.ps1` —— check-all + AOT + 目录 + zip + Setup + 固定名副本 + `update.json`（含 purge jsDelivr）；
3. 提交 `update.json` / `docs` 并推 `upstream main` + 打 tag 推 tag；
4. GitHub Release：建 `v<版本>`、传 zip / Setup / 固定名副本 / `update.json`、写标题与说明；
5. `tools\gitcode-release.ps1` —— GitCode 建发行版、传附件；
6. 旧仓库过渡清单：把同一份 `update.json` 提交到 `..\InkTeach-Releases`（不传附件）。

常用开关：`-DryRun`（只打包不发布）、`-SkipChecks`（已跑过 check-all）、`-NoLegacy`（不再写过渡清单）。

## 三、客户端更新链路

`src/InkEngine/Platform/Update.cs` 的候选源（**十条并行，先报"有新版"的赢**）：

1. 五个国内加速站（`gh-proxy.com` / `ghfast.top` / `gh.jasonzeng.dev` / `gh.llkk.cc` / `ghproxy.net`）→ 原仓库 `update.json`
2. GitCode 镜像 raw（`api/v5/repos/XueRenYI0/InkTeach-Releases/raw/update.json`）→ 内容指向原仓库最新版
3. GitHub 直连 raw
4. jsDelivr ×3（`cdn` / `fastly` / `gcore`）→ 原仓库 `main/update.json`

清单里的 `cn` 字段是 GitCode 的 zip 直链，下载时永远排第一。

**老客户端（9.7–9.9.2）**：读的是 `InkTeach-Releases/main/update.json`，第 6 步把这份写成新版本，
它们就会看到新版并按新地址下载；升级后自然改用原仓库的清单，之后这条过渡清单可以停。

## 四、官网（不再手改）

- 唯一数据源：`docs\release.json`（版本、日期、四个下载地址、安装包/绿色包大小）。
- 生成：`tools\sync-site.ps1`（版本取自 csproj，大小取自 `dist\` 真实产物，按 1e6 计 MB）。
- 渲染：`docs\site-release.js` 把 `{V}` / `{SETUP_MB}` / `{ZIP_MB}` 填进页面，
  并用 `data-href="setup|zip|setup-cn|zip-cn"` 赋下载地址；切语言后会自动再填一次。
- 兜底三档：`index.html` 内联的 `window.INKTEACH_RELEASE_FALLBACK`（发版时就地改，保证首屏正确）
  → 同目录 `release.json` → jsDelivr 上的 `release.json`。
- 自检：`node tools\site-selftest.js`（兜底与 release.json 一致、页面无写死的当前版本、无残留占位）。

## 五、注意

1. **只有 `<Version>` 一处版本号**；不要单独钉 `AssemblyVersion` / `FileVersion`。
2. **GPL-3.0 生效**：源码公开，修改后再分发仍须开源。
3. 第三方许可（`THIRD-PARTY-NOTICES.md`、`pdfium-licenses/`）必须随包，和开不开源无关。
4. GitCode 令牌在 `%USERPROFILE%\.gitcode-token`；GitHub 用 `gh`（已登录 `XueRenYi0`）。
5. 这台机器直连 `github.com` 不稳，`gh` 传大文件失败就重跑（`--clobber` 是幂等的）。

## 附：2026-11-11 旧流程（已废弃，仅存档）

从 9.7.0 起曾把源码转私有、新建公开 `InkTeach-Releases` 只放附件，客户端清单也指向它；
每次发版要手工 `Copy-Item update.json` → 提交发布仓库 → `gh release create` → GitCode，
还要另外同步旧仓库清单，步骤多、容易漏。**9.9.2 之后不再用这套。**
