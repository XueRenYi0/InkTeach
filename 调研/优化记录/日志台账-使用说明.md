# 日志台账（问题分诊 / 标记 / 追踪）

> 2026-10-17 起。以前日志只是“一堆 zip”；现在每份日志要么**未分诊**，要么挂到一个
> **案子（case）** 上，修完标记版本，下一份新日志可以接着验证或重开。

## 一、一次问题从发生到关闭

```text
老师点「日志」上传
        ↓
.\tools\log-case.ps1 -Action triage        # 只列没分诊过的日志
        ↓
分析（看 1Hz 性能行 / 慢帧 / 动因 / GPU/刷新率）
        ↓
.\tools\log-case.ps1 -Action open -Title "..." -Logs <日志文件> -Symptom "..."
        ↓
修完、发版
.\tools\log-case.ps1 -Action fixed -Case C-YYYYMMDD-NN -Version 9.1.x -Commit <sha>
        ↓
让老师用新版本再传一份日志
.\tools\log-case.ps1 -Action verified -Case C-... -Log <新日志>
        ↓
.\tools\log-case.ps1 -Action close -Case C-... -Note "复测正常"
```

关键规则：

- **一份日志只分诊一次**：处理过就写进台账的 `logs` 表；`triage` 不会再列它，
  避免同一份日志反复分析。
- **修完后再来的新日志**：先 `attach` 到老案子；如果老案子已经是 fixed/verified/closed，
  会自动变成 `reopened`。如果是**另一个问题**，直接 `open` 一个新案子。
- 状态：`new → investigating → fixed → verified → closed`；中途可 `reopen`。
- 开发机自检/基线日志用 `ignore` 标记（不进案子，但也不会再出现在 triage 里）。
- 台账在**日志仓**里：`cases/ledger.json`；本机缓存 `reports/log-ledger.json`
  （已加 `.gitignore`）；下载的日志在 `logs-download/`（也已忽略）。

## 二、命令

前置：`%USERPROFILE%\.gitcode-token`（有 `InkTeach-Logs` 仓读写权限）。

```powershell
# 看案子 / 看未分诊日志 / 看单份日志的 session 元数据
.\tools\log-case.ps1 -Action list
.\tools\log-case.ps1 -Action triage
.\tools\log-case.ps1 -Action meta -Logs log-20261017-110327-DESKTOP-0IOUN0S-865a9b.zip

# 开案（-Logs 多个用逗号分隔；带 -NoPush 只写本地）
.\tools\log-case.ps1 -Action open -Title "Win10 45fps / 13ms" `
    -Logs log-a.zip,log-b.zip -Symptom "空闲 45fps，记录 13ms" -Device "DESKTOP-XXX"

# 追加新日志 / 标记修复 / 验证 / 重开 / 关闭
.\tools\log-case.ps1 -Action attach   -Case C-20261017-01 -Logs log-new.zip
.\tools\log-case.ps1 -Action investigating -Case C-20261017-01 -Note "9.1.5 日志：空闲 45fps / 13ms，等新版 GPU/动因"
.\tools\log-case.ps1 -Action note     -Case C-20261017-01 -Note "确认是界面动画一直全屏重绘"
.\tools\log-case.ps1 -Action fixed    -Case C-20261017-01 -Version 9.1.9 -Commit abc1234 -Note "改了..."
.\tools\log-case.ps1 -Action verified -Case C-20261017-01 -Log log-new.zip -Note "60fps / 3ms"
.\tools\log-case.ps1 -Action reopen   -Case C-20261017-01 -Note "又出现了"
.\tools\log-case.ps1 -Action close    -Case C-20261017-01 -Note "复测正常"

# 不作为问题处理（自检 / 基线），不建案子
.\tools\log-case.ps1 -Action ignore -Logs log-a.zip,log-b.zip

# 清理台账里已经不存在的日志键
.\tools\log-case.ps1 -Action prune

# 只拉 / 只推
.\tools\log-case.ps1 -Action pull
.\tools\log-case.ps1 -Action push
```

## 三、日志里现在有什么（9.1.9 起）

每份 zip 里新增 **`session.json`**（机读），同时日志正文有：

| 字段 | 例子 | 用途 |
|---|---|---|
| `gpu` / `vramMb` / `soft` | `Intel(R) Iris(R) Xe Graphics` / `128` / `false` | 先分清“真显卡 / 软件渲染（WARP）”；同一版本 2ms 和 14ms 常常差在这里 |
| `hz` | `60` / `144` | 60Hz 地板 16.7ms；48Hz 20.8ms；4K@30Hz 33ms——“卡”有时是显示链路 |
| `dpi` / `ui` / `screen` | `192` / `1.00` / `2520x1680` | 缩放/分辨率相关的问题 |
| `perf.fps` / `avgMs` / `maxMs` / `presentMs` / `wsMb` | `46.3` / `13.07` / `20.17` / `0.12` / `30` | 一眼看出是 CPU 记录慢、上屏慢，还是内存 |
| `perf.slow50` / `slow150` / `worstDrive` | `12` / `1` / `界面动画` | 慢帧数量和“最差那一帧在干什么” |
| `logs` | `["inkteach.log"]` | 这份 zip 里实际有哪些日志 |

日志正文新增/增强：

- 启动一行 `[env] gpu=... soft=... hz=... dpi=... ui=... screen=... session=...`
- 1Hz 性能行末尾加 **`动因=`**（脏区/书写/激光/界面动画/翻页/计时器/点名/呼出盘/提示/轨迹收尾）；
- 单帧 ≥150ms 的慢帧行也带动因；
- 5 分钟快照增加 **慢帧 ≥50ms / ≥150ms 次数**；
- **空闲仍在出帧**告警：10 秒没有按下/按键、却持续出帧且动因是界面动画/选中/翻页/提示时，
  30 秒最多一条（正常写字、PPT 翻页、计时器、回放不会误报）。

设备卡（`devices/<id>.json`）同步加了 GPU/显存/是否软件渲染/刷新率/DPI/界面缩放/最近
fps/记录耗时/内存/慢帧数，后续看“哪台机器什么配置、跑得怎么样”不用再翻日志。

## 六、边界

- 日志仓是**私有仓库**，但仍建议不要把含学生姓名/文件内容的截图往里传；
  运行日志只应包含路径、设备、性能数字。
- 台账的 `logs` 表是“已分诊”的唯一判据；手工改在线台账时，保持日志名与
  `logs/` 里的文件名完全一致（大小写、后缀）。
- `fetch-logs.ps1` 只负责“列/下载”；分诊和标记一律走 `log-case.ps1`，避免两套状态。
