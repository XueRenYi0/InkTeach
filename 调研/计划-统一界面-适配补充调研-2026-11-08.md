## 〇、结论先行

1. **主计划不变，只在 P0 与 P1 之间插一个 `A0 适配基础`（4–6 天）。**
   先做 Action 表/稳定 ID/FocusRing/Popup 栈，再开始 PageHost；否则 PageHost 会把
   “行 → 命中 → 执行 → 置灰 → 快捷键”的重复原样带进去。
2. **A0 只包 UI 层，不动引擎输入主循环。**
   先让「更多 / 设置 / 帮助 / 日志」的动作、行、菜单项有稳定 ID 和统一执行入口；
   引擎的 `KeyAction`/`OnPointerDown` 保持原样，P4 再桥接。
3. **四个基础设施，四个明确收益：**

   | 基础设施 | 解决什么 | 直接收益 |
   |---|---|---|
   | `UiActionTable` | 工具条/菜单/设置行/快捷键各写一套 | 新增功能只注册一条 Action |
   | 稳定 ID + `HitTarget` | `MoreHitRow + i` 下标串段 | 插入/删除/重排行不串 |
   | `FocusRing` | Tab 顺序/初始焦点/焦点恢复 | 键盘可完整操作设置/API 页 |
   | `PopupStack` | 菜单/下拉各自判断 Esc/点外 | 只关最上面一层，不误关 |

4. **不现在做**：Docking、Editor Groups、命令面板（可选）、自绘 IME/TSF、
   完整 UIA 无障碍树、把 Overlay 的 87 个 Draw/Hit 全搬走。
5. **净增约 1–2 周**（A0 4–6 天 + 设计/测试适配 3–5 天），主计划核心仍 **8–12 周**，
   总计约 **9–14 周**；后面 P1–P4 返工减少。
6. **P1 停止点不变**：设置页行为一致、`--settingsaudit` 全绿、`FullUi` 变短、
   新增一个测试页只写内容不改输入优先级。不通过就停在 P1。

### 1.1 目标

│    ├─ PopupStack.cs           菜单/下拉/确认框的栈

│    └─ LegacyPage.cs           包现有 DrawMoreXxx
├─ Pages
│    ├─ MoreHomePage.cs
│    ├─ SettingsPage.cs
│    ├─ ApiSettingsPage.cs
│    ├─ HelpPage.cs
│    └─ LogPage.cs
└─ FullUi.cs                    只做装配：工具条 + PageHost + 浮层

├─ KeyBindings.cs               引擎快捷键（保留）
├─ TextInputHost.cs             P2：一个原生输入宿主
├─ Input
│    ├─ InputCapture.cs         P4：全局捕获状态
│    └─ InputRouter.cs          P4：按优先级路由
└─ OverlayLayers
     ├─ OverlayLayerRegistry.cs P4：层注册/优先级
     └─ LegacyLayerAdapter.cs   P4：包 PPT/回放/计时/点名/收藏/选择条

### 3.1 数据流

```text
Win32 pointer/key/wheel
  → Engine.OnPointerDown/Move/Up/Wheel
      → TextInputHost（编辑中优先）
      → PageHost（页面模态）
      → InputRouter（P4：捕获 + 浮层优先级）
      → FullUi 工具条/色带
      → Canvas/墨迹

UiActionTable
  ├─ 工具条/更多/设置行/菜单 查表
  ├─ FocusRing 执行（Enter/Space）
  ├─ PopupStack 打开/关闭
  └─ Perform → IEngineCommands / PageHost / FullUi 内部状态
```

**关键**：`UiActionTable` 不是第二套命令系统；它只是把“UI 上一个可点项”的元数据集中。
真正的业务仍然走 `IEngineCommands` 和 `PageHost`。

### 3.2 分层职责

| 组件 | 管什么 | 不管什么 |
|---|---|---|
| `UiActionTable` | Id/标题/图标/快捷键显示/可用/选中/执行 | 页面栈、绘制、输入优先级 |
| `HitTarget` | 命中结果 = 稳定 ActionId | 几何计算、业务 |
| `FocusRing` | 页面内焦点顺序/初始焦点/恢复 | 全局快捷键、画布焦点 |
| `PopupStack` | 弹层顺序/Esc/点外/焦点恢复 | 页面栈、窗口 |
| `PageHost` | 页面栈/标题/遮罩/高度/滚动/转场 | 工具条、浮层 z-order |
| `InputRouter`（P4） | 捕获/优先级/命中路由 | 绘制、业务 |
| `TextInputHost`（P2） | 原生 EDIT/RichEdit/IME/定位 | 页面布局、校验 |

## 四、适配原则

1. **先表后壳**：A0 的 Action/ID 先做，再上 PageHost；否则 PageHost 会把重复带进去。
2. **双跑**：新旧命中/执行同时存在，自检对比；通过后再删旧路径。
3. **一层一层**：一次只迁一个页面/一个弹层/一个浮层；每层有停止点。
4. **保留旧路径**：`MoreHitAt` 先保留，新增 `MoreHitTargetAt`；旧代码不改，新代码用新接口。
5. **不做大爆炸**：不重写 `Overlay.cs` 的 87 个 Draw/Hit，只加适配器。
6. **只借模式**：不复制第三方源码；不引入运行时依赖。
7. **每步自检**：只跑相关专项，≤1 分钟；全量只在发布前。
8. **前台不打扰**：无窗口/离屏/隐藏窗口；不弹前台窗口。

public sealed class FocusRing
{
    public string? FocusedId { get; }
    public void SetTargets(IReadOnlyList<FocusTarget> targets, string? initialId = null);
    public bool MoveNext();
    public bool MovePrev();
    public bool MoveUp();
    public bool MoveDown();
    public bool MoveLeft();

## 十四、一句话总结

**先花 4–6 天把“动作、ID、焦点、弹层”四张基础表做出来，再让 PageHost/TextInputService/OverlayLayerManager 直接用。**

这样做的不是“新框架”，而是把成熟系统已经验证过的四个模式——
**Action 表（Excalidraw/JetBrains/VS Code）、稳定 ID（Dear ImGui）、FocusRing（APG/Unity）、
Popup 栈（Dear ImGui/Radix/Web top layer）**——适配到我们现有的 D2D + 原生 HWND 架构里。

做完 A0，再开始主计划的 P1；A0 不通过就停在 A0，不铺开。
