# 图形引擎：性能预算与手写隔离（调研补充）

日期：2026-11-09
原则：**允许引入方便的库，但控制性能；绝对不能影响手写体验。**

---

## 0. 结论

图形引擎可以引入库，但必须遵守两条硬规则：

1. **手写路径（WM_POINTER / 笔迹采样 / 笔迹渲染）上，绝不做图形引擎的工作**：
   不解析、不布局、不栅格化、不建 D2D 资源、不等待后台、不抢锁、不分配大对象。
2. **图形分“静态缓存”和“活动图形”两种状态**：
   - 静态/未选中的图：缓存成位图或 D2D command list，每帧只画一张；
   - 正在拖参数/选中的那一个图：才走矢量实时绘制；
   - 手写进行中：所有图形都用缓存，不更新、不重建。

这样既能用成熟库/算法，又不会把手写延迟拖坏。

---

## 1. 手写关键路径（不能碰）

```
WM_POINTERDOWN/MOVE/UP
  → 采样/预测
  → Stroke 点写入
  → D2D 笔迹几何/湿墨渲染
  → Present
```

这条路径的目标：

- 120Hz 屏幕：每帧 **≤ 8.3ms**；60Hz：≤ 16.7ms；
- 不允许 GC gen2 / 大数组分配 / 同步 I/O；
- 不允许等待后台线程、锁、Task.Result；
- 不允许在 `PointerMove` 里做表达式解析、曲线采样、布局、字体创建、位图上传。

**图形引擎的入口只能是“空闲调度器”**，不能挂在笔迹事件上。

---

## 2. 图形引擎的分层与线程模型

```
主线程（手写/输入/呈现）
  ├─ 笔迹：最高优先级，永远不阻塞
  ├─ 图形：只画缓存位图 / command list
  └─ 活动图形（当前选中/拖参数）：矢量直画，仅一个

图形工作线程（BelowNormal，单线程串行）
  ├─ 表达式求值 / 曲线采样
  ├─ 几何/刻度/标签布局
  ├─ 生成位图（Skia 或 D2D 离屏）
  └─ 完成后原子替换缓存，通知主线程重画

空闲判定：
  最后一次笔迹/触摸后 120–200ms 才允许启动图形重算
```

### 2.1 缓存策略

- 每个 Figure 有 `SceneVersion`；
- `SceneVersion` 不变 → 直接画缓存；
- 变了 → 标脏，**不立即重算**，等空闲；
- 缓存对象：`ID2D1Bitmap`（简单）或 `ID2D1CommandList`（矢量复用）；
- 只缓存当前页可见图形；LRU，内存上限（建议 64MB）；
- 拖动参数时：当前图形可以低质量/低采样实时画；松手后高质量重算一次。

### 2.2 手写期间

- 笔按下 → 取消/暂停图形 worker；
- 笔迹期间只画旧缓存；
- 抬笔 + 空闲 120–200ms → 恢复 worker；
- 图形更新只标图形自己的矩形脏区，不 `InvalidateAll`，不碰笔迹 tile。

## 3. 允许引入的库（按手写风险排序）

| 库/方案 | 许可 | 用途 | 手写风险 | 结论 |
|---|---|---|---|---|
| **D2D（现有）** | Windows | 主画布、活动图形、缓存位图/command list | 低（同线程、可控） | **主渲染** |
| **SkiaSharp** | MIT | 公式位图（已有）、静态图形快照 | 中（CPU 栅格化，放 worker） | 仅静态/公式 |
| **ScottPlot 刻度算法** | MIT | 10→5→2.5→1 刻度、标签密度 | 无（只移植算法） | **采用算法** |
| **function-plot 渐近线算法** | MIT | 函数断段、渐近线检测 | 无（只移植算法） | **采用算法** |
| **NCalc** | MIT | 表达式解析/求值 | 低（解析一次，缓存表达式；求值快） | 可选 |
| **MathEvaluator / NTDLS.ExpressionParser** | MIT | 更快的表达式求值 | 低 | 可选（新库，需验证 AOT） |
| **DynamicExpresso** | MIT | C# 表达式树 | 中（编译/JIT、AOT 风险） | 不优先 |
| **AngouriMath** | MIT | 符号化简/验证 | 中（重，放后台） | 仅后台可选 |
| **Clipper2** | BSL/MIT | 多边形布尔/偏移 | 低（按需，不在笔迹路径） | 可选 |
| **planegcs** | LGPL | 完整 2D 约束求解 | 高（WASM/C++、重） | 后置独立模块 |
| **NeoGeoSolver.NET** | **GPL-3** | C# 约束参考 | — | **不能抄** |
| **JSXGraph / WebView2** | MIT/LGPL | 整体交互几何 | **高**（独立进程/焦点/延迟） | 不采用运行时 |
| **HelixToolkit** | MIT | WPF 3D | 高（另一套 GPU/窗口） | 不采用 |

### 3.1 表达式求值的选择

函数采样典型量：每帧 500–2000 个点。

- 若每点重新解析：几十 µs～ms/点，不可接受；
- 正确做法：**解析一次，编译/缓存 AST 或 delegate**，之后每点只求值；
- NCalc 可缓存 `Expression`，支持参数更新/编译；MIT、成熟；
- MathEvaluator/NTDLS 更快，但较新，需验证 NativeAOT/数值边界；
- 第一版建议：**自研小型 AST 解释器**（+ - * / ^、sin/cos/tan/log/exp/sqrt/abs、括号、参数），
  或 NCalc；不引入符号计算。
- AngouriMath 只用于后台“AI 结果校验/化简”，不进入采样循环。

### 3.2 3D

- 不建议 HelixToolkit/WPF 3D（另一套窗口/GPU/输入）；
- 用 D2D 自己做：
  - 4×4 投影矩阵（JSXGraph `view3d.js` 同思路）；
  - 顶点→屏幕；
  - 边/面深度排序；
  - 隐藏线先不做精确消隐，用深度排序/虚线近似。
- 计算量小，主线程/worker 都可控。

## 4. 图形缓存 vs 实时绘制的取舍

| 场景 | 方案 | 理由 |
|---|---|---|
| 手写中，画布上已有图 | 画缓存位图/command list | 每帧 1 次 DrawBitmap，成本极低 |
| 未选中、无参数变化 | 缓存 | 不重算 |
| 选中一个图，拖参数 | 只这个图矢量实时画；其他缓存 | 只有一个活动图，成本可控 |
| 松手 | 高质量重算 + 换缓存 | 拖动时可低采样 |
| 多图同屏 | 全部缓存；只画可见页 | 内存/帧率可控 |
| 导出/打印 | 离屏高分辨率 | 不在手写路径 |

### 4.1 缓存格式

- 简单图：`ID2D1Bitmap`（D2D 离屏或 Skia 生成 BGRA）。
- 复杂矢量图：`ID2D1CommandList`（录制一次，回放便宜；参数变要重录）。
- 不要每帧 `CreateBitmap`/上传纹理；缓存对象复用。

---

## 5. 性能预算（建议）

| 项目 | 预算 |
|---|---|
| 手写帧 | 120Hz ≤ 8.3ms；60Hz ≤ 16.7ms |
| 图形缓存绘制 | 每图 ≤ 0.2ms（DrawBitmap/command list） |
| 活动图形矢量绘制 | ≤ 2ms（简单图）；复杂图降采样 |
| 后台图形重算 | 每次 ≤ 10ms；串行，BelowNormal |
| 缓存内存 | ≤ 64MB；LRU |
| GC | 手写期间 0 gen2；图形 worker 不产生大垃圾 |
| 图形更新延迟 | 抬笔后 120–200ms 才启动，避免抢手写 |

## 6. 验收/测试

新增 `--figurestress`（后续实现）：

1. 画布放 20 个图（函数/圆锥/几何/立体混合）；
2. 用合成笔迹以 120Hz 连续写 5 秒；
3. 同时后台不断改一个图的参数（模拟 AI/参数变化）；
4. 记录：
   - 笔迹输入→呈现 p50/p99；
   - 丢帧数；
   - GC gen2 次数；
   - 图形缓存命中率；
5. 通过标准：p99 不高于基线 +1ms，无 gen2，无输入丢失。

没有这个测试，不允许把图形引擎接到主循环。

## 8. “小透明墨迹画布”怎么理解（2026-11-09 补充）

先说结论：**不建议再开一个小透明墨迹窗口；建议在同一窗口的 DirectComposition 合成树里做“湿墨层 + 图形缓存层”。**

当前代码已经是 DirectComposition：

- `Overlay.cs` 里已有 `_swapVisual`（主内容 swap chain）和 `_inkVisual`（系统委托墨迹轨迹）；
- 也就是说，“多视觉层”这件事已经有基础设施，不需要另起 HWND。

### 8.1 三种做法

| 做法 | 说明 | 性能/手写 | 结论 |
|---|---|---|---|
| A. 单 swap chain + 图形缓存 + 脏矩形 | 图形静态缓存；笔迹只脏自己的区域 | 最简单，通常够用 | **先做 A** |
| B. 双视觉/双 swap chain：内容层 + 湿墨层 | 内容层画已提交笔迹/图形；湿墨层只画当前一笔 | 手写隔离最好；DComp 合成 | **图形变复杂后再上** |
| C. 另开透明 HWND 做墨迹 | 两个窗口、焦点/DPI/层级/输入路由 | 复杂、易出延迟/穿透问题 | **不做** |

### 8.2 “小”不是窗口小，是“湿墨只覆盖当前笔画”

- 输入仍然是整块画布：笔可以在任何地方落；
- `WetInkLayer` 只覆盖**当前这一笔的包围盒**（加一点余量），抬笔后把这一笔提交到内容层；
- 图形层/已提交墨迹层在笔迹期间**不重画**；
- 这样“小”带来的是填充率/重绘面积小，而不是把可写区域变小。

### 8.3 目标合成树（B 形态）

```
一个透明 Overlay HWND
  DirectComposition
    ├─ FigureVisual     图形缓存（位图/command list，低频更新）
    ├─ CommittedInkVisual 已提交笔迹（静态/脏矩形更新）
    ├─ WetInkVisual     当前笔画（高频，小 bbox）
    └─ UiVisual         工具条/面板
```

- 手写期间只更新 `WetInkVisual`；
- 抬笔后把湿墨并入 `CommittedInkVisual`，清空湿墨；
- 图形 worker 在笔迹期间暂停，空闲后更新 `FigureVisual`；
- 输入、命中、坐标仍在一个 HWND 里，不引入第二套焦点/DPI。

### 8.4 建议路线

1. **先做 A**：单 swap chain + `FigureCache` + 湿墨脏矩形；用 `--figurestress` 验证手写 p99。
2. 如果压力测试显示图形绘制影响手写，再把湿墨提升为独立 visual/swap chain（B）。
3. **不要**做 C（小透明墨迹窗口）；也不要让 JSXGraph/WebView2 进主画布。

---

## 9. 最终建议

- **主渲染/手写：D2D，不动。**
- **图形静态缓存：位图或 command list；后台重算，手写暂停。**
- **活动图形：D2D 矢量实时；只允许一个。**
- **表达式：解析一次 + 缓存 AST；NCalc/自研，不用符号引擎进采样循环。**
- **刻度/断段：移植 ScottPlot/function-plot 算法（MIT）。**
- **3D：自研 D2D 投影，不引 Helix/WebView2。**
- **约束求解：planegcs 后置独立模块；NeoGeoSolver 只参考（GPL）。**
- **JSXGraph：只参考依赖图/状态机，不整体跑。**
