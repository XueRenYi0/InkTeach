# 调研：教育内容对象（公式 / 化学式 / 化学结构 / 其它）

> **状态：已排后（用户 2026-10-01 决定）——方向保留，暂不施工。**
> 等语音主线（《计划-语音命令.md》）落地、真有人要用公式/化学式/结构图时再翻出来，
> 作为那时的方案依据。下面的结论与出处都还有效。
>
> 2026-10-01。你的问题：创建图形命令能不能做完善——把图、公式、化学式、化学结构、
> 跟教育有关的"通通放进来"？
>
> **结论先行：能，但不能"往引擎里堆学科"。** 正确姿势是：
> **引擎只加一种通用"内容对象"，学科知识全部放进一个可插拔的"渲染助手"**——
> 数学/化学/图表各自有成熟的现成渲染器，我们负责调度和托管，不自己造。
>
> 本文只调研与方案，不动代码。

---

## 〇、结论速览（七条）

1. **分清两类东西**：参数化图形（引擎原生，能拖顶点）和**内容对象**（排版/结构，
   渲染成图后能移动缩放旋转撤销，但不能拖顶点）。公式、化学结构都属于后者。
2. **引擎只加一种对象 + 一条命令**：`Content`（或复用 `Image` 的容器）+ 
   `InsertContent(renderer, source)`；**学科知识一行都不进 InkEngine**——守住
   《架构-分层与规则》"核心只回答画在哪画多快"。
3. **渲染助手 = 独立进程**（WebView2 + KaTeX/MathJax/Ketcher/Mermaid），
   按需启动、空闲退出、崩溃隔离——主程序的空闲内存指标不被破。
4. **关键事实**：Direct2D 从 Win10 1607 起**原生支持渲染独立 SVG**
   （支持 `path/use/defs/g/rect/...` 常用元素；**不支持 `<text>`**，不支持滤镜）。
   MathJax 的 SVG 输出是**纯 path**（字体转路径），天然适配，可做矢量放大不糊。
5. **其余内容先在助手进程里光栅化成高倍 PNG**（透明底 2～4x），稳、快、全兼容；
   矢量留作逐类升级。
6. **质量红线**：AI 生成的公式/结构必须**本地渲染校验**——渲染失败、SMILES 解析失败
   的，一律不许贴上画布。教育场景不贴"可能错"的东西。
7. **顺序**：数学公式（含理化公式排版）→ 化学结构 → 图表/流程图 → 生物/地理/五线谱等
   按需。**每加一类 = 加一个渲染适配器**，引擎与 UI 一行不改。

## 一、两类东西别混（这是全篇的题眼）

| | 参数化图形（已有 22 种） | **内容对象（新）** |
|---|---|---|
| 本质 | 几何参数（顶点/外框/表达式） | 源文本（LaTeX / SMILES / Mermaid…） |
| 编辑 | **拖顶点、改档位** | 移动/缩放/旋转/层级；**双击改源文本重生成**（二期） |
| 渲染 | Direct2D 原生描边 | 外部渲染器 → PNG/SVG |
| 例子 | 三角形、圆、抛物线、坐标系、立体族 | 数学公式、化学式、结构式、图表、流程图、五线谱 |
| 存档 | 已有 | **源文本 + 渲染结果一起存**（源文本是"可重制的真相"） |

把公式硬做成参数化图形（比如"给根号定义顶点手柄"）是走不通的——排版是排版，
几何是几何。反过来，把三角形做成一张图也亏——你们已经做对了。

## 二、引擎侧要加什么（很小的一块）

| 项 | 做法 | 说明 |
|---|---|---|
| 新对象 | `StrokeKind.Content`（**追加在枚举末尾**，存档版本 +1） | 存档纪律照旧（`Model.cs:561` 的规矩） |
| 载荷 | `RendererId`（"latex"/"smiles"/"mermaid"…）+ `Source` + 渲染位图（或 SVG 字节）+ 渲染版本号 | 源文本永远留着，随时可重渲 |
| 命令 | `IEngineCommands.InsertContent(rendererId, source, position)` | 内部：找助手 → 渲染 → 建对象 → 选中 → 进撤销栈 |
| 复用 | 移动/缩放/旋转/层级/复制/导出/橡皮 | **图像对象已经支持这些**（`StrokeKind.Image`），Content 走同一条路 |
| 高分渲染 | 存 1x 基准尺寸；按显示缩放重渲（或先用 4x 位图顶着） | 打印/投影不糊 |

> 这比"为每种图形加一条 Create"更通用：**创建图形的命令是砖，内容对象是楼。**
> A1 那条"创建图形命令"按这份设计一次做到位，就不用来回返工。

## 三、渲染助手（学科知识全在这）

```
主程序(InkEngine/InkUi) ──IPC(JSON)──> InkContentHost(独立进程)
                                         └ WebView2 + 本地 HTML
                                             ├ KaTeX / MathJax  → 公式
                                             ├ Mermaid          → 流程图/思维导图
                                             ├ ECharts          → 统计图表
                                             └ （原生适配器可替换，如 Indigo .NET）
```

- **请求协议**：`{renderer, source, theme, scale, maxWidth}` → 返回 PNG/SVG + 宽高 +
  是否失败（错误信息回传，供 UI 显示）。
- **生命周期**：第一次用到才启动（约 0.5～1.5s），**空闲 N 分钟自动退出**；
  崩了重启；主程序被卸载时助手目录一并清。
- **依赖**：WebView2 Runtime——Win11 自带，Win10 大多数已装；缺失时一次引导安装
  （微软官方小型引导器）；**没装也不影响批注与手绘功能**。
- **资产**：本地 JS/CSS/字体随安装包（几 MB 量级）；不依赖 CDN、离线可用。
- **备选**：化学结构如果 Indigo .NET 绑定好用，可以**不经过浏览器**直接在助手进程里
  调用原生库——助手是个框架，允许"每个渲染器换实现"。

## 四、各内容的渲染器候选（含许可证）

| 内容 | 源格式 | 候选 | 许可 | 结论 |
|---|---|---|---|---|

| **统计图表** | 数据/JSON | ECharts / Chart.js | Apache-2.0 / MIT | 二期 |
| **流程图/思维导图** | Mermaid 文本 | Mermaid | MIT | 二期 |
| **五线谱** | 音符文本 | VexFlow / OSMD | MIT | 三期 |
| **电路图** | — | circuitikz（要 LaTeX 全套，重） | LPPL | 后置 |
| **生物/地理/历史地图** | — | 无轻量通用方案（BioRender 类为商业在线） | — | 后置，或接图片库 |

**注意**：所有 JS 渲染器都输出 SVG，但**Direct2D 不认 `<text>`**——如果 SVG 里带文本
标签（很多结构图、图表默认如此），D2D 会静默丢掉文字。所以：
**一期统一"助手进程光栅化 PNG"**；等某类内容确认能输出纯 path（如 MathJax），
再逐类升级成矢量。

## 五、Direct2D 的 SVG 能力（技术备忘，摘自官方文档）

- **开始支持**：Windows 10 Anniversary（彩色字体 SVG）/ Creators Update（独立 SVG 图）；
- **支持元素**：`circle / clipPath / defs / ellipse / g / image / line / linearGradient /
  path / polygon / polyline / radialGradient / rect / stop / svg / use` ＋常用表现属性
  （fill、stroke、transform、opacity、dash 等）；
- **不支持**：`text`、滤镜等——**不支持的元素直接忽略**（不是报错），所以必须实测；
- 入口 API：`ID2D1DeviceContext5::CreateSvgDocument(stream, viewportSize)`；
  Vortice 绑定覆盖度要还原后花半天确认；
- **退路**：光栅化 PNG（助手进程里做），任何内容都能兜住。

## 六、AI / 语音怎么接（和《计划-语音命令》同一套命令层）

1. **模板库先行（一期，零 LLM）**：常用公式 20～50 条人工校对（勾股定理、求根公式、
   导数定义、欧姆定律、H₂SO₄…）——"写勾股定理"直接命中模板，最快最稳；
2. **LLM 生成（三期）**：词表未命中 → 大模型输出 `insert_content(renderer, source)`；
3. **本地校验回路（必须有）**：渲染失败/`SMILES` 解析失败 → 不贴、回退成"生成失败，要重试吗"；
   化学还可用 Indigo 顺手算分子式/分子量做交叉验证；
4. **双击编辑（四期）**：公式编辑器（KaTeX 实时预览）/ Ketcher（化学）→ 改源文本重生成。

| 阶段 | 内容 | 验收（自检） |

# 十、追问（2026-10-01）：能不能"用墨迹表示"？

> 你的问题：这些内容（公式、化学式、结构图）能不能不做成图片，而是**用墨迹画出来**？
>
> **答案：能，但要分清两种"墨迹化"**——它们的代价、外观、能做的事完全不同。

## 10.1 两种"墨迹化"

| | **A. 矢量对象**（推荐主力） | **B. 中心线笔迹**（真·一笔一画） |
|---|---|---|
| 本质 | 把渲染结果转成**填充轮廓 + 描边**的矢量路径 | 把内容变成一串**中心线**，用现有 `Stroke` 画 |
| 外观 | 和渲染器**完全一致**（印刷体） | 像绘图仪/手写体，风格统一但有取舍 |
| 缩放 | 无限放大不糊 | 不糊，但笔宽要跟着调 |
| 存档 | path 数据（几 KB～几十 KB）+ 源文本 | 采样点 + 宽度（几十 KB） |
| 编辑 | 移动/缩放/旋转/整删；改源文本重生成 | 同上；**可做"一笔一笔写出来"的动画** |
| 橡皮 | **整对象删**（延续图形规矩） | 整对象删；或"打散成笔迹"后逐段擦 |
| 适合 | 公式、图表、流程图、汉字、化学结构 | 化学键、几何图、坐标系、五线谱、**手写风公式** |

**一句话**：A 是"看起来像墨迹的矢量对象"，B 是"真的用笔画出 来"。两者都能在你们引擎里
落地，只是渲染分支不同。

## 10.2 技术事实（已核对）

- **你们现在有**：中心线 + 等宽描边的 `Stroke`（含参数化图形）、位图 `Image` 对象、
  选中/变换/撤销/存档。**没有**"填充轮廓"的渲染分支——加它很小（D2D `FillGeometry`），
  但几何来源要把 SVG 的 `d` 解析成 D2D 几何（几百行的解析器，或直接用 D2D 的 SVG 文档）。
- **Direct2D SVG 不支持 `<text>`**（静默忽略）——所以矢量路线要求"文字已转 path"；
- **MathJax 的 SVG 输出天然是纯 path**（字体转路径）→ 矢量化的最佳输入；
- **Hershey 单线字体：公有领域**（美国海军武器实验室 1967，数据免费、限制极少），
  覆盖**拉丁/希腊/西里尔 + 数学符号 + 日文汉字**，天生就是"坐标表连成线"——
  正是 B 路线要的东西（[Wikipedia](https://en.wikipedia.org/wiki/Hershey_fonts)）；
- **Cairo 有 `cairo_text_path()`**（文字转路径）——Indigo 的 SVG 是否已把原子标签转成
  path 需实测；没转也有两条退路（光栅化 / 自己转）；
- **汉字单线数据**（笔顺类）许可参差（多衍生自文鼎字体），**正式发布前必须单独核实**。

## 10.3 如果目标是"书写动画"（这笔钱花得值不值）

B 路线真正的独门价值是**书写动画/逐步出现**——课堂上"把公式一笔一笔写出来"、
"把化学键按顺序连起来"，这是 A 路线做不到的。实现套路是成熟的：

1. **排版**交给 MathJax（它算每个字符的精确位置和大小）；
2. **字形**换成 Hershey 单线字（数学符号、希腊字母都有）；
3. 输出 = 按顺序的一串中心线 → 你们的 `Stroke` 直接吃 → 可以逐段播放。

代价：字形的"印刷品质感"没了（是手写/绘图仪风）、复杂排版（矩阵、大分式）会退化；
中文不进入这套（单线汉字另说）。

## 10.4 建议的组合

| 内容 | 怎么表示 | 为什么 |
|---|---|---|
| 数学/物理公式 | **A（矢量）**；可选"手写风"切到 B | 排版精度优先；书写动画作为演示彩蛋 |
| 化学式（H₂SO₄） | A（就是排版公式） | 同上 |
| 化学结构式 | **A 整图**，键可后续拆成 B 笔迹 | 先简单可靠；拆键是二期优化 |
| 几何图/坐标系/函数曲线 | 已有的参数化笔迹（更早就是墨迹） | 已完成 |
| 图表/流程图 | A | 复杂、无需手写感 |
| 汉字/古诗/英文文本 | A（字体轮廓）**不做单线** | 单线汉字数据+许可都不划算 |
| 手写风格内容（可选） | B（Hershey） | 演示、动画价值 |

## 10.5 结论与新的待拍板项

- **"用墨迹表示"可以，推荐"矢量对象为主、中心线笔迹为增值"**：引擎多一个"矢量对象 +
  填充渲染分支"，公式/化学/图表全部可覆盖；想要手写感或书写动画，再加 Hershey 那一档；
- 原第九节的三件事不变，新增一件：**要不要把"书写动画（逐步出现）"列为二期的目标**？
  要，就先按 B 路线的数据结构设计（中心线 + 顺序 + 时长）；不要，就纯 A，
  工期和复杂度都显著下降。
