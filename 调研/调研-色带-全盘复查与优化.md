# 色带规则全盘复查：现状 / 业界 / 课堂习惯 / 优化建议

日期：2026-10-09　　状态：**等拍板**（本轮只做复查与方案，不动代码）
范围：上带（色带 / 设置条）的**开合与写字保护**规则；不含格内控件布局（那部分另见第五轮设计稿）。

---

## 〇、结论先行

1. **现在这套规则方向是对的**，三块核心（悬停意图、写字保护、反向张开）都立得住，与"沉稳"的目标一致，真机也认了。
2. 和业界比，**唯一明显的缺口是"点一下就开"这条明路**——业界所有白板/批注软件的工具设置都是"点开"；
   我们鼠标用户现在只能"悬停等 240ms"，写字刚写完还要过"余温 + 离开一次"（最快 ~0.84s 才等到自动开）。
   老师最想快速换色换粗细的那一瞬，恰恰是最慢的一瞬。
3. **建议做的最小优化包（两小条，一条参数、一条行为）**：
   - **① 点色带区（收起的色线）= 立即张开**（鼠标/笔/触摸一致；明确动作不再等悬停计时）。
   - **② 点工具格 = 该格的设置条立即张开**（现在不仅不即时，还会把悬停倒计时**重置**——
     注释写着"不用再等"，实现却反了，见发现 2）。
4. **可选（真机再定，不用先做）**：写字余温 600→400ms；"刚碰过面板 1.5 秒内再回来=立即张"（业界"探索模式"惯例）。
5. **不做**：改成"点工具弹浮层、点空白收"的业界面板模型——改动大、会丢掉现有手感与自检积累，收益不匹配。

## 一、现状：规则全量清单（截至 v9.0.0）

### 1. 视觉与几何

| 状态 | 样子 | 参数 / 出处 |
|---|---|---|
| 收起 | 一条 **10 像素色线**，整条用**当前笔色**；近白时补一道暗边 | 2026-09-27 用户："大屏看不大见"→ 6→10px |
| 张开 | **34 像素设置条**（图形格 3 行更高），内容 = 当前工具的设置（色片/滑条/分段…） | 第五轮设计稿：上带＝当前工具的设置条 |
| 位置 | 在主条**朝屏幕中心那一侧**长（面板贴底→朝上长；拖到上半屏→朝下长） | 假面板时期的做法 |
| 动画 | 开/合都是 **230ms**；"线淡出、控件淡入"的中间过渡 | `Tokens.RailMs` |

### 2. 张开（4 条触发）

| # | 触发 | 行为 | 出处 |
|---|---|---|---|
| 1 | 鼠标/笔**悬停**在【主条 ∪ 色带判定区】 | 停留 **240ms** → 张开。判定区=主条+色带全高+上下 10px 余量 | 2026-09-17 用户定："焦点在面板上它就张开" |
| 2 | 手指/笔**按下面板任意处**（工具格也算） | **立即**张开，并保持 **2.5s** | 2026-10-05 用户实测："点击图标色带不会展开，必须点色带位置，触摸屏上太麻烦" |
| 3 | 色带常开（设置开关） | 一直张开 | 2026-10-05 用户点名（给触摸屏的选项） |
| 4 | 拖粗细滑条 | 一直张开 | 防"拖到一半收掉" |

### 3. 收起（3 条）

| # | 触发 | 行为 |
|---|---|---|
| 1 | 指针**离开判定区** | 等 **800ms** → 收起（慢隐；2026-10-09 用户定"不要一点就收"） |
| 2 | 进穿透 | **立即收回色线，穿透期间永不张开**（"折叠起来，不是没有"；2026-10-02 用户口径） |
| 3 | 正在收时指针回来 | **立刻反向张开**（不重来一遍延迟；2026-10-09） |

### 4. 写字保护（2026-10-09 三条硬规则，用户原话："只要收起来，它就一定是色带……只有退出来以后才能变成卡片"）

| # | 时机 | 行为 |
|---|---|---|
| ① | **落笔那一刻** | 没收干净（含"张到一半"）→ **收回色线**；已完全张开 → 保持 |
| ② | 整笔期间 | **冻结**（不张不收） |
| ③ | 抬手之后 | 进"**余温**"：距抬手 **600ms** 内 + **必须让指针离开判定区一次**（用位置时间戳判"真的离开过"，不拿落笔期间的旧悬停值），才允许重新张开 |

### 5. 其它既有语义

- 收起时**不吃点击**（指针一靠近它就张开——所以以前"点色线"没有独立含义）。
- 点**已选中**的笔/荧光笔格 = 直接换下一个颜色（手不离格；2026-09-27）。
- 触摸按下后的 2.5s 内，色带的张开状态**优先于**写字余温/离开规则（触摸没有悬停，必须给一条明路）。
- 点工具格时 `_railEnterAtMs` 被重置（意图是"跳过开门等待"，实际是反的，见发现 2）。

## 二、业界通用规则（公开资料与常见实现归纳）

### 1. 悬停意图（hover intent）——自动弹出的第一原则

- **Baymard / NN/g 的口径：悬停 300–500ms 才算"有意图"**，短于它一律视为"路过"，防止菜单/浮层乱闪。
  （vocab.design"hover intent"词条引 Baymard；NN/g timing 指南 0.3–0.5s。）
- **打开要有延迟、关闭通常更短**；两者要分开调（CSS-Tricks / NN/g）。
- **"同一区域连续操作可以即时"**：第一次悬停等延迟，之后短时间内再进来立即显示——"你已经处在探索模式"。
  （CSS-Tricks 的经典 hover-delay 模式。）
- 打开之后要**宽容指针路径**（安全三角/方向判定，Amazon 式），别让指针去目标的路上碰到别人就换。
- 触摸没有悬停 → 一律"点开"，不适用延迟。

### 2. 自动隐藏控件的两条路（Windows 任务栏 / 媒体播放器 / VS 面板）

- 边角悬停 → **立即出**（边角本身是明确的"我要用它"信号，不再加延迟）；无动作 2–3s 收。
- 内容优先的播放器/绘图软件：**一切以不挡笔尖/画面为准**，工具栏多为固定或可拖，很少自动弹。

### 3. 白板 / 批注软件的"工具设置"交互（清一色"点开"）

| 软件 | 工具设置怎么出来 |
|---|---|
| **Microsoft Whiteboard** | 点笔选中；**再点一次笔** → 弹出颜色/粗细选择 |
| **Goodnotes（教育版）** | 点工具 → 出**浮动副工具条或弹窗**；点空白/再点收 |
| **myViewBoard（ViewSonic，教室大屏常见）** | 底部主工具条 + 浮动工具条；都是**点按**，工具条可整体拖走 |
| **希沃白板 5 授课模式** | 工具栏浮动在屏上，保留笔/橡皮/选择/翻页等；选项**点开** |
| **Zoom / 各批注条** | 固定工具条；"格式"点开改颜色线宽；点别处收 |
| **看板类在线白板** | 点（或双击）笔图标 → 弹"画笔设置"窗；"点空白收" |

**归纳**：教学/批注软件里，"设置"几乎全部是**点开**；悬停展开只出现在桌面专业软件的自动隐藏面板里
（Photoshop/VS 那种"要腾画面空间"的场景），而且都遵守 hover-intent 的 300ms 级延迟。

### 4. 把业界规则折成 5 条，用来体检我们

1. 明确动作（点/按）→ **立即响应**，不给延迟；
2. 模糊动作（悬停路过）→ **延迟 + 停留判定**；
3. 触摸没有悬停 → 必须"点开"；
4. 弹出物**别挡笔尖/画面**，或不写时自己走；
5. 开了以后"路径要宽容"，别刚出去就收（我们的反向张开 + 800ms 慢隐就是这条）。

## 三、课堂使用习惯 → 设计约束

### 教师行为模型的 5 条

1. **连续书写，笔不离板**：写一行、写一段是十几秒的连续动作，中间"停顿"比"移动"多；
   → 悬停信号里**夹杂大量写字伴生的移动**，必须防误触（我们的硬规则正是干这个的）。
2. **换色/换粗细发生在"句子之间"的 1–3 秒窗口**：目标是**不打断讲解节奏**；
   → 要快（延迟可感知就烦）、要准（一次点中）、要可预期（点一下就出来，不用记"要不要等"）。
3. **注意力在学生，不在 UI**：操作应当**盲操可成**；
   → 越少"看提示才知道"的隐藏状态越好（比如"必须离开过一次"这种规则老师永远不会知道，但会被它挡）。
4. **三种输入都要顺**：大屏触摸、手写板悬停/落笔、鼠标；
   → 同一条规则不能只在一种设备上成立（触摸已经有"按下即开"，鼠标反而缺）。
5. **误触代价高**：突然弹出的设置条会**遮住正在写的区域**、打断全班视线；
   → "自己不冒出来"比"出来得快"更重要；但**老师主动点的**应当立即执行。

### 推论

> **"慢悬停 + 快点按" 双通道**：
> 模糊的靠近 = 慢一步（240ms 悬停 + 写字余温）——保沉稳；
> 明确的点击/按 = 立即响应——保效率，且因为"是老师自己点的"，不破坏沉稳观感。

现在的实现是"单通道"（悬停慢、点击也慢），所以老师会觉得**防守很稳、进攻偏钝**。

## 四、逐条体检

| 现行规则 | 体检 | 结论 |
|---|---|---|
| 悬停 240ms 开 | 业界 300–500ms 的低端；偏灵敏但可接受 | 保留（有快路后更不该动） |
| 判定区=主条∪色带 | 对：鼠标从工具格走到色片的必经之路（2026-09-17 的初衷） | 保留 |
| 触摸/笔按下即开+2.5s | 与业界一致，触摸用户的唯一明路 | 保留 |
| 鼠标**没有**"点开"路 | **缺口 1**：鼠标老师最常用的动作反而最慢 | **建议补（方案 A①）** |
| 点工具格把开门倒计时**重置** | **缺口 2**：注释写"不用再等"，实现却让等待重新计（快速点格比不点更晚开） | **建议修（方案 A②）** |
| 写字落笔收线 + 整笔冻结 | 独有、正确、已真机验收 | 保留 |
| 余温 600ms + 离开一次 | 正确，但"离开一次"是老师**看不见的规则**；点开快路补上后，这条只挡悬停路，代价可接受 | 保留（可选调 600→400） |
| 慢隐 800ms + 反向张开 | 沉稳偏好，用户已认 | 保留 |
| 收起不吃点击 | 以前合理（唯一交互是悬停）；补上"点开"后，这条变成"点击有含义" | 随方案 A 调整 |
| 穿透永不开、常开、拖滑条常开 | 各有明确出处 | 保留 |

## 五、优化建议

### A. 推荐做（最小包，改动小、自检可钉）

1. **点色带区（收起的色线，含 10px 余量）= 立即张开**（跳过悬停延迟、写字余温、离开一次——明确动作优先）。
   - 穿透里不生效（跟随"永不张开"口径）；笔/触摸本来就已即时，这条主要服务鼠标，顺便统一三种输入。
   - 实现要点：`PointerDown` 在"上带空白不吃"之前加一条命中；`_rail.To(1f, RailMs)` + 清两条守卫。
2. **点工具格 = 该格设置条立即张开**：修掉 `Activate()` 里 `_railEnterAtMs = -∞` 的反向重置；
   点的是哪个工具，那格设置条直接 `To(1f)`（穿透口径不变）。
   - 顺带效果：鼠标"点笔 → 立即见色片"，与 Whiteboard/Goodnotes 的"点开"习惯对齐。

### B. 可选（建议随 A 一起真机复测，先不动））

3. **写字余温 600 → 400ms**：只影响悬停路的等待时长；"离开一次"不受影响。收益：写完即转身换色少等 200ms。
   风险：写字间歇"停 400ms 又把笔放回条上"会开——但那种情况本来就该开（老师就是去换色的）。
4. **"探索模式"即时化**：最近 1.5s 内碰过面板，再次进入判定区**立即张开**（业界惯例：第二次悬停不用等）。
   风险：需要真机确认"不会显得一惊一乍"；如果 B3 已够，这条可以不做。

### C. 不做（理由）

- **改成"点工具弹浮层、点空白收"**：是业界主流形态，但我们会**丢掉**：常驻可见的当前色线（老师余光可见）、
  "手不离格换色"、以及一整轮已验收的手感与自检；收益（少一个自动开合规则）不值这个价。
- **安全三角/方向判定**：那是"窄菜单条上排着多个触发器"才需要的；我们的目标是屏幕底边一整条面板，
  没有"路过邻座触发器"的问题。
- **关得比 800ms 更快**：与"沉稳"及用户已验收的"不要一点就收"相反。

## 六、验证计划（A 落地后）

- 自检（`--paneltest` 加锁）：
  ① 收起的色线点一下 → 下一帧 `RailValueForTest > 0.9`；
  ② 写字余温期间（刚抬手 <600ms）点色线 → 仍立即张开；
  ③ 点工具格（快速点，不进悬停等待）→ 该格设置条立即张开；
  ④ 穿透里点色线 → **不**张开（维持色线）。
- 真机复测（用户）：写完立刻点色线换色；快速连点两个工具格看设置条跟不跟手；
  触摸长按/按格的老习惯不受影响。
