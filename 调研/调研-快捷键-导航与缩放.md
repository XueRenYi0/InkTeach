## 〇、先给结论（TL;DR）

1. **"放大、缩小"我们的白板/画布完全不存在**——相机只有平移（`Overlay.CanvasToWindow`
   是纯 Translation），画布级缩放一直排在触摸手势那边的 **P2**
   （`调研-触摸手势-学校大屏.md`："P2：画布缩放（捏合）"）。
   现有"放大缩小"只有两条别的含义：**选中对象的缩放手柄**（已有）和
   **截图取景的放大镜**（没做，P2）。所以这一项不是"改个键"，是**引擎级新功能**。
2. **方向键现在的语义是断的**：白板里"有选中 = 微调；没选中 = ↑↓滚画布、←→什么都不做"。
   ←→ 空转这一条值得补成"上一屏/下一屏"（和放映模式的 ←→ 语法统一）。
3. **按住方向键微调 = 每一下一条撤销记录**（代码里自己标了"已知待改"）。
   这是"常用功能"里体验最差的一处，修法不用改键，但要做"连续微调合并成一步"。
4. **鼠标滚轮**：一格 72 逻辑像素、只纵向、**没有 Ctrl / Shift 分支**。
   另外发现一处**文档与实现不一致**：计划里写"画布收起时滚轮还给底层（PPT 翻页），
   我们已经是这样了"——代码不是这样（只有穿透才还给下层），放映时滚轮多半是
   "被我们吃掉但滚不动"的状态。需要真机确认 + 拍板。
5. 三个包：
   - **A 导航三件套（小，1~2 天）**：←→ 补翻屏；微调合并撤销；放映时滚轮 = 代翻页。
   - **B 画布缩放（大，引擎级）**：Ctrl+滚轮 / Ctrl+=、-、0 / 双指捏合；放映批注必须禁用。
   - **C 可选小件**：白板开关 `Ctrl+B`、`Ctrl+Shift+Z` 重做别名、设置页"键位一览"。
6. **保持不动的**：图形无键（8 种在上带上点选，2026-09-19 定的）、工具子类型不上键
   （2026-10-05 收口）、全局只有 3 条、编辑类永不全局。

## 二、逐项核对（用户点名的五个）

### 2.1 放大、缩小——先确认你说的是哪一个

"放大缩小"在这类软件里有三种完全不同的东西，我们的状态各不相同：

| # | 含义 | 现状 | 工程量 |
|---|---|---|---|
| A | **画布/视图缩放**（把白板内容拉近拉远，写小字/看细节） | **没有**。相机只有平移；`Overlay.CanvasToWindow`（`Overlay.cs:224`）是纯 Translation；触摸调研里画布缩放一直是 **P2** | **大**（引擎级，见 §四） |
| B | **屏幕放大镜**（讲课时把屏幕某一块放大给全班看，ZoomIt 那种） | **没有**。截图流程里那个"放大镜"（`调研-截图模式-优化.md` P2）是取景对像素用的，不是这个 | 中～大，独立功能 |
| C | **选中对象缩放**（把一段板书/一张图拉大） | **有**：八个缩放手柄（四角等比）+ 触摸双指 + `Shift` 约束 | 已完成，不需要键盘 |

**判断**：你列在"上下左右 / 上一页下一页 / 鼠标滚轮"这一串里，多半指的是 **A
（画布缩放）**——它确实是我们现在唯一缺的那块"导航能力"。本文 §四 按 A 来做方案；
C 不需要做；B 建议单独立项、不与 A 混在一起（它会抢全局键、还要抓屏，是另一条技术路）。

### 2.2 上下、左右

三个具体问题：

1. **白板里 ←→ 是空转的。** 没选中时按 `←`/`→` 什么都不发生（`Nudge` 对空选区
   直接 `return false`），而 `↑`/`↓` 却能滚画布。同一个键位组，两个方向做事、
   两个方向不动，这不像"设计"，像"没人补过"。
2. **按住方向键 = 撤销栈爆炸。** `Nudge` 每触发一次就走一次 `ApplyTransform → Commit`
   （`Model.cs:6796-6803`），Windows 的按键自动重复会连发 → **按住半秒可能进十几条
   撤销记录**。代码注释里自己写着："已知待改：按住方向键会重复触发，每次都是一条
   撤销记录；要接'连续微调合并成一步'，得等编辑命令支持合并"（`Engine.cs:8397-8399`）。
   对老师来说就是"移歪了想撤销，结果要按十七次 Ctrl+Z"。
3. **步长**：方向键一格 = 屏幕高 1/10（粗调），滚轮一格 = 72 逻辑像素（细调），
   两者本来就不该一样，这个分布是合理的，**不建议动**。

**建议**：
- `←→` 在"没选中"时补上 **上一屏 / 下一屏**——这样四个方向键的语法在
  白板和放映里就完全统一了：**有选中 = 微调；没选中 = ↑↓ 滚动、←→ 翻屏**
  （放映里 `←→` 本来就是翻页，白板补上正好对齐）。
- **微调合并撤销**：连续微调（按住 / 快速连按）合成一步，松开或停顿约 400ms 封口。
  不改任何键位，只改"撤销粒度"。

### 2.3 上一页、下一页

现状已经**三套入口**：白板 `PageUp/PageDown` + 面板 `[‹][›]` + 触摸双指横滑；
放映里 `←→` 代翻页（临时全局），`PageUp/PageDown` 原生给 PPT/WPS（PPT 自己就认它们）。
穿透时全部让给下层。**骨架是齐的**，只有两处可以补：

1. 白板 `←→`（同 §2.2）。
2. **文档口径**：现在《快捷键总表》只写了"放映翻页用 `←→`"，没写
   "PgUp/PgDn 在放映里原生给 PPT、照常能翻"——补一句，免得下次有人以为它们失效了。

**不建议**：把 `PageUp/PageDown` 注册成全局（会把 PPT / PDF / 浏览器 / 资源管理器的
翻页全抢走——这条 2026-09-16 就定过，理由在《快捷键总表》§2 末尾）。

### 2.4 鼠标滚轮

现状：一格 72 逻辑像素、细粒度、只纵向、没有修饰键分支；滚动条可拖（16px 命中）、
静止 3 秒淡出；触摸双指纵滑走同一个函数（系数 2×）。

发现两个要处理的点：

1. **`Ctrl+滚轮` 空着**。等画布缩放做出来（§四），这是全行业最标准的缩放操作
   （OneNote / 浏览器 / 设计工具都是它）。现在按下去和普通滚轮一样，只是白白浪费。
2. **放映时滚轮的归属，文档和代码对不上。**
   《计划-底层性能与功能》13.2 与《计划-白板与PPT-页逻辑》写的是
   "画布收起时，滚轮**穿透给底层应用**（PPT 翻页），**我们已经是这样了**"。
   但代码里滚轮**只**在穿透（`WS_EX_TRANSPARENT`）时才还给下层；
   非穿透放映时滚轮进的是我们的 `HandleWheel`（`Engine.cs:2768` 无条件），
   滚我们的画布——而放映时画布范围通常被夹死，所以实际表现多半是
   **"滚轮没反应"**，老师想用滚轮翻页会失败。
   ⚠ 补充一个变量：Windows 的"悬停滚动非活动窗口"设置（默认开）决定滚轮是投给
   鼠标下那个窗口还是焦点窗口。真机上要先确认一下现在的实际表现，再定怎么改。

   **建议**：放映且非穿透时，滚轮 **代 PPT 翻页**（下 = 下一页，上 = 上一页），
   走和 `←→` 完全同一条命令（`PostPptCommand`）；白板照旧细滚；穿透照旧让给下层。
   这样三种状态下滚轮的归属一句话说得清：**能画 → 滚自己；在放映 → 翻 PPT；穿透 → 全给下层。**

### 2.5 常用功能

对照表见 §1.3。键盘侧真正缺的只有**白板开关**；另外做两个"顺手的补充"和
一个"要不要扩呼出盘"的问题：

1. **白板开关 `Ctrl+B`（批注内）**——面板第 3 格的白板，键盘上竟然没有入口；
   老师从"透明批注"换到"白板"要拿鼠标去点。候选：`Ctrl+B`（B = Board，批注内空着）。
   放映中不加进临时表（PPT/WPS 的键不动），保持现状。**推荐做**。
2. **`Ctrl+Shift+Z` = 重做别名**——很多软件的习惯键；批注内空着，零风险。
   **可选**（`Ctrl+Y` 已经够，多一条要同步文档和自检）。
3. **呼出盘要不要装"常用功能"**（撤销 / 翻页 / 清空 / 截屏）？现在 8 个扇区 =
   5 工具 + 3 常用色，是 2026-09-30 定的"一只盘子记住"。扩的代价是第二层菜单
   （比如"划过一扇区后再停顿 = 二级盘"），会破坏"一划就走"的速度优势。
   **我的建议：先不扩**；等 A/B 包落地、真机用一段时间后，如果发现键盘用户
   很少按 `Ctrl+Z`（更常去点面板），再考虑把"撤销"塞进盘里。

## 三、包 A：导航三件套（小改，推荐先做）

| # | 内容 | 改动点 | 成本 | 风险 |
|---|---|---|---|---|
| A1 | 白板 `←→`（无选中）= 上一屏 / 下一屏 | `RunAction` 的 `NudgeLeft/Right` 分支加 else 走 `FlipPageFromUi`；`--pagetest` 补两条 | 半天 | 误翻页——可接受（翻页只动相机、到顶/底就不动、无破坏性） |

## 四、包 B：画布缩放（大件，先拍板再动）

### 4.1 它要解决什么

- 大屏上**写小字**（放大画布，落笔更精细）；
- 一屏**放更多内容** / 讲评时**拉近看细节**；
- 和 PPT 里"视图缩放"的心智一致（但注意：PPT 缩放是 PPT 的，跟我们无关）。

### 4.2 为什么是"引擎级"

相机现在是 **平移 only**（`ViewOffsetX/Y`）。加一个 `Scale` 会牵动一整条链：

| 环节 | 现状 | 缩放后要处理 |
|---|---|---|
| 渲染 | `Overlay.CanvasToWindow` = `Translation(-Origin + ViewOffset)`（`Overlay.cs:224`） | 矩阵加 Scale；分块缓存（`CanvasTiles`）是按物理像素 1:1 光栅化的——缩放后要么按新比例重铺（代价 + 内存），要么位图拉伸（糊） |
| 命中 / 输入 | 窗口↔画布是纯平移（`Overlay.cs:1243` 一带） | 全部换成逆矩阵；落点反馈、预测、光标尺寸跟着走 |
| 滚动范围 | `ClampOffset` 用 `_virtualH - extent.MaxY`（`Engine.cs:6823`） | 视口高要除以 Scale；滚动条几何也要重算 |
| 笔宽语义 | 现在笔宽是物理像素 | 要定：屏幕恒定（手感优先，推荐）还是画布恒定（跟着内容缩放） |
| 其它消费者 | 选中框/手柄/操作条（画布坐标）、截图落图、导出、触摸手势 | 逐一对表；**放映批注必须禁用缩放**（批注要和幻灯片像素对齐，一缩放就串位） |
| 内存红线 | 4GB 教室机 | 分块缓存不能因缩放常驻两份；建议"只保留当前 scale 的缓存，切回 100% 重铺" |

这也是它一直是 **P2** 的原因：不是难在"乘法"，难在缓存 / 命中 / 内存这几条线。

### 4.3 键位与手势语法（先定，实现再排）

| 入口 | 方案 | 说明 |
|---|---|---|
| 鼠标 | **`Ctrl+滚轮` = 以光标为中心缩放** | 行业标准；锚点必须是指针，不然"想放大的地方跑掉了" |
| 键盘 | **`Ctrl+=` 放大 / `Ctrl+-` 缩小 / `Ctrl+0` 回 100%** | 批注内作用域；不占全局 |
| 触摸 | **双指捏合（未选中时）= 画布缩放** | 触摸调研既定 P2；选中时双指仍 = 缩放选中对象（不动） |
| 范围 | 建议 25% ~ 400%，步进 ~1.1× | 复位键必须有（`Ctrl+0`），否则容易"迷航" |
| 边界 | 放映批注 / 穿透下不生效 | 穿透本来就收不到键；放映禁用是硬约束（像素对齐） |

### 4.4 分两刀切

- **B1（先）**：引擎相机 Scale + `Ctrl+滚轮` + `Ctrl+0`。先让这一个入口能用、能复位，
  自检把"缩放后命中还准、笔迹不错位、翻页/滚动仍正常"钉住。
- **B2（后）**：`Ctrl+=` / `Ctrl+-`、双指捏合、滚动条几何细化。

> 备选：如果你要的其实是 **B 含义（屏幕放大镜）**，那是另一条路（全屏抓屏 + 放大渲染，
> 还要一个全局键进门），工程量和风险都不小，**建议单独立项**，不要和画布缩放混做。

## 六、改键的既有规矩（动手时必须遵守）

1. 《快捷键总表.md》是**唯一权威**：改了键必须同一次改动改它（键 + 动作名同一行），
   否则 `--keytest` 会红（`App.cs:5313` 的 `CheckHotkeyDoc`）。
2. 全局白名单（`KeyMap.GlobalAllowed`）不是不能动，但加一条全局必须有"无焦点也必须能用"
   的硬理由；现在 3 条（穿透 / 呼出盘 / 退出）。
3. 放映临时表只放"放映时真必须"的键，**PPT 官方键不动**（例如 `Ctrl+M` 是 PPT 的
   "显示/隐藏墨迹"，2026-09-30 调研明确不抢）。
4. 自检要跟着长：`--keytest`（文档核对）、`--hotkeytest`（真实键盘 + 焦点）、
   `--ppttest`（放映键）、`--pagetest`（翻页）——各包按需补。
5. 手测台/摆样可以复用：`--radialshow`、`--panelshow`。
