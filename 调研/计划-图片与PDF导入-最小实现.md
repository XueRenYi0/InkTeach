# 计划：图片 / PDF 导入批注 —— 最小实现（v1）

> 2026-10-07。**依据**：
> `调研-文件导入与PDF批注.md`（2026-10-03 定稿：范围收窄到图片+PDF、P1/P2 分期、内存账、
> 入口结论、验收口径都在里面）+ 用户 2026-10-07 的新要求（一图一页、长图要特别处理、
> PDF 宽度对齐屏幕、注意性能、先跑最小实现）+ 本次对现存代码的接线勘探（结论带 file:line）。
>
> **一句话**：不缺架构 —— 缺的是"**文件 → 一叠页底图**"这条输入口。
> 页图做成**独立的"文档页底层"**（不进笔迹列表），PDF 用 **PDFium 直连 P/Invoke**，
> 图片用 **GDI+ 解码**，页位图**惰性生成 + 窗口化驻留**（跟分块缓存同一个手法）。

---

## 0. 两个裁决

### 0.1 渲染器：选 **PDFium**（自己写最小 P/Invoke，不用 PDFiumSharp）

| | Windows.Data.Pdf（系统自带） | **PDFium（本次选它）** |
|---|---|---|
| 部署 | 零依赖 | + `pdfium.dll` **7.15 MB**（zip 里 ≈ 3.7 MB） |
| AOT / 单文件 | WinRT 投影要升 TFM 到 `net10.0-windows10.0.19041`；投影层在 NativeAOT 下没把握，要花时间试错 | **纯 DllImport**，AOT 天然友好（和 Wintab 那套一个道理） |
| 渲染粒度 | 只有整页（API 限制） | 整页 ＋ **子矩形（屏切片/瓦片）** —— 把内存窗口做小的唯一前提 |
| 缓冲 | 渲染到流，多一次拷贝 | 直接渲进我们自己的 BGRA 缓冲，`ImageData.Adopt` 零拷贝 |
| 许可 | 系统组件 | PDFium **BSD-3** ＋ freetype/harfbuzz/icu 等（全宽松）；署名进 `THIRD-PARTY-NOTICES.md` |

**裁决理由**：10-03 文档 8.4 的内存账（2× 屏上：整页口径 47 MB/页 vs 切片口径 20~42 MB）
把"性能差不多就用系统"里的**"内存也差不多"**否掉了；系统那条的 WinRT＋AOT 风险还要花时间试错。
**多带 3.7 MB** 换"确定能跑 ＋ 有切片控制力"，划算。
（**替换口保留**：渲染在 `Doc/` 里是个小接口，将来想换只改一处。）

### 0.2 长图：**切片成多页**（"一页一张"撑不住时的正解）

图片专用规则（PDF 页**不切** —— PDF 页是语义页，靠连续滚看）：

- 页宽 = 屏幕物理宽（**fit width**；最多放大 2×，不无限放大糊掉）；
- 页高 ≤ 2 屏 → **一页**（滚动看）；
- 页高 > 2 屏 → 按 **1 屏高**切片，每片一页，片间同样留页缝；
- 例（本机 2520×1680）：1080×32000 的长截图 → 宽不放大（1080）→ 32 屏高 → 切 32 片，
  每片原样清晰；**而不是**压成"一根针"。

## 1. 内存账（本机：2520×1680 物理、DPI 2.0）

| 项 | 数字 |
|---|---|
| 一屏（2520×1680×4） | **16.9 MB** |
| A4 整页 fit width（2520×3564） | **35.9 MB/页** |
| PDF 驻留窗口（当前 ±1 页，最坏 3 页） | ≈ **108 MB**（要更省 → 切"屏切片渲染"，见 §6 兜底） |
| 图片切片（1 屏/片）驻留（≤3 片） | ≈ **51 MB** |
| 解码源缓存（≤12MP 才留，只 1 份） | ≤ **48 MB**（离开视口就放） |
| pdfium.dll | 磁盘 7.15 MB；**第一次真开 PDF 才加载**（不调用 = 零开销） |

## 2. 架构落点（页图另起一层，**不碰笔迹**）

**关键决定**：页图**不做成 Image 笔迹**。10-03 调研已指出三个坑（`.inkb` 会把原图裸写进存档、
回放/导出带上它、撤销栈持有整页位图）。做成**独立层**后：存档 / 导出 / 回放 / 选中 / 橡皮
**零影响**，`Doc.Strokes` 语义不变。

| 新东西 | 落点 |
|---|---|
| 页模型 / 布局 / 切片 / 窗口 / 回收 | 新文件 `src/InkEngine/Doc/DocPages.cs` |
| 图片解码（GDI+） | 新文件 `src/InkEngine/Doc/DocImageSource.cs`（EXIF 方向、白底合成、降采样） |
| PDF（P/Invoke ＋ 文档包装） | 新文件 `src/InkEngine/Doc/Pdfium.cs` |
| 文件对话框（多选） | `Export.cs` 加 `AskForOpenDocuments`（抄 `AskForInkOpen`，加 `OFN_ALLOWMULTISELECT`） |
| 自检 | 新文件 `src/InkTeach/SelfTests/Documents.cs`（`--doctest`） |
| 取 dll 工具 | `tools/fetch-pdfium.ps1` → `vendor/pdfium-win-x64/`（gitignore，不进 git） |
| 署名 | `src/InkEngine/THIRD-PARTY-NOTICES.md` 加 PDFium 一节 |

**宿主接口（改现有文件，行号是当前的）**：

- `Overlay.RasterizeTile`（`Overlay.cs:1185`）：在底色之后、底纹/笔迹之前插"画页"
  → 页图由此**进分块缓存**，滚动仍只是贴块；
- `Overlay.SyncTiles`（`Overlay.cs:1086`）：① 可见页缺就生成；② 页层版本变化 →
  `MarkDirty(页矩形)`（**生成完成 / 释放 / 换文档 / 关闭**，四处都要）；
- `Overlay.RenderFrame` 的 `NoContentCache` 分支（`Overlay.cs:2208`）：也要画页（调试路径）；
- `Engine.CanvasExtent`（`Engine.cs:1124`）：并入页层范围，否则相机会被夹住、滚不到最后一页；
- `Engine.FlipPage`（`Engine.cs:7820`）：文档模式下改成"跳到上/下一页**页顶**"；
- 空闲预取：`Overlay.PrefetchStep`（`Overlay.cs:1162`）顺手把"环里的页"生成掉（滚之前就绪）；
- UI：`FullUi.HubTileInfo`（`FullUi.cs:2628` 一带）加两格「打开文档… / 关闭文档」
  → `IEngineCommands`（`Ui.cs`）→ `UiHost.cs` → 引擎；状态行 `InkStatus` 报"文档：xxx.pdf（12 页）"。

## 3. 显示规则（能看见的）

- **fit width**：PDF 页宽 = 屏幕物理宽（2520）；图片页宽 = min(屏宽/图宽, 2×)；
- 页与页**纵向挨着铺**：缝 = 24 逻辑像素 ＋ 一条很淡的边线（白板页界线同款语言）；
- 每页**白底**（图片先合成到白底；PDF 先铺白再渲）—— 覆盖层上不能透出桌面；
- 未生成的页：浅灰占位 ＋ "第 N 页 渲染中…"；
- **连续滚**（滚轮细滚）＋ `PageUp/PageDown` 跳上/下一页页顶（167ms 同款动画）；
- 批注、橡皮、选中、复制、撤销、清空、激光、图形……**全部照旧**（零改动）；
- v1 已知边界：清空/撤销是**整份文档**一条栈（不是按页）；「保存图片」导的是**墨迹层**（不含页底）。

## 4. 生成与回收（性能核心）

- **惰性生成**：打开文档只读"页数 ＋ 页尺寸"（PDF 只读文档头；图片只读尺寸头），
  页位图**进入视口环才做**：
  - 可见页（`SyncTiles` 里）：缺就同步生成（PDF 单页 ~5–80ms；图片解码慢些）；
  - 环里的页（`PrefetchStep` 空闲拍）：提前生成，滚动通常追不上；
- **驻留窗口**：视口 ±1 屏内的页留着，其余 `Release()`（GPU＋CPU 一起放）
  → **内存不随页数涨**（口径见 10-03 文档 7.4 三条）；
- **图片源缓存**：≤12MP 的解码结果留 1 份（给切片生成/回访复用），离开或换图就放；
- **不调用 = 零开销**：pdfium.dll 第一次真开 PDF 才加载；不开文档时线程/内存/句柄与现在一模一样。

这是选 PDFium 的主要原因，留到真需要时再上。

## 7. 风险与坑（实现时逐条核对）

1. **页图不进笔迹**（否则存档膨胀、回放/导出/撤销污染）—— 代码里加断言防回归；
2. **失效漏一处就残影**：生成完成 / 释放 / 换文档 / 关闭，四处都要 `MarkDirty(页矩形)`；
   自检覆盖"滚走滚回"；
3. **`CanvasExtent` 不含页** → 滚不到底 / 相机被夹（S3 处理）；
4. **GDI+ 大图瞬时内存**：解码是"整张全解"，超长图有几十 MB 瞬时峰值——只在生成那一下；
   更省要换 WIC（不进 v1）；超过 32MP 的图先降采样再进缓存；
5. **EXIF 方向**：手机照片读 `0x0112` 转正，否则横竖颠倒；
6. **PDFium 线程安全**：所有调用一把锁 ＋ 只在渲染线程调（我们本来单线程渲染）；
7. **加密 / 损坏 PDF**：`FPDF_LoadDocument` 返回 NULL → 一句提示，**不改变当前状态**
   （规矩三：失败当没有）；
8. **`--nocache` 调试路径**：也要画页（容易漏，写进自检）；
9. **AOT**：P/Invoke、GDI+ 都没问题（GDI+ 已在导出里用着）；dll 不进 exe、随包走；
10. **`Doc.Clear()` 清的是当前槽** —— 文档墨迹就是这一个槽（v1 语义：清空 = 清文档墨迹，
    可 Ctrl+Z 撤销）。

## 8. 用户实测验收（最小版）

1. 打开 3 张图片 → 一图一页、宽度贴合屏、页缝清晰、能写能擦；
2. 打开一张**超长截图**（>2 屏）→ 自动切片、翻页连读、不糊；
3. 打开一份 A4 试卷 PDF（≥5 页）→ 宽度 = 屏宽、连续滚顺滑、`PageUp/Down` 按页跳；
4. 快速滚 20 页再滚回来 → 页会重新出现（短暂占位）、**内存不随页数涨**（`--memory` 对照）；
5. 关闭文档 → 回收正常；重开 → 页面回来。

## 10. 实施记录（as-built，2026-10-07 当天完成 S1~S8）

**与计划不同的几处**（都是被真机数据 / 同行经验改的，逐条有据）：

| 计划里写的 | 实际做法 | 为什么改 |
|---|---|---|
| 页位图生成"同步在渲染帧里"（v1 简化） | **后台渲染线程**（`DocPages` worker） | 真机实测：122MB/663 页那份 PDF 一页 270~900ms；同步 = "滚到那页卡半秒"。10-03 文档 7.5 本来就定的后台线程 |
| `FPDF_InitLibrary()` | **`FPDF_InitLibraryWithConfig(version=2)`** | 官方 getting-started 的姿势；旧入口只是兼容壳、将来废弃 |
| 图片直接 `new Bitmap(路径)` | **FileShare 复制进 MemoryStream、与 Bitmap 同生共死** | MSDN：`new Bitmap(路径)` 锁文件（老师改不了删不了）；`Image.FromStream` 又要求流陪到最后（GDI+ 延迟解码）——两个坑一起堵 |
| 翻页 = 跳到下一页页顶 | 同左，另加：**往上翻先回本页页顶**（已在页顶才去上页） | 长页（A4 一页 >1 屏）上翻更顺手 |
| S7 才"性能兜底（屏切片渲染）" | **暂不启用**：整页 + 后台线程实测够用 | 留作接口（`DocPages.Generator` 换实现即可，不动渲染接线） |

**踩过并修掉的坑**（都进过自检 / 编译，不靠记性）：

1. `FPDF_GetPageSizeByIndexF` 第三个参数是 **`FS_SIZEF*` 结构体指针**（头文件为准）。
   写成两个 `out float` → 原生往栈上写 8 字节 → **访问违例闪退**（自检当场抓住）；
2. P/Invoke 传中文路径要按 **UTF-8 字节**（`CharSet.Ansi` 会按 GBK 编，中文路径打不开）；
3. 页生成 / 回收**既要标分块脏、也要进上屏脏区**（双缓冲记两帧）——漏一边就是残影或不刷新；
4. `ImageData.LiveBytes/LiveImages` 仓库里**只加不减**（以前没人用过）；
   做"关闭回基线"判据时暴露 → 改 `_accounted` 配平 + `Interlocked`（worker 会并发进账）；
5. 空闲时引擎不给帧 → worker 渲完必须 **PostThreadMessage 叫醒主循环**（照 PptWatcher 先例）；
6. 关文档要**等在途渲染收手**再释放 PDFium 文档（否则原生代码踩已释放的文档）。

**真机数字（本机 2520×1680 / DPI 2.0）**：

| 场景 | 数字 |
|---|---|
| 文字型 PDF（0.9MB） | 11~22 ms/页 |
| 大图 / 扫描型 PDF（122MB、663 页） | 首页 891ms、次页 270ms（**都在后台**；主线程一拍 0.2ms） |
| 打开 → 首页上屏（含启动） | **1.5 秒**（零输入；"渲完叫醒"这条链是通的） |
| A4 页位图（fit width，含页缝） | 2520×3564 ≈ 35.9 MB/页；只留视口 ±1 屏（≤3 页），关文档回基线 |
| pdfium.dll | 7.15 MB（zip 里约 +3.7MB，随包带许可文本） |

**验证**：`--doctest` **78 项全绿**（页底层 37 / 图片 23 / PDF 18 / 后台线程 4）＋ `--pdfprobe` 探针；
回归 `cameratest / pagetest / ghosttest / tiletest` 全绿；`--doc` 真机截图确认"宽度铺满、文字清晰"。
