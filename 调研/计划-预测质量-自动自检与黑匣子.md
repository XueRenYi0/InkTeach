# 计划：预测尾质量 —— 自动自检与"黑匣子"（不让用户慢慢找问题）

日期：2026-10-08　　状态：**方案稿，等拍板（先做哪件/热键选型）**。背景：8.11.1 修了两处已知问题后，
用户真机上仍"有时候还会跳"——**症状说不清、复现靠运气**。本计划把"跳"变成机器可测的量 + 一键取证。

## 〇、一句话

三件套：**①黑匣子（真机一键录→我离线回放，把"那一跳"精确到帧）＋ ②语料自检（把每个已发生的现象变成永久回归用例，自动 PASS/FAIL）＋ ③看门计数（HUD 一眼看有没有、多了没）**。
以后你看到"跳"，只需按一下（或点一下）导出，把文件发我——**不需要描述、不需要复现**。

## 一、资料结论（口径对齐，2026-10-08 查）

| 来源 | 关键结论 | 对我们的用法 |
|---|---|---|
| **1€ 滤波（Casiez, CHI'12）** | 人**慢速时对"抖动"敏感、快速时对"滞后"敏感**；经验门槛：抖动 <1mm 均峰、滞后 <60ms，滤波预算 10~20ms | 把"跳"归为**抖动类缺陷**；指标用**帧间伪位移/方向翻转**，与"滞后"分开量、分开定红线 |
| **三星/Google 笔迹预测专利（2024~25）** | **"用户对'角度误差'的感知比'距离误差（超前/滞后）'更尖锐"**——所以人家的目标函数优先压角度误差 | 指标必须有**角度项**（转弯处"墨迹方向 vs 真实方向"的差），不能只看距离 |
| **SML 论文（2025）** | 笔迹预测 6/14/20ms 地平线的平均误差 0.47/1.30/2.24px；把"延迟补偿 vs 副作用"拆成两个任务 | 给我们一个"别人能做到多少"的参照；我们 10ms + 阻尼 0.8 要报出同口径数字 |
| 本仓库既有 | `--predictdata`（吃到/超前 p99 的评估框架）、`--tailjumptest`（前沿/回缩）、`--motiontest`（语料滞后表）、`--penlive`（真机端到端） | **全部复用**，只补"跳"这一维与"回放取证" |

## 二、把"跳"翻译成指标（定义表）

> 判据核心：**输入（笔尖采样）没这么跳，而屏幕上的墨尖跳了 = 伪跳**。所有指标都拿"输入的实际运动"当基线。

| # | 指标 | 定义 | 初值/红线（待真机标定） |
|---|---|---|---|
| J1 | **前沿伪跳** | 单帧墨尖位移 − 该帧输入位移（>0 的溢出部分） | p99 ≤ 4px、max ≤ 8px（先量正常笔迹再定） |
| J2 | **回缩事件** | 墨尖倒退 >阈值（输入未反向） | 次数 = 0（tailjumptest 已用此判据） |
| J3 | **方向翻转** | 帧间墨尖方向变化 > θ°（转折期之外） | θ 由语料标定；转弯期用 J4 |
| J4 | **角度误差** | 转弯处"墨迹切线方向 vs 真实运动方向"的夹角 | 与专利同口径；转弯段 p95 红线 |
| J5 | **滞后/超前** | 墨尖 vs 笔尖采样的有符号距离 | 已有实测口径（滞后 1.7px 等） |
| J6 | **尾长振荡** | N 帧内"伸-缩-伸"次数（长度限速层的健康度） | 次数红线待标定 |

**输出格式**：每个用例一行 `用例 | J1..J6 | PASS/FAIL`，FAIL 时附**最差帧的帧号 + 出图**（复用出图链）。

## 三、三件套设计

### 3.1 黑匣子（关键件：不用你说清）
- **环形缓冲（常驻）**：最近 **~30 秒**的原始输入事件（`t(QPC) / x / y / p / 类型`）+ 配置快照（turndeg、pred2ms、刷新率、模型档、版本）。数据量：每秒几百条 × 30s ≈ 几万字节，**常驻无感**。
- **一键导出**：把缓冲写成 `桌面\InkTeach取证-yyyyMMdd-HHmmss.txt`。
  - 入口（两选一，待拍板）：**全局热键**（给有键盘的机器）＋/或 **「更多」面板里的"保存最近 30 秒"按钮**（给学校触摸屏、没有键盘的机器）。
- **离线回放器**：`--replayinput 文件`——用**假时钟**把输入 1:1 喂进真入口（DwellProbe 同款驱动），算出 §二 全部指标 → 打印"第 X 秒那一笔、第 Y 帧、J1=9px"，并出该帧画面。
  - 为什么一定要回放：真机上"说不清/偶发"的东西，回放后**变成确定的帧号和数字**；顺带把文件存进回归语料库。

### 3.2 语料自检（把每个现象变成永久用例）
- 新探针（暂名 `--tailmatrix`）：一组**缺陷导向语料**逐一跑**真实输入通路**（合成笔/合成鼠标 + 推时钟 + ScreenProbe 量像素），按 §二 出表：
  - 直道快写（既有 tailjumptest 保留）；
  - **急转矩阵**：60/75/90/120° × 慢/中/快三档速度（专打"跳"）；
  - 连续 S 弯、锯齿、快速反折（"3"）、闭口方、螺旋；
  - 写字串（"3""7""口""勾"）；
  - **每个已发生的 bug 语料**：从黑匣子导出的真机数据直接进语料库（用户板/学校屏各留几条）。
- 通过标准：§二 红线 + 与"上一版"逐项对比（**防止治一个坏一个**，像全套自检那样）。
- 跑得动：确定性、无人工、秒级~分钟级。

### 3.3 看门计数（可选、轻）
- 引擎挂几个计数器（J1/J2/J3 的同款判据、超阈 +1），HUD 上加一段 `尾:J0 R2 F1`。
- 用途：**一眼看有没有、有没有变多**；用户随手拍照即可（连导出都不用）。
