## 二、把"跳"翻译成指标（定义表）

> 判据核心：**输入（笔尖采样）没这么跳，而屏幕上的墨尖跳了 = 伪跳**。所有指标都拿"输入的实际运动"当基线。

| # | 指标 | 定义 | 初值/红线（待真机标定） |
|---|---|---|---|
| J1 | **前沿伪跳** | 单帧墨尖位移 − 该帧输入位移（>0 的溢出部分） | p99 ≤ 4px、max ≤ 8px（先量正常笔迹再定） |
| J2 | **回缩事件** | 墨尖倒退 >阈值（输入未反向） | 次数 = 0（tailjumptest 已用此判据） |
| J3 | **方向翻转** | 帧间墨尖方向变化 > θ°（转折期之外） | θ 由语料标定；转弯期用 J4 |
| J4 | **角度误差** | 转弯处"墨迹切线方向 vs 真实运动方向"的夹角 | 与专利同口径；转弯段 p95 红线 |
| J5 | **滞后/超前** | 墨尖 vs 笔尖采样的有符号距离 | 已有实测口径（滞后 1.7px 等） |
| J6 | **尾长振荡** | N 帧内"伸-缩-伸"次数（长度限速层的健康度） | 次数红线待标定 |

**输出格式**：每个用例一行 `用例 | J1..J6 | PASS/FAIL`，FAIL 时附**最差帧的帧号 + 出图**（复用出图链）。

## 三、三件套设计

> **✅ 进度（2026-10-08 晚）**：**①黑匣子 v1 与 ②语料自检第一层已实现并验证**（见每节开头的状态行）；
> ③看门计数与"热键/按钮一键导出"留作 v2。

### 3.1 黑匣子（关键件：不用你说清）—— ✅ v1 已实现
- **实现**：`--reclive <文件>` 记录喂进引擎的输入（挂三处真入口：`BeginFreehandStrokeAt` / `AddPointCleaned` 入参 / `EndStroke`；**每笔收笔即落盘**）；`--replayinput <文件>` 按原时间轴 1:1 回放（推时钟、走真入口），算出 **供给率 / 帧间墨尖位移（前 5 大）/ 方向翻转 / 门触发**。
- **验证**：合成"快写→75° 急转"文件回放 ✓ 供给率 97.9%、急转门恰好 1 次、最大帧间位移 35.4px 出现在转弯处（正常步 30px）——量纲全对。
- v2 待做：全局热键/面板按钮"一键导出"（含环形缓冲）、HUD 看门计数。


### 3.1 黑匣子（关键件：不用你说清）
- **环形缓冲（常驻）**：最近 **~30 秒**的原始输入事件（`t(QPC) / x / y / p / 类型`）+ 配置快照（turndeg、pred2ms、刷新率、模型档、版本）。数据量：每秒几百条 × 30s ≈ 几万字节，**常驻无感**。
- **一键导出**：把缓冲写成 `桌面\InkTeach取证-yyyyMMdd-HHmmss.txt`。
  - 入口（两选一，待拍板）：**全局热键**（给有键盘的机器）＋/或 **「更多」面板里的"保存最近 30 秒"按钮**（给学校触摸屏、没有键盘的机器）。
- **离线回放器**：`--replayinput 文件`——用**假时钟**把输入 1:1 喂进真入口（DwellProbe 同款驱动），算出 §二 全部指标 → 打印"第 X 秒那一笔、第 Y 帧、J1=9px"，并出该帧画面。
  - 为什么一定要回放：真机上"说不清/偶发"的东西，回放后**变成确定的帧号和数字**；顺带把文件存进回归语料库。

### 3.2 语料自检（把每个现象变成永久用例）—— ✅ 第一层已实现
- **实现**：`--pdmetrics <语料> [--dt 15] [--limit N] [--sweep]`——离线逐点过**当前预测器**，量
  **供给率 / 吃到率 / 角度误差 / 超前 / 门触发**（口径见 `PdMetrics.cs` 注释）。
  尾渲染层的帧级语料自检（用黑匣子回放机制）留 v2。
- **首张真实数据表（SCUT 中文、20000 字、183 万点、dt=15ms 假设）**：

  | 转度阈值 | 供给率 | 吃到率 | 角度均值 | 急转门/千点 | 反向门/千点 |
  |---|---|---|---|---|---|
  | 180°（老行为） | 85.7% | 15.7% | 37.8° | 0.0 | 131.2 |
  | 90° | 85.5% | 15.7% | 37.8° | 2.1 | 130.9 |
  | 75° | 84.1% | 16.2% | 36.8° | 22.6 | 124.1 |
  | **60°（现默认）** | **82.6%** | **16.8%** | **35.8°** | **44.3** | 117.7 |
  | 50° | 81.5% | 17.2% | 35.1° | 59.5 | 113.2 |

- **结论（数据说话）**：**维持 60° 默认**——比老行为（180°）只少 3.1 个百分点的供给，换来
  吃到 +1.1pp、角度均值 −2.0°；再往 50° 走收益递减（供给再 −1.1pp 只换 +0.4pp）。
  ⚠ 口径：SCUT 是 PDA 稀疏采样（91 点/字）、整数坐标，方向噪声大——"反向门 130/千点"里
  相当部分是采样噪声；真机（密采样+亚像素）的绝对值会更好。**相对比较可信，绝对值保守**。
- 新探针（暂名 `--tailmatrix`）：一组**缺陷导向语料**逐一跑**真实输入通路**（合成笔/合成鼠标 + 推时钟 + ScreenProbe 量像素），按 §二 出表：
  - 直道快写（既有 tailjumptest 保留）；
  - **急转矩阵**：60/75/90/120° × 慢/中/快三档速度（专打"跳"）；
  - 连续 S 弯、锯齿、快速反折（"3"）、闭口方、螺旋；
  - 写字串（"3""7""口""勾"）；
  - **每个已发生的 bug 语料**：从黑匣子导出的真机数据直接进语料库（用户板/学校屏各留几条）。
- 通过标准：§二 红线 + 与"上一版"逐项对比（**防止治一个坏一个**，像全套自检那样）。
- 跑得动：确定性、无人工、秒级~分钟级。

### 3.3 看门计数（可选、轻）

## 九、ML 模型评估（2026-10-08 用户问：Graves LSTM / ochwpro / USST / PEN-Net 能不能用）

**一句话**：这四个都**不是为"实时补帧"设计的**（它们是：整段生成 / 3D 手部预测 / 离线图像恢复），直接搬来做我们的延迟优化——**不行、现在也不值**；但有三处**概念**可吸收。

| 模型 | 它真正解决什么 | 对我们的判定 |
|---|---|---|
| **Graves LSTM（3×400 + 20 高斯混合 MDN）** | **手写生成**：给文本，合成一整段"像人写的"笔迹（离线、生成式、可采样多样性） | ❌ 任务不符：它输出"下一步的**分布**"，我们要"10ms 后的**确定位置**"；单步 3×400 LSTM 在 4G 弱机上吃预算；且要 ML 运行时。**当"理解轨迹预测的经典教材"读** ✓ |
| **ochwpro（d_model192 / 4 头 / 3 层 / 1.72M）** | 面向移动端的手写模型（大概率仍是生成/识别类） | ⚠ **尺寸上唯一可能上车的**（1.7M）——但仍是"别的任务 + 要 ML 运行时 + 训练/导出链"；**留作"哪天真上模型时的尺寸档参考"**（别上 Graves 那种 3×400） |
| **USST（不确定性感知，状态空间 Transformer）** | **3D 手部轨迹**预测（AR/VR/摄像头的 IMU 场景） | ❌ 我们没有 3D/IMU 输入；**"不确定性感知"的思想可借**——与我们"置信度低就不预测、失效快收"的哲学同源 |
| **PEN-Net（双流编码器+全局追踪解码器）** | 从**静态手写图像"恢复"出书写轨迹**（离线） | ❌ 我们没有这个问题（我们拿到的本来就是实时轨迹）；与延迟无关，**可忘** |

**可吸收的三点（概念层）**：
1. **MDN 的启发是"反的"**：人写字的"下一步"本就是多峰分布——我们**故意不采样**，用"阻尼 + 门口 + 宁可不预测"的保守策略，这是对的方向（文献里"对角度误差更敏感"同样支持保守）；
2. **轻量尺寸档**：ochwpro 证明"1.7M 参数级"就能做手写任务——将来若真做模型，照这个量级封顶；
3. **不确定性门**：USST 的"感知不确定性"可以借鉴到我们未来的"预测置信度门"（现在已有雏形：MinSpeed/反向/急转）。

**现实约束（为什么现在不碰）**：
- 硬约束：4G 学校机 / NativeAOT / 零依赖；引 ONNX/TFLite（10~40MB+）+ 训练链，成本与收益倒挂；
- 上轮实测：线性+阻尼已吃掉 ~58% 滞后；**剩余的"跳"是门/边界问题**（我们正在用大数据评测量化），不是"模型不够大"；
- 而且"生成得像不像"和"补帧准不准"是两回事——论文的指标（AIoU、生成质量）都不是我们的指标（帧间伪跳、角度误差、吃到率）。

**如果将来数据证明"简单模型真的差"**，正确路线（按既有调研）：
1. 先抄**设计**（极坐标 r/φ + jerk + 定间隔重采样——AOSP 那套）→ 2. 再考虑**微型改正模型**（预测 2~3 个特征 → 输出一个"修正量"，ochwpro 尺寸或更小）→ 3. 最后才谈大模型；
2. 训练数据我们已经在攒：UCI/SCUT（离线）+ 真机黑匣子（在线）；部署要么 ONNX，要么手写 tiny 推理（1~2M 参数的小 MLP 可接受，但要维护成本）。
