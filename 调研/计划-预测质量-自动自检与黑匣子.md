# 计划：预测尾质量 —— 自动自检与"黑匣子"（不让用户慢慢找问题）

日期：2026-10-08　　状态：**方案稿，等拍板（先做哪件/热键选型）**。背景：8.11.1 修了两处已知问题后，
用户真机上仍"有时候还会跳"——**症状说不清、复现靠运气**。本计划把"跳"变成机器可测的量 + 一键取证。

---

## 〇、一句话

三件套：**①黑匣子（真机一键录→我离线回放，把"那一跳"精确到帧）＋ ②语料自检（把每个已发生的现象变成永久回归用例，自动 PASS/FAIL）＋ ③看门计数（HUD 一眼看有没有、多了没）**。
以后你看到"跳"，只需按一下（或点一下）导出，把文件发我——**不需要描述、不需要复现**。

## 一、资料结论（口径对齐，2026-10-08 查）

| 来源 | 关键结论 | 对我们的用法 |
|---|---|---|
| **1€ 滤波（Casiez, CHI'12）** | 人**慢速时对"抖动"敏感、快速时对"滞后"敏感**；经验门槛：抖动 <1mm 均峰、滞后 <60ms，滤波预算 10~20ms | 把"跳"归为**抖动类缺陷**；指标用**帧间伪位移/方向翻转**，与"滞后"分开量、分开定红线 |
| **三星/Google 笔迹预测专利（2024~25）** | **"用户对'角度误差'的感知比'距离误差（超前/滞后）'更尖锐"**——所以人家的目标函数优先压角度误差 | 指标必须有**角度项**（转弯处"墨迹方向 vs 真实方向"的差），不能只看距离 |
| **SML 论文（2025）** | 笔迹预测 6/14/20ms 地平线的平均误差 0.47/1.30/2.24px；把"延迟补偿 vs 副作用"拆成两个任务 | 给我们一个"别人能做到多少"的参照；我们 10ms + 阻尼 0.8 要报出同口径数字 |
| 本仓库既有 | `--predictdata`（吃到/超前 p99 的评估框架）、`--tailjumptest`（前沿/回缩）、`--motiontest`（语料滞后表）、`--penlive`（真机端到端） | **全部复用**，只补"跳"这一维与"回放取证" |

## 二、把"跳"翻译成指标（定义表）

> 判据核心：**输入（笔尖采样）没这么跳，而屏幕上的墨尖跳了 = 伪跳**。所有指标都拿"输入的实际运动"当基线。

| # | 指标 | 定义 | 初值/红线（待真机标定） |
|---|---|---|---|
| J1 | **前沿伪跳** | 单帧墨尖位移 − 该帧输入位移（>0 的溢出部分） | p99 ≤ 4px、max ≤ 8px（先量正常笔迹再定） |
| J2 | **回缩事件** | 墨尖倒退 >阈值（输入未反向） | 次数 = 0（tailjumptest 已用此判据） |
| J3 | **方向翻转** | 帧间墨尖方向变化 > θ°（转折期之外） | θ 由语料标定；转弯期用 J4 |
| J4 | **角度误差** | 转弯处"墨迹切线方向 vs 真实运动方向"的夹角 | 与专利同口径；转弯段 p95 红线 |
| J5 | **滞后/超前** | 墨尖 vs 笔尖采样的有符号距离 | 已有实测口径（滞后 1.7px 等） |
| J6 | **尾长振荡** | N 帧内"伸-缩-伸"次数（长度限速层的健康度） | 次数红线待标定 |

**输出格式**：每个用例一行 `用例 | J1..J6 | PASS/FAIL`，FAIL 时附**最差帧的帧号 + 出图**（复用出图链）。

## 三、三件套设计

### 3.1 黑匣子（关键件：不用你说清）
- **环形缓冲（常驻）**：最近 **~30 秒**的原始输入事件（`t(QPC) / x / y / p / 类型`）+ 配置快照（turndeg、pred2ms、刷新率、模型档、版本）。数据量：每秒几百条 × 30s ≈ 几万字节，**常驻无感**。
- **一键导出**：把缓冲写成 `桌面\InkTeach取证-yyyyMMdd-HHmmss.txt`。
  - 入口（两选一，待拍板）：**全局热键**（给有键盘的机器）＋/或 **「更多」面板里的"保存最近 30 秒"按钮**（给学校触摸屏、没有键盘的机器）。
- **离线回放器**：`--replayinput 文件`——用**假时钟**把输入 1:1 喂进真入口（DwellProbe 同款驱动），算出 §二 全部指标 → 打印"第 X 秒那一笔、第 Y 帧、J1=9px"，并出该帧画面。
  - 为什么一定要回放：真机上"说不清/偶发"的东西，回放后**变成确定的帧号和数字**；顺带把文件存进回归语料库。

### 3.2 语料自检（把每个现象变成永久用例）
- 新探针（暂名 `--tailmatrix`）：一组**缺陷导向语料**逐一跑**真实输入通路**（合成笔/合成鼠标 + 推时钟 + ScreenProbe 量像素），按 §二 出表：
  - 直道快写（既有 tailjumptest 保留）；
  - **急转矩阵**：60/75/90/120° × 慢/中/快三档速度（专打"跳"）；
  - 连续 S 弯、锯齿、快速反折（"3"）、闭口方、螺旋；
  - 写字串（"3""7""口""勾"）；
  - **每个已发生的 bug 语料**：从黑匣子导出的真机数据直接进语料库（用户板/学校屏各留几条）。
- 通过标准：§二 红线 + 与"上一版"逐项对比（**防止治一个坏一个**，像全套自检那样）。
- 跑得动：确定性、无人工、秒级~分钟级。

### 3.3 看门计数（可选、轻）
- 引擎挂几个计数器（J1/J2/J3 的同款判据、超阈 +1），HUD 上加一段 `尾:J0 R2 F1`。
- 用途：**一眼看有没有、有没有变多**；用户随手拍照即可（连导出都不用）。

## 七、外部资源利用（"拿网上的书写数据 / 别人的参数 / 别人的经验优化自己"）

**答案：可以，而且我们干过一次**（UCI Character Trajectories，48.7 万点扫出阻尼 0.8 / 平滑别开那批参数）。
本轮把"还能借什么"查全，分三路：

### 7.1 公开书写数据集（拿来当"广度语料 + 对标的尺子"）

| 数据集 | 是什么 | 对我们特别有用的点 | 许可 |
|---|---|---|---|
| **UCI Character Trajectories** | 2858 条英文单字轨迹、**200Hz**、含笔尖力 | 已用于扫参；保留作回归 | CC BY 4.0 |
| **CASIA-onDo**（中科院自动化所） | 2012 份在线手写文档（文字/公式/表格/图形），**华为平板**采集，点含 x/y/pressure/笔状态/**时间戳** | **最贴学校场景**（消费平板 + 含时间戳 + 汉字急转多）；200MB 直接下（学术免费、商用收费） | 学术免费（申请表） |
| **CASIA-OLHWDB** | 在线中文字+文本（Intuos2；x/y/**时间戳**/压力/倾角），~5090 页文本 | 汉字快写下的**急转/连笔**检验 | 学术免费（需注册） |
| **IAM-OnDB** | 英文在线手写（白板采集，221 人、1.3 万行在线） | 大样本"书写风格方差"；对标用 | 非商业研究免费（注册） |
| **SCUT-COUCH** | 华南理工中文在线库（多子集，公开下载） | 备用广度语料 | 学术免费 |
| perfect-freehand 演示数据 / tldraw | 合成/社区自由笔迹 | 观感交叉对照（非真笔） | MIT/CC |

**三件用法**：①**参数复查**——我们当年只用拉丁字母扫过参；中文笔画"急转更多更碎"，正好复查 `--turndeg` 60°、阻尼、地平线在中文快写下是否还合适；②数据集带时间戳 ⇒ **直接进 `--tailmatrix` 当永久回归语料**（按原始节奏回放）；③**对标**：用论文同口径（6/14/20ms 平均误差、角度误差）出"我们 vs 别人"的一张表。

### 7.2 别人的参数与实现（拿"值域/公约数"抄设计）

| 来源 | 可借的 |
|---|---|
| **Chromium**（已借） | `linear_predictor` 常数（kTimeInterval 8ms / kMaxTimeDelta 20ms / kMaxPredictionTime 25ms）、one_euro_filter；继续跟版本 |
| **AOSP MotionPredictor** | 极坐标（r/φ）+ JerkTracker + 固定重采样 + 状态机（只支持笔/单点）——**设计照抄，代码不搬** |
| **perfect-freehand / tldraw**（观感参数的行业公约数） | 默认值 `size 8 / thinning 0.5 / smoothing 0.5 / streamline 0.5 / simulatePressure true / 起收笔 taper`；drawio 还分了 `NORMAL/MILD/HYPER_SMOOTH`（默认 0.5、20=hyper）。⚠ 这些是**观感平滑**参数、不是延迟预测——拿来做"大众手感值域"的交叉验证，不直接套 |
| **1€ filter 官方调参法**（Casiez 两段式） | 先固定 beta=0 调 mincutoff（慢速去抖）、再快速移动拉 beta（提速抗滞）——照官方流程给我们的平滑/预测做一次"流程化复查" |
| 微软 / 苹果（闭源） | 只有口径：`PredictionTime` 默认 15ms、Apple 触摸预测 1 帧——对齐参数区间用 |

### 7.3 别人的经验（设计规则，已用/继续用）
- **慢速抗抖、快速抗滞**（1€/CHI）→ 我们的"速度自适应 + 分级门"思路 ✓
- **"角度误差比距离误差更刺眼"**（三星/Google 专利）→ 指标与调参目标加**角度项**（J4）✓
- **"预测必须被真实数据替换"**（Android 文档）→ 失效快收 / 换笔复位规则 ✓
- tldraw v5.2（2026-07）重写 freehand 管线（2~3× 快、路径小 57%）——矢量输出效率可借鉴（与"墨迹量/脏区"相关）

### 7.4 边界（诚实说清）
1. **外部数据救不了"你那台设备"**：手写板/学校触摸屏的采样节奏、60Hz 屏的观感——只有**黑匣子（真机数据）**能抓 ✗ 公开数据集 = 广谱校准，真机 = 专项校准 ✓
2. 公开集多是 Wacom/高端板 + 100~200Hz；学校触摸屏是低采样 + 大接触面——**别把公开集的"最优参数"直接当默认**，当"范围参照"用 ✓
3. 许可：仅内部评估使用（不发布衍生数据）；引用来源 ✓

### 7.5 建议（等你拍板）
1. **加一份中文数据集**（首选 CASIA-onDo，华为平板最贴）→ 跑一次"中文快写"参数复查（急转门槛/阻尼/地平线）；
2. 公开数据抽 N 条进 **`--tailmatrix` 回归语料**；
3. 出一张**对标表**（我们 vs 论文/别人：误差、角度误差、慢/快分档）。
