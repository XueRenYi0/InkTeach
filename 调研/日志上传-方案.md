# 日志上传（云端收集）· 方案与操作手册（2026-10-17）

> 用户定："用户如果卡了我让他点击上传日志，就可以传到云端，我们能拿到数据就可以直接分析了。"
> 约束：**免费**、国内教室网络可达、老师侧**零配置一键**。

## 一、链路

```
老师机器                             云端                                       我们
「设置 → 上传日志…」 ──打包 zip──▶ GitCode「InkTeach-Logs」仓
                                    logs/<名字>.zip（仓库文件）   ◀── tools\fetch-logs.ps1（列出/下载）
```

- 客户端：`DiagLog.ExportZip` 打 zip（日志 + 环境.txt + last-crash.txt）→
  `UploadZipToGitCode`（`src\InkEngine\DiagLog.cs`）——POST `contents/logs/<名字>`，
  正文 = base64（Gitee 形状的 contents 接口：**新建 POST / 更新 PUT**）。
- 取回：`tools\fetch-logs.ps1` 列 `logs/` 目录 → 逐份取回（base64 解码落盘）。
- 为什么选 GitCode：免费；**国内直连**（教室网络上 GitHub 不稳——我们自己的更新都靠
  GitCode 镜像兜底）；接口现成；**不需要我们养服务器**。

## 二、踩坑记录（换设计的原因，别再踩）

1. **私有仓的发行版附件下载 403**：上传（upload_url + PUT）明明能成，但
   `releases/download/...` 对私有仓一律 403——试过 `?access_token=`、Bearer、
   private-token、Access-Token 各种头，全不行；`attach_files/{id}/download`
   这类接口也不存在（404）。**所以日志不走发行版**。
2. **contents 接口是 Gitee 形状**：新建文件用 **POST**（用 PUT 会被要
   `'sha': param is missing`）；更新才用 PUT（带 sha）。
3. 好在这条链全在 `api.gitcode.com + access_token` 上：**读、写、列表都通**
   （实测字节级往返一致）。

## 三、为什么把令牌放进客户端（风险与止损）

没有服务器，"谁有权写"就只能靠一个藏在客户端里的令牌。控制爆炸半径的做法：

- **专用令牌**：只在 GitCode 给「InkTeach-Logs」一个仓用，**绝不复用发版令牌**；
  勾法：项目组"查看、创建、更新你的项目"——其余（用户/组织/企业/PR/Issue/
  Notes/Hook/**Repository**/Action/项目讨论）**全禁止**；
- GitCode 没有"按仓库"的细粒度：等"只读版"验证过（如果只读也能传）→ 换成只读的，
  泄漏的最坏后果就只剩"能读这个仓"；
- 发现异常：GitCode 上**吊销旧令牌** → 新令牌回填 `DiagLog.LogUploadToken` →
  随下个小版本发出（一条 const 的改动）；
- 上传文件名 = `log-<日期时间>-<机器名(ASCII化)>-<6位随机>.zip`：一眼对号；
  垃圾直接在网页上删。

## 四、建仓与配置步骤（一次性，约 3 分钟）

1. GitCode 新建仓库：**InkTeach-Logs**，选**私有**，勾初始化（README）；
2. 头像 → 设置 → 访问令牌：新建一个令牌（勾法见上）——把令牌回填到
   `src\InkEngine\DiagLog.cs` 的 `LogUploadToken`；
3. 编译后用 `--logupload` 模式真传一次验证（见下）；发布即可。
4. 我们这边：`%USERPROFILE%\.gitcode-token` 的令牌需有该仓读权限（发版令牌通常够）。

> 备用方案（任何一代版本都保留）：「导出日志…」把 zip 存 U 盘 / 发微信 / 邮件。

## 五、日常使用

- **老师**：卡了 → 更多 → 设置 →「上传日志…」→ 界面显示"日志已上传：log-…zip" →
  把这个编号报给开发；
- **我们**：`.\tools\fetch-logs.ps1`（列出）或 `-Download`（全部下到 `.\logs-download\`）；
  也可以直接在 GitCode 网页上打开该仓的 `logs/` 目录。

## 六、自检与验证

- `--recoverytest`：未配置 / 自检档下「上传日志」**只提示、不抛错、不卡**
  （“上传未配置/自检模式不上传”，钉子 17 项在册）；
- `--logupload`（开发用）：**真传一次**运行日志——发布前 / 换令牌后用它验
  "仓 + 令牌 + 接口"还通；真机上也可以用它做端到端；
- 端到端记录（2026-10-17）：应用 POST → 仓里出现文件 → `fetch-logs.ps1`
  列出 → 取回 → 字节数一致。
