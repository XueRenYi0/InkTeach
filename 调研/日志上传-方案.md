# 日志上传（云端收集）· 方案与操作手册（2026-10-17）

> 用户定："用户如果卡了我让他点击上传日志，就可以传到云端，我们能拿到数据就可以直接分析了。"
> 约束：**免费**、国内教室网络可达、老师侧**零配置一键**。

## 一、链路

```
老师机器                                 云端                                   我们
「设置 → 上传日志…」 ──打包 zip──▶ GitCode「InkTeach-Logs」仓
                                      `logs` 发行版的附件        ◀── tools\fetch-logs.ps1（列出/下载）
```

- 客户端：`DiagLog.ExportZip` 打 zip（日志 + 环境.txt + last-crash.txt）→
  `UploadZipToGitCode`（`src\InkEngine\DiagLog.cs`）——取 upload_url → PUT 二进制。
- 接口和 `tools\gitcode-release.ps1` **同一条"发行版附件"链路**（9.1.x 发版一直在用）。
- 为什么选 GitCode：免费；**国内直连**（教室网络上 GitHub 不稳——我们自己的更新都靠
  GitCode 镜像兜底）；接口现成；**不需要我们养服务器**。

## 二、为什么把令牌放进客户端（风险与止损）

没有服务器，"谁有权写"就只能靠一个藏在客户端里的令牌。控制爆炸半径的做法：

- **专用令牌**：只在 GitCode 给「InkTeach-Logs」一个仓（读+写），**绝不复用发版令牌**；
- 泄漏的最坏后果 = 有人往这个仓灌垃圾附件（读不到别的仓、删不了仓库、动不了主仓）；
- 发现异常：GitCode 上**吊销旧令牌** → 新令牌回填 `DiagLog.LogUploadToken` → 随下一个
  小版本发出即可（一条 const 的改动）；
- 上传文件名 = `日志-<日期时间>-<机器名>-<6位随机>.zip`：一眼能对号；`fetch-logs.ps1`
  列一遍就能分辨"真日志"和"垃圾"，垃圾直接在网页上删。

## 三、建仓与配置步骤（一次性，约 5 分钟）

1. GitCode 新建仓库：**InkTeach-Logs**，选**私有**；
2. 仓库 → 发行版（Releases）→ 新建一条，**标签填 `logs`**（标题随便，比如"日志收集"）；
3. 头像 → 设置 → 访问令牌：新建一个令牌（权限尽量只勾"该仓的仓库读写 / 发行版"）；存好；
4. 把令牌回填到 `src\InkEngine\DiagLog.cs` 的 `LogUploadToken`；编译发版，功能即通；
5. 我们这边：`%USERPROFILE%\.gitcode-token` 里的发版令牌需有该仓读权限
   （或单独另存一份用于 `fetch-logs.ps1`）。

> 备用方案（不想用令牌时）：老师改用「导出日志…」把 zip 发微信/邮件——任何一代版本
> 都保留这条路，上传只是把这一步自动化。

## 四、日常使用

- **老师**：卡了 → 更多 → 设置 →「上传日志…」→ 界面显示"日志已上传：日志-…zip" →
  把这个编号报给开发；
- **我们**：`.\tools\fetch-logs.ps1`（列出）或 `.\tools\fetch-logs.ps1 -Download`
  （全部下到 `.\logs-download\`）；也可以直接在 GitCode 网页上打开该仓的 `logs` 发行版。

## 五、自检钉子

- `--recoverytest`：未配置 / 自检档下「上传日志」**只提示、不抛错、不卡**
  （`UploadLogsFromUi` 遇到任何问题都不许影响使用）；
- 端到端（填上真令牌之后）发布前人工过一遍：上传 → fetch 列出来 → 下载 → 打开能读。
