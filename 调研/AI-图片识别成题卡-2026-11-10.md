# 图片识别成题卡（2026-11-10）

## 一句话

图片 AI 菜单只有一项 **「🧩 识别成题卡」**：原图保留 → OCR → 按题拆卡（题干/选项）→
答案默认不生成，卡上点「生成答案」才调模型 → 结构化失败兜底放富文本原文。

## 参考（先找成熟做法，再按我们的场景改）

| 参考 | 照搬的部分 | 没搬的部分 / 原因 |
|---|---|---|
| Mathpix Snip（2024–2026） | 图片 → LaTeX 文本；保留题号、选项、上下标；看不清不硬编 | 不照搬它的“整页公式导出”，我们只要题目文本 |
| Microsoft Lens / CamScanner | 拍卷面先做美白/去阴影，再 OCR；原图始终保留 | 不做透视矫正、不自动裁边（风险大、收益小） |
| Google Lens “复制文本” | 识别结果可编辑、可复制，不直接替换原图 | 不把识别结果铺在原图上（数学公式会错位） |
| ChatGPT / Claude 图片问答 | 一图多题按题号拆分；同一道题的 (1)(2)(3) 不拆 | 不做“直接看图出答案”，太慢且不可核对（实测一张 53 秒） |
| 小猿搜题 / 作业帮 | 题干、选项、答案、解析分块；答案默认折叠 | 不做学生端自动答疑，只做教师助手 |

## 为什么只做一个入口（用户 2026-11-10 定）

- 手写已经有「识别文本」；图片再来一个“识别文本”，用户分不清该点哪个；
- 题卡本身就是可编辑文本框：要纯文字，双击改、复制即可；
- 所以图片 AI 菜单 = `识别成题卡` + `识别作图`，两项。

## 流程 / 状态机

```
选中图片 → AI → 识别成题卡
  ├─ 没有能看图的模型 → Toast「设置里选一个（如 qwen3.5-ocr）」，不动文档
  ├─ 正在识别 → 再做一次只提示「正在识别上一张」，不排队、不并发
  ├─ OCR 失败 / 空 → Toast 失败原因（不落任何对象）
  ├─ 结构化失败 → 富文本只读框放 OCR 原文（能渲染 $...$），状态栏写原因
  └─ 成功 → 一张题卡（N 道，按题号分块；小问不拆）
              ├─ 原图保留；卡放图片右侧，放不下放下面，都放不下居中
              ├─ 答案默认空 → 每题一个「✦ 生成答案（AI）」
              ├─ 点生成 → 一次请求批量出答案 → 填回 + 展开 → 一步撤销
              └─ need_review=true → 题干前加「【请核对】」
```

## 模型选择（不在代码里写死）

- **看图**：优先当前选中的服务商（如果它本身能看图）；否则在已填 Key 的服务商里按
  `ocr`(5) > `omni`(4) > `vl`/`vision`(3) > `qwen3.5–3.8 通用多模态`(2) 挑一个。
  实测 `qwen3.5-ocr` 最稳（中文卷面 22/22，1.2–2.0s）；`qwen3.8-flash` 排版更好但 7–26s；
  `qwen3.5-omni-flash` 快，但会被红笔批改带偏（img02 把 `m>16` 读成 `m<16`）。
  完整对比 + 原始输出：`reports/ai-image-test/model-ocr/`。
- **写 JSON**：优先当前选中；但当前若是 `*-ocr` 这种只认字的模型，就换一条别的。
- 两边都走既有 `ai.json`（设置 → AI），不新增第二套密钥。

## 提示词要点（实测踩坑）

1. **必须关思考**：`deepseek-flash` 不关会把 4096 tokens 全烧在 reasoning 上，`content` 为空。
2. 输出用**数组**，且明确“只有独立题号才分卡、(1)(2)(3) 合并”，否则一道大题会被拆成 3 张。
3. 模型可能连着输出多个 JSON 对象（不是数组），解析端按平衡花括号逐个抠，不能假设只有一个。
4. `\frac` 直接写进 JSON 时 `\f` 是合法转义，会被吃成换页符 → 解析后要救回 `\f/\b/\t/\v` + 字母。
5. 不要用 `response_format=json_object`：实测反而返回多个对象、更难解析。

## 性能（2026-11-10，中文卷面 22 张）

| 环节 | 中位 | 范围 |
|---|---|---|
| 图片 → 文字 | 1.5s | 1.2–2.0s |
| 文字 → 题卡（只题干） | 1.8s | 1.4–1.9s |
| 文字 → 题卡（带答案解析） | 2.7s | 1.8–3.2s |

整链约 **3.3 秒**（不生成答案）；「生成答案」约 +2–3 秒。

## 撤销 / 存档

- 插卡：`Doc.AddStroke` 自带一步撤销。
- 生成答案：`TextBoxAnswersAction`（答案/解析/展开状态/来源行/高度一起进撤销栈）。
- 答案写进 `.ink` 存档；原图不动，不产生双份。

## 自检

- `--imgcardtest`：离线 15 项（JSON 抠取 / 菜单 / 排版 / 摆位 / 生成答案行 / 撤销 / 兜底）。
- `--imgcardlive [图片路径]`：真实 API，一条命令打印模型、耗时、题数，并出三张图。

## 附：AI 图片纠正 / 去手写（2026-11-11 测，未接入）

跑遍手里能出图的 API（百炼 qwen-image-2.1-turbo / 3.0、火山 seedream-5.0-flash、硅基流动 Qwen-Image-Edit-2509），
结论：**全是“重新画一张”，不是“原图擦除”**。

| 模型 | 单价 | 耗时 | 实测问题 |
|---|---|---|---|
| doubao-seedream-5-0-flash | 0.12 元/张 | 13–16s | 两样本数字没变，但整页重画 |
| qwen-image-2.1-turbo | 0.10 元/张 | 13–17s | `-3` → `-8` |
| qwen-image-3.0 | 0.18 元/张 | 31–42s | “则” → “刬” |
| Qwen/Qwen-Image-Edit-2509 | 0.30 元/张 | 37–60s | 丢过一个数字 |

主链（OCR+题卡）≈0.01 元/张，AI 清理是它的 10–100 倍，且改内容。
要做只能放 `⋯` 当实验功能：保留原图、出图后自动 OCR diff、黄标提示。
完整记录：`reports/ai-image-test/image-edit/README.md`。

## 附二：百度 OCR（2026-11-11）

> **2026-11-11 用户拍板：页面矫正 / 去手写先不做（代价太大）**，以下只作记录。
- 通用/高精度/手写/试卷切题：**没有 LaTeX、把红笔批改一起识别、拍歪就乱码**，
  `paper_cut_edu` 能切题但题干截断、选项丢失 → **不能做图片→题卡**。
- **文档去手写V2**（0.13 元/次，1.8–2.3s）：擦笔画、不生成内容，红像素基本清零，
  是目前最安全的去手写；但手写压住印刷体时会连字一起擦掉，之后 OCR 会脑补数字
  （img02 擦掉 `>16`、`(-3,-4)` 后读成 `m<0`、`(12/5,-9/5)`）。
- **文档矫正增强V2**（0.13 元/次，1.4–1.8s）：裁边/透视/转正，不改字，推荐。
- 记录：`reports/ai-image-test/baidu-ocr/README.md`。
- 合合 TextIn xParse（0.35 元/页）公式很漂亮，但不区分手写、价格是 qwen 的约 250 倍，
  **不做默认/备选**；只适合干净印刷页。记录：`reports/ai-image-test/textin/README.md`。
- PaddleOCR-VL-1.6（讯飞 MaaS，Model ID `xoppaddleocrv16`）：正常卷面 1.8–2.8s、LaTeX 规范，
  img02 的 `m > 16` 读对了；但**会把红笔批注当正文**（img21 输出 5697 字 / 15.1s）。
  提示词加“忽略手写”无效，只有 `OCR` 最好。**不做默认**，适合干净印刷页/PDF。
  记录：`reports/ai-image-test/paddle-16/README.md`。魔搭 API-Inference 不支持该模型
  （`has no provider supported`）。
- 腾讯云 OCR：通用/高精度/手写均无 LaTeX、把手写当正文；`EduPaperOCR`/`FormulaOCR` 已下线，
  `QuestionOCR`/`QuestionSplitOCR` 要买资源包。后付费 0.15–0.50 元/次。**不用**。
  记录：`reports/ai-image-test/tencent/README.md`。
- 千问 3.8（没有 4.0，最新是 3.8）：`qwen3.8-flash` 关思考 + 原图 2.8–4.4s、≈2 元/千张、
  红笔样本全对；`max` 30 元/千张、默认思考 104–162s；`omni` 读错负号。**升级候选，暂不换**。
  记录：`reports/ai-image-test/qwen38/README.md`。
- 百度千帆 OCR：`qianfan-ocr` 同一参数下 1.5–57s 不稳定、会把草稿全读；
  `paddleocr-vl-0.9b`/`pp-structurev3` 240s 超时；`deepseek-ocr` 输出乱码；`qwen3-vl-30b` 无权限。**不用**。
  记录：`reports/ai-image-test/qianfan/README.md`。
- OpenRouter（163 个视觉模型）：主链仍是 qwen3.5-ocr；`gemini-3.6-flash`
  是唯一在红笔样本上全对的备选（3.4–4.9s、≈0.012 元/张，约 8.6 倍），可作“高质量识别”开关；
  qwen3-vl-235b/ling 更便宜但会串手写。记录：`reports/ai-image-test/openrouter/README.md`。
- 全平台功能/价格/推荐度总表：`reports/ai-image-test/功能选型总账-2026-11-11.md`。
