# 高中数学图形引擎：需求汇总 + 开源调研 + 最优路径

日期：2026-11-09
状态：调研报告（不直接改产品代码）
目标：高中数学所有图都能画、能选中、能拖参数；题目带图就带图，不带图 AI 也能生成；含参；贴合高考/教材题。

---

## 0. 结论（先看这一段）

**最优路径不是把 GeoGebra/JSXGraph 整体塞进来，而是做一套原生 `FigureScene` 引擎：**

- **AI 负责“复杂计算/决定画什么”**：解析题目、选图形类型、给坐标/参数/方程；
- **本地负责“实现逻辑”**：场景校验、依赖求值、函数采样、坐标轴/刻度、命中/拖动、撤销/存档；
- **渲染**：主画布一直用 **D2D**；图形引擎也用 D2D 矢量绘制。Skia 只保留给现有的 LaTeX 公式位图（`MathRenderer`），不进入图形引擎。
- **借鉴开源算法/架构，不整体采用运行时**：
  - JSXGraph：元素依赖图、曲线采样、3D 场景/投影；
  - ScottPlot：刻度间距/标签密度算法（MIT，可直接移植小段）；
  - function-plot：函数区间采样 + 渐近线断段（MIT）；
  - planegcs / NeoGeoSolver：只作约束求解参考（LGPL/GPL，先不引入）。
- **第一版不做完整约束求解**：先做自由拖点/拖参数 + 中点/交点/点在线上这些“显式依赖”，避免掉进 GeoGebra 级的大坑。

### 0.1 渲染栈澄清（重要）

| 层 | 现在 | 目标 |
|---|---|---|
| 主画布 / 图形 | Direct2D | Direct2D |
| 公式（LaTeX） | SkiaSharp → 位图（`MathRenderer`，已有） | 保持（公式专用） |
| 本次 `FigureRenderer` 原型 | SkiaSharp → 位图 → 再交给 D2D 画 | **替换为 D2D 直接画**，不长期保留第二套图形栅格化 |
| 卡片静态题图 | 位图 | 可以由 D2D 离屏位图生成，或直接画矢量场景 |

结论：**不是“D2D + Skia 双渲染引擎”**。Skia 是旧的公式渲染依赖；图形引擎必须回到 D2D，避免缩放糊、两套抗锯齿、两套命中/坐标。

## 1. 需求汇总

### 1.1 功能

| 类别 | 要求 |
|---|---|
| 函数 | 一次、二次、反比例、指数、对数、三角、分段、绝对值；定义域、渐近线、交点、最值 |
| 圆锥曲线 | 圆、椭圆、双曲线、抛物线；标准方程、焦点、准线、离心率、参数 a/b |
| 平面几何 | 三角形、四边形、圆、角；边长/角度/中点/交点/垂线/平行/切线 |
| 立体几何 | 正方体、棱柱、棱锥、棱台、圆柱、圆锥、圆台、球；旋转/缩放、标签、隐藏线 |
| 解析几何 | 直线/圆方程、交点、距离、轨迹 |
| 含参 | a/b/c/k 等参数可拖、可输入；方程/数值实时更新 |
| AI | 题目带图→识别/生成；不带图→按题意生成；手写函数→识别→画图 |
| 坐标系 | 按题型显示/隐藏：函数/圆锥/解析几何要；纯平面/立体默认不要；数轴单独 |
| 对象 | 可选中、移动、缩放、删除、撤销、存档、导出；卡片内只读图 / 独立可操作图 |
| 性能 | 拖动实时；大图不卡；NativeAOT；触控/笔 |

### 1.2 现有基础（可复用）

`StrokeKind` 已经有：

- 平面：Line、Rectangle、Ellipse、Circle、Triangle、Parallelogram、Trapezoid、Sector、Star
- 曲线：Parabola、Hyperbola、ConicEllipse、Sine、Cosine、Tan
- 立体：Cuboid、Prism、Pyramid、Frustum、Cylinder、Cone、ConeFrustum、Sphere、Tetrahedron
- 坐标：Coordinate、NumberLine、SpaceCoordinate

并且已经有：选中框/顶点手柄、移动/缩放、撤销、存档 v33、图片对象、文字卡片。
**结论：不需要从零造“图形对象”体系，先把“场景 + 参数 + 依赖 + 函数”补上。**

## 3. 代码研究笔记

### 3.1 JSXGraph（最值得抄“状态机/依赖图”）

关键文件：

- `src/base/board.js`
  - 每个元素有 `prepareUpdate() / update() / updateRenderer()`；
  - 拖动时只更新被拖元素及其后代（`reducedUpdate`），松手再全量；
  - 有 `updateQuality`（低质量拖动 / 高质量静止），曲线采样点数量随之变化。
- `src/base/curve.js`
  - `Curve` 同时服务 function graph、参数曲线、极坐标曲线、数据点；
  - `minX/maxX`、`numberPoints`、`updateDataArray()`；
  - 函数/参数/极坐标只是 term 不同，渲染层统一。
- `src/base/ticks.js`
  - `Ticks` 挂在 axis line 上，`ticks` 可以是固定数组或“间距函数”；
  - 标签/大小/方向都是属性。
- `src/3d/view3d.js`
  - 4×4 矩阵：世界→相机→屏幕；
  - `projectionType` 支持 parallel / central；
  - `depthOrdered` 做深度排序；
  - 3D 元素：point3d/line3d/curve3d/face3d/polygon3d/polyhedron3d/sphere3d/surface3d。
- 依赖关系不是“数值约束求解器”，而是**构造依赖**：
  - 自由点 / glider（点在线上）/ intersection / midpoint / perpendicular 等；
  - 每个元素记录 parents，更新时按拓扑顺序算。
- **可抄**：依赖图 + 拖动时局部更新 + 曲线统一采样 + 3D 矩阵/深度排序 + 刻度属性模型。
- **不抄**：JS 运行时/DOM/SVG 渲染、整体嵌入 WebView2。

### 3.2 planegcs（约束求解的“重型方案”）

- FreeCAD 的 2D 约束求解器，C++ 移植到 WASM；
- 几何：点/线/圆/圆弧/椭圆/椭圆弧/双曲线/抛物线/B 样条；
- 约束：距离、平行、垂直、相切、同心、重合、点在线上、角度、半径等；
- 求解：DogLeg、Levenberg-Marquardt、BFGS、SQP 数值优化；
- 输入是 JSON primitives，带 id 引用；支持 driving / non-driving / temporary 约束；
- **优点**：完整、成熟；**缺点**：LGPL、WASM/C++ 依赖、重、对“课堂图”过重。
- 结论：**第一版不用**；以后如果老师需要“拖动时保持几何关系”，再把它作为独立可选模块评估。

### 3.3 NeoGeoSolver.NET（C# 约束求解参考）

- C# 实现，39 个约束类：点重合/距离/水平/垂直、点在圆/弧上、中点、平行/垂直/相切/角度/等长等；
- `EquationSystem` + 参数/方程 + 高斯消元/迭代；
- 结构清晰，适合看“C# 约束怎么建模”；
- **GPL-3.0，不能复制**；只能参考接口/约束分类。

### 3.4 ScottPlot（刻度/自动缩放最值得移植）

- `TickGenerators/DecimalTickSpacingCalculator.cs`
  - 从 10 的幂开始，按 2 / 2 / 2.5 依次细分，得到 10、5、2.5、1、0.5… 的“好看刻度”；
  - 用轴像素长度和最大标签宽度决定刻度密度；
  - 主刻度/次刻度分开（`EvenlySpacedMinorTickGenerator`）。
- `AxisPanels/`：轴的位置/标签/刻度绘制分层清楚；
- `AutoScalers/`：数据范围 → 轴范围（留边距）。
- **可抄**：刻度间距算法、标签密度、主/次刻度、自动范围；MIT。
- **不抄**：它自己的 Plot/渲染控件（会和 D2D 画布打架）。

### 3.5 function-plot（函数采样/断点）

- `src/samplers/builtIn.ts`
  - `checkAsymptote`：检测相邻采样点是否跨渐近线，把曲线**断成多段**；
  - 避免 `tan`、有理函数在渐近线处被连成一条竖线；
- `src/graph-types/interval.ts` + `samplers/interval.ts`
  - 区间采样、按像素密度取点、支持异步；
- **可抄**：渐近线检测、断段、按像素密度采样；MIT。
- **不抄**：D3/SVG 渲染。

## 5. 最优路径：原生 `FigureScene`

### 5.1 分层

```
AI / 题库
   ↓  scene JSON（只给语义/参数，不给像素）
FigureScene
   ├─ entities: point / segment / polygon / circle / conic / function / solid / label
   ├─ parameters: a,b,c,k,...（可拖/可输入）
   ├─ relations: glider / midpoint / intersection / perpendicular / parallel
   └─ coordinate: mode/grid/xRange/yRange/equalScale
   ↓  validate + topological update
FigureEngine
   ├─ expression parser/evaluator（安全，不 eval 代码）
   ├─ function sampler（分段/渐近线/定义域）
   ├─ conic/geometry evaluator
   └─ 3D projection/depth
   ↓
D2D renderer（axes/ticks/grid/curves/labels/selection）
   ↓
交互：自由拖点、拖参数、框选、缩放、撤销、存档
```

### 5.2 关键决策

1. **函数用表达式 AST + 采样，不用 AI 给一堆点**：
   - AI 给 `y = a*x^2 + b*x + c`、参数范围；
   - 本地解析/求值/采样；安全、可缩放、可拖参数。
2. **依赖先做“显式关系”**：
   - 中点、交点、点在线上、垂线/平行线；
   - 不做完整数值约束求解；拖点时按依赖顺序重算。
3. **坐标轴策略**：
   - 函数/圆锥/解析几何默认 Cartesian；平面/立体默认 none；
   - 数轴单独；3D 坐标法题才显示 space。
4. **AI 输出场景 JSON，不执行代码**：
   - 校验类型/引用/范围；失败回退纯文字/静态图；
   - 不执行 TikZ/LaTeX/任意 SVG。
5. **卡片 vs 独立对象**：
   - 题卡可带只读图；需要拖参数时“拆分为独立图形对象”或直接生成独立对象；
   - 独立对象复用现有选中/撤销/存档。

|---|---|---|
| P1 | 二次函数 + 坐标轴/刻度 + a/b/c 参数 | 表达式采样、参数手柄、刻度算法 |
| P2 | 一次/反比例/指数/对数/三角/分段/绝对值 | 定义域、渐近线断段、参数 |
| P3 | 圆/椭圆/双曲线/抛物线（含焦点/准线） | 标准方程、参数 a/b、焦点/准线 |

## 7. 风险/避坑

- **约束求解是最大坑**：不要第一版做完整 solver；先自由拖动 + 显式依赖。
- **函数采样**：必须处理渐近线/定义域/极大值；否则 `tan`、`1/x` 会出现竖线。
- **AI JSON 不稳定**：必须 schema 校验、引用校验、失败回退；不要让 AI 直接给像素/SVG。
- **表达式安全**：自己解析 AST，禁止 `eval`/反射/任意代码。
- **性能**：拖动只更新受影响元素；曲线按像素密度采样；缓存静态层。
- **坐标轴**：等比例 vs 自适应要明确；函数图默认等比例，否则斜率误导。
- **许可**：NeoGeoSolver GPL 不能抄；planegcs LGPL 只做独立模块；JSXGraph/ScottPlot/function-plot MIT 可参考/移植并保留声明。
- **NativeAOT**：避免反射 JSON；用 JsonDocument/manual/源生成。
