# 调研：ClassIn、希沃与主流批注软件的文本框全套交互

日期：2026-11-01　　状态：**已定稿并落地（2026-11-01 晚）**

用户目标：

> 调研 ClassIn、希沃以及其他主流批注软件的文本框逻辑，包括从点击文本开始，到输入、编辑、移动等全套流程和交互。想优化一下。

---

## 〇、一句话结论

市面上的文本框大致分两派：

1. **教学白板派（ClassIn / 希沃 / Pencil Spaces）**
   - 文本是一个**独立对象**；
   - **文本工具负责“输入”**，**选择/移动工具负责“选中、移动、再次编辑”**；
   - 选中后出属性栏（字体、字号、颜色、加粗、下划线、对齐等）；
   - 再编辑通常是**双击**；
   - 文本框多为**固定框**，内容多了靠换行/缩放/裁切，富文本能力较强。

2. **无限白板派（Excalidraw / Confluence / Microsoft Whiteboard）**
   - 点击或拖拽创建；
   - **双击进入编辑**；
   - 高度多按内容自动；
   - 格式更少，交互更轻；
   - 空文本通常自动删除。

**用户想要的“第一下选中、双击编辑”是主流做法**，Pencil Spaces、PowerPoint、Excalidraw、希沃都符合这个方向。
ClassIn 的公开手册只写到“选择&移动工具可以选中并再次编辑”，**没有公开单击/双击的细节**，需要真机确认。

**建议**：保持我们现在的“文本工具创建/选中、双击编辑、自动高、无内部滚动”主模型，只补 P1 的几项：双击空白新建、拖拽创建固定宽、属性面板不打断编辑、触摸滚动、悬停高亮、Tab 缩进。不要现在去抄富文本、固定高、旋转。

## 二、ClassIn

### 2.1 可确认的官方行为（A）

ClassIn 教师手册里写得很简洁：

> **【选择 & 移动工具】** 支持对黑板中内容点选移动和圈选移动。
>
> **【文本工具】** 可以在黑板输入文字，内容可以更改文字粗细和颜色。

英文版教师手册写得更清楚：

> **Select & Move**: Select the elements on the blackboard and move them or **edit them again**.
>
> **Text Box**: Input some words.

学生手册里，文本输入是教室工具栏的固定工具之一；移动端“画笔和文本工具下，此处可选择颜色和形状等”。

### 2.2 由此能还原出的流程

| 阶段 | ClassIn 的做法 | 证据 |
|---|---|---|
| 进入输入 | 点「文本」工具 → 点黑板 → 输入文字 | A |
| 输入中 | 可改文字颜色、粗细 | A |
| 结束输入 | 官方手册未写；按黑板类产品惯例是点画布外/切工具 | D |
| 选中 | 用「选择 & 移动」工具点对象 | A |
| 移动 | 选中后拖动；支持圈选多个 | A |
| 再次编辑 | 选择 & 移动工具可以“再次编辑” | A（具体单击/双击未写，D） |
| 改字号 | 公开手册只写“粗细”，没有明确字号菜单 | D |
| 改宽高 | 公开手册未写；按对象框惯例有手柄 | D |
| 空文本 | 公开手册未写 | D |
| 旋转 | 公开手册未写 | D |

### 2.3 ClassIn 的关键设计取向

1. **工具分离**：文本工具负责“写”，选择/移动工具负责“管”。这比“一个工具包办所有事”更接近老师的心理模型：写完就切回选择，开始排版。
2. **属性极简**：公开资料只强调颜色、粗细，没有一长排富文本按钮。说明课堂场景里“快速写、快速改色”比“排版”重要。
3. **对象化**：文本是黑板上的一个对象，能被选择、移动、圈选，和图片/形状同级。
4. **细交互不透明**：ClassIn 没有像希沃那样把每个手势写进说明书。要确认“第一下选中还是直接编辑”“双击还是再点一下”“有没有 8 个手柄”，只能真机录屏。

### 2.4 用户实测补充（ClassIn，2026-11-01 口述）

> 这是用户自己在 ClassIn 上看到/试到的行为，比公开手册更细，按 **D（实测观察）** 记录。

- 点「文字」后，会弹出**字号下拉 + 颜色面板**；字号是常用字号下拉，颜色有很多格。
- 在画布上点一下进入文本模式；初始是一个**很窄的框**，输入汉字时框跟着字走（自动宽）。
- **缺点**：在屏幕边缘输入时，框会一直长到屏幕外面去，不会自动换行/回拉。
- 输入完在别处点一下，会**再出一个新的输入框**（文本工具保持激活，点哪写哪）。
- 光标移到已经输入的文字上，会变成**带箭头的十字（移动光标）**；此时单击 = 移动。
- **双击**已输入文字 = 进入编辑；编辑时光标在**最后面**，可以再点其他位置把光标调过去。
- 复制粘贴长文本：框会**自适应**，一行就是一行，有多高就多高。
- **缺点**：这个框**不能调整大小**；不能把宽度拖窄/拖宽。
- 它没有 Markdown 兼容，所以编辑汉字时是**完全所见即所得**；它的文本能力更接近“纯文本 + 富文本属性”，不是 Markdown 源码。
- 输入文字时，鼠标滚轮可以正常上下滚**屏幕**。
- 橡皮擦**擦不了文字**；它只有面积擦，没有整笔擦（所以不存在“整笔擦把文字整块删掉”的路径）。
- 清空画布时，文字也会一起清掉。

> 这段非常重要：它说明 ClassIn 的文本框是**“自动宽 + 自动高 + 不可手动改尺寸 + 文字保护”**的模型。
> 优点：输入快、所见即所得、不会误擦文字。
> 缺点：屏幕边缘会溢出、不能手动调宽、没有 Markdown/公式源码能力、文字只能靠选择+删除。
> 我们不需要照抄缺点，只抄它的“输入顺手”和“文字保护”。

### 2.5 二次实测补充（2026-11-01 第二轮）

- 光标移到**未选中**文字上：先变 **I 字光标**；单击 = 选中；点住直接拖 = 移动；直接双击 = 编辑。
- 双击进入编辑后，**光标永远在末尾**；再点一下文字内部，光标才落到点击处（第三下才定位）。
- 屏幕边缘输入：内容**直接溢出**；哪怕只剩半个字也不换行、不挪位置；手动左推或手动换行也一样溢出它的框。
- 框**没有手柄**，只有一圈很淡的虚线；选中后下方出现操作条；**没有隐藏的宽度设置**。
- 粘贴**不含换行**的长文本：不换行，一直往右延伸；高度也不限制，文本往下就往下长。
- 选中时操作条在下方；**移动时操作条隐藏**；**双击编辑时下方没有操作条**。
- 字号/颜色面板是**管下一次输入**；选中后的操作条是**修改已有文本**。两者像“画笔色板 vs 选中面板”，不冲突。
- 编辑和选中是**同一个框、同一个底**，只是文字在变；编辑时**没有白色底**。
- 橡皮擦：ClassIn 只有面积擦、没有整笔擦，所以文字不会被擦；清空会清掉文字。
- 用户拍板：**采纳我们的橡皮策略**——整笔擦删整个文本框（可撤销），面积擦只擦墨迹、不碰文字。
- 选中文字后的操作条（用户截图）：`×`、字号下拉、`A` 颜色、锁定、图层、复制、删除，右侧还有一个 `AI`。
- 字号下拉只有 6 档：**10 / 14 / 18 / 24 / 48 / 64**；默认看起来是 18。
- 颜色面板 16 格：白、浅灰、深灰、黑 / 亮红、橙、黄、绿 / 青、蓝、紫、粉 / 最下面一格是彩虹（自定义）。
- 当前颜色用同色圆环标出，不是色带上的选中框。
- 操作条**不会超出屏幕**：文本靠下时，操作条卡在屏幕边缘，不翻到上面。
- 但画板模式下滚动时，操作条**不会粘在屏幕边缘**，会跟着文本滚到消失。
- 编辑时没有选中框、没有操作条；只有文字和一个很淡的框。
- 文本压在图片/PPT 上时，ClassIn 的编辑底是**真透明**，不盖住下面。
- 内容全部删空：框消失；**Ctrl+Z 不能撤回**。通过垃圾桶删除：可以撤销。
- 触屏：单击选中、双击编辑，和鼠标一致。
- 触屏双指上下滚：滚屏幕，并**取消文本框选中**；鼠标滚轮滚：滚屏幕，**不取消选中**。用户不确定这是故意还是小问题。



### 2.6 还需要真机确认的（剩余）

- [ ] 双击进入编辑后，**第三下点击**能否把光标放到点击处？（用户说可以，再确认一次）
- [ ] 编辑中按 Esc / Ctrl+Enter / 点画布外，分别是提交还是取消？
- [ ] 编辑中改字号/颜色，会不会退出编辑？
- [ ] 选中文字后，下方操作条是一直显示，还是点空白就消失？
- [ ] 触摸屏上双指是滚画布还是滚文本框？
- [ ] 文本在 PPT/图片上时，编辑底是透明还是盖住下面？
- [ ] 内容清空后，文本框是保留还是消失？

## 三、希沃白板 5

### 3.1 官方说明书（A）

希沃白板 5 使用说明书“3.2.2.4 文字”写得很具体：

> 点击 **文字** 按钮后，光标移动到工作区域变为“I”，**单击后可在停留位置插入文本输入框**，输入文字完成添加文本元素。
>
> 选中工作区域的文字元素后，属性栏默认处于**文本 tab**，用户可以选用模板、修改字体以及布局方式，还可以设置文本元素相对于其他元素的**层级关系**、在当前页面的**对齐方式**等。
>
> 文本项提供：**字体、大小、颜色、加粗、斜体、下划线、格式刷、清除格式、上标、下标**；以及**对齐、缩进、编号、行高**。
>
> 绘制好形状后，选中形状元素**双击**后可在其中输入文本。

第三方入门教程（C）补充：

> 进入编辑界面后……**双击任意位置输入文字，拖拽调整位置**。

### 3.2 还原出的流程

| 阶段 | 希沃的做法 | 证据 |
|---|---|---|
| 进入输入（空白） | 点「文字」→ 光标变 I → 单击画布 → 出现文本框 → 输入 | A |
| 进入输入（快捷） | 编辑界面**双击任意位置**也能输入文字 | C |
| 形状内文字 | 画好形状 → **双击形状** → 输入文字 | A |
| 输入中 | 文本框内直接编辑；属性栏可改字体/字号/颜色/加粗/斜体/下划线/对齐/行高 | A |
| 结束输入 | 点文本框外（官方未逐字写，按编辑惯例） | D |
| 选中 | 选择工具点文本元素；出选中框 + 属性栏 | A |
| 移动 | 拖拽调整位置 | C |
| 改宽高 | 选中框手柄/属性栏布局；具体手柄形态官方图未展开 | A/D |
| 再次编辑 | 双击文本（形状内文字也是双击进入） | C/D |
| 空文本 | 官方未写 | D |
| 富文本 | 字体、字号、颜色、粗/斜/下划线、上下标、格式刷、清除格式 | A |
| 排版 | 对齐、缩进、编号、行高、层级、相对其他元素对齐 | A |

### 3.3 希沃的关键设计取向

1. **双击是文字的主入口**：空白处双击、形状上双击都能直接写字。老师不需要先找“文本工具”再点一下。
2. **属性栏是选中后的主战场**：字体、字号、颜色、粗斜下划线、对齐、行高、层级全在右侧属性栏，不在画布上摆一排按钮。
3. **富文本是完整能力**：它把文本框当“小型 PPT 文本框”，不是“纯文本便签”。
4. **对象模型完整**：文本和形状、图片同级，支持层级、对齐、组合等。

### 3.4 对我们的启发

- **值得抄**：双击空白直接新建文本；选中后属性栏集中管理；文本对象和形状同级。
- **不要全抄**：富文本工具条、格式刷、上下标、缩进/编号、固定框裁切。我们只做简单文本框 + Markdown，抄全套富文本会把存档、AI 输入、渲染复杂度都拉高。

## 四、其他主流产品

### 4.1 Pencil Spaces（教学白板，最接近我们的目标流程）

官方帮助（A）：

> **Adding text**: Click the Text (T) button → click anywhere on the whiteboard → start typing.
>
> **Editing Text**: **Double-click the text** to start editing. You can change font, color, size, formatting from the text toolbar.
>
> Use the **Select tool** to move, resize, layer, or delete your text box.

结论：**T 工具创建 → 单击选中 → 双击编辑 → 选择工具移动/缩放/层级/删除**。这正是用户这次提的模型。

### 4.2 Collaboard（教学/会议白板）

官方帮助（A）：

> **Direct edit**: Select an object with single click → start typing → text editing mode is automatically triggered; existing text will be overwritten.
>
> **Selective edit**: Select an object with a single click → **click again** → text editing mode is triggered where you placed the cursor.

结论：它用“单击选中、再点一下进入编辑”，不是双击。优点是单击后可以直接打字替换；缺点是“再点一下”和拖动容易混。适合键盘重度用户，不如双击稳。

### 4.3 Ziteboard（轻量白板）

官方 FAQ（A）：

> On devices with a physical keyboard, place a dot anywhere and start typing. On touch devices, long tap an empty space until the virtual keyboard comes up.
>
> To edit a text, select the text by long-pressing and **click again**. Alternatively, select the text by long-pressing and press any key.
>
> Click out from the text box to close it and draw again.

结论：**没有显式文本工具**，点哪打哪；触摸长按；再点一下编辑。极简，但“发现性”差，老师第一次用不一定知道可以这样。

### 4.4 Microsoft Whiteboard

官方支持（A）只列了基础能力；第三方教程（C）指出一个关键限制：

> Resizing the text box only changes the container dimensions, not the text size. The formatting toolbar only offers bold and underline controls, missing font size and alignment options.

结论：**改框不改字**是很多白板的通病，用户会以为“我把框拉大，字怎么没变大”。这正好支持我们“角拖缩放字号、边拖改宽”的分离设计。

### 4.5 Confluence Whiteboard

官方帮助（A）：

> Select **Aa** in the toolbar → text elements add text on top of other elements or directly on the whiteboard.
>
> Floating toolbar: color, **7 preset text sizes** + custom size, bold/italic/underline/strikethrough, bulleted/numbered lists.

结论：**浮动工具条 + 预设字号 + 富文本**。适合文档型白板，不适合课堂快速板书。

### 4.6 Excalidraw（我们上一轮的主参考）

官方文档/源码（A）：

- 单击 = Auto width；拖框 = Fixed size；
- 手动改尺寸 = Fixed size；
- 双击编辑；
- 左右改宽；角拖按比例缩放字号；双指缩放画布；
- 空文本层自动删除；
- 高度按内容算，无内部滚动。

结论：**对象模型和尺寸状态机最干净**，但富文本能力最弱。我们保留它的尺寸/空文本/编辑模型，叠加 Markdown。

### 4.7 PowerPoint / OneNote（传统 Office 派）

- PowerPoint：单击选中，双击或 Enter 进入编辑；文本框固定，AutoFit 三选一（Do not Autofit / Shrink text on overflow / Resize shape to fit text）；富文本完整。
- OneNote：笔记容器随内容自动长；手动拖宽后锁宽；富文本；没有显式“文本框工具”，点页面就能写。

结论：**Office 的“双击编辑 + 固定框 + AutoFit”是老师最熟悉的模型**，但它的“固定框 + 滚动/裁切”正是用户不喜欢的地方。我们保留“双击编辑”，去掉“固定框 + 滚动”。

| **OneNote** | 点页面直接写 | 容器拖动 | 双击 | 点击处 | 手动拖宽锁宽 | 自动长 | 有 | 有 | 未公开 | 有 |

> “未公开”不是“没有”，是公开资料没写到；需要真机确认的项不要当成设计依据。

## 六、共性结论

### 6.1 第一下选中、双击编辑，是主流

- Pencil Spaces：明确双击编辑。
- PowerPoint：单击选中，双击/Enter 编辑。
- 希沃：双击是文字入口（空白/形状）。
- Excalidraw：双击编辑。
- Collaboard/Ziteboard：单击选中，再点一下编辑（不是双击，但同样区分“选中”和“编辑”）。

**结论**：我们现在的“第一下选中、双击编辑”方向是对的，不需要改回“单击即编辑”。

### 6.2 文本工具 vs 选择工具

- ClassIn/希沃/Pencil Spaces 都把“写”和“管”分开：文本工具负责输入，选择工具负责移动/缩放/层级/删除。
- 我们的文本工具目前是“创建 + 选中 + 可拖动 + 双击编辑”的合体。对老师更方便，但和 ClassIn 的“两段式”不完全一样。
- **建议保留合体**：老师不用来回切工具；想纯排版时再切选择工具。只要双击编辑的规则一致，不会混。

### 6.3 固定框 vs 自动高

- 希沃/PowerPoint 以固定框为主，内容多了靠 AutoFit/滚动/裁切。
- ClassIn 公开资料没写，但教学白板通常也会限制在一个框里。
- Excalidraw/OneNote 更偏“高度随内容”。
- **我们选择“高度随内容、无内部滚动”**，更接近 Excalidraw/OneNote，也符合用户明确说的“不喜欢滚动”。这是主动取舍，不是漏做。

### 6.4 富文本 vs Markdown

- 希沃/Confluence/PowerPoint：完整富文本（粗/斜/下划线/字号/颜色/对齐/行高）。
- ClassIn：公开资料只强调颜色/粗细，偏轻。
- Excalidraw：纯文本，无富文本。
- **我们保留 Markdown**：编辑窗显示源码，提交后渲染。这样不背富文本 run/选区/存档的复杂度，也方便以后 AI 直接读写纯文本。

### 6.5 属性修改的时机

- 希沃：选中对象后属性栏修改，通常不要求在“正在输入”状态。
- Excalidraw：编辑中可以通过属性面板改字体/字号，编辑窗保持打开（properties 特判）。
- 我们目前点色带/字号会让编辑窗失焦并提交。**这是可以优化的点**：让“点属性面板”不结束编辑，改完继续输入。

## 七、建议我们采用的目标流程

### 7.1 创建与进入编辑

1. 文本工具单击空白：新建，进入编辑，光标在点击处。
2. 文本工具横向拖 > 36px：新建**固定宽**文本，进入编辑。
3. 文本工具单击已有文字：**只选中**，不编辑；点住可拖。
4. 文本工具/选择工具**双击**已有文字：进入编辑，光标落在点击处。
5. 选择工具双击空白：可选，建议做成“新建文本”（希沃习惯），但需要确认是否和现有双击手势冲突。
6. 编辑中再点文本工具格 = 提交（触摸屏没有 Ctrl+Enter）。

### 7.2 输入与提交

- Enter = 换行；Ctrl+Enter / Esc / 点画布外 / 点「完成」= 提交。
- 中文输入法、选区、复制粘贴交给 RichEdit。
- 粘贴只取纯文本，Tab 转空格。
- 空文本提交 = 删除整个文本框；老框清空删除后 Ctrl+Z 恢复原文。
- 编辑中滚轮 = 滚画布；光标到屏幕底部时画布自动上移。
- 编辑中不出现文本框内部滚动条。

### 7.3 选中、移动、改尺寸

- 单击选中；拖动框体移动；方向键微调（已有）。
- 左右两条整高竖线 = 改宽；高度继续自动。
- 四个角 = 等比缩放字号；双指 = 画布缩放。
- 没有上下边手柄；没有旋转柄。
- 选中后操作条提供复制/删除/层级/收藏等通用动作。

### 7.4 样式

- 字号：`[18 ▾]` + 常用字号网格（10/14/18/24/48/64）；编辑中也可以改。
- 颜色：黑/红/当前色 3 格 + 取色板；文字色和笔色分开记。
- 不加粗/斜体/下划线工具条；Markdown 渲染。
- 对齐、字体族：P2。

### 7.5 触摸

- 单指：选中/拖动/改尺寸。
- 双指：画布缩放/滚动；编辑窗上也要能双指滚画布（P1）。
- 编辑时提供「完成」大按钮。
- 长按文字 = 选中；双击 = 编辑（与鼠标一致）。

### 7.6 二次实测后的定稿规则

#### 7.6.1 两个面板，各管各的

| 面板 | 管什么 | 什么时候出现 |
|---|---|---|
| **文本工具色带**（字号/颜色） | **下一次输入**的默认值 | 文本工具激活时；我们的色带默认展开，所以不需要“再点一下画布”才出现 |
| **选中操作条**（字号/颜色/锁定/层级/复制/删除） | **当前选中的文字** | 选中一个文本框时；移动/编辑时隐藏 |

- 两者不会互相改：色带只改默认值；操作条只改选中的那一个。
- 选中文本时，**色带可以继续留在原位**（它管下一次输入），但**下方操作条一定会出现**（它管当前文本）。
- 编辑中**不显示操作条**；移动中也不显示（和 ClassIn 一致）。
- 我们现在的代码是“色带被选中文本接管”，要改成上面的分工：色带永远只做默认值，选中文本的字号/颜色走操作条。


#### 7.6.2 编辑框 = 选中框，编辑时不带操作条

- 编辑和选中用**同一个几何框**，不要另做一个白色卡片。
- 编辑时下方不显示操作条；点「完成」/点外面/`Ctrl+Enter` 提交后才回到“选中 + 操作条”。
- 底色：
  - 白板模式：编辑底 = **当前板色**（白/绿/黑），看起来就是“同一个底”；
  - 文档/图片上：暂时仍用页面底色（白），因为 RichEdit 不能真正透明；
  - 完全透明需要换掉 RichEdit（自绘编辑器 + IME），成本高，先不做。

#### 7.6.3 光标与点击

| 指针位置 | 光标 | 单击 | 拖动 | 双击 |
|---|---|---|---|---|
| 未选中的文字上 | **I 字** | 选中 | 选中后可直接拖 | 进入编辑 |
| 已选中的文字框内 | **移动十字** | 保持选中 | 移动 | 进入编辑 |
| 左右竖线 | 左右箭头 | — | 改宽 | — |
| 四个角 | 斜箭头 | — | 缩放字号 | — |
| 空白画布 | I 字 | 新建文本 | — | — |

- 双击进入编辑：光标落在**点击处**（比 ClassIn 的“永远末尾”更省一步）。
- 如果用户想改末尾，进入编辑后按 `Ctrl+End` 或再点末尾即可。

#### 7.6.4 屏幕边缘

- 宽度到**屏幕可用宽**（左右各留 16×Unit）就**停止变宽、开始换行**；
- 如果框的右边缘已经贴到屏幕边，换行后仍放不下，就把整框**往左让一次**，绝不让内容长到屏幕外；
- 粘贴无换行的长文本同理：先到上限换行，不向右无限延伸。

#### 7.6.5 橡皮与清空

- **整笔擦**：点到文本框 = 删除整个文本框，一步撤销；
- **面积擦**：只擦墨迹，**不碰文字**（和 ClassIn 一样保护文字）；
- **清空**：文字一起清掉，可撤销。

#### 7.6.6 选中操作条（照 ClassIn 的信息结构，颜色用我们的）

- 位置：文本框下方；**所有对象统一不翻转**；靠近屏幕底部时夹在屏幕边缘。
  - 现在代码里只有 `BarRectForTextBox` 会翻到上方，其他对象都不翻——这是历史特例，**要删掉**，统一走 `BarRect`。
  - 画布滚动时，操作条跟着对象走；对象滚出视野后条也消失，不单独粘在屏幕边。
- 显示时机：只有选中时显示；**移动中、编辑中都不显示**。
- 收起：点最左边的 `×` 收缩成一颗 `+` 圆钮；再点 `+` 展开。这个我们已经有，保持。
- 按钮：`×`（收起）、字号下拉、`A`（颜色）、锁定、图层、复制、删除。
- 字号：**10 / 14 / 18 / 24 / 48 / 64** 六档，默认 **18**（2026-11-01 用户拍板；老配置里的 15 自动迁到 18）。
- 颜色：文字单独 4 个色位 **红 / 黑 / 白 / 自定义**；窄带只显示 3 个，宽带到 4 个。
  点已选中的色位再点一次 = 改这一格（和画笔同一套逻辑）。色带只管下一次输入，
  选中文字的颜色走操作条。
- 操作条：**七格**（收起 / 字号 / 颜色 / 锁定 / 层级 / 复制 / 删除），
  **所有对象统一不翻面**，贴底时卡在屏幕边缘；编辑、移动时隐藏。
- 颜色：**不抄 ClassIn 的 16 格固定色**；复用我们画笔的色位/自定义/最近逻辑，但文字单独存一份，不和笔色互相改。
- `AI`：ClassIn 有；我们第一版先不放，避免多一个未完成入口。


#### 7.6.7 选中框与编辑框

- 选中框只在选中时显示；点空白消失；编辑时连选中框一起消失。
- 编辑框和选中框同一几何、同一底色；编辑时没有操作条。
- 编辑底：白板模式直接用板色；图片/PPT 上先做“很淡的白”而不是纯白；完全透明需要换自绘编辑器，暂不做。

#### 7.6.8 滚动与选中状态

- 鼠标滚轮滚画布：**保留选中**（ClassIn 的做法，也符合“滚轮只是看，不是换上下文”）。
- 触屏双指滚：建议也**保留选中**，和鼠标一致；ClassIn 会取消选中，我们认为是它的触屏特例，不必照搬。
- 点空白才是取消选中。

#### 7.6.9 空文本删除

- 内容删空 → 文本框消失。
- **我们保留 Ctrl+Z 可恢复**（恢复清空前的原文）；ClassIn 不能撤销，这是我们可以做得更好的地方。
- 垃圾桶删除同样可撤销。


### 7.7 用户观察到的 ClassIn 缺陷，我们怎么避免

| ClassIn 的行为 | 问题 | 我们的处理 |
|---|---|---|
| 在屏幕边缘输入，框一直长到屏幕外 | 内容看不见、要手动移回来 | **宽度上限 = 屏幕可用宽**；到边界换行；必要时把整框往左让 |
| 文本框不能调大小 | 长文本/窄栏无法排版 | 左右两条整高竖线可拖宽；最窄到“最长不可断 token”（中文一个字） |
| 双击编辑时光标在末尾 | 想改第二行要先点一下 | 双击时**光标落在点击处**，不用先点一下 |
| 没有 Markdown | 不能写公式/粗体/标题 | 保留 Markdown；编辑窗显示源码，提交后渲染 |
| 橡皮擦不了文字 | 想删文字只能选择+删除 | 建议：**整笔擦 = 删整个文本框**（可撤销）；**面积擦 = 只擦墨迹，不碰文字** |
| 清空画布会清掉文字 | 误清空风险 | 保留（和清墨迹一致），但清空可撤销 |
| 文本工具点完别处又出新框 | 容易误建空框 | 我们保留“点空白新建”，但空文本提交即删；不想新建就切选择工具 |
