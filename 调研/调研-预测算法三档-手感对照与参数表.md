## 二、怎么切（三个入口是同一件事）

- **设置页**：更多 → 设置 → 书写 → **「预测算法」**（点一下切换 **v6 ⇄ Google**，右侧显示当前档；
  落盘。经典 B4 已退役、不在循环里）。
- **设置页**：同列下方 **「预测时长」**（自动 / 10 / 15 / 25 ms，点一下换一档，**三引擎统一**；落盘）。
- **全局键**：`Ctrl+Alt+Shift+P` 切换预测算法 v6 ⇄ Google（任何程序在前台都生效；落盘）。
- **命令行**：`--predengine b4|v6|google`（b4 为退役后的对照口）、`--predlatency N`
  （均**本会话对照用、不落盘**——跑一次实验不该把用户选好的档改掉；要"记住"就用设置页那两行）。
- ⚠ 总开关是「**墨迹预测**」（**默认开**——2026-10-14 发布测试版起，用户开箱直接体验；
  不想用就在设置里点掉）：算法与时长的**档位只决定"打开时怎么跑"**，不负责开关。
- 启动日志会打一行：`笔迹预测: 开（自绘尾；算法 N = …；地平线/预测时长 …）`——"调了没调上"
  一眼可见（这条和湿墨档位同一条纪律）。

## 三、参数表（以下一律按**进仓代码**的默认值，不按各包 README）

### 3.1 共同形状（三档对照）

| 参数 | 经典 B4 | 改进版 v6 | Google | 单位 | 说明 |
|---|---|---|---|---|---|
| 预测时长上限 | `HorizonMs` **10** | `HorizonMs` **21.3**（= `LatencyMs`） | `PredictionIntervalMs` **21.3** | ms | 预测尾最长外推多久（各自夹 8~200） |
| 整体阻尼 | `Damping` **0.8** ① | `Damping` **1.0**（再 × 自适应系数） | ——（无此概念） | — | 预测位移乘的系数 |
| 加速度项衰减 | `AccelDamping` **0.4** | `AccelDamping` **0.4**（再 × 自适应系数） | `AccelerationWeight` **0.5** | — | 二阶项权重（Google 另有 `JerkWeight` 0.1） |
| 最小速度（不预测门槛） | `MinSpeed` **0.02** | `MinSpeed` **0.06** + 迟滞 0.4 | `MinTravelSpeed` **0.015** / `MaxTravelSpeed` **0.075** | px/ms | v6 进入/退出分离；Google 是置信度因子 γV 的上下限 |
| 断笔间隔 | `MaxGapMs` **40** | `MaxGapMs` **40** | 时间戳缓冲 20 样本 | ms / 个 | 间隔超过就当新轨迹 |
| 单次最多点数 | `MaxPoints` **4** | `MaxPoints` **4** | 由置信度决定（前推 ≤ ⌈21.3ms×240Hz⌉ ≈ **6 点**，另加追赶段 ≤48） | 个 | 尾长上限的另一半 |

> ① B4 在引擎里**每帧覆盖**：有压感 Damping 0.8 / 无压感 0.7；速度平滑 0.4 / 0.6（见 3.4）。

### 3.2 经典 B4 专属

| 参数 | 默认 | 说明 |
|---|---|---|
| `SharpTurnCos` | 0.5（cos60°） | 夹角 >60° **硬丢速度**（拐弯这一帧不预测）；命令行 `--turndeg` 可改，180° = 只挡完全反向 |
| `MaxDistance` | **12 px** | 硬限幅（数学封顶，"任何情况不甩过 12px"） |
| `AccelDamping` | 0.4 | 见 3.1 |

### 3.3 改进版 v6 专属 / 新增

| 参数 | 默认 | 说明 |
|---|---|---|
| `LatencyMs` | **21.3** | ① 延迟绑定（= InkTeach 实测端到端：Present→屏 16.3 + 采样 5）；`SetMeasuredLatency()` 一步到位 |
| `AdaptiveCapFactor` | **1.0** | ② 自适应限幅：cap = min(6px, 速度 × 延迟 × 1.0)——慢写自动收紧、快写兜底 |
| `AccelRatio` | **0.5** | ③ 线性度门控：二阶项 ≤ 0.5 × 一阶项（学自 Google 的 γμ） |
| `MinSpeedExitRatio` | **0.4** | 门槛迟滞：进 > 0.06，退 < 0.024（切档次数 21 → 15 次/字） |
| `HardTurnCos` / `TurnDepth` | **0 / 0.75** | 只挡 >90° 硬底线；60~90° **软收缩**（按角度压到最多 0.25×），不再丢速 |
| `DirAdaptive` / `DirThresh` / `DirFloor` / `DirEmaA` | **2.0 / 0.35 / 0.15 / 0.3** | 方向不稳定度自适应：乱涂/锯齿主动收缩；正常板书（0.03~0.32 rad/点）不触发 |
| `SpeedAdaptive` / `AdaptiveFloor` | **0 / 0.35** | 速度突变收缩。⚠ 代码默认 **0（关）**——README 老表里的 2.0 是 v3 口径，认代码 |
| `MaxDistance` | **6 px** | 硬限幅（比 B4 更紧：实测 6px 是"悬崖点"，7px 极端甩尾就从 3.4% 涨到 13.5%） |
| `VelocitySmoothing` | **0** | v3 曾默认 0.6；v6 重扫后关回 0，平滑职责交给方向自适应 |

### 3.4 引擎运行时的公共口径（三档都吃这一层，`Engine.UpdatePredictTail`）

| 层 | 值 | 说明 |
|---|---|---|
| B4 每帧覆盖 | Damping 0.8（压感）/ 0.7（无）；VelocitySmoothing 0.4 / 0.6 | 按"这一笔有没有压感"；**只作用于 B4**（v6 / Google 用各自文件默认值，原味对照） |
| 长度限速（显示层） | 伸 0.20 / 缩 0.11 / 失效快收 0.72 px/ms（90Hz ≈ 2.2 / 1.2 / 8 px 每帧） | 治"跳跃的笔头"；对三档完全相同 |
| 湿墨退场 | 本笔有系统委托轨迹时，预测整体 ×0.35（`--wetpred`） | 委托湿墨已负责"墨跟笔"，预测只留一丝对冲 |
| 锚点 | 建模平滑输出末点（`StrokeMotion`），不是原始末点 | 接头处不跟笔身错开；三档相同 |

### 3.5 Google 专属（置信度四因子是它防甩尾的核心）

| 参数 | 默认 | 说明 |
|---|---|---|
| `ProcessNoise` / `MeasurementNoise` | **1e-2 / 0.25 px²** | 卡尔曼噪声（**改后必须 `ApplyParams()`** 重建滤波器） |
| `MinOutputRate` | **240 Hz** | 内部上采样率（位置模型按它逐拍推进） |
| `MinStableIteration` / `MaxTimeSamples` | 4 / 20 | 起笔前 4 点不预测；时间戳窗口固定 20 个 |
| `DesiredNumberOfSamples` | **20** | γs：样本数置信度饱和点 |
| `MaxEstimationDistance` | **0.375 px**（=1.5×测量噪声） | γε：估计位置与最后输入点的偏离 |
| `MaxLinearDeviation` / `BaselineLinearityConfidence` | **2.5 px**（=10×测量噪声）/ 0.4 | γμ：三次预测 vs 线性预测的偏离（"飞出去"的闸） |
| `EnableWobbleSmoother` / `EnablePositionModeler` | **true / true** | 输入已平滑过可关前者（少一级延迟）；想更跟手/不要弹簧滞后可关后者 |
| `AccelerationWeight` / `JerkWeight` | **0.5 / 0.1** | 原作者默认；让预测偏向线性 |

## 五、单位标定（换画布单位时怎么改）

- 三档都按**屏幕像素 + 毫秒**标定（InkTeach 喂进来的就是屏幕坐标，`NowMs` 一把单调时钟）。
- 如果哪天喂的不是屏幕像素（DIP / 缩放 1.5× / 毫米）：
  - **Google**：`MeasurementNoise ÷ 1.5²`；长度类（`MaxEstimationDistance`、
    `MaxLinearDeviation`）与速度阈值（`MinTravelSpeed` / `MaxTravelSpeed`）`÷ 1.5`；
    改噪声后 **`ApplyParams()`**。
  - **v6 / B4**：长度类（`MaxDistance`）与速度类（`MinSpeed`）按同一比例换算；
    `HorizonMs` / `LatencyMs` 是时间，不动。
- **别把三个算法"调到看起来一样"再比**——它们的参数语义不同（硬限幅 vs 置信度），
  保持一致的是**单位**，不是数值。

## 七、已知边界（看手感时先知道这几条）

1. **v6 / Google 不吃 B4 的每帧覆盖**（压感相关的 0.7 阻尼 / 0.4-0.6 平滑）——它们跑各自
   文件默认值，这是**有意**的"原味对照"；要调就在 `UpdatePredictTail` 里加一行。
2. **Google 的预测基准点不是笔尖**——它前面有弹簧位置模型（滞后），预测尾的连接段可能
   先往回兜一小截再前推。这是算法设计（"追赶段"），不是 bug。
3. **抬笔 / 换笔 / 换档都要复位**：三档共用 `ResetPredictTail`，都走这条路。
4. `--predict3`（DL 网络那条通道）**不在这三档里**：它强制开启时优先级最高，
   起笔预热段仍用 B4 兜底；两套互不干扰。
5. 三档共用显示层限速（伸 2.2 / 缩 1.2 px/帧 @90Hz）——**尾巴在屏幕上"长出来"的速度
   三档基本一样**，能看出的差别在方向、长度上限、以及折角处怎么收。对比手感时别把
   限速的功劳算给算法。

## 八、预测时长（补多长）怎么定 —— 「预测时长」那一行的来历

> 2026-10-14 用户提问："微软不就有这个吗？我最大的问题好像就是一帧延迟——按一帧来设
> 应该是多少？" 这一节就是那个讨论的结论。

**规则（学微软 Wet Ink）**：预测距离 = 速度 × **本机实测端到端延迟**——延迟多长就补多长。
不能凭感觉拍，也不能照抄别人的数：

| 你测的屏 | 一帧（刷新周期） | 本机实测端到端 | **推荐预测时长** |
|---|---:|---:|---:|
| 60 Hz | 16.7 ms | ~17~21 ms（上屏段 ≈16ms + 采样→提交 1~5ms） | **17~21 ms** |
| 120 Hz | 8.3 ms | ~10~11 ms（上屏段 ≈10ms + 1ms） | **10~12 ms** |

（上屏段 = Present 返回 → 像素亮，DWM 合成 + 扫描输出的硬地板，应用侧改不动；
原始数据见 `调研/延时-实测与优化.md` §四/§九。）

**「预测时长」档位**：设置页「书写 → 预测时长」，点一下循环
**自动 → 10 → 15 → 25 → 自动**，对三个引擎统一生效（B4 改 `HorizonMs`、
v6 走 `SetMeasuredLatency`、Google 改 `PredictionIntervalMs`——同一件事三种叫法）。

| 档 | 谁适合 |
|---|---|
| **自动** | 各引擎出厂默认：B4 = 10ms（60Hz 下偏短）、v6 / Google = 21.3ms（60Hz 下正好、120Hz 下偏长） |
| **10 ms** | 120Hz 屏的对准值；也用来把 v6/Google 从 21.3 收到"一帧"看差别 |
| **15 ms** | 中间值：60Hz 略欠、120Hz 略过；先感受"欠一点 vs 过一点"的手感差 |
| **25 ms** | 60Hz 的激进端（>一帧）；"舒服地过头"就说明余量还够，但停笔/折角的回缩会更明显 |

**注意四件事**：
1. 预测补不了「起笔第一下」「急转瞬间」「停笔回缩」——这些地方的余感不归时长管；
2. 显示层限速（伸 ~2.2px/帧）会把大档位的效果**分几帧慢慢长出来**，别只写一笔就下结论；
3. 每多补 10ms ≈ 多伸 `速度 × 10ms × 阻尼`（1px/ms 时约 +8px）——这段就是在
   急停/急转处"多拱一下"的来源；v6 有 6px 硬顶兜底，Google 没有，时长直接是它的最坏甩尾乘数；
4. 命令行 `--predlatency N` 与档位等效但**不落盘**（本会话对照用），N 任意（夹 8~200）。

## 九、Google 档"尾巴跑到后面/方向反了"排查记录（2026-10-14）

> 用户真机反馈：Google 档"就算画一条线，预测尾都会乱跑、跑到后面、方向刚好反了"。
> 这一节是**对照上下游源码 + 用进仓代码复现**的完整结论。**结论先行：卡尔曼核心没有抄错；
> 两个真问题——① 接入时间线错位（主因）；② 三处 1000× 单位错位（放大器）。**

### 9.1 逐段对照：对得上的部分（不用怀疑）

| 组件 | 对照结果 |
|---|---|
| 卡尔曼滤波（F/Q/增益/协方差更新/一阶只设位置/`P=I` 重置） | 与上游 `kalman_filter.cc` **逐项一致** |
| 单轴预测器、`max_time_samples=20` 时间窗、"dt=1 假设 + 幂次修正" | 一致 |
| 置信度组合 `γs·γε·γV·γμ`、`n=⌈γ·τ/Δt⌉`、追赶段三次曲线公式、前推三次多项式 | 一致 |
| 位置模型弹簧（半隐式欧拉、`11/32400`、`72`） | 一致（仅"锚点路径"简化，见 9.3-⑤） |

### 9.2 主因：接入时间线错位（**不是移植的错，是接入的错**）

上游里，**正在写的墨迹本身就是模型器的输出**——预测段的起点（弹簧笔尖）和屏幕上的
笔迹末梢是同一条时间线，首尾无缝。我们的 App 画的是**原始点**（比模型器笔尖快），
而预测点列是"**从滞后的弹簧笔尖出发的追赶段 + 前推段**"。相对原始末点画出来：

| 匀速直线（8ms 采样） | 预测点相对末点 | 弹簧笔尖滞后 |
|---|---|---:|
| 0.5 px/ms | **从 −6.7px 开始** → +13.2px | −8.7px |
| 1.0 px/ms | **从 −13.4px 开始** → +26.3px | −17.5px |
| 2.0 px/ms | **从 −26.7px 开始** → +52.6px | −35.0px |
| 减速到停 | **整段都在后面**（−0.9~−0.1px） | ≈0 |

→ 速度越快，"往后的钩子"越长；减速停笔时整条预测都在笔尖后面。**这就是"跑到后面"**。

### 9.3 放大器：被噪声来回拨的置信度 + 三处单位错位

用鼠标式输入（整数坐标 + ±0.75px 抖动）在 1px/ms 下复现：

| 帧 | 追赶段 | 前推段 | \|估计−输入\| | 预测偏移 |
|---|---:|---:|---:|---|
| 80 | 5 | 5 | 0.014px | [−13.8, +20.8] |
| 100 | 5 | **0** | **0.515px** | [−13.9, 0.0] ← 整条在后面 |

### 9.4 三处 1000× 单位错位（均为 px/s 与 px/ms 混用；与对拍脚本同源，对拍查不出）
