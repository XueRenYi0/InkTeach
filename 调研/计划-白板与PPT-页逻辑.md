# 白板与 PPT 的"页"逻辑：参考 InkClass，避开它的先天缺点

日期：2026-09-16　　状态：**调研完成，等拍板**（第六节有"我替你定的三条默认"）

对照对象：本机 `D:\文件集中\code\画布测试\Ink-Canvas-Dev`（下称 InkClass）。
所有"事实"都带行号，都是从源码读出来的；"判断"和"建议"分开写。

---

## 〇、先说结论（给不想读长文的人）

InkClass 的"页"**不是**为了限制书写范围（它的白板页内部照样是无限画布，往下不设上限），
它给老师的其实是**三件事**：

1. **回看**——"我在第几页，翻回去还能看到"；
2. **清空这一页**——清屏只清当前这页，不是整卷；
3. **和 PPT 对齐**——一页 PPT 一套批注，翻页自动跟着换。

**这三件事我们都能给，而且不用它那套实现。** 代价是给引擎加一个很小的"页"概念：

> **页 = 画布上的一段纵向区域（相机看到的范围）＋ 每个对象身上的一个归属标记。**

加完以后，图片、截图、将来任何新对象**天生按页走**，不会再出现"InkClass 那种第 6 个平行数组"。

已经做好的"整屏翻页"不白做——它正好变成新模型里的**页内导航**（第 5 节）。

## 一、InkClass 的白板页：事实（都带行号）

### 1.1 页就是"一套笔迹 + 一套撤销历史 + 一个滚动位置"

| 事 | 在哪 | 是什么 |
|---|---|---|
| 每页一套撤销历史 | `MW_WhiteboardControls.cs:50` `TimeMachineHistory[101][]` | 它的注释原话：**"0 用来存储非白板时的墨迹以便还原"**——一个数组同时在装两种东西 |
| 页数上限 | 上表那 6 个数组都是 `[101]`（见 1.4）| **硬上限 101**：1..99 是白板页，0 被征用去装"非白板墨迹" |
| 每页一个滚动位置 | `MW_Scroll.cs:255` `_pageScrollOffsets = new double[101]` | 因为滚动会改笔迹坐标，**滚动位置变成了"内容"的一部分**，必须跟着页存 |
| 当前页 / 总页数 | `MW_WhiteboardControls.cs:48-49` | 两个裸 `int` |
| 换页 | `:107-144` Previous/Next | `SaveStrokes()` → `ClearStrokes(true)` → 改页号 → `RestoreStrokes()` |
| 插页 / 删页 | `:163` / `:181` | **数组整体搬移**（`[i] = [i-1]` / `[i] = [i+1]`）|

### 1.2 "保存 / 恢复一页"到底是什么（最该看清的一处）

```csharp
// MW_WhiteboardControls.cs:52-70  保存一页
var timeMachineHistory = timeMachine.ExportTimeMachineHistory();
TimeMachineHistories[CurrentWhiteboardIndex] = timeMachineHistory;
NoteScroll_SavePageOffset(CurrentWhiteboardIndex);   // 顺便记下这一页滚到哪
timeMachine.ClearStrokeHistory();                    // 撤销栈清空

// MW_WhiteboardControls.cs:83-105  恢复一页
timeMachine.ImportTimeMachineHistory(TimeMachineHistories[CurrentWhiteboardIndex]);
foreach (var item in TimeMachineHistories[CurrentWhiteboardIndex])
    ApplyHistoryToCanvas(item);                      // 逐条重放，把这一页"重演"回来
```

**恢复一页 = 把这一页的撤销历史逐条重演一遍。** 它连"这一页有哪些笔"都是靠重放
操作记录重建的，不是存一份笔迹列表。

### 1.3 滚动是"坐标物化"（一切麻烦的源头）

```csharp
// MW_Scroll.cs:194-215  ScrollNote
var matrix = new Matrix(1, 0, 0, 1, 0, -actual);
inkCanvas.Strokes.Transform(matrix, true);   // 直接改**每一支笔的每一个点**的坐标
```

它的设计说明（`MW_Scroll.cs:17-31`）写得很清楚：这样"橡皮命中检测、墨迹保存、
撤销/重做天然保持坐标一致"。代价写在同文件 `:250-253`：

> "滚动是坐标物化……`_noteScrollOffsetY` 若仍是全局单值，换页时会被 `ClearStrokes`
> 触发的归零清掉，切回原页就出现'内容位置对不上、且被滚上去的内容再也滚不回来'。"

### 1.4 那 6 个平行结构（我数了一下）

| # | 结构 | 装什么 | 在哪 |
|---|---|---|---|
| 1 | `TimeMachineHistories[101][]` | 页 → 撤销历史（**真正在用的那一份**）| `MW_WhiteboardControls.cs:50` |
| 2 | `_pageScrollOffsets[101]` | 页 → 滚动位置 | `MW_Scroll.cs:255` |
| 3 | `_pageImages` ＋ `_imagePageKey` | 页 → 图片元素（＋反查表） | `MW_ImageLayer.cs:39,43` |
| 4 | `memoryStreams[slides+2]` | **PPT 幻灯片号** → 那一页的批注 | `MW_PPT.cs:66,140,307` |
| 5 | `strokeCollections[101]` | 页 → 笔迹集合，**只写不读**：全仓库只有 3 处往里写（`MW_RightPanel.cs:230`、`MW_SimulatePressure.cs:738`、`MW_TouchEvents.cs:415`），**没有任何一处读它**——换页实际走的是第 1 行那份历史 | `MW_WhiteboardControls.cs:44` |
| 6 | `whiteboadLastModeIsRedo[101]` | 页 → 撤销/重做方向标志。**声明了但整个仓库没有任何地方用过**（死代码）| `:45` |

**第 5、6 行本身就是这个设计的墓志铭**：结构建起来了、写进去了，然后没人读。
不是因为作者不小心，而是因为"页"这个概念散在太多地方，谁也不敢确定哪个才是权威。

**这是它最深的先天缺点**：每多一种"按页存的东西"，就要新增一个数组，并且改遍所有
"插页 / 删页 / 换页 / 存盘"的地方。而人一定会漏。

**据我看，已经漏了一处**：插页 / 删页时 `TimeMachineHistories` 和 `_pageScrollOffsets`
都跟着搬移了（`MW_WhiteboardControls.cs:163-170,181-186`），**但图片层没有任何"页号平移"
的调用**（`MW_ImageLayer.cs` 里只有按页取图、刷新显隐、滚动同步，没有插页 / 删页处理）。
所以在第 2 页插一张图、再在前面插一页，那张图还留在"第 2 页"这个编号上，与原来的内容错开。

## 二、InkClass 的 PPT：事实（都带行号）

### 2.1 它怎么知道"现在是第几页"

```csharp
// MW_PPT.cs:53（轮询那条路在 :124）
pptApplication = (PowerPoint.Application)Marshal.GetActiveObject("PowerPoint.Application");
pptApplication.SlideShowBegin     += PptApplication_SlideShowBegin;      // :59-61 / :132-134
pptApplication.SlideShowNextSlide += PptApplication_SlideShowNextSlide;
pptApplication.SlideShowEnd       += PptApplication_SlideShowEnd;
```

- 只对**已经运行着**的 PowerPoint 实例取对象（`GetActiveObject`）；
- 另有一个轮询定时器 `TimerCheckPPT_Elapsed`（`:100` 起），专门为 WPS 做特判（看 `wpp` 进程）；
- 换页回调 `PptApplication_SlideShowNextSlide`（`:555-585`）：
  **把当前页的笔迹序列化成 `MemoryStream` 存进 `memoryStreams[上一页]` → 清空画布 →
  把新页的字节流反序列化进来**；
- 退出放映 `PptApplication_SlideShowEnd`（`:430` 起）：逐页写盘到
  `我的文档\Ink Canvas Strokes\Auto Saved\Presentations\<演示文稿名>_<页数>\`，
  文件名是页号 `0001.icstk`；另外写一个 `Position` 文件记"上次播到第几页"（`:450-455`）。

### 2.2 它为此付出的代价（代码里留下的痕迹）

| 痕迹 | 在哪 | 说明 |
|---|---|---|
| `isEnteredSlideShowEndEvent` 防重入 | `:429,434,439` | 注释原话"**防止重复调用本函数导致墨迹保存失效**"——退出放映的回调会被调两次 |
| `_isPptClickingBtnTurned` 消歧标志 | `:567,569,592,602,635` | "页变了"有两个来源：老师点了**我们的**翻页按钮，还是用了遥控器/键盘。要靠一个标志位区分，免得自己点自己的时候触发自动截图 |
| `MemoryStream[50]` 字段残留 | `:553` | 字段初始化写成 50，后面又被换成 `slidescount+2`（`:66,140,307`）——历史遗留 |
| 存盘键 = 名字 ＋ 页数 | `:450-455` | **改文件名、或者加/删一页，之前所有批注就找不到了**（目录名对不上）|
| 批注坐标 = 屏幕坐标 | 全篇 | 4:3 放映时只用来判断"有没有黑边、要不要换主题色"（`:280-282`）。**批注矩形和幻灯片矩形之间没有任何对齐关系**——所以它做不到"把批注印回 PPT 里" |

### 2.3 还有一条不在 PPT 里、但同属"页"的问题：**白板页关软件就没了**

```csharp
// MW_SaveOpen.cs  SaveInkCanvasStrokes
inkCanvas.Strokes.Save(fs);      // 只存"当前可见的这一页"
```

手动保存存的是**当前这一页**；白板 1..99 页只活在内存的那几个数组里。
（PPT 的每页批注倒是会自动落盘，走的是上面那套按演示文稿命名的目录。）

我们的自动存档是"整份文档一次写"，加页以后天然覆盖所有页，不会有人漏。

## 三、哪些直接沿用，哪些必须换掉

### 3.1 直接沿用（这是它花钱买的、用户真正在用的东西）

| 沿用什么 | 为什么 |
|---|---|
| 白板**分页**：页号显示（`n / N`）、上一页 / 下一页 / 新增 / 删除 | 老师真实需求，且和"整屏翻页"天然是一件事 |
| **清空 = 只清当前这一页** | 这是分页最实在的好处：讲完一题清一屏，不毁整节课的板书 |
| **换页记住每页的位置** | 它的原话教训：不能翻回来又回到顶部 |
| PPT：**一页幻灯片一套批注**，换页自动跟着换 | 教室最常见的用法，也是它"页"这个概念最大的价值 |
| PPT：**记住上次播到第几页**、下次问"要不要跳过去" | 一节课没讲完、下节课接着讲的真实场景 |
| **滚轮要有归属**：画布收起时滚轮还给底层（PPT 翻页） | 我们已经是这样了，继续保持 |

### 3.2 必须换掉（它的先天缺点，换了我们才不出那些 bug）

| 它的做法 | 会出现什么 | 我们改成 |
|---|---|---|
| 每页一套笔迹，切页 = 清空 ＋ 逐条重放历史 | 切页有可见的清空瞬间、代价随内容增长；撤销栈每页一条，**翻回去撤不了上一页** | **一份文档 + 页归属标记**；切页 = 改一个整数（相机跳一屏，O(1)）；撤销栈全局一条，每步记着"发生在哪一页" |
| 滚动 = 改写所有笔迹坐标（坐标物化） | 滚一格是 O(对象数)；滚动位置变成内容、必须跟着页存；图片要单独跟着平移；选区装饰层要手动刷新 | 滚动 / 翻页 = 只动相机（**已经实现**）；对象坐标永远不动 |
| 页状态散在 6 个平行结构里 | 每加一种"按页的东西"就要改所有插页 / 删页 / 换页点——已经漏了图片那一处 | 页信息**只在对象自己身上**（一个字段）；页列表由对象算得出来 |
| 页上限写死 101，插页删页靠数组搬移 | 页数有硬顶；搬移逻辑容易错 | 页是**动态列表**，没有 101 这种硬顶 |
| 白板页只在内存，保存只存当前页 | 关掉软件，99 页板书全没 | 自动存档写整份文档（含所有页） |
| PPT 靠 COM 拿"当前页"，存盘键是"文件名 + 页数" | 没装桌面 Office / WPS / COM 被挡 → 整个功能不可用；改个文件名批注就找不到 | **页的所有者永远是我们**；"现在是第几页"只是输入之一，来源可以换（截图块 / 手动 / 将来的 COM） |

## 四、我们的做法：保留它的语义，换掉它的实现

### 4.1 页是什么（一句话）

> **页 = 画布上的一段纵向区域 ＋ 每个对象身上的一个归属标记。**

两半各有分工，**缺一不可**：

- **纵向区域**（相机看到的那一屏）负责"看到什么"，以及"翻页整屏跳"的视觉与位置感；
- **归属标记**负责"这一页有哪些内容"——清空本页、删本页、存档、撤销回退都靠它。

为什么不能只用前者（按 y 坐标算页）：一支笔可以横跨页缝（写满一页往下写一行），
对象被拖动以后也会换位置。**"归属"是内容属性，不该由坐标推**。

### 4.2 页标记加在哪儿（增量改造，能回退）

| 改动 | 内容 | 影响面 |
|---|---|---|
| 对象加 `Page` | 笔迹 / 图形 / 图片 / 截图各加一个 `Page` 字段，新建时 = 当前页 | `Model.cs` 的对象结构 ＋ 存档格式（**加字段，旧文件默认 0**）|
| 引擎加 `CurrentPage` | 一个整数；翻页时跟着相机一起 ±1 | `Engine.cs`，和已有的 `FlipPage` 同一个地方 |
| 清空改成"清本页" | `Clear` 只删 `Page == CurrentPage` 的对象（**一步撤销**，和现在一样） | `ClearFromUi` |
| 撤销栈**不加页**，只给每一步记一个"发生在哪一页" | 撤销到别的页时**先翻过去**，再执行，并显示一句小提示（"已回到第 2 页"） | `Doc.Undo/Redo` |
| 页列表**不单独存** | "一共有几页" = 所有对象的 `Page` 最大值 ∪ 当前页；空页也能存在（页号带一个"最高到过第几页"） | 一个 `MaxPageSeen` 整数 |
| 存档 | 一份文档带全部页（现在就是这样，加字段即可）| `InkSerializer` |

**关键收获**：图片、截图、将来任何新对象**天生带页**，不需要"InkClass 的第 7 个数组"。

### 4.3 行为对照表（老师说一句，两边各发生什么）

| 老师做的事 | InkClass | 我们 |
|---|---|---|
| 翻到下一页 | 存档 → 清空 → 重放（可能有一下清空感）| 相机整屏跳 167 ms，**内容一直在，不重铺** |
| 回头看上一页 | 同上，且**撤销栈跟着换** | 相机跳回去；**撤销栈还是同一条**，Ctrl+Z 能撤上一页那一步（自动翻过去）|
| 写满一屏继续写 | 只能往下滚（页内无限画布）| 滚轮滚下去（细粒度）**或者**点"下一屏"——两条都在 |
| 点"清空" | 清掉当前这一页 | **一样**：清掉当前这一页 |
| 关掉软件再打开 | 白板页全丢（只存了当前页）| 自动存档写整份文档，**所有页都在** |
| 投影 4:3 的 PPT | 批注铺满屏幕，和幻灯片矩形没有对齐关系 | 一期同样铺满屏；**二期**：截图块可以对齐幻灯片矩形（见 4.4）|

### 4.4 PPT 那一半：页的所有者是我们，页码只是输入

我们的产品是"**覆盖层 ＋ 相机 ＋ 分块缓存**"，底下是什么程序我们都能批注，
所以"和 PPT 对齐"不该等于"绑定 PowerPoint"。分两步：

**一期的做法（不依赖任何外部程序）**：**冻结截图块**
- 按一下"抓这一页"：抓当前屏幕（或 PPT 窗口）→ 变成一页的底图 → 老师在它上面批注；
- 翻到下一张 PPT 就再抓一页；块与块纵向排开，一页一块；
- 老师的体验和"一页 PPT 一套批注"**一模一样**，但：不需要装桌面 Office、不需要 COM、
  WPS / 网页版 / PDF / 视频 全都能用，而且**批注和底图天然对齐**（因为底图是我们自己放的）。

**二期的做法（可选增强）**：能连上 PowerPoint 就读它的放映页码，**自动**帮老师翻到对应的页；
连不上就退回手动。COM 在这里的角色是"**告诉我现在是第几页**"，不是"页的主人"——
它挂了，产品照样能用（这正是 InkClass 没做到的：它把整件事押在 COM 上）。

### 4.5 一条容易被忽略的边界：白板的页和 PPT 的页是**两套**

老师在放 PPT 时，可能切到白板写一屏再切回来。这时候：

- **PPT 页**跟着幻灯片走（第 5 张幻灯片 → 第 5 页）；
- **白板页**是老师自己的第 1、2、3 屏，和幻灯片号无关；
- 两套页各自独立、互不影响，切回去相机保持不动（老师切回去通常就是想看刚才那一块）。

InkClass 是把这两套塞进同一个数组（0 = 非白板）才勉强共存；我们分成两个"页空间"，
不共用索引，也不共用页号显示。

## 五、分阶段（每阶段都能单独验收、单独提交）

| 阶段 | 做什么 | 代价 | 验收（都进 `Run-FuncSuite`）|
|---|---|---|---|
| **1** | 页归属 ＋ "清空本页" ＋ 页号从对象算出来（不接 PPT、不加页管理） | 1.5 天 | 新 `--pagetest`：在第 1 页写 3 笔、翻到第 2 页写 2 笔 → **清空只清第 2 页**；撤销一步把第 2 页那 3 笔要回来；第 1 页一个对象都没动；存档往返页号不变 |
| **2** | 页管理：新增页 / 删除页 / 跳到第 N 页 ＋ 面板上的页号与三颗按钮 | 1 天 | 删第 2 页后，原第 3 页变成第 2 页、内容跟着走（**图片也跟**——这是 InkClass 漏掉的那一处）；空页也能插；撤销能回退"删页" |
| **3** | 冻结截图块：一页一块底图 ＋ 抓图入口 | 1～2 天 | 抓两页 → 翻页看到两块底图；底图不进分块缓存以外的地方（不炸内存）；存档往返还在 |
| **4** | （可选）COM 读出放映页码 → 自动翻到对应页 | 1 天 | 连不上 PowerPoint 时功能照常、只少一个自动跳转；连上时翻页跟随；**这条失败不许影响其它任何功能** |

**顺序是硬的**：4 依赖 3 的"页 == 幻灯片"对应关系；2 依赖 1 的页归属。

## 六、我替你定的三条默认（不同意就推翻）

1. **页与页之间不设墙**：还能滚到页缝、能跨页书写，但"翻一屏"按钮整屏跳。
   好处是保留"连续板书"（这也是我们比 InkClass 强的地方：它一页一套，写不到下一页去）。
   如果你要"绝对不许写到下一页"，我加一条"写到页底自动翻页 ＋ 页边界吸附"，
   代价是手感变硬，而且老师想"在页缝处写一整张图"就做不到了。
2. **撤销是全局一条栈**（不是每页一条）。撤销到别的页时**自动翻过去**并给一句提示。
   这是明确比 InkClass 好的地方（它翻回去撤不了）。
3. **白板页和 PPT 页是两个独立页空间**（4.5），互不共用页号。
