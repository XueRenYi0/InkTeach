# 设计计划：文字工具退纯文本 + 生成内容只读卡 + 背景样式

日期：2026-11-09
状态：**P1 / P2 / P4 已完成；P3 公式对象、P5 粘贴路由由用户取消**
前置调研：`设计-文本输入框-背景与输入安全-2026-11-09.md`

---

## 0. 用户拍板

1. **普通文本输入只做纯文本**，不做 Markdown、不做行内公式。
   - 用户原话：“文本输入单独走富文本或者纯文本……不走 md 公式渲染。”
   - 后续确认：“纯文本，整框一套样式。”
2. **OCR 识别结果、AI 出题结果**保持“文字 + 公式”混在一个**只读卡片**里，不拆成画布上的独立浮动对象。
3. **公式对象**：原计划 P3，用户 2026-11-09 决定不做；普通文本框和只读卡都不再要求独立公式对象。
4. **旧文档不用兼容**：目前没有真实用户，旧格式/旧渲染分支可以直接删。
5. 文字框、卡片的背景要能透明或调色；编辑态可以是实色（窗口版 RichEdit 限制）。**P4 已完成。**

## 1. 目标与非目标

### 1.1 目标

- 文字工具从“文档编辑器”退回“标注工具”：
  - 纯文本、整框字体/字号/颜色/行距/对齐；
  - 双击编辑时看到什么，提交后就是什么，不再有 Markdown 源码态。
- OCR/AI 生成内容走只读卡片：
  - 卡片内可混排文字和公式；
  - 不参与文字编辑，不会因为输入而重排；
  - 渲染一次、缓存，失败可降级。
- 代码上去掉普通文本框的 Markdown/公式解析，减少“源码/渲染”双状态。
- 为后续独立公式对象、图片/图形块、背景样式留好数据位置。

### 1.2 非目标（本批不做）

- 富文本（逐字粗体/斜体/字号切换）。
- 行内公式插入纯文本框。
- AI 流式输出。
- 交互式几何图（GeoGebra 类）。
- 旧文档迁移（没有用户）。

## 2. 内容模型

### 2.1 对象类型

| 对象 | 数据 | 可编辑 | 公式 | 背景 |
|---|---|---|---|---|
| 文字标签 | `TextBoxData Role=Normal, Rich=false` | 双击改纯文本 | 无 | 透明/纸面（后续可调色） |
| OCR 结果卡 | `Role=Normal, Rich=true, ReadOnly=true` | 否 | 卡片内混排 | 默认浅色纸面（后续可调） |
| AI 题卡 | `Role=AiQuestion` | 否（现有交互） | 卡片内混排 | 现有 AI 纸面 |
| 公式对象（P3） | 新对象/新 Role，存 LaTeX | 双击改 LaTeX | 自身 | 透明 |

> 为什么 OCR 用 `Role=Normal + Rich + ReadOnly`，而不是新增 Role：
> 现有选中、缩放、移动、存档、绘制都按 Normal 文本框走；只加两个标志位，
> 改动面最小，也避免 AI 卡片专用分支被误用。

### 2.2 排版分支

```
TextBoxLayout.Build(card):
    Role == AiQuestion  -> BuildAi      (现有，不动)
    Rich == true        -> BuildRich    (原 BuildPlain：Markdown + 行内/块级公式，只读卡用)
    else                -> BuildPlainText (新：纯文本 + 换行/换行色，不解析任何语法)
```

`BuildRich` 只服务 OCR 卡；普通文字永远走 `BuildPlainText`。
以后 OCR 卡要加图片/图形块时，在 `BuildRich` 里加 `ImageBlock/FigureBlock`，不影响文字工具。

## 3. 分阶段计划

### P1 文字工具退纯文本（本批）

改动：

- `AiCard.cs`
  - `TextBoxData` 增加 `Rich`、`ReadOnly` 两个字段（默认 false）。
  - 原 `TextBoxLayout.BuildPlain` 改名 `BuildRich`，内容不动（OCR 卡继续用）。
  - 新增 `BuildPlainText`：只做硬换行、自动换行、逐行颜色、逐字颜色 span；不解析 `#`、`- `、```、`**`、`$`。
  - `Build` 按上面的分支选择。
  - `CreatePlain` 明确 `Rich=false, ReadOnly=false`。
- `TextBoxEditing.cs`
  - `BeginTextBoxEdit` 遇到 `ReadOnly` 直接返回。
  - 其他编辑入口统一走这个 guard。
- `InkSerializer.cs`
  - 版本 +1（31），在文本框块末尾写/读 `Rich`、`ReadOnly` 两个字节。
  - 旧版本按 false 读；没有用户，不需要迁移分支。
- 纯文本的自动宽高/行距/颜色行为保持现状；只去掉语法解析。

验收：

- 输入 `**粗体**`、`# 标题`、`$x^2$`、`---`：
  - 编辑态和提交后都按字面显示；
  - 不出现加粗、标题变大、公式图、分隔线。
- 普通纯文本的编辑/提交宽度、行距、光标位置与现在一致。
- `--textboxsim`、`--textboxedit` 通过。

- `reports/newtext-plain-committed.png`（提交后同样字面）

### P2 OCR 结果改只读卡（本批）

改动：

- `HandwritingOptimize.cs`
  - `CreateRecognizedTextBoxForGroup` 返回的文本框设置：
    `Rich=true; ReadOnly=true; Paper=true;`
  - 重新 `InvalidateLayout()` / `FitToContent`，按富文本排版算高。
- `TextBoxEditing.cs`
  - ReadOnly 的框不进入编辑；选中仍走普通文本框的移动/缩放/删除。
- `Overlay.cs`
  - 只读卡按 `Paper` 画浅色底；文字/公式颜色由 `Tint` 决定，不用 AI 卡的黑红规则。
- `InkSerializer.cs`
  - 持久化 `Rich/ReadOnly`，重新打开仍是只读卡。

验收：

- OCR 结果卡显示文字 + 行内公式，不能双击进编辑；
- 可选中、移动、缩放、删除；
- 存档→读档后仍是只读卡；
- AI 题卡显示不变。

截图：

- `reports/newtext-ocr-card.png`（文字+公式混排、只读）
- `reports/newtext-ai-card.png`（AI 题卡对照）

### P3 独立公式对象（已取消，不做）

- 新对象：`Formula`（LaTeX + 字号 + 颜色 + 背景样式）。
- 插入入口：主条/更多里的“公式”；点击后在光标处插入。
- 渲染：`MathRenderer` 矢量优先，退高清位图；缓存。
- 交互：选中/移动/缩放/删除；双击改 LaTeX（简单编辑框，复用纯文本输入）。
- 存档：LaTeX 源码，不存位图。
- 不参与文字流；不做行内公式。

验收：

- 插入 `\frac{-b\pm\sqrt{b^2-4ac}}{2a}`；
- 4x 放大不糊（矢量）或至少不劣化；
- 双击可改源码；撤销/重做/存读/导出通过。

### P4 背景样式（已完成）

- `TextBoxData`/卡片增加：
  - `Fill`（含 alpha，0 = 透明）
  - `Border`（含 alpha，0 = 无边框）
  - `Radius`、`Padding`
- 绘制：`Overlay.DrawTextBox` 统一按样式画；`Paper=true` 迁移为 `Fill=白 0.98 + Border`。
- 编辑底：
  - 最终 Fill 不透明 → 编辑底用同色；
  - 半透明 → 编辑底用和画布混合后的实色近似；
  - 透明 → 编辑底用板色/纸色（现有行为）。
- UI：选中条“背景”入口：透明 / 白纸 / 板色 / 自定义；透明度放高级。
- AI/OCR 卡默认浅色纸面，可改透明。

### P5 粘贴路由（已取消，不做）

- 画布粘贴检测：
  - 含 `$...$`、`\(...\)`、`**`、`#` → 提示“粘贴为题目卡 / 纯文本 / 公式”；
  - 纯文本 → 文字标签。
- 粘进纯文本框：保持字面；给“转为题目卡”提示。
- 不把 Markdown 再塞回可编辑文本框。

## 4. 稳定性设计

- 普通文字只有一条渲染路径：`BuildPlainText` + DirectWrite；没有解析器、没有公式位图。
- 只读卡只有一条渲染路径：`BuildRich`/`BuildAi` + 缓存；坏了可降级为源码/占位。
- 公式对象（P3）独立渲染、独立缓存；渲染失败不影响文字和卡片。
- 失败隔离：文字输入不依赖卡片；卡片不依赖文字编辑器。
- 不再保留“旧框 Markdown 兼容”分支，代码路径更少。

## 7. 参考

- Excalidraw：文字 `textarea` 纯文本；公式靠独立元素/插件。
- tldraw：富文本 WYSIWYG（TipTap/ProseMirror），不解析 Markdown；公式是自定义 shape。
- Word/OneNote：富文本 + OMML 公式对象，可行内，但不是 Markdown。
- ChatGPT/Claude：聊天输出只读 Markdown/KaTeX；输入框纯文本。
