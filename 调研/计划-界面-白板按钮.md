## 〇、先说现状：这不是"新增功能"，是"把已有能力摆到界面上"

引擎里**白板早就有了**：

| 已有的东西 | 位置 |
|---|---|
| `IEngineCommands.SetBoard(bool)` | 界面能切白板的唯一入口 |
| `UiState.Board` | 界面能读到"板开着没有" |
| `BoardOn` / `BoardColor`（默认近白 `0.99,0.99,0.98`） | 引擎内部状态与板色 |
| `SetBoardFromUi(bool)` | 会**整层重画**（内容缓存是按旧底色画的） |

但**界面上一个入口都没有** —— 现在只有一个开发期的命令行开关 `--board`（给自检截图用的）。
老师根本不知道有这个功能。所以这一格的成本极低，收益很直接。

---

## 一、先定语义：白板是"画布开关"，不是工具

**白板 = 画布底色开关**：打开 → 桌面被不透明底色盖住，**笔迹还在**；关掉 → 回到透明批注。
它不是"新的一页"，也不是"清空"。

所以它属于**画布模式**这一类 —— **和"穿透"是同一族**：

| | 管什么 |
|---|---|
| 穿透 | 输入能不能到达下层 |
| **白板** | 画布**画**不画在下层上面（视觉上盖住） |

这条语义直接决定三件事：

1. **点它不改变当前工具**（点完还是拿着笔）；
2. 按钮高亮的意思是**"板开着"**，不是"当前工具＝白板"；
3. 它和穿透**会打架**：开着白板还穿透，点下去打到的是看不见的窗口
   → **开白板时自动把穿透关掉**（假面板里已经这么做）；关白板**不自动恢复**穿透（那是用户自己的选择）。

---

## 二、放哪里：三个候选，推荐第一组

| 候选 | 好处 | 代价 |
|---|---|---|
| **① 主条第一组，挨着"鼠标/穿透"（推荐）** | 语义正确（都是画布模式）；和穿透的联动就在旁边 | 加一格：592 → **640（屏宽 +8%）**；要重排一次工具下标 |
| ② 主条最右、"更多"左边 | 不动现有分组 | 语义上跑到了"编辑/设置"那一边，远离穿透 |
| ③ 放进「更多」抽屉 | 不占主条 | **白板是高频动作**（一节课要切几次），藏进抽屉不合适 |

**推荐 ①。** 我在假面板里先做成了"**末尾单独一组**"——只是为了不重排工具箱下标、降风险；
接引擎时再挪到第一组，你看到的样子和最终版只差位置。

> 极简档：建议**默认也钉上白板**（讲课刚需）：3 格 → 4 格，宽 201 → 245。

## 三、按钮的样子与它的"上带"

| 状态 | 画法 |
|---|---|
| 关 | 普通单色图标（Fluent `Board`） |
| 开 | **强调色底 ＋ 白图标**（和"当前工具"同一套视觉，但语义是"板开着"） |

**它的上带 = 三种板色：`[白板] [绿板] [黑板]`** ——
正好复用"上带＝这个按钮的设置条"那条已经跑通的规则，不用新机制。
（选了某块板 = 顺便把板打开：选板色的人一定是要用板。）

---

## 四、图标

- Fluent 有 `Board`（一块带边框的板），**已经在我们的图标表里** ✓
- 建议常态就用它；激活态 = 白图标（现有机制）
- **唯一值得考虑的"给图标上色"的例外**：让图标里那块"板面"填当前板色（因为它表达的就是板色）。
  先不做 —— 这是"彩色图标"话题里唯一说得通的一处，等你看过再说。
- 不建议用 `Whiteboard`：那枚更像"白板架/白板笔"，而且语义偏"白"（我们的板有绿有黑）。

## 五、边界与坑（这一节最容易漏）

| 情况 | 应该怎样 | 为什么 |
|---|---|---|
| 开白板 ＋ 穿透 | **开板时自动关穿透** | 否则点下去打到看不见的窗口 |
| 开白板 ＋ 截图 | "隐藏批注截取"变得没有差别（下面就是板本身），但**保持可用** | 不为了一个模式去改另一个模式的语义 |
| 开白板 ＋ 清空 | 清空**只擦墨、不动板**；**关白板也不清墨** | 否则等于偷偷帮用户清屏 |
| 白板 ＋ 笔色 | 白板配白笔、黑板配黑笔都看不见 → **选板色时给一次提示**，但不替用户改色 | 用户选的色不能替他改（这条在"白块黑块"那轮定过） |
| 切换的代价 | 引擎里切底色会**整层重画**：几百笔无感；**一万笔时约 180～212 ms 会看得见** | 重度板书下建议加 120 ms 淡入遮一下 |
| 存档 / 撤销 | 白板是**视图状态**：不进撤销栈、不进存档（和穿透一样） | 不然按 Ctrl+Z 会莫名其妙把板关了 |
| 命令行的 `--board` | 保留（自检截图还要用） | 产品入口和开发开关互不影响 |

- **改完要同步改《快捷键总表》**（你们的规矩：改键必须同步改表，`--keytest` 会自动核对）

## 七、分两步做

### 第 1 步：最小闭环（半天）

主条加一格 ＋ 开/关 ＋ 高亮状态 ＋ 快捷键 ＋ 开板自动关穿透。

验收：
1. 点一下 → 桌面被盖住、**笔迹还在**；
2. 再点 → 回到透明批注；
3. 开板时穿透自动关（且按钮上能看出来）；
4. 关板**不清墨**。

### 第 2 步：板色（半天）

上带给三种板色 ＋ 板色与笔色的对比提示。

验收：
1. 白/绿/黑三种板色都对；
2. 选板色会顺手把板打开；
3. 切板色之后笔迹颜色正常、没有被底色污染。

## 八、假面板里已经能演示的部分

### 顺带做的一件事：工具下标改成具名常量

白板要插到"鼠标"后面，意味着后面所有工具的下标都要挪一位。
为了以后不再来一次这种折腾，我把散在代码里的数字下标换成了具名常量：

```csharp
public const int ToolMouse = 0, ToolBoard = 1, ToolPen = 2, ToolHighlighter = 3, ToolLaser = 4,
                 ToolEraser = 5, ToolSelect = 6, ToolShapes = 7, ToolCapture = 8,
                 ToolUndo = 9, ToolRedo = 10, ToolMore = 11;
```

以后**再往主条里插一格，只改这一处**（加常量 ＋ 在 `Tools` 表里插一行 ＋ 改 `GroupEnds`），
不用满文件找数字了。
