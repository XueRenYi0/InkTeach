## 一、四家对比（先查，再写——"站在巨人的肩膀上"）

| 参考 | 连接方式 | 批注存储 | 评价 |
|---|---|---|---|
| **InkClass**（本地 `画布测试\Ink-Canvas-Dev`）| 后台定时器 + `GetActiveObject` + 放映事件 | 每页一个 `MemoryStream`，退出放映写 `.icstk` | 最早那版；**目录名带页数**（插/删页或改名，批注就找不到）；防重入靠标志位 |
| **Ink Canvas Ultra**（本地 `Ink-Canvas-Ultra-26.9.6`）| 加 COM 重试、进程探测、幂等保护 | **按 SlideID 命名**（插/删页不错位）+ 旧目录迁移 | 细节修得最多；但仍是"每页一套 + 切页清空重放" |
| **Inkeys 智绘教**（本地 `Inkeys-20260713a\PptCOM\PptCOM.cs`）| **手写 ROT 扫描**：多 PPT 实例按优先级挑、WPS 的 ProgID 特判、忙重试、COM 逐个释放 | 只输出"当前第几页/共几页"，存储完全归主程序 | **连接层最好**——唯一把"拿页码"和"用页码"解耦的；`dynamic` 写法，.NET 8 可直接搬、零依赖 |
| **ICC 社区版**（GitHub 上最新，2026 年仍在维护，`PPTInkManager.cs`）| **策略模式**（COM / ROT 两套连接 + `PPTROTConnectionHelper`）| 每页流 + **写锁**（防快速翻页串页）+ 100MB 上限清理 + `{名字}_{页数}_{哈希}` + `Position` | **结构最好**；是能找到的最新实现 |

**InkCanvasForClass CE**：<https://github.com/InkCanvasForClass/community>（站点 <https://inkcanvasforclass.github.io/>），
其 PPT 模块分在 `Helpers/PPTManager.cs`、`PPTInkManager.cs`、`PPTUIManager.cs`、`ROTPPTManager.cs`、
`PPTROTConnectionHelper.cs`、`MainWindow_cs/MW_PPT.cs` 六个文件里（资料来自 DeepWiki 的模块页）。

## 二、择优：三块参考 + 一块必须换

1. **连接层参考 Inkeys**：ROT（运行对象表）扫描 + 多实例优先级（有 `ActivePresentation`=1 ＜
   有 `SlideShowWindow`=2 ＜ 放映窗口在前台=3）+ WPS 的 `WPP/KWPP` ProgID 特判 + 进程名探测
   （参考 Ultra："没开 PPT 就别碰 COM"，不然每秒一个 COMException 刷屏）。
   **为什么必须自己扫**：.NET Core / .NET 8 **没有** `Marshal.GetActiveObject`（那是 .NET Framework 的 API）
   ——Inkeys 当年也是因为这个才手写的，我们用同一份逻辑。
2. **存取语义参考 ICC**：进放映读回、退出放映逐页写盘、`Position` 记"上次播到第几页"、
   一页一个文件。
3. **页的键参考 Ultra**：用 **SlideID**（不是页码）——PPT 里插一页/删一页，批注不会整体串位；
   读不到 SlideID 时用**负页码**兜底（参考它的 `GetStrokeCacheKey`）。
4. **必须换掉的一处**：它们都是"每页一套笔迹、切页 = 清空 + 重放/换流"。
   我们换成 **页槽**（见下）：切页是 **O(1)** 的换引用，而且**页内照样能滚动**
   （用户明确要的那条："它们不能上下滚动，我这个依然支持向下滚动"）。

## 三、我们的实现（落在哪）

| 件 | 位置 | 说明 |
|---|---|---|
| 页槽 | `src/InkEngine/Model.cs`（`PageSlot` / `InkDocument.SwitchPage`）| 每页一套：对象、空间索引、撤销栈、计数。**0 号页 = 桌面批注页**（进放映前的批注天然留在那儿——所以不需要 Ultra 那套 `_desktopStrokesBackup` 备份/还原）|
| 状态机 | `src/InkEngine/Ppt.cs`（`partial class InkEngine`）| 进放映 → 读盘 → 切页；翻页 → **离开的页先落盘** → 切页；退出 → 逐页写盘 → 回 0 号页。相机**每页记一个偏移**（翻回来还停在原来滚到的位置）|
| 连接层 | `src/InkEngine/PptLink.cs` | `IPptSource` 接口 + `PptWatcher` 轮询线程（200ms）+ `PptComSource`（ROT + `dynamic`）+ `PptFakeSource`（自检注入）|
| 存取 | `PptStore`（同 `Ppt.cs`）| `%LOCALAPPDATA%\InkTeach\Ppt\{名字_路径哈希}\{SlideID}.inkb` + `Position`；先写 `.tmp` 再换名（防写一半断电）|
| 界面 | `src/InkUi/FullUi.cs`（白板那一格的上带）| PPT 模式时两端箭头**变成"上一页 / 下一页"**（命令走 PPT，不走我们）、右边文字变成 `n/N 页` |

**COM 对象只在轮询线程上碰**（读状态和 Next/Prev/Exit 命令都在那一条线程执行，
命令从主线程入队）——跨线程传 COM 对象会抛 `RPC_E_WRONG_THREAD`（Ultra 的注释里记着这个坑）。

**自动存档那条路也分了岔**：PPT 模式下自动存档改成"写当前这一页到 PPT 目录"
（自动存档是桌面那份板书，把某一页 PPT 的内容写进去，下次启动会被当成桌面批注接回来）。

## 四、自检与真机验证

- `--ppttest`（**31 项**，假页码源驱动）：进放映隔离 / 页内滚动 + 位置记忆 / 清空只清本页 /
  撤销栈每页一套 / 翻页先存上一页 / 退出写盘（两页都在、不含桌面页、Position 记页码）/
  模拟关软件再进 → 从盘里读回 / 界面按钮命令走 PPT / 连不上 PPT 时零症状 / SlideID 读不到时的负键兜底。
- **真机探针 `--pptprobe [秒]`**（我这边没有 PowerPoint 环境，这条路只能用户跑）：
  ```powershell
  dotnet run --project src/InkTeach -c Release -- --pptprobe 20
  ```
  跑起来之后**打开一个 PPT 按 F5 放映、翻两页**（WPS 演示也试一次），
  看到"放映中=True、页码跟着翻页变、SlideID 是个大整数"就是通了。
- `--paneltest` 补了 6 项：进 PPT 模式后点两端 = 给 PPT 的命令、页码跟着变、
  退出放映后回到"翻自己的屏"。（这台机器上"合成输入"被占，跑不出 paneltest，留用户在真机跑。）

## 四之二、底部那两条（"显示在外部，不跟着批注软件走"）

> ⚠ **这一节的形态后来被用户改掉了**（2026-09-26 晚）：从"底部左右各一条 ＋ 可拖进度条"
> 收成 **一条、默认左下角、点页码弹页号面板、长按拿起可拖走**。
> 现行的设计、手势分工与验收见 [计划-PPT条-单条与拖动.md](../计划-PPT条-单条与拖动.md)。
> 下面这段保留，是因为"为什么一开始参考 Inkeys 的两条 + 进度条"仍然是有用的背景。

用户 2026-09-26 追加的要求：

> "我打算把翻页按钮也页码显示模仿 inkeys 显示在外部……外部就是 ppt 页面上，不跟着批注软件走。"

拍板结果：**底部左、右各一条**（参考 Inkeys 的默认档）＋ **可拖的页码进度条** ＋
**页码格长按 600ms 弹菜单**（第一批只有"结束放映"，后期往一张表里加）。

Inkeys 的做法（本地源码 `IdtPlug-in.cpp` 的 `PptUiRoundRectWidget` 一族）：它在 PPT 所在
那块屏上放一组页码组件（`[◀ 50×50] [页码] [▶ 50×50]` ＋ SeekBar 进度条），**底部左 / 底部右**
（设置里还能选"两侧中部"竖排），坐标只按 `PPTMainMonitor` 算、进放映滑出来、退出收回去，
底部中间另有一个"结束放映"按钮。

我们的做法（等价、但少一层）：

| 件 | 位置 | 说明 |
|---|---|---|
| 几何 | `src/InkEngine/PptBar.cs` | 两条的矩形、条内分段（箭头 / 页码格 / 进度条）、菜单矩形；尺度 264×56 逻辑像素，贴底 16 |
| 交互 | `Ppt.cs`（`PptBarPointerDown/Move/Up`、`StepPptBar`）| 箭头**点一下翻一页**；进度条**点/拖跳页**（松手才发命令，"已经在那一页就不发"）；页码格**长按 600ms** 弹菜单 |
| 绘制 | `Overlay.DrawPptBar` | 画在**浮层**上（和选中操作条同一套令牌）——但**必须在 `Matrix3x2.Identity` 之下**：坐标是屏幕坐标，画在画布变换里会被相机平移（出图时当场抓到这个 bug） |
| 穿透 | `Engine` 的 `WM_NCHITTEST` 分支 | 条那一块也算"我的地盘"（`UiContains || PptBarContains`）——不然开着穿透时点它会落到 PPT 上被当成翻页点击 |
| 跳页命令 | `IPptSource.GotoSlide` | COM 侧是 `View.GotoSlide(n)`（Inkeys 那里的同款调用）；命令队列带参数（`Post(cmd, arg)`）|

自检 `--ppttest` 又补 9 项（共 **40 项**）：位置（左下/右下、贴底、都在屏幕里）、
点箭头命令走 PPT、按住进度条进入拖动、拖动中只预览不发命令、**松手才跳页**、
**已经在那一页不发命令**（自检当场抓出来的口径）、长按 600ms 弹菜单、
点菜单"结束放映"命令走 PPT、退出放映后条不再命中。
出图命令 `--pptshow <图>` 看外观（排版自检判不了，按项目规矩单开一条）。

### 箭头的尺寸与"视觉重量"（用户 2026-09-26："我感觉是这个翻页箭头太大了"）

先量了 Inkeys 的原始数字（`IdtPlug-in.cpp:1569-1570`、`:1607-1608`）：

| | 组件 | 箭头按钮 | **箭头图形** | 图形占组件高 |
|---|---|---|---|---|
| Inkeys | 195×60 | 50×50 | **40×40**（图标框） | **67%** |
| 我们 | 264×56 | 52×56 | 9×15 逻辑像素 | 27% |

**结论有点反直觉：我们的箭头本来就比它小一半多。** 它不显得扎眼，是因为箭头是
**图标位图**（笔画相对细）＋ 有按钮底承着；我们是"短粗线"——9 像素宽的 chevron
配 2 逻辑像素线宽（物理 4px），短笔画上就显得又粗又黑，还用了最重的正文色。

所以这一次**不缩尺寸**（再缩触摸屏上就点不中了），只降重量：
线宽 **2 → 1.5**（对齐项目图标规范"1.4~1.5 描边"，见 调研-界面-假面板与图标.md）、
尺寸微收 7%、常态色从正文色改为**次要色**（悬停才转深）——页码才是主角，箭头是配角。
对比图 [reports/PPT条-箭头改前改后.png](../reports/PPT条-箭头改前改后.png)（上=改前，下=改后）。

### 条本身的尺寸（用户 2026-09-26："好大……最起码高度跟着我们的主界面走，大小设置为黄金比"）

| | 改前 | 改后 |
|---|---|---|
| 高 | 56 | **48**（= 界面 `Tokens.BarHeight`，主界面那条的高） |
| 总宽 | 264 | **158** |
| 中区（页码 ＋ 进度条） | 160 | **78** |
| 中区 ÷ 高 | 2.86 | **1.618（黄金比）** |

**黄金比只能落在中区、落不在整条**：48 × 1.618 = 78，而两个箭头格就要 80——
整条做黄金比连页码都放不下。所以取"两端箭头格 40×48 站边上、中区 78 是黄金矩形"；
40×48 的热区在触摸屏上也够用（高度那一维是 48，旁边没有会误触的东西）。

两条护栏（都写进 `--ppttest`，会真跑）：

- **"PPT 条的高 = 主界面那条的高"**——`PptBar.BarH` 在引擎里、`Tokens.BarHeight` 在界面里，
  **同一个数写在两处**，改一个忘另一个就当场红。为什么只能写两遍：分层纪律规定
  依赖只能从上往下，**引擎看不见界面工程的令牌**；所以用断言兜住，而不是让引擎去引用界面。
- **"中区是黄金矩形"**（容差 0.02）——以后改尺寸时这条会拦住"随手把宽度拉长"。

对比图 [reports/PPT条-尺寸改前改后.png](../reports/PPT条-尺寸改前改后.png)（上=改前，下=改后）。

### 白板那一格**不再管 PPT**（用户 2026-09-26 更正）

原话："取消掉白板区的翻页，白板区不需要 ppt 翻页。"
（中间有一版让它"放映时两端变成 PPT 的上一页/下一页"，**撤掉了**。）

- 白板格恢复成"只管白板"：两端 = 上一屏 / 下一屏，右边 = "第 N 屏"；
  语义上也对——这一格是"这块板怎么摆"，不该管幻灯片翻到第几张；
- PPT 的翻页入口只有**底部那两条** ＋ PPT 自己的遥控器/键盘；
- 顺带删掉**没有消费者**的 `IEngineCommands.PptPrev/PptNext/PptExitShow` 和
  `UiState.PptMode/PptSlide/PptTotal`（底部那两条由引擎自绘自命中，界面不需要它们）；
- `--paneltest` 那一条从"放映中两端翻幻灯片"改成**负向断言**：
  "放映中点两端，命令一条都不许跑到 PPT 上去"。

**还没动的（留给下一轮，用户没点头之前不动）**：两条一模一样同时在屏上（视觉重复）、
卡片圆角不上不下（56 高配 10 逻辑像素圆角，看着像"没做完的胶囊"）、投影层数偏多、
进度条两端离卡片边太近（8 逻辑像素）、卡片偏高显空（56）。

## 五、第二批（优化清单，用户已点头的部分）

用户提的：

- **一键删除墨迹**（清当前页）——引擎里已经是"清空 = 清本页"，只差在 PPT 那一条上加个入口；
- **一键保存到本地**（显式导出到"我的文档"，与"下次自动读回"的内部缓存分开）。

调研时发现、值得做的：

- ~~**"结束放映"按钮**（InkClass 有，老师没键盘/遥控器时用鼠标退场）~~
  → **2026-09-26 已做**：长按页码弹的菜单里第一项就是它（`PptMenuItems`）。
- **底部那两条上的三件小事**（都是 Inkeys 有、我们还没做的）：
  · 箭头上**长按连续翻页**（它的长按手势给了"翻页"，我们的长按先留给菜单）；
  · 按 **PPT 窗口所在那块显示器**定位（现在按虚拟桌面底边算，多屏时会贴整个桌面的底边）；
  · 拖进度条时条内的**页码气泡**（现在页码就在条上，气泡是"放大给手指看"）。
- **上次播到第 N 页要不要跳**：`Position` 已经在写了，缺一个**不打扰老师**的询问方式
  （注意：我们的界面规范是"屏幕上一个字都不留"，所以不能参考 InkClass 的弹窗）。
- **页槽内存上限与清理**（ICC 是 100MB 上限、清非活跃页）——一节课 30 页写满也只是十几 MB，
  先不做，但留一笔账。
- **事件替代轮询**：现在 200ms 轮询，翻页后最多 200ms 才切页；Inkeys/ICC 都是
  "事件 + 轮询兜底"（事件要 `ComAwareEventInfo` 注册，.NET 8 上要先验证）。
- **切走的页释放几何缓存**（省显存；切回来重建）。
- 页的底图（`CanvasBlock` / 冻结截图）：页槽里的 `Blocks` 现在还是全局一块，将来要按页。
