# 设计：题目图片块（AI 题卡 / OCR 卡）

日期：2026-11-09
状态：P1 已完成，图片引擎升级为“结构化题图 + 位图兜底”；已用真实 DeepSeek 测试

---

## 0. 用户问题

1. OCR 识别结果、AI 出题卡能不能调背景？——**能**，已经和普通文字框共用背景样式。
2. 如果题目有图片，怎么和 AI 对接？——本文回答并先落地“图片块”。

---

## 1. 调研：成熟产品怎么放题目图

| 产品/方案 | 做法 | 对我们的意义 |
|---|---|---|
| **Mathpix** | OCR 返回文字 + 公式 LaTeX + 图片区域 bbox；图裁成图片，不塞进文字流 | OCR 有 bbox 就裁图；图片是独立块 |
| **ChatGPT / Claude** | 消息内容按 block 排：text / image 各自一块，图片不参与文字换行 | 生成内容用 block，不往 RichEdit 里塞图 |
| **Notion** | image block：可缩放、可加 caption、在文档流里占一行 | 卡片里加 ImageBlock，跟着卡片走 |
| **Word / OneNote** | 图片是 inline object，锚在文字段落；公式是 OMML 对象 | 不是 Markdown；图片/公式都是对象 |
| **GeoGebra / Desmos** | 几何图是结构化对象（点/线/函数），不是截图 | 2D/3D 题图优先结构化 JSON，矢量清晰 |
| **Excalidraw / tldraw** | 图片是画布 shape，文字是另一类 shape | 画布层不把图塞进 textarea；卡片层同理 |

**结论：**

- 题目里的图片应该是**卡片内的一个图片块**，不是独立浮动对象，也不进 RichEdit 文本。
- 图片来源分三种：
  1. OCR 从原图裁出来的图（有 bbox 最可靠）；
  2. AI 返回的图片 URL / base64（适合插画、非几何图）；
  3. AI 返回的结构化几何 JSON（点/线/圆/顶点/棱），App 画矢量图（最适合数学）。
- 不执行 AI 返回的 TikZ/LaTeX/任意 SVG：安全和依赖都太重。

## 2. 数据模型

### 2.1 图片块

```
TextBoxLineKind.Image
TextBoxLine.Image      : ImageData
TextBoxLine.ImageW/H   : 显示尺寸（卡片局部坐标）
```

- 卡片排版时按内容宽度等比缩放，最大高度限制（约 360 逻辑像素）。
- 图片由卡片持有：移动/缩放/复制/删除/导出都跟卡片走。
- 第一版不存“图片文件引用”，直接存 BGRA（和现有图片对象一致，简单）；
  后续可换成 PNG/资产 hash 降低文档体积。

### 2.2 题目图挂在哪

| 卡片 | 字段 | 位置 |
|---|---|---|
| AI 题卡 | `TextBoxQuestion.Figure` | 该题题干之后、答案之前 |
| OCR 结果卡 | `TextBoxData.Figure` | 文字之后（识别结果底部） |
| 普通文字框 | 不挂图 | 普通文字框保持纯文本 |

## 3. AI 接口约定

AI 出题返回可选 `figure` 字段；没有就省略，卡片只显示文字。

```json
{
  "stem": "如图，正方体 ABCD-A1B1C1D1 中，AB=2，求……",
  "figure": {
    "kind": "geometry3d",
    "vertices": { "A": [0,0,0], "B": [1,0,0] },
    "edges": [["A","B"], ["B","C"]]
  }
}
```

也支持：

```json
{ "kind": "image", "data": "base64...", "mime": "image/png" }
```

- `kind = image`：下载/解码后放进 ImageBlock；
- `kind = geometry2d`：点/线段/圆/标签 → 矢量绘制；
- `kind = geometry3d`：顶点/棱/面 → 斜二测/等轴测投影；
- 解析失败/没图：只显示文字，不阻塞出题。

**普通文本大模型不能生成图片**，所以数学题优先让它返回结构化几何 JSON；
插画类才用图片模型/URL。老师也可以手动插入图片作为兜底。

## 4. 分阶段

### P1 图片块进只读卡（本批）

- 数据：`TextBoxQuestion.Figure`、`TextBoxData.Figure`、`TextBoxLineKind.Image`。
- 排版：`BuildAi` 在题干后插图；`BuildRich` 在文字后插图；
  等比缩放到内容宽度，卡片自动长高。
- 绘制：`Overlay.DrawTextBox` 的 `Image` 分支，D2D DrawBitmap。
- 存档：格式 v33，题目/卡片图片写 BGRA；读回仍显示。
- 自检：`--figure` 生成一张立体几何线框图，插进 AI 卡；截图 + 存读。

### P2 AI 图片接口（下一批）

- `figure` JSON 解析；`image` URL/base64 下载、超时、缓存；
- 图片压缩到显示尺寸，按 hash 存资产，避免文档膨胀；
- 失败降级为纯文字/占位。

### P3 OCR 裁图（下一批）

- 当前 OCR 流程是“选中手写笔迹 → 渲染 PNG → 识别文字”，不是拍题照片，
  所以暂时没有“原图 bbox”可裁。
- 以后接“图片/PDF 拍题识别”时，用 OCR bbox 裁出图区域，插 `TextBoxData.Figure`。

### P4 2D/3D 几何渲染（后续）

- 2D：点/线/圆/标签，D2D 矢量；
- 3D：顶点/棱/面，简单投影；隐藏线先不做精确消隐；
- 交互式 GeoGebra 类不做。

## 5. 验收

- AI 题卡：题干、图片、答案顺序正确；图片不超卡片宽；卡片高度包含图片。
- OCR 卡：文字后图片；只读；背景样式仍可调。
- 存读：图片字节、尺寸、位置顺序不变。
- 失败：无图/解码失败只显示文字，不崩溃。
- 截图：`reports/figure-ai-card.png`（本题图）、`reports/figure-ocr-card.png`（OCR 图）。

- `Clone()` 带上图片字段；复制/存档/撤销不丢图。

### 图片引擎重构（2026-11-09）

用户反馈“截图看着完全不一样”，把原来的“手画线框位图”升级为真正的题图引擎：

- `FigureSpec`：AI 返回结构化 JSON（点/线段/圆/标签；2D/3D）。
- `FigureRenderer`：Skia 高分辨率渲染，自动缩放居中、点小圆、线宽、标签外移、
  透明底；3D 用等轴测投影。
- `AiQuestionClient`：真实 OpenAI 兼容 `/chat/completions`，要求模型返回
  `stem/answer/analysis/figure`，解析 JSON 后交给 `FigureRenderer`。
- `--figurelive` 已用真实 **DeepSeek（deepseek-flash）** 测试：约 3–6 秒返回题目 +
  `geometry2d` 点/线段，渲染成带 A/B/C 标签的三角形。
- 产品里的“AI 出题”按钮目前仍走 mock；真实客户端已经能跑，下一步把它接到按钮/状态。

### 最小可交互闭环（2026-11-09）

- `--figurelive` 真实 DeepSeek 返回 `geometry2d` 点/线段；
- 本地不只渲成图片，还直接创建现有 `StrokeKind.Triangle` 对象：
  - AI 负责坐标/题型（复杂计算）；
  - 本地负责对象、顶点手柄、拖动、撤销、存档（实现逻辑）。
