# 调研：线性预测（Chromium 同族）+ 弧长安全层（2026-10-15 接入，替代 v6）

> 来源：用户 2026-10-15 提供的 `线性预测-Chromium.zip`（`LinearPredictor.cs`，零依赖 /
> Native AOT 直编）。对照 Chromium `ui/base/prediction/linear_predictor.cc`（BSD-3）。
> 交付件与 v6 一起备份在 `.revert/2026-10-15-预测线性接入/`。
> 接入后的产品口径（用户定）：**只有「墨迹预测」一个开关**；**毫秒不可调**（地平线固定
> 21.3ms）；取代 v6（退役原因：用户 Win10 真机实测甩尾明显）。

## 一、算法（交付件口径）

| 部分 | 内容 |
|---|---|
| 核心 | **一阶**：`p(t) = p0 + v·t`（v 由最近两点算，用点自己的时标）；`p(t) = p0+v·t+½at²` 是 Chromium 原式，**默认不用**——交付件 A/B：一阶·无限幅 消除率 58.8% / 横向偏离最大 53.84 / 闪烁 4.22；二阶 8.7% / **153.35** / 11.74（a 由速度差分、噪声极大；Chromium 能用是因为前面还有 one-euro filter）。想要原式：`UseAcceleration = true` |
| 预测点铺法 | 按真实采样间隔铺满地平线（**末点必落在 21.3ms**）、最多 8 个点 |
| 安全层 ① 径向限幅 | `MaxDistance = 12px`：每个点沿"笔尖→该点"射线压到半径内 |
| 安全层 ② **弧长截断** | `ArcCap = 6px`：从笔尖起沿预测折线累积长度、超过就在该段内切断——**保留形状、只砍总长**。这就是"最坏偏离 6px 硬保证"的来源（交付件实测 6→7px 是悬崖：极端场景可见甩尾 3.4%→13.5%） |
| 安全层 ③ 方向自适应 | 最近 4 段方向变化的 EMA（`DirEmaA=0.3`）；超过 `DirThresh=0.35 rad/段` 后按 `DirAdaptive=4` 线性收缩弧长上限；`DirFloor=0` = 极不稳时直接不预测。正常板书（实测 0.03~0.32）不触发 |
| 断笔 | 相邻采样间隔 > `MaxGapMs = 40ms` 重置（同 v6 口径） |

交付件自带 A/B（625 条轨迹，四档延迟 15/21.3/30/60ms 结论一致，vs v6）：

| 指标 | 线性（本版） | v6 |
|---|---|---|
| 延迟消除率 | 42.0 | 41.9 |
| 感知滞后 p95 | 22.66 | 23.36 |
| 偏离 p95 | 1.59 | 2.25 |
| 偏离最大 | **6.00** | **6.00**（同为硬保证） |
| 可见甩尾率 | 0.04% | 0.13% |
| 方向夹角 95 | 32.2° | 56.8° |
| 尾端闪烁 | 2.72 | 2.85 |
| 不预测帧 | 7.8% | 2.2%（唯一代价） |

⇒「一阶核心 + 弧长截断 + 方向自适应门控」约 1/5 代码量、全面不弱于 v6。

## 二、接入方式（与本引擎的接口）

- 喂点：`AddPointCleaned` 里 `_predictor.Add(x, y, NowMs)`（与 v6 相同的单调时钟口径）；
- 取点：`UpdatePredictTail`（每帧）`_predictor.Predict(_predBuf)` → 偏移 → **显示层限速**（未动）；
- 开关：`PredictTailEnabled`（设置「墨迹预测」/ `--nopredict2` / `--predict2`）；
- 抬笔 / 换笔 / 换档 → `ResetPredictTail()`；
- 委托轨迹（湿墨）活跃时偏移 ×0.35（`--wetpred`）——沿用 v6 时代规则，未动。

## 三、60Hz 表现（本机即 60Hz，全链路实测）

**本机实测：2520×1680 @ 60Hz**（`EnumDisplaySettings` 读回）——这套自检本来就是
60Hz 节奏上跑的。三段与刷新率相关的账：

1. **预测本身与刷新率无关**：喂点、地平线、安全层全部用"毫秒 + 像素"，60/90/120Hz 同款；
2. **显示层限速按 px/ms 标定**（`UpdatePredictTail`：伸 0.20 / 缩 0.11 / 失效快收 0.72）：
   - 60Hz 每帧预算 = 伸 **3.3px** / 缩 1.8px / 快收 12px；
   - 6px 弧长顶：从 0 到顶 ≈ 1.8 帧（≈30ms）——下笔两个刷新周期内尾就到满；
3. **60Hz 专项实测**（`--tailjumptest`，合成鼠标突发节奏，本机 60Hz 全链路）：

| 指标 | 实测 | 判据/说明 |
|---|---|---|
| 急转 75° 旧方向残留 | **1.6px** | 要求 ≤4（v6 时代的同一钉子） |
| 往前跳最大 | **36.0px/帧** | = 步长 30 + 弧长顶 6，正好设计上限（判据 ≤40） |
| 往后退 | **0 次** | "突突跳"的正身，必须 ~0 |
| 墨前沿−报点 | 平均 **4.9~5.0px** / 最大 **6.0px** | 尾几乎总吃满 6px 硬顶（两次运行） |
| 预测尾激活 | **87/103 帧** | 采样 34Hz 的突发鼠标节奏下 |

**`--noisy` 节奏（间隔 6~41ms、步长 2~34px 随机，更像真鼠标）与 v6 基线对照**（同机同日）：

| 指标 | 线性（新） | v6（9.0.9） |
|---|---|---|
| 回缩次数 | 6（最大 3px） | 8（最大 3px） |
| 明确回退（>3px） | **0** | 0 |
| 单帧前跳最大 | 39px | 39px |
| 墨前沿−报点 | 平均 3.6 / 最大 6.0px | 平均 3.7 / 最大 6.0px |
| 预测尾激活 | 82/111 帧 | 85/110 帧 |

⇒ 抖动节奏下的小回退（≤3px）是**尾长随速度抖动调整**的固有现象（v6 也有、还更多），
不是"突突跳"；`--tailjumptest` 的 noisy 判据据此改为"**>3px 的明确回退 ≤2**"
（默认节奏维持"回缩 ≤2"，两者实测都是 0）。

**解读**：60Hz 下"每帧要补的墨"是 3.3px 量级，6px 的顶两层就够——不会出现
"尾巴慢慢爬"；实测量到的 36px 单帧位移正好等于设计上界，说明限速没有被 60Hz 拉爆。

## 四、参数表（当前生效值）

| 参数 | 值 | 含义 | 何时动 |
|---|---|---|---|
| `HorizonMs` | **按刷新率自动缩放**（2026-10-16 起）：`clamp(0.6 × 帧周期ms, 4, 10)`——60Hz=10ms / 90Hz≈6.7ms / 120Hz=5ms | 预测地平线：对"本机端到端延迟"的近似 | 产品里**不可调**（用户定）；口径"宁可少补、不要多补"——**慢写段的尾会更短更保守；高速段可见长度由弧长顶决定、基本不变** |
| `UseAcceleration` | false | 一阶 | 一般不动 |
| `MaxDistance` | 12 | 径向限幅 | 备胎（被弧长顶统治） |
| `ArcCap` | **6** | 弧长截断 | **最关键旋钮**：0 = 纯 Chromium（无硬保证）；8 更跟手但最坏偏离变 12（需配 `DirAdaptive=2, DirFloor=2`） |
| `DirAdaptive` / `DirThresh` / `DirFloor` | 4 / 0.35 / 0 | 方向不稳收缩 | 乱涂/锯齿场景的安全阀 |
| `MaxPoints` / `MaxGapMs` | 8 / 40 | 铺点数 / 断笔 | 与 v6 同口径 |

## 五、怎么复现（验证命令）

- `--predlinetest`——**纯算法自检**（12 项，不需要真笔/屏幕）：弧长硬保证 ≤6px（跨速度）、
  地平线 21.3ms、急转沿新方向、方向门控不预测、断笔重置、出厂参数钉子；
- `--tailjumptest`（默认节奏）/ `--tailjumptest --noisy`（忽大忽小 + 间隔不齐）/
  `--tailjumptest --off`（关预测对照）——看"往前跳 / 往后退 / 墨前沿−报点"三行；
  判据分档：默认"回缩 ≤2"、noisy"明确回退（>3px）≤2"（依据见上一节 v6 基线对照）；
- `--paneltest`——设置页只剩「墨迹预测」一行的断言；「预测时长」行"已撤"钉子；
- `--pdmetrics <语料> --sweep`——弧长 cap（0/3/6/9/12）离线对照（语料见 `tools/datasets/`）。
