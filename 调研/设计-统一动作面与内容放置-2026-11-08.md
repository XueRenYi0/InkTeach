# 设计：统一动作面与内容放置（AI 结果 / 选择条 / 图形 / 文本 / 照片）

日期：2026-11-08
状态：**规则设计，暂不动代码**
用户原话（整理）：
> AI 识别到文本框/识别为文本以后，没有放在居中或其他合适的位置；以后能不能设计一条规则，自动放到合适位置，不要每次手动调。
> 点点点和 AI 相关部分要优化；图形、照片、文本、各种操作条都可以统一优化。
> 这个操作条走的是什么界面逻辑？是不是也能统一成一套界面？之前设计的悬浮层/界面框架能不能复用？
> 不要这里改一下、那里改一下，先想清楚规则。

---

## 〇、结论

两件事分开做，但共用一条“先定位置、再定表面”的规则：

1. **内容放置**：新增一个纯几何的 `PlacementService`，所有“新内容”都问它要位置。
   - AI 识别（替换手写）：**居中放在原选区**，不是屏幕中央，也不是原选区的左上角。
   - AI 图像 / 图库 / 粘贴：有落点用落点，没有就用**可视工作区中心**；中心被占就按 24px 级联错开。
   - 任何结果都必须完整落在 `FurnitureViewport`（已去掉工具条/面板）内，留 16–24px 边距。
2. **动作面**：保留现有两个渲染目标（`InkUi` 主界面 / `InkEngine` 浮层），但把“动作”统一成一份 `ActionItem` 注册表 + 一套 `BarLayout/PopoverLayout` + 一个 `PopoverHost`。
   - **不**把主工具条和选中条强行合成一个窗口；那是大改且收益低。
   - **要**统一：动作身份、顺序、可见性、溢出规则、弹层翻转/夹取、同一时间只开一个、Esc/点外关闭、脏区。
   - 这样以后加 AI 功能只改注册表，不改条宽、不改命中、不在每个面板里再写一套。

一句话：**把“菜单”当动作的视图，把“内容”当放置服务的请求；两个薄服务，不新造大框架。**

## 一、现状：为什么现在会“这里改一下、那里改一下”

### 1.1 三套渲染体系

| 表面 | 代码 | 渲染目标 | 输入/命中 |
|---|---|---|---|
| 主工具条（笔/白板/图形/收藏/更多…） | `src/InkUi/FullUi.cs` 的 `Cells` 表 | 界面层（UI 窗口） | `FullUi` 自己的命中 → `IEngineCommands` |
| 选中操作条（普通 11 格 / 文本 7 格） | `InkEngine/Selection.cs` 的 `SelectionHandles` + `Overlay.cs` | 引擎覆盖层 | `OverlayLayerManager` 的 `selection` 层（priority 400）→ `ActivateBarButton` |
| 收藏/图形面板、图层面板、AI 菜单 | `InkEngine/LibraryLayout.cs`、`Selection.cs`、`Overlay.cs` | 引擎覆盖层 | 同上，`SelectionLayerHit` / library 层 |
| 更多/设置/帮助/日志/API 整页 | `src/InkUi/Framework/PageHost.cs` + `FullUi` | 界面层 | `PageHost` + `TextInputService` |

### 1.2 三个几何所有者

- `FullUi.CellRect`：主工具条的格子。
- `SelectionHandles.BarRect / BarButtonRectIn / BarAiMenuRectIn`：选中条、文本条、AI 菜单、颜色/图层/字号面板。
- `LibraryLayout`：收藏/图形网格面板。

三者各自算一套，**没有共享的“条/弹层布局”**。所以：
- 加一格要改 `BarButtonCount`、`BarButtonOf`、`ActivateBarButton`、`Overlay` 的图标 switch、以及一堆自检；
- AI 菜单是单独的 `BarAiMenuRectIn`，再长一个收纳菜单就会各算各的；
- 每个动作的位置/避让都在自己的 `Create*` 里写一遍。

### 1.3 已有的框架其实用到了，但只用了“路由”那一半

- `OverlayLayerManager`：已经管选中条/AI 菜单/收藏/回放/计时/点名/PPT/截图的**优先级、捕获、Esc、点外、阻断**（P5.0/A4 收口）。
- `FloatingDirtyPad`：已经管浮层脏区外扩（虚影问题）。
- `PageHost`：已经管整页（更多/设置/帮助/日志/API）的栈、动画、命中。
- `TextInputService`：已经管页面输入框。
- `SelectionHandles`：已经做到“画和命中同一份几何”。

**缺的不是又一个框架，而是两个契约：**
1. `PlacementService`（新内容放哪）；
2. `ActionItem + ActionSurface`（一个动作只登记一次，条/菜单只是它的视图）。

## 二、规则一：内容放置 `PlacementService`

### 2.1 输入与输出

```text
PlaceRequest {
  Kind:        TextBox | Image | Shape | Multi
  Mode:        ReplaceSource | AtPoint | ViewportCenter | Cascade
  SourceRect:  原选区/原墨迹外接矩形（可空）
  ContentSize: 内容原始尺寸（文本框排版后 / 图片像素 / 图形外框）
  Anchor:      Center | TopLeft（默认 Center；点击建文本框用 TopLeft）
  Viewport:    FurnitureViewport（已去掉工具条/面板）
  Avoid:       需要避让的矩形（当前选中、已插入结果、打开的面板）
  Margin:      16–24 逻辑像素
}
→ RectF（最终画布坐标）
```

它是**纯几何**，不碰文档、不碰绘制；所有调用方（AI、图库、粘贴、图片、文本框）只问它一次。

### 2.2 五种模式与优先级

| 模式 | 什么时候用 | 位置规则 |
|---|---|---|
| `ReplaceSource` | AI 识别到文本框、AI 识别为图像（有原墨迹） | **源矩形中心**（水平/垂直居中）；文本框宽度不超过源宽 + 2×pad；图片按 contain 放进源矩形；整体再夹进视口 |
| `AtPoint` | 点击建文本框、拖放/粘贴到落点、图库插入到落点 | 落点作为 `Anchor`（默认中心；文本框点击建用左上角）；夹进视口 |
| `ViewportCenter` | AI 生成图像（无源）、粘贴无落点、图库双击插入 | `FurnitureViewport` 中心；不占屏幕中心，避开工具条 |
| `Cascade` | 中心/落点已被占 | 在 `ViewportCenter`/`AtPoint` 基础上按 (24,24) 逻辑像素逐次偏移，最多 8 次；仍冲突就取最后一个可见位置 |
| `Special` | 截图、回放导出 | 原位/固定位置，不走避让（明确例外） |

### 2.3 决策表（按场景）

| 场景 | 模式 | 锚点 | 尺寸 | 说明 |
|---|---|---|---|---|
| AI 识别到文本框（替换手写） | ReplaceSource | 原选区中心 | 先按原宽，文本多向下扩展；字号按原行高 | **不再从左上角起排**；原墨迹在纸面下，居中后不会偏到一边 |
| AI 识别为图像（来自墨迹） | ReplaceSource | 原选区中心 | contain，比例不变，最大 1.5× 源框 | 图像完整可见，不裁切 |
| AI 生成图像（无源） | ViewportCenter | 工作区中心 | contain，最大 60% 工作区 | 中心被占走 Cascade |
| 粘贴 / 图库插入 | AtPoint（有落点）否则 ViewportCenter | 落点/中心 | 原尺寸，超出视口缩到 90% | 与当前选中重叠时 Cascade |
| 点击建文本框 | AtPoint | 点击点 = 左上角 | 默认 420×60，按内容长 | 保持现有手感 |
| 多对象 | ReplaceSource/AtPoint 的组版本 | 组并集中心 | 保持相对布局 | 整组只移动一次 |
| 截图 | Special | 截图原位 | 原尺寸 | 不移动、不避让 |

### 2.4 现有调用点的改造

- `CreatePlainTextBoxAt(...)`（AI 识别到文本框）：`target` 从“原选区左上角 + pad”改为 `PlacementService.ReplaceSource` 返回的居中框。
- `CreateRecognizedTextBoxes` 多栏：每栏用自己 bbox 的源矩形；不再按整页左上角排。
- `CreatePlainTextBox(...)`（点击建）：`AtPoint`，左上角锚点。
- `CreateRecognizedImage` / AI 图像（新增）：`ReplaceSource` / `ViewportCenter`。
- 图库 `Insert` / 粘贴 `Paste`：`AtPoint` / `ViewportCenter` + `Cascade`。
- `ClampTextBoxIntoView` 保留为兜底，但正常路径由 `PlacementService` 一次算对。

## 三、规则二：动作面 `ActionSurface`

### 3.1 数据模型

```text
ActionItem {
  Id:       稳定字符串（"flipH" / "save" / "ai.recognize.text"…）
  Group:    Primary | Ai | More | Panel
  Label, Icon
  Enabled:  () => bool
  Visible:  () => bool（少数上下文动作）
  Danger:   bool（删除）
  Execute:  () => void
  Shortcut: 可空
}

ActionSurface {
  Id:          "selection" / "text" / "shape" / "main" / "ai" / "more"
  Items:       ActionItem[]
  Layout:      HorizontalBar | Popover | GridPanel
  MaxPrimary:  7（含 AI 格和 ⋯ 前）
  AiSlot:      bool（固定彩色 AI 格）
  Overflow:    bool（放不下/低频进 ⋯）
}
```

**一个动作只登记一次**；条、AI 菜单、`⋯` 菜单、图形面板都是它的视图。增加功能 = 往注册表加一项，不改布局/命中。

### 3.2 布局规则

**横条（选中/文本/图形）**
- 每格 40×40，图标 24，内边距 8，格间距 0（沿用现有 token）。
- 外侧 **核心 4 个主动作 + AI 格 + `⋯`（6 格）**；其余走 `⋯`，不缩点击目标。
- 顺序：开关类在左（收起/颜色/锁定），动作在中（图库/复制），危险动作靠右（删除），AI 格固定倒数第二，`⋯` 固定最右。
- 删除永远外露，不埋进 `⋯`；`⋯` 里不放删除。

**竖弹层（AI / `⋯` / 图形分类）**
- 宽 200，行高 32，图标 + 文字，图标列固定、文字垂直居中。
- **始终贴着操作条**：条下方 → 条右侧 → 条左侧 → 条上方；不按选中对象高度跑
  （大图形时不会把菜单甩到很远）；靠近屏幕边再翻转/夹取。
- 超过 7 行内部滚动，不出现第二个 `⋯`；不做二级嵌套菜单（置顶/置底直接两行）。
- 同一时间只开一个；打开一个自动关另一个。
- 弹层是界面：光标一律箭头，不显示画布工具光标。

**网格面板（收藏/图形）**
- 继续用 `LibraryLayout`，不并进动作条；它是“内容库”，不是“动作列表”。

### 3.3 宿主与互斥

- `OverlayLayerManager` 作为唯一宿主：每个弹层注册一个 layer，`ExclusiveGroup = "selection-menu"`。
- 状态从 `SelAiMenuOpen` + 未来的 `MoreOpen` 合并为：
  ```text
  SelectionMenuOpen : bool
  SelectionMenuKind : None | Ai | More
  ```
  打开时先 `CloseSelectionMenu()`，再开目标；Esc/点外只关当前这个。
- 大结果（AI 预览、AI 设置页）是**独立模态**，打开时先关菜单；菜单不负责承载结果。
- 脏区继续走 `FloatingDirtyPad`，弹层位置变化/关闭时擦旧矩形。

### 3.4 表面清单（迁移目标）

| 表面 | 现在 | 迁移后 |
|---|---|---|
| 主工具条 | `FullUi.Cells` 固定 15 格 | 用 `ActionItem` 注册表；布局仍由 InkUi 画；先做到“加动作不改三处”即可 |
| 选中条 | 11 格固定顺序 | 6 格：收起/颜色/复制/删除/AI/`⋯`；置顶/置底/保存/翻转/锁定/图库进 `⋯` |
| 文本条 | 7 格固定顺序 | 同一套 `ActionSurface`：6 格（收起/字号/颜色/复制/删除/`⋯`），无 AI |
| AI 菜单 | 独立 `BarAiMenuRectIn`，1 行 | 同一套 `PopoverLayout`；AI 动作动态行数/滚动 |
| `⋯` 菜单 | 不存在 | 同一套 `PopoverLayout`；7 行（置顶/置底/保存/左右翻转/上下翻转/锁定/图库） |
| 图形条/面板 | 39 卡 + 分类 | 面板保持；外侧常用 6–8 + `⋯` 用同一套弹层 |
| 收藏面板 | `LibraryLayout` | 不动（内容库） |
| 更多/设置 | `PageHost` | 不动（整页） |

## 四、AI 与 `⋯` 的边界（为什么以后不会打架）

> 2026-11-08 用户拍板：采用 **A（两个入口、一个弹层、一个 open 状态）**。
> AI 格和 `⋯` 都是入口；弹层宿主、几何、互斥组只有一份。

1. **AI 格固定外露**（彩色，倒数第二），不因为 AI 功能多了而移动。
2. **AI 动作只出现在 AI 菜单**；`⋯` 只放非 AI 的低频对象动作。两个菜单不重复同一项。
3. AI 功能超过 6 项：AI 菜单内部滚动/分页；**不给 AI 再长第二个 `⋯`**。
4. `⋯` 不做“AI 子菜单”；需要 AI 就点 AI 格，路径唯一。
5. 大结果/设置/预览是独立模态，不是菜单项；打开时先关菜单。
6. 所有动作有稳定 `Id`，自检断言“无重复 Id、全部可达、同时只开一个”。

**不补**
- 不新造一套 UI 框架；不把主工具条和选中条合成一个窗口；不做通用布局引擎。

## 七、验收（每条规则都要能自检）

**Placement**
- 源选区在左上/右下/屏幕外：结果都完整可见，中心对齐源选区。
- 多栏：每栏独立居中，相对顺序不变。
- 中心被占：Cascade 后不重叠，最多 8 次。
- 工具条/面板开着：结果不压工具条，不钻到面板下面。
- 缩放 0.8/1.0/1.3：边距/字号/框宽一致。

**ActionSurface**
- 每个表面：无重复 Id、Primary ≤7、所有动作可达。
- AI/`⋯`：同时只开一个；Esc/点外只关当前；靠近屏幕边翻转/夹取。
- 加一个假动作：只改注册表，条宽/命中/自检表不变（证明没有硬编码散落）。
- 0.8/1.0/1.3 截图；触摸 40px 点击目标不缩。

## 十、需要拍板的一个点

AI 识别到文本的默认位置：

- **A（推荐，本文规则）**：居中在**原选区**——看起来像“原地替换手写”，最不容易丢上下文。
- B：放在**当前视口中心**——像“弹出一张新卡片”，适合老师讲完一段再展示结果。

我建议 A；只有“没有源选区 / 源在屏幕外”时才退回视口中心。你确认后我按 P0 → P1 → P2 做。
