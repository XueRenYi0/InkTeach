# 截图之后快捷键失效：排查 + 修复（8.3.2）

日期：2026-09-30　　状态：**已修复并自检通过**（`--hotkeytest` 12 项）

用户原话：

> "这个截图现在倒是挺好看的，但是发现截完图以后，笔的快捷键没有用了。
>  因为快捷键比较重要，上课使用频率比较高，所以我希望你建立一个单独的快捷键测试。……
>  我猜可能是因为失去了焦点，你可以排查一下原因。……大体上先排查原因，然后再进行纠正吧。"

**一句话结论**：用户猜得对——**就是焦点**。截图进屋那一下要藏窗口（`隐藏窗口截图`），
藏掉的正好是**前台窗口**，系统把前台转给了别人；恢复显示用的是 `SW_SHOWNOACTIVATE`
（**不许抢焦点**，这是当年为了"不抢 PPT 的键盘"特意选的），**它不会自己回来**。
于是 `Ctrl+P` 这些应用内快捷键全被别的窗口收走。

而且比"截完图"更严重：**取景中的 `Esc`/`Enter` 也一起死了**（它们同样靠我们的窗口收键），
我们的窗口又是 `WM_MOUSEACTIVATE → MA_NOACTIVATE`（点它也不激活），用户自己救不回来。

---

## 一、怎么定位的（先写测试、看它红）

新建 `--hotkeytest`，**必须用真实键盘**（`SendKeyInput` 那条路），理由：
这类故障是"按键发给了别人的窗口"，而旧自检里测批注内按键用的是 `PostMessage`
——**直接投给窗口，焦点丢了照样通过**，永远测不出这个 bug。

判据两条一起看：
1. `GetForegroundWindow()` 是不是我们的覆盖窗口；
2. 真按一次 `Ctrl+P`，工具是不是真换成了笔。

先跑（修之前）——**8 项红**，现场长这样：

```
基线：批注窗口是前台                    PASS  前台 = 批注窗口
基线：真按 Ctrl+P 切到笔              PASS  工具 = Pen            ← 键盘通路本身是好的
隐藏窗口截图 · 取景中：前台还是我们        FAIL  前台 = 别的窗口，取景 = True   ← 根因
隐藏窗口截图 · 真按 Esc 能退出取景         FAIL  取景 = True          ← 同一个根因
隐藏窗口截图 · 退出后真按 Ctrl+P 能用      FAIL  工具 = Eraser
截图（连批注）· 取景中：前台还是我们        FAIL  前台 = 别的窗口       ← 另一种截法也中
焦点恢复后：真按 Ctrl+P 立刻能用          FAIL  工具 = Eraser
```

一眼能看出：**藏窗口那一步之后，前台就再没回来过**。

> 顺带排掉的两个嫌疑人：
> ① `CaptureActive` 卡住（那样所有键会被取景的模态吞掉）——测试里 `取景 = False` 之后
>    按键照样不生效，排除；
> ② 测试环境的焦点/键盘通路——基线的真按键是通的（`工具 = Pen`），排除。

## 二、修复（8.3.2）

三处改动，一个中心思想：**"从别的状态切回批注态"必须把前台/键盘要回来**——
这条纪律引擎里早就写了（`SetPassThrough` 那段注释里点名："以后凡是……都要做这一步"），
`Ppt.ExitPptMode` 也做过；**截图这条流程漏了**（8.3.0/8.3.1 都是）。

1. `Engine.RegainKeyboardFocus()`：`SetForegroundWindow` **＋ `SetFocus`**（幂等）。
   只给前台不够——从"被藏过"的状态回来时，窗口是前台、键盘焦点却可能还在别人那儿，
   屏幕上一切正常、按键全收不到（这正是自检里最后一条红的样子）。
2. 调用点：`BeginCaptureFreeze`（藏完窗口立刻要回来——**取景中的 Esc/Enter 也靠它**）、
   `ConfirmCapture`、`CancelCapture`（回到批注态）。
3. `SetKeyboardMode(on)`：`SetForegroundWindow` 之后补一句 `SetFocus`——
   键盘模式承诺的就是"键盘归批注层"，这一句让承诺成立。

> 边界照旧：**键盘模式关着时什么都不做**（`RegainKeyboardFocus` 先判 `KeyboardMode`）。
> 那种模式下我们本来就不抢键盘（给 PPT 留的），截图同样不该抢。

## 四、教训

- **凡是动过窗口的"隐藏/置顶/激活"三件事，回来时都要把前台和焦点一起要回来**。
  这个坑踩了三次（穿透开关 / 退出放映 / 截图），三次的现象都是"快捷键突然全死了"。
- **自检要用真实键盘**：`PostMessage` 测不出焦点问题——它绕过了系统投递那一段。
  这条以后照着用：凡是"验按键能不能到我们这儿"的用例，走 `SendInput` + 前台判据。
- 合成鼠标**偶尔会丢一次移动**（引擎注释里早就记了），所以和指针有关的判据要有重发余量；
  这次 `--paneltest` 的一次红就是它（重跑即绿），和本修复无关。
