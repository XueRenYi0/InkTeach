## 〇、结论先行

1. **Avalonia 的优势主要在"窗口 / 表单 / 列表 / 文字 / 无障碍"，不在笔迹画布。**
   如果期待"写字更跟手"，Avalonia 帮不上；它甚至会更差。
   如果期待"设置、收藏、PDF 窗口、展台、通用控件更像一个成熟软件"，Avalonia 帮助很大。
2. **推荐架构：Avalonia 做所有"真窗口"的外壳与控件，画布仍是原生 D2D 子窗，批注覆盖层仍是原生。**
   这是"体验收益最大、笔迹风险最小"的组合。
3. **先用 2 周做隔离试点，再决定是否全量迁移。**
   试点要验证的不是"能不能跑"，而是：
   笔迹延迟有没有变、画布空域会不会露馅、触屏键盘能不能用、中文 IME 是否正常、
   12 版的客户区装饰贴靠/动画是否可接受、4 GB 机器是否换页。
4. **不要把所有东西都搬进 Avalonia。**
   覆盖层（透明/置顶/不激活/穿透）和墨迹画布（WM_POINTER/ID2D1Ink/湿墨）
   是这两年最值钱的两块，继续原生。
5. **Avalonia 12 是"强制客户区装饰"**，标题栏由 Avalonia 画（不是原生 NC 区）。
   好处是能完全自定义，坏处是贴靠/动画/DPI 都由框架模拟；试点必须实测。
   如果坚持原生标题栏，要评估 Avalonia 11.3 LTS（`SystemDecorations=Full`）。

## 一、Avalonia 的优势（按课堂体验拆）

| 场景 | Avalonia 给什么 | 自研现状 | 体验差异 |
|---|---|---|---|
| **设置页** | 现成 `TextBox / ComboBox / ToggleSwitch / Slider / TabControl / ScrollViewer`；布局、焦点、键盘、校验、UIA 都有 | `FullUi` 6996 行手绘 + 手写命中；新增一项要改绘制/命中/存取/自检 | **最大**：设置更像现代软件，加项快，键盘/读屏可用 |
| **收藏 / 图形** | `ListBox/ItemsControl` 虚拟化、选择、拖放、动画、空态样式 | 自绘列表；100+ 条目和拖放要自己维护 | **大**：滚动更顺，拖放/多选/空态更稳 |
| **PDF / 白板窗口** | 多窗口、每屏 DPI、模态/非模态、任务栏、贴靠、窗口状态 | 只有覆盖层；没有正常窗口壳 | **大**：能最小化/并排/最大化，老师不用学新操作 |
| **文字输入** | `TextBox` 自带选区/剪贴板/撤销/IME/无障碍；`ComboBox` 可编辑 | 9 组原生 EDIT/RichEdit 各写一套 | **中**：设置类文字更稳；画布富文本仍用 RichEdit |
| **主题/观感** | Fluent 主题 + 样式/模板/动画；暗色/高对比；圆角/阴影一致 | Tokens + 手绘；每类控件都要自己对齐 | **中**：统一感更容易，但要把 Tokens 映射过去 |
| **无障碍** | 内置控件有 `AutomationPeer`，Windows UIA 完整支持 | 自绘按钮默认读屏读不出 | **中**：设置/表单可达；画布仍需自己补 |
| **开发效率** | XAML + 编译绑定 + 预览器/热重载（部分工具付费）；改布局不用改命中 | 画 + 命中 + 状态三份代码 | **大**：新窗口从"几天"变"几小时" |
| **性能（12 版）** | 官方称复杂场景 FPS 提升最高 1,867%，空闲 CPU 修复，内存略降 | 已经很快，但界面代码是手写 | **小**：界面不是瓶颈；主要收益在开发与稳定性 |
| **跨平台** | Windows/macOS/Linux | 只 Windows | 不需要 |

> 一句话：**Avalonia 让"外围界面"从手工作坊变成现代框架；笔迹本身仍然是我们的引擎。**

## 二、代价与体验风险（必须试点验证）

| # | 风险 | 具体表现 | 影响 | 缓解 |
|---|---|---|---|---|
| 1 | **画布嵌入** | `NativeControlHost` 是原生子窗，永远盖在 Avalonia 内容上、只按宿主矩形裁剪；滚动/遮挡/圆角会露馅 | 高 | 画布只占一个矩形区域；浮动面板/菜单用 Avalonia `Popup`（独立顶层窗）浮在上面；不要把 Avalonia 内容叠在画布上 |
| 2 | **笔迹延迟** | 如果把墨迹改成 Avalonia/Skia 画，压感/触控/延迟都会退化 | 高 | **画布保持原生 D2D**；Avalonia 只做壳/控件 |
| 3 | **触屏键盘** | Avalonia 的 `TextBox` 在 Windows 上不会自动弹系统触摸键盘（#10136 仍 open）；官方虚拟键盘是付费组件 | 高 | 试点里手写 `TabTip`/`ITipInvocation` 调用；或接受"教室配键盘"；或买 Pro 组件 |
| 4 | **中文 IME** | Avalonia 文本框的候选窗/组合串在部分输入法下有差异 | 中 | 微软拼音/搜狗/QQ 拼音手测；画布富文本继续用原生 RichEdit |
| 5 | **客户区装饰** | Avalonia 12 强制客户区装饰，标题栏由框架画；贴靠/最小化/最大化动画是模拟的 | 中 | 试点实测 Win10/Win11；不接受就用 11.3 的原生 `SystemDecorations=Full` |
| 6 | **两套视觉语言** | Avalonia Fluent 控件 vs 自绘工具条/画布；圆角/字重/间距不一致会像两个软件 | 中 | 把 Tokens 映射成 Avalonia 资源；按钮/滑条做自定义模板；先做组件画廊 |
| 7 | **跨栈拖放** | 收藏（Avalonia）拖到画布（原生子窗）要跨窗口/跨栈 | 中 | 用 OLE `DoDragDropAsync` + 原生 `IDropTarget`；试点先做一条 |
| 8 | **焦点/快捷键** | 两套输入系统：Avalonia 焦点 vs 原生画布焦点 | 中 | 窗口级路由：画布获得焦点时快捷键给引擎，其余给 Avalonia |
| 9 | **内存/启动** | 首次打开 Avalonia 窗口初始化 Skia/主题，内存 +100～200 MB；4 GB + PPT + 浏览器可能换页 | 中 | **懒初始化**：覆盖层先启动，打开第一个真窗口才初始化 Avalonia；试点量 4 GB 真机 |
| 10 | **付费组件** | 富文本编辑器、PDF Viewer、TreeDataGrid、虚拟键盘、媒体播放器是 Pro 组件 | 中 | 这些我们本来就有替代：RichEdit、PDFium、自绘列表、自研键盘调用 |
| 11 | **版本/回归** | 12.0 的自定义 chrome 出过动画回归（#21212）；框架升级可能带新问题 | 中 | 锁版本；关键窗口截图回归；不追最新 |
| 12 | **覆盖层仍是原生** | 两套 UI 模型长期并存 | 低 | 覆盖层是特殊形态，保持原生；不要试图统一 |

### 2.1 特别说明：Avalonia 不会让"写字"更好

- 墨迹的跟手程度取决于：`WM_POINTER` 采样、湿墨自绘、D2D 上屏、压感曲线；
  这些 Avalonia 都不参与；
- 如果把画布改成 Avalonia 的 `Control` + Skia，反而会丢掉：
  `ID2D1Ink` 变宽、湿墨轨迹、分块光栅、Raw Input 补点、触摸手势；
- 所以"画布原生 + 外围 Avalonia"是硬边界。

## 三、三种架构

| 架构 | 做法 | 体验收益 | 风险 | 结论 |
|---|---|---|---|---|
| **A. Avalonia 真窗口 + 原生画布** | 设置/收藏/展台/白板/PDF 外壳和控件用 Avalonia；画布用 `NativeControlHost` 嵌原生 D2D；覆盖层原生 | **最大** | 画布空域/触屏键盘/客户区装饰 | **推荐试点** |
| B. Avalonia 只做设置/展台 | 白板/PDF/收藏仍原生 | 中 | 两套窗口/观感；收藏拖画布仍跨栈 | 保守备选 |
| C. 全部 Avalonia（含画布） | 墨迹也用 Avalonia/Skia | 外观统一 | **笔迹延迟/压感/触控退化** | 不做 |

## 四、推荐架构 A

```
进程
├─ 覆盖层（原生 Win32 + D2D）        批注、透明、置顶、穿透、湿墨
├─ 引擎（原生）                      WM_POINTER / ID2D1Ink / 分块 / 文档
└─ Avalonia 应用（懒初始化）
     ├─ 设置窗口                    Avalonia 控件 + 主题
     ├─ 收藏 / 图形窗口              Avalonia 虚拟列表 + 拖放
     ├─ 视频展台窗口                Avalonia 壳 + 原生视频表面
     └─ 白板 / PDF 窗口             Avalonia 壳 + NativeControlHost（原生 D2D 画布）
```

关键边界：

- Avalonia 窗口负责：标题栏/边框/最小化/最大化/贴靠/DPI/任务栏/焦点/弹窗/控件；
- 原生画布负责：笔迹、湿墨、手势、相机、分块；
- 两者只通过"矩形 + 命令 + 状态快照"交互，不共享视觉树；
- 覆盖层永远不进 Avalonia。

### 4.1 画布嵌入的具体做法

- `NativeControlHost` 子类创建原生画布子窗（已有 `OverlayWindow` 的渲染/输入可以抽成 `CanvasHost`）；
- 宿主矩形 = Avalonia 布局给它的 Bounds（DIP）→ 物理像素；
- `WM_DPICHANGED`/尺寸变化时同步子窗位置；
- 画布上的浮动菜单/色带/提示：用 Avalonia `Popup`（独立顶层窗）或原生小窗，**不要**用 Avalonia 内容叠在子窗上；
- 画布圆角/裁剪：如需圆角，用原生 `SetWindowRgn` 或让画布自己画圆角背景，不要指望 Avalonia 裁剪子窗。

## 五、2 周试点（隔离 demo，不动产品代码）

### 5.1 做什么

| 天 | 内容 |
|---|---|
| 1～2 | 最小 Avalonia 12 应用：主窗口 + 设置页（侧栏 + 10 个控件）+ 暗色主题 |
| 3～4 | 收藏窗口：200 条虚拟列表、多选、空态、拖放起点 |
| 5～6 | 白板窗口：Avalonia 壳 + `NativeControlHost` 嵌入现有 D2D 画布（只读/可写各一版） |
| 7 | 画布上浮一个 Avalonia `Popup`（色带/菜单），验证空域 |
| 8 | 从收藏拖一个图形到画布，验证跨栈拖放 |
| 9 | 设置里的 TextBox：中文 IME + 触摸键盘（TabTip） |
| 10 | 4 GB 真机/低端机跑一遍，记录内存/启动/延迟 |

### 5.2 量什么

| 指标 | 目标 |
|---|---|
| 笔迹输入→上屏 | 与现在持平（±1 ms），不能变差 |
| 画布空域 | 缩放/滚动/弹层/圆角无露馅 |
| 触屏键盘 | 点 TextBox 能弹出/收起，输入框不被盖住 |
| 中文 IME | 微软拼音/搜狗不丢字，候选窗跟随 |
| DPI | 100/150/200%，跨屏拖动不缩不错位 |
| 窗口 | 最小化/最大化/贴靠/任务栏/还原正常 |
| 内存 | 打开 2 个 Avalonia 窗口 ≤ +150 MB（相对现在） |
| 启动 | 覆盖层启动不变；第一个 Avalonia 窗口 ≤1.5 s |
| 4 GB | 不出现明显换页/卡顿（和现在对比） |
| 拖放 | 收藏→画布成功，取消不产生半截对象 |

### 5.3 Go / No-Go

**Go（进入正式迁移）**：

- 笔迹延迟不退化；
- 画布无空域问题；
- 中文 IME + 触屏键盘可用（或可接受的手动调用）；
- 窗口贴靠/动画可接受；
- 内存 +≤150 MB、4 GB 不换页；
- 开发效率明显提升（设置页 1～2 天能做完）。

**No-Go（回到自研窗口层）**：

- 画布必须叠 Avalonia 内容才好看，或子窗裁剪/DPI 一直出问题；
- 触屏键盘无法稳定调起；
- 4 GB 机器明显变卡/换页；
- 客户区装饰的贴靠/动画不可接受，且 11.3 也不满足。

---

## 六、如果 Go：迁移顺序

1. **设置窗口**（收益最大、风险最低）——先做，替换 `FullUi` 设置页；
2. **收藏 / 图形窗口**——虚拟列表 + 拖放；
3. **视频展台**——壳 + 视频表面；
4. **白板 / PDF 窗口**——壳 + 原生画布；
5. **最后**才考虑把工具条/色带搬进 Avalonia（也可以永远不搬）。

每一步都保留旧实现，直到新实现通过同一套自检；不做"一刀切"。

---

## 七、如果 No-Go：回退

回到 `调研-界面框架-真正窗口与统一控件-2026-11-07.md` 的方案：
自研 `WindowManager/WindowHost` + 系统 chrome + D2D 内容 + 原生文字。
试点的代码是隔离 demo，不污染产品；决策成本只有 2 周。

---

## 八、许可与组件（重要）

- **Avalonia 核心 MIT**，免费；70+ 免费控件（含 DataGrid）；
- **Pro 组件**（订阅制）：RichTextEditor、PDF Viewer、TreeDataGrid、Virtual Keyboard、
  Media Player、Charts、Dev Tools/Hot Reload 等；
- 我们的替代：
  - 富文本 → 现有原生 `RichEdit`；
  - PDF → 现有 PDFium；
  - 虚拟键盘 → 调 Windows `TabTip`/`ITipInvocation`，或自研；
  - 列表 → Avalonia 免费 `ListBox/ItemsControl` 够用；
  - 图表 → 不需要或自绘；
- 如果试点依赖 Pro 组件，先算订阅成本；不要假设"Avalonia 全免费"。
