# 架构：分层、边界与写码规则

日期：2026-09-14　　状态：已落地（界面层待拆）

> **2026-09-14 两次减法**：
> 1. **笔迹优化层整层删除**（`src/InkEngine.Optimize`：1€ 滤波、RDP 抽稀、
>    贝塞尔拟合、笔锋预设）——用户实测结论是不需要，而且观感问题比收益多。
> 2. **我们自己拼的笔迹轮廓整层删除**（等宽带子、半圆端帽、外侧圆弧、内角补角、
>    压感→宽度）。笔迹的几何现在**只有一条中心线**，宽度/端帽/拐角由 Direct2D
>    按描边样式自己算（`DrawGeometry` + `Gfx.Round`）。
> 所以下面"核心不允许出现的造型"一条都不用再开例外了。

这份文档是**约束**，不是介绍。加新代码之前先看它一眼：东西该放哪一层，
放错了就会被后面的人（包括未来的你）反复搬。

## 零、最高原则：站在巨人的肩膀上（用户 2026-09-23 定）

**动手写任何功能之前，第一步必定是找有没有现成的实现可以参考**——参考原理、参考逻辑、
参考代码，而不是自己从头推。用户原话：

> "以后凡是我们要写功能之类的，你必定是先在网上看有没有类似原理参考的，
>  或者说参考原理、参考逻辑、参考代码。这叫站在巨人的肩膀上的最高原则。"

照这个顺序试，**不要跳步**：

1. **先翻本地已有的参考实现**——`d:\文件集中\code\画布测试\` 下那几份
   （InkClass / Inkboad 等），它们就是"别人怎么做"的现成答案；
2. **再上网搜**：官方文档 → 官方参考实现 → 开源库 → 论文伪码；
3. **理解它的做法，用自己的代码落地**——参考的是**原理 / 逻辑 / 判据 / 参数取值**，
   **不整段复制别人的代码**；确实需要引用某段具体实现时，**先看它的许可证**：
   MIT / BSD 可以带声明引用，GPL 一类的**只参考思路、不复制代码**
   （见 `src/InkEngine/THIRD-PARTY-NOTICES.md`）；
4. **写清出处**（URL / 项目名 / 论文），并**遵守许可**（BSD / MIT 要保留版权声明）；
5. **只有确实找不到可参考的，才自己推**——这时候在注释里写明"为什么没有可参考的"；
6. 参考完要**用数字量出来**（自检 / 对比）；同类实现里优先选"有大量项目在用、
   有论文或官方背书"的那个。

⚠ **反例（本项目 2026-09-23 的真实教训）**：停顿成型的识别器一开始是我们自己推的
几何判据（数角点、判直角、外接框），被用户连续打回两次（"形变太大，完全和墨迹对不上"
"感觉不对"）；最后**逐函数参考**华盛顿大学官方 **$P Point-Cloud Recognizer**
（New BSD，`src/InkEngine/PointCloudRecognizer.cs`，出处与许可在文件头）才过关。
查"InkClass 到底怎么写"这一步本身也是收获：它根本不是自己写的，而是调系统 Ink Analysis
（官方文档明确**只能 32 位**）——**先查，再定方案**。

## 一、分层

```
核心 InkEngine          文档模型 · 指针输入 · 脏区渲染 · 空间索引 · Win32 封装
  └ InkEngine.Ui       界面实现（待拆，现在还在核心里）
       ↑
   InkTeach           开发期宿主：自动化测试、基准、报告（不属于产品）
```

**依赖只能从上往下，不能反向。** 核心不认识上面两层里的任何东西。

---

## 二、每一层允许出现什么

### 核心 `src/InkEngine/`

允许：文档与笔画数据、指针采样、热键、脏区计算、上屏、空间索引、
Win32 / DirectX 的 P/Invoke、几何的**渲染**（把给定的点画出来）。

不允许：

- 任何形式的**信号处理**——滤波、平滑、去抖，一个都不要。
- 任何形式的**拟合或简化**——RDP、贝塞尔、道格拉斯-普克。
- 任何"**让笔迹更好看**"的造型——笔锋、渐细、端帽、拐角、粗糙边缘。
  **这些现在全归渲染器的描边样式**（`Gfx.Round` = 圆头 + 圆角），核心只给中心线。
- 任何**具体界面**——按钮、悬浮条、配色方案。

核心只画一样东西：**中心线 + 等宽描边**（宽度、圆头端帽、圆角拐角全由
渲染器的描边样式决定）。采样点上的压力值仍然存着，但不再参与渲染。

一句话：**核心回答"画在哪、画多快"，不回答"画得好不好看"。**

**核心内部的两条坐标纪律**（2026-09-13 补，代价是踩了四个 bug）：

1. **数据与索引一律用画布坐标**。文档、脏区、空间索引、命中测试、块缓存，
   全是画布坐标；只有"上屏"和"输入"两处做换算。
2. **内容层是画布空间的分块缓存**（`CanvasTiles.cs`），不是屏幕空间的一张位图。
   相机只允许出现在两个地方：`CanvasToWindow`（渲染）和 `ScreenToCanvas`（输入）。
   任何"拿窗口矩形去筛笔画"的写法都是 bug，相机为 0 时看不出来，一滚动就露馅。

### 界面层（待拆）

允许：`IOverlayUi` 的实现、悬浮条、按钮、命中测试自己的矩形。

不允许：直接碰文档模型。改状态一律走 `IEngineCommands`——撤销栈、
空间索引、脏区都靠引擎维护，越权就会破坏这些不变量。

### 宿主 `src/InkTeach/`

只放开发期的东西：命令行解析、自动化测试、基准、报告生成。
**产品代码不要 import 这一层。**

## 三、加新功能时先问自己

| 我要做的事 | 放哪一层 |
|---|---|
| 换一种上屏方式、改脏区策略、换输入通道 | 核心 |
| 让笔迹更顺、更细、更像毛笔 | （已删除：2026-09-14 起不做这件事，见文首变更说明） |
| 加一个按钮、换一套配色、做悬浮条 | 界面层 |
| 加一个自检、一个基准、一份报告 | 宿主 |

判据很简单：**如果把它删掉，笔迹的位置和条数会不会变？** 不会变的，就不是核心。

## 五、写码与注释约定

1. **算法和它的调用点分开写**。算法本身不带状态、不碰 UI；什么时候调用
   由上层决定。
2. **注释写"为什么"，不写"是什么"**。代码已经说清楚是什么了；
   注释要交代当初为什么这么选、踩过什么坑、哪个数字是怎么量出来的。
3. **实测数字写进注释**。例如"取 0.7 逻辑像素是实测值"，比"取 0.7"有用得多。
4. **一个文件一个职责**。空间索引不要和滤波器挤在一个文件里。
5. **改核心前先想清楚会不会破坏不变量**（撤销栈、空间索引、脏区、几何缓存）。
6. **每完成一件事就提交一次**，提交信息写清"改了什么、为什么"。
   回退能力是靠提交粒度换来的，不是靠记得住。
7. **每新增一种图形（工具 / 对象类型），必须同时给它自检**——用户 2026-09-20 定的规矩
   （原话："以后每个新增图形都要自检"）。这条不是"再小心一点"，而是有**机制**兜着：
   `--shapebandtest` 里有两条断言，加图形忘了写自检会**当场红**——
   · **自检覆盖**：把引擎里"能画的图形"`Enum` 出来，要求它们**一个不漏**地出现在自检表里
     （漏了会直接打出名字）；
   · **逐个真拖一笔**：每个有入口的图形都点它那一格、按引擎说的笔数真拖，
     断言画出来的 `Kind` 就是它。
   配套的两条"不要人写"：**段号**问 `FullUi.ShapeSegmentIndexForTest(Tool)`、
   **拖几笔**问 `Engine.ShapeStepCount(Tool)`——都是"从表里算"，不再各写一份名单
   （写死的段号 / 笔数会随增删图形静默失效，仓库里栽过好几次）。
   > 为什么立这条：加棱锥 / 棱台那一轮，自检"抽查 6 个图形"正好漏在它们身上，
   > 加上一条断言写了默认值（`PrismSidesClamped == 4`）而另一条把 bug 当成了期望
   > （"三格共用同一档"）——**两个 bug 全是用户上手才发现的**。省下的几秒不值。
8. **自检要写"不变量"，不能只写"我挑的那几个例子"**（用户 2026-09-24 问"这类 bug
   到底能不能自动抓"）。例子型断言只覆盖**你想到的**输入；**不变量**覆盖你没想到的——
   · 写法：把"用户的东西绝对不许怎样"写成一条**与实现无关**的句子。
     例：**一笔结束之后，「文档 +1」或「撤销栈 +1」必须命中一个**——
     两个都不动就等于"用户画的墨凭空没了"；
   · 再配**固定种子的交叉扫掠**把维度叉起来（`--dwelltest` 的 L：
     7 种语料 × 3 档尺寸 × 按住期乱动 2 档 × 一个状态位 2 态 = 84 次，逐点可复现）。
   > 为什么立这条：2026-09-24 那个"停顿识别平行四边形时图形整个消失"是**交互故障**
   > （NIST 的 interaction rule：绝大多数故障由 1~2 个因素交互触发）——单看每一维都正常，
   > 必须三个条件同时成立才炸。把不变量写出来 + 叉起来跑，它**自己报了坐标**
   > （修之前 6 例、修完 0 例），没靠人上手点。
9. **改完 bug 抽查一句"这条用例真的抓得住吗"**：把修复那一行**打回原样**，看自检会不会红
   （红了 = 变异体被杀死了；绿了 = 这条用例是摆设）。
   > 2026-09-24 实测：把"点一下"的判据改回"首末两点位移" → 扫掠红；删掉 `commit` 里
   > 停顿成型那行豁免 → H4 红。**顺带抓出一条"用例太温柔"**：H4 起初用的平行四边形太大，
   > 缩完仍在门槛以上——变异删掉了、用例却照样绿，等于没钉住（尺寸是后来压小的）。
