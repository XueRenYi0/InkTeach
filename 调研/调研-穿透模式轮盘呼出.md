# 调研：穿透模式下，手势呼不出轮盘

- 日期：2026-10-25
- 状态：**只调研，不改代码**
- 问题：非穿透时两指长按/轻点能呼出轮盘；一开穿透，只剩 `Ctrl+Alt+Shift+Q` 能呼出，手势完全没反应。

---

## 0. 结论

**这不是轮盘自己的 bug，是穿透模式的必然结果。**

- 穿透 = 覆盖层加 `WS_EX_TRANSPARENT`，Windows **不再把 `WM_POINTER` 发给覆盖层**；
- 轮盘的两指长按/轻点完全依赖 `WM_POINTER`，所以收不到；
- 快捷键走的是 `RegisterHotKey`，和窗口命中测试无关，所以还能用；
- 键盘呼出后能用鼠标选扇区，是因为引擎每帧用 `GetCursorPos` 轮询，不是靠触摸消息。

**要解决，不能“让整屏继续收触摸”**（那就不是穿透了），而是**留一块小的、可交互的输入面**：

1. **长按浮动小球**呼出轮盘（推荐，最稳）；
2. **两指按住工具栏**呼出轮盘（更接近原手势，但只在工具栏上有效）；
3. 专用 80×80 手势点（角落/边缘，可隐藏）；
4. 工具栏加一个“轮盘”按钮（最简单，但不是手势）。

另外，**触发只是第一步**：轮盘出来以后，还要能让手指点/划扇区。做法是把现有的 `_uiInputHwnd`（穿透时本来就留给工具栏的那个 1/255 透明输入窗）在轮盘打开期间**临时扩到轮盘范围**，轮盘关闭再收回。

---

## 1. 为什么现在不行

### 1.1 穿透的样式

`ApplyPassThroughStyle` 在穿透时给覆盖层加：

```csharp
WS_EX_TRANSPARENT | WS_EX_LAYERED
```

`WS_EX_TRANSPARENT` 的语义就是“鼠标/触摸命中测试跳过这个窗口”。所以：

- 单指、两指、三指……全部直接落到下层程序；
- 我们的 `WndProc` 收不到 `WM_POINTERDOWN/UPDATE/UP`；
- `TouchGestures` 没有触点，`TwoFingerHold`/`TwoFingerTap` 永远不成立。

出处：`Engine.cs:10635` 的 `ApplyPassThroughStyle`。

### 1.2 为什么快捷键还能用

`Ctrl+Alt+Shift+Q` 是 `RegisterHotKey` 注册的全局热键，系统直接把 `WM_HOTKEY` 发给我们，不经过窗口命中测试。

键盘呼出后，选扇区靠：

```csharp
SyncPointerFromCursor();   // 每帧 GetCursorPos
```

它看的是**系统鼠标指针**，不是触摸触点。所以键盘 + 鼠标能用，触摸不行。

出处：`Engine.cs:15371-15403`、`15467`、`15558-15570`。

### 1.3 有没有“全局看触摸”的 API

查过两条路，都不适合：

| API | 问题 |
|---|---|
| `RegisterPointerInputTargetEx(..., fObserve:TRUE)` | 微软文档明确标 **not supported / may be altered or unavailable**，不建议依赖 |
| `RegisterPointerInputTarget` | 需要 **UIAccess 权限**（签名、装到受信任位置），而且会把**所有**该类型指针输入重定向到我们的窗口——下层程序收不到，等于破坏穿透 |
| `WH_MOUSE_LL` 低级鼠标钩子 | 只能看到鼠标，看不到第二根手指；触摸合成的鼠标消息也不可靠 |
| Raw Input（`WM_INPUT` + `RIDEV_INPUTSINK`） | 部分触摸屏能收到 HID 报告，但不同 IR 框的报告描述符/触点格式不同，Windows 也可能不暴露；要逐机型解析，2~4 周且高风险 |
| ETW / 全局消息钩子 | 需要注入/驱动级能力，不适合桌面绿色软件 |

**结论：不要为了“两指任意位置”去做全局触摸钩子。** 正确方向是“留一块小的可交互面”。

## 2. 推荐方案：长按浮动小球

### 2.1 交互

```
穿透模式
  ↓
长按浮动小球 500ms（不移动）
  ↓
轮盘在工具栏上方/屏幕内出现（粘滞）
  ↓
手指抬起，点/划扇区
  ↓
选中 = 退出穿透 + 切工具；点空白/Esc = 取消，仍留在穿透
```

- **一根手指**，不需要两指；
- 穿透时小球/工具栏仍然可见，也仍然能收 `WM_POINTER`（现有 `_uiInputHwnd` 就是干这个的）；
- 长按阈值 500ms，移动 >8px 视为拖小球，不触发；
- 短按小球仍然是原来的展开/收起，不改变现有习惯。

### 2.2 为什么它能选扇区

轮盘打开时，把 `_uiInputHwnd` 临时扩到“工具栏 ∪ 轮盘外接矩形”：

```
平时：_uiInputHwnd = 工具栏范围（1/255 透明，收指针）
轮盘打开：_uiInputHwnd = 工具栏 + 轮盘范围
轮盘关闭：收回工具栏范围
```

- 这个窗口是 1/255 alpha，肉眼看不见，但能收 `WM_POINTER`；
- 轮盘打开期间，它盖在轮盘区域上，手指点/划都能收到；
- 轮盘关闭后恢复，穿透语义不变；
- 下层程序只在轮盘这块矩形内暂时收不到点击——轮盘是模态菜单，可以接受。

### 2.3 实现步骤

1. `IEngineCommands` 加 `OpenRadialPalette(float x, float y, bool sticky)`；
2. `FullUi` 的小球指针按下时启动 500ms 计时；移动 >8px 取消；到点调用命令；
3. `Engine` 打开轮盘，`_radialTouchMode=true`，盘心夹取到屏幕内（球在底部，盘会落在工具栏上方）；
4. `UpdateUiInputWindow` 在 `RadialPaletteActive` 时把输入矩形扩到“UI ∪ 轮盘 + 提示条”；
5. `UiInputWndProc` 在轮盘打开时优先把 `WM_POINTERDOWN/UPDATE/UP` 路由到轮盘：
   - Down：`PointerX/Y` + `UpdateRadialSelection` + `SetCapture`；
   - Move：更新扇区；
   - Up：`CommitRadialPalette`；
6. 轮盘关闭后 `UpdateUiInputWindow` 自动收回；
7. `--radialtest` 增加“穿透 + 长按小球 + 点扇区”的用例。

### 2.4 工作量

约 **3~5 天**（含穿透/取消/恢复自检）。

## 3. 备选方案

### 3.1 两指按住工具栏（更接近原手势）

- `_uiInputHwnd` 本来就能收多个 `WM_POINTER`；
- 在 `UiInputWndProc` 里额外维护一个“两指表”：两个 pointer 同时落在工具栏、都没移动、按住 500ms → 打开轮盘；
- 轮盘打开后同样扩输入窗，让手指继续划/点；
- 优点：还是两指手势，老师不用学“长按小球”；
- 缺点：只在工具栏上有效（工具栏高 58px，两指略挤）；两指同时按两个按钮可能误触；需要处理“两个 pointer 都被 UI 吃掉”的冲突。
- 工作量：**3~5 天**。

### 3.2 专用手势点

- 在屏幕角落放一个 80×80 的 1/255 透明输入窗；
- 两指按住 500ms → 打开轮盘；
- 优点：不依赖工具栏，两指空间够；
- 缺点：多一个“看不见的热区”，老师不知道在哪；需要画一个很淡的提示点。
- 工作量：**2~3 天**。

### 3.3 工具栏“轮盘”按钮

- 在工具栏加一个 `◎` 图标，点一下打开轮盘；
- 最简单、最可发现，但不是手势；
- 如果小球长按已经能用，这个可以作为“教一次就会”的兜底。
- 工作量：**1~2 天**。

### 3.4 全局 Raw Input（不建议）

- 解析触摸 HID 报告，理论上能拿到全屏两指；
- 但不同 IR 框的报告格式不同，Windows 还可能不暴露 digitizer；
- 需要逐机型验证，维护成本高；
- 不建议为了这个入口付这个代价。

---

## 4. 建议的落地顺序

1. **长按小球**（3~5 天）——解决穿透 + 单指模式，最稳；
2. **工具栏“轮盘”按钮**（1~2 天）——给不会长按的老师一个明显入口；
3. 如果老师坚持两指：再做**两指按住工具栏**（3~5 天）；
4. 专用手势点/全局 Raw Input 暂不做。
