# AI 开发守则（硬性）

> 完整规范见 `docs/dev-standard.md`；本文件是 10 条速查。

配合 `AGENTS.md`（入口/空间预算）使用；冲突时以本文件为准。

## 动手前

1. **先查树再查语义**：先看 `docs/tree-map.md` 找目录/文件（自动生成）；
   再看 `docs/module-map.md` 的 30 条跨文件流程找“首读 + 下一跳”；
   行号看 `docs/section-map.md` 或 `grep -n`；只读要改的那一段 + 调用它的 1 处，
   不整文件通读。
2. **一句话设计**：入口在哪、状态存哪、失败怎么办。写不出来先停下问，不许边写边想。
3. **先找参考**（AGENTS.md §0.2）：照搬成熟实现的逻辑，再按本场景改。
4. **先定数据再写 UI**：字段、默认值、落盘 key、旧配置迁移。

## 写代码

5. **改动最小**：30 行能解决不写 100 行；不顺手改无关代码、不顺手重命名。
6. **跟随现有风格**：partial class 拆文件（参考 `FullUi.Ai.cs`）、命名、中文注释都照现有。
7. **大文件只加一段**：`Engine.cs` / `FullUi.cs` / `App.cs` 每次只加一小段；成块功能放新的 `Xxx.<功能>.cs` partial。
8. **不新增 NuGet 包、不换库、不改 csproj / run.ps1 / publish.ps1**；要改先停下说理由等我确认。
9. **新设置四件套**：默认值 + 落盘 + 旧配置迁移 + 关闭后行为正确。
10. **不留垃圾**：不留调试输出、不留 TODO、不注释掉旧代码（git 里有）。

## 收尾

11. 只跑与改动相关的 **1 条**自检，不跑全量（AGENTS.md §0.1）。纯函数 / 序列化 /
    EditAction 这类改动先跑 `.\run.ps1 --unittest <过滤词>`（毫秒级），
    碰界面 / 输入 / 渲染再跑对应专项；测试怎么选见 `docs/test-playbook.md`。
12. 界面改动必须给截图或录帧；没证据不说“完成”。
13. 汇报固定 5 行：改了什么 / 证据 / 替你做的决定 / 风险。
14. 一次只做一个功能；做完停下，不顺手做下一个。
