# 修复记录：快速画圆出折线（2026-10-06）

用户报的现象（手写板，**Windows Ink 关掉 / 不用系统湿墨**）：

> 快速画圆时是折线，慢速画时是圆；**画的时候是折线，最终也是折线**；没用橡皮擦过。
> 同样条件下 ClassIn / InkCanvas 一直是圆的。

---

## 一、根因（已复现、已定位到行）

`StrokeSmoothing.MarkCorners()` 的**窗口判据**（`StrokeSmoothing.cs:226-234`）用
**"±CornerWindow 个点"**当窗口，而不是按**弧长**：

```csharp
int w = Math.Max(1, CornerWindow);        // 默认 2
int a = Math.Max(0, i - w);               // 只看"第几个点"
int b = Math.Min(_m - 1, i + w);
...


Vector2 va = _p[i] - _p[a];
Vector2 vb = _p[b] - _p[i];
float la = va.Length(), lb = vb.Length();
if (la < MinArmPx || lb < MinArmPx) continue;   // ← 只有"太短"的下限(1px)
float cos = Vector2.Dot(va, vb) / (la * lb);
if (cos <= cosThr) _corner[i] = true;          // cosThr = cos(35°)
```

**这条判据量到的转角 ≈ 2 × (点距 / 半径)。** 点距越大，量出来的转角越大：

| 场景 | 点距 | 量到的转角 | 结果 |
|---|---|---|---|
| 慢画（点密） | 3px | 2×3/R 很小 | 不误判 ✅ |
| 快速画圆（点稀） | 58px，R=150 | **44.7° > 35°** | **每个点都判成角点** ❌ |

一旦每个点都被判成角点，`Build()` 在每个点处切断切线 → 相邻点之间退化成直线段
→ **整条笔迹变成多边形**。而且这发生在**几何生成**阶段，所以**画的时候和最终都是折线**
（不是活笔/湿墨的显示层问题）。

**为什么 Windows Ink 开就没问题**：湿墨由系统合成器（DWM 委托墨迹轨迹）画，
走的是微软自己的墨迹管线，不经过我们的角点判据。

**为什么 ClassIn / InkCanvas 没问题**：它们直接用系统墨迹管线（`InkPresenter` /
`InkCanvas` 的 `StrokeCollection`），曲线化是原生必做的一步，不存在"某条岔路忘了上曲线"。

### 作者其实记录过同一个失效模式

`StrokeSmoothing.cs:53-54`：

> ⚠ 默认关的原因（实测踩过）：24px 臂在**小半径笔画**上会超过角点阈值（半径 20px 时
> 弧长约 69°），**正常弯曲被误判成角点 → 过点曲线被切断** → 细笔放大后"很脏、不流畅"。

他当时把它归因到新加的 `CornerMacroPx`（宏观窗）并默认关掉了那个功能，
**但没发现基础那条"±点数窗口"在"点稀"方向上有一模一样的毛病**——因为他只测了
"点密"方向（演示图的用例是 4.9px/点的密采样弧）。

## 二、复现器

`--smoothshow` 加了第 ⑦ 个用例：**半径 150、每 22.5° 一个点（弦长 ≈58.5px）**，
就是"快速画圆"的采样密度。

- 修前（`--smoothcornerpx 0`）：**明显的八边形**，每个灰点一个尖角
- 修后（默认）：光滑圆弧，且仍然过每一个采样点

---

## 三、改了什么（三处，都可回滚）

### 1. 给窗口判据加**臂长上限**（主修）

`src/InkEngine/StrokeSmoothing.cs`

- 新增 `CornerWindowMaxPx = 24f`（`--smoothcornerpx N` 调，`0` = 关闭护栏做对照）
- `MarkCorners` 的窗口判据里：任一臂超过它 → **跳过这条判据**

**为什么"上限"是对的修法**：这条判据存在的理由是"**慢画**时一个直角被摊到四五个点上，
只看相邻两点每段只有十几度、判不出来"——那是**点密**的场景。点稀的时候，相邻两点
本身就是长臂（每段转角就很大），角点由**局部判据①直接得出**，不需要外推。
默认 24px 与作者自己那个 `CornerMacroPx = 24` 同一口径：点距 ≤12px 时行为完全不变。

### 2. `Enabled` 不再被运动模式强制关掉

`src/InkEngine/StrokeMotion.cs`（`SetMode`）

原来有 `StrokeSmoothing.SetEnabled(mode == Catmull)`，即默认档（mean2）下
`Enabled` **恒为 false**。它和两处文档矛盾（文件头与 `Engine.Run` 都写"默认开，
2026-09-28 用户拍板"），而且它管的那条路**根本没有"第二条曲线"**——
`Enabled` 只被**非模型路径**读（被橡皮擦过的笔、回放前缀、建模失败的笔），
那条路没有模型输出。把它关掉的结果是**这些笔直接退化成折线**。

### 3. `--nosmooth` 接回来（它是被注释掉的死开关）

`src/InkEngine/Engine.cs`：`--nosmooth` 原来整行被注释（`// [停用] ...`），
所以它没有任何效果；`--smoothshow` 出的 off / on 两张图**逐像素完全相同**
（实测不同点数 = 0，即"对照"是假的）。

现在 `--nosmooth` / `--smooth` 只控制它该管的：曲线化开/关；
`Model.cs` 与 `Overlay.cs` 的模型路径也受它管，所以它是一个**真正的对照组**。
修完实测 off vs on 差异 8148 像素（之前 0）。

### 4. 修掉一个**写错标签的测试用例**

`--smoothshow` 的用例 ⑤ 原名"慢画直角"，但用的是 **120px 一段**——
130Hz 下那是 15600px/s，是"飞笔"不是慢画；而且"90° 摊在 3 个 120px 点上"与
"半径 ≈229px 的圆弧"在数学上**无法区分**（只有 4 个点），逼着判据去误伤圆弧。
已改成 **11px 一段、每段 20°**（真·慢画的采样密度），它才真的在测它声称要测的东西。

## 四、验收（都做了）

| 项 | 方法 | 结果 |
|---|---|---|
| 快速画圆不再折线 | `--smoothshow` 用例⑦，裁图放大看 | **修前八边形 → 修后光滑** ✅ |
| 真直角仍然保住 | 用例②（56px 直角）判据开/关逐像素比 | 差异 943 像素（判据仍在起作用）✅ |
| 点密时的行为不变 | 用例⑤ 判据开/关逐像素比 | 差异 **0**（亚像素级，加了上限没损失）✅ |
| `--nosmooth` 成了真对照 | off vs on 全幅逐像素比 | 8148 像素（修前 0）✅ |
| 回归 | 全套功能自检（39 项） | 见下 |

**保留一个诚实的说明**：严格来说，把窗口判据限制到 24px 之后，
"点稀 + 缓弯"这种输入不再被判成角点——而这正是**修复的目的**。
代价是：如果有人在**点稀**的情况下画一个真的、摊得很开的转角，
它现在会被画成圆滑过渡。但用例⑤的实测说明：点密时这条判据的影响本来就是
**亚像素级**，所以这个代价可以忽略。

## 五、没做但该记着的

- **mean2 在高速下会退化成"几乎不平滑"**：它的平均窗是 12px **距离**窗，
  点距 16.9px 时窗里只有 1 个点 → 平均值就是它自己。实测把语料从 400px/s 提到
  2200px/s，抖动 RMS 从 0.072 涨到 0.225（=Catmull 同值）。**这是"快速书写手感"的
  下一个可啃点**（建议：距离窗 + 最少点数保底，或改时间窗）。
- **项目自己的"折线度"指标测不出这个问题**：语料速度翻 5.5 倍，折线度纹丝不动
  （1.02° → 0.96°）。以后拿它当验收口径时要小心。
