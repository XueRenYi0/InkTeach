## 二、明天接着干的（按优先级）

### 🔴 P0 · 「偶尔缺墨」—— 正确性问题，**已有重大线索：PHRC**

**新线索（2026-10-07，查资料查到的）**：Wacom 官方文档说
**Press-And-Hold-To-Right-Click（按住变右键）会吞掉笔的输入**，
并明确推荐「**用 Wintab 当输入源**」来绕开（因为它不走系统 ink）。

用户在 Microsoft Q&A 的描述和我们症状一模一样：
> "I have to drag it out of the circle, **about 4mm, before it creates a line**."

→ 笔停住约 1 秒 → Windows 判"长按手势" → **后面约 4mm 的移动被吞** → 看起来就是"缺一小段墨"。
详见 `同行做法-参考资料.md` 第二节。

**30 秒验证**：画线画到一半**故意停住约 1 秒**（笔尖别抬），再继续。
停住之后紧跟着缺一小段 → **PHRC 确认**。

**原来要问的三条**（仍然有用，问到了能缩小范围）：
1. 是**开 ink** 时出现，还是**关 ink** 时？
2. **以前有没有**？（我这几轮改动之后才有，还是原来就有）
3. 出现在**正在写的那一笔**上，还是**已经写过的旧笔画**上？

### 🟢 P0.5 · Wintab —— **已实测打通，可直接用**

本机高漫表实测（`--wintabprobe`）：**168 Hz / 压力 0~16383（14 位）/ 倾斜也有**。
而 Windows Ink 那条路压力被钳在 1024 → **16 倍差距**。
关 ink 时现在完全没有压力，通了之后就有。

**判据**：`悬停压力=0、实压 0~16383`（1156 个包实测）。
**唯一坑**：包体布局与规范差 4 字节（见 `同行做法-参考资料.md` 第四节），
所以**必须带运行时合法性自检**，不能硬编死偏移。

**这件事同时是 P0 的解法**（Wacom 官方推荐的绕开 PHRC 的办法）。

### 🟡 P1 · mean2 在高速下退化成"几乎不平滑"

- 它的平均窗是 **12px 距离窗**；点距超过 12px 时窗里只剩 1 个点 → 平均等于没做
- 实测：语料 400px/s → 2200px/s，抖动 RMS **0.072 → 0.225**（=Catmull 同值）
- **注意：这一条和 Raw Input 正交** —— 接了 Raw Input 之后点距 17px，窗里还是 1 个点，照样退化
- 建议方向：距离窗 + **最少点数保底**，或改时间窗。属于手感调参，**要你手上试过再定**

### 🟡 P2 · Raw Input 的**真机验证**（默认已经开了）

请在你的手写板上跑一次，看 `[笔画]` 行新多出来的那栏：

```powershell

```

- **N ≈ 10~25** → 生效了（把你的 13 点补到 30 点左右）
- **N = 0** → 你那台设备在指针这条路上没被合并，Raw Input 白开（那就考虑默认关回去）
- 顺带试试**小的、快的**圆（差异在那里最大：点距 48px + 半径 45px 时曲线会"压扁" 6.4px，接上后降到 0.8px）

### 这一轮新加的排查开关（都在 `InkTeach.exe` 上）

| 开关 | 作用 |
|---|---|
| `--geomtrace` | 每一笔报几何走了哪条岔路（通道 A/B × 数据源 × 曲线/折线） |
| `--cornerdump` | 打**抽稀后每个顶点的转角序列** + 相邻最大差（定参数必须看这个） |
| `--notrend` | 关掉趋势判据（回固定阈值，做对照） |
| `--smoothcorner N` / `--smoothcornerpx N` / `--smoothcornerdeg N` | 三个角点参数 |
| `--norawinput` | 关掉 Raw Input（对照） |
| `--rawprobe` | 只数原始输入条数 |
| `--rawmindist N` / `--rawmax N` | raw 补点的最小距离（默认 3px）/ 每笔上限（默认 3000） |
