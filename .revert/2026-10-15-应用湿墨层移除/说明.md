# 已停用：应用侧湿墨层（FastWet）＋ 湿墨档位精简为两档（2026-10-15，9.1.0）

> 用户拍板（原话）："石墨（湿墨）档位中有一个'应用湿墨迹层'，这个从代码中**完全拿掉**，
> 不需要了。因为我在湿墨下测试时，它好像有**锯齿，松手以后才会变平滑**，这个应用有问题，
> 而且我也感觉不到它有什么优势。"
> 处置："应用湿墨"就用之前的逻辑——**Win 下有系统湿墨（委托轨迹）就用，没有就退回软件自绘**。

## 一、删掉了什么

| 东西 | 位置（删除前） | 处置 |
|---|---|---|
| 湿墨档位 2「应用湿墨层（FastWet）」/ 3「全开」 | 设置「墨迹 → 湿墨档位」、`--wetmode N`、`Ctrl+Alt+Shift+W` | **档位只剩 0 / 1**（0 原路径 / 1 +系统委托轨迹）；旧配置里存的 2/3 读回时并入 1 |
| FastWet 实现（应用侧独立 DComp 虚表画湿墨） | `Overlay.cs`：`BeginFastWet` / `UpdateFastWet` / `DrawFastWetStroke` / `ClearFastWetBounds` / `EndFastWet*` / `TryCreateFastWetResources` / `FastWetFallbackEnabled` 等整块 | **整块删除**（本目录 `Overlay.cs` 是删除前全文） |
| FastWet 接线（起笔 / 喂点 / 每帧 / 收笔 / 轨迹运行时失败兜底） | `Engine.cs`：`_fastWetStroke` / `_fastWetPending` / `IsFastWetStroke` 与各处调用 | 整块删除（`--syswet` 的"轨迹运行时失败就不再让位"这一条保留，逻辑不变） |
| `--nofastwet` / `--fastwettest` | `Engine.cs` 参数、`App.cs` 模式分发、`InkMotion.cs` 的 `FastWetTest` | 撤除（测试模式整段删除） |
| `--lagtest` / `--camlag` 里的 FastWet 档 | `InkMotion.cs` | 四档 → **三档**（1 主绘 / 2 系统轨迹 / 3 产品组合） |

## 二、为什么（真机观察）

- 应用湿墨层是应用侧自己画"整笔湿墨"的另一条 DComp 通道（当年为"系统轨迹不渲染"准备的替身）。
- 用户在湿墨档 2/3 下看到：**笔画有锯齿、松手后才变平滑**——即湿墨层画的是参考线/折线观感，
  与干墨的曲线建模不一致；同时相对自绘没有可感知的收益。
- 9.0.6 起系统委托轨迹已在目标机器（Win11 24H2+）真正可用，"有就用、没有退回自绘"已经够用。

## 三、怎么恢复（只停用不删除的规矩）

1. 本目录 6 个 `.cs` 是 **`3e10976`（9.0.9 后、移除前）** 的原文，拷回对应位置：
   `Overlay.cs` / `Engine.cs` / `Ui.cs` → `src/InkEngine/`；`App.cs` / `InkMotion.cs` → `src/InkTeach/`、
   `src/InkTeach/SelfTests/`；`FullUi.cs` → `src/InkUi/`。
2. 或者直接看 git 历史：`git show 3e10976:<路径>`——那一版的文档同步（快捷键总表等）也在一起。
3. 恢复后先跑 `--paneltest`（湿墨档位四档循环的旧断言）与 `--lagtest`（四档模式）。
