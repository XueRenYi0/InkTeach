# 计划：模拟压力（无压感设备也出粗细）

日期：2026-10-05　　状态：**实验实现完成，待真机验收**
前置：`计划-墨迹运动模型-mean2.md`（M5/M7 同源 Xournal++）、`调研-压感与预测-原理.md`

## 一、目标（用户定的统一逻辑）

「根据压感粗细」开关的最终语义：

- **ON**：有真实压感（笔）→ 用真压力；没有压感（鼠标 / 触摸 / 关 Windows Ink 的笔）
  → **模拟压力**按书写速度出粗细；
- **OFF**：所有设备一律等宽。

当前先做**实验开关** `--simpressure`（默认关）；验收通过后才并进设置开关的 ON 语义。
OFF 语义与现状一致，不需要改。

## 二、来源与纪律

- 行为口径：Xournal++ `pressureGuessing`
  （`src/core/gui/inputdevices/PenInputHandler.cpp` 的 `inferPressureValue` / `filterPressure`）。
  GPL-2.0+ 上游，**只参考思路自实现**（`src/InkEngine/PressureSim.cs`），未复制代码；
  署名见 `src/InkEngine/THIRD-PARTY-NOTICES.md`。
- 顺带同源拿了一块「**缺压回填**」：个别事件不带 `PEN_MASK_PRESSURE` 时沿用上一次有效压力
  （上游原注释：*"Use the last recorded pressure value then"*），落在
  `PenSampleBuffer.Read`，起笔由 `BeginStroke()` 复位。以前会给 0.5 占位，笔画中间凹一下。

## 三、行为（一字不改的部分）

- 反速度 =（时标差 ÷ 10）÷（距离 + 0.001）；`p = π/2 + atan(反速度 × 3.14 − 1.3)`；
- EMA：`p = min(p, 2)/5 + 上次 p × 4/5`（起笔 last = 0）；
- 静止特判（两点重合）：`p = sqrt(dt/10) − 0.1`（不走 EMA）；
- 输出 `(p × 1.1 + 0.8)/2`，再 `max(下限 0.05, ×倍率 1.0)`。

**外壳适配**（见 `PressureSim` 文件头，只此四处）：

1. 距离换算到上游 72dpi 页面单位（`×72/(96×DpiScale)`）——不同 DPI 手感一致；
2. 负时标差钳 0（上游无符号会回绕）；
3. 时间不可用（全 0/全同）→ 整条回退 0.5（等宽），不给假压力；
4. **量纲映射**：上游输出是"线宽倍数"语义，运动中稳态约 0.761~1.5；我们的压力域是 0..1
   （0.5 = 档位宽度）。把运动区间线性压进 `0.5 ± Depth`：
   默认 `Depth=0.20` → `0.30~0.70` → **0.6×~1.4× 档位宽度**（与真笔常用区间一致），
   差异不会被 `PressureWidth` 0.10/2.0 两端的夹子吃掉；静止特判的更大值夹在上端。

## 四、开关与参数

- `--simpressure`：模拟压力总开关（**默认关**）；
- `--simpressdepth N`：深浅，默认 0.20（0.05~0.45）；
- 压力总开关仍是 `PressureWidth.Enabled`（设置「根据压感粗细」/ `--nopressure`）；
- 只对"没有真实压力 + 笔 + 自由笔迹（≥2 点）"生效；**高亮笔 / 激光笔维持等宽**（现有约定）。

## 五、验收

- `--pressuretest` 33/33 通过（含新增 5 项：速度方向 / 相邻连续 / 值域 [0,1] /
  时间不可用回退 / 真压感优先不参与）；
- `--selftest 8 --simpressure`、`--selftest 8 --simpressure --simpressdepth 0.35` PASS；
- 默认路径回归：`--selftest 8`、`--motiontest`（8 模式）、`--smoothtest` 12/12 全绿；
- **待用户真机验收**：鼠标写字、触摸屏、关 Windows Ink 的笔、快速画线，与 OFF 对照。

## 六、已知边界（记录）

- 真笔 + 委托轨迹（DWM）开着时：live 湿墨的逐点半径仍来自采样压力（缺压回填已改善"个别缺压"）；
  "设备完全不报压力 + 轨迹开着"的 live 段不加模拟，落笔后的成稿才走模拟——若这个组合出现
  "写完粗细跳一下"，先记下来，验收后再决定要不要把模拟并进轨迹半径；
- 命中 / 紧框：`HalfWidthAt` 已跟随模拟压力，不会"看得见点不中"；
- 存档 / 撤销 / 回放：不读模拟压力（渲染期按存档的时间戳重算，结果确定、可重现）。

## 七、怎么试（用户）

```powershell
dotnet run --project src/InkTeach -c Release -- --simpressure
dotnet run --project src/InkTeach -c Release -- --simpressure --simpressdepth 0.35   # 更明显
dotnet run --project src/InkTeach -c Release -- --nopressure                          # OFF 对照（等宽）
```

看点：鼠标 / 触摸写字是否更有"笔感"；**会不会显得脏乱（这是主要风险）**；
快慢线的粗细差是否自然；"口 / 国"转折处粗细会不会乱跳；触摸屏与鼠标是否一致。
不行就去掉 `--simpressure`，默认路径一个字没动。

## 八、实测反馈与优化选项（2026-10-05）

用户实机：模拟压力"有是有"，但**写出来的字没有等宽好看** → 倾向不采用。
这与参考项目的默认一致：Xournal++ `pressureGuessing` 默认关；Ink Canvas 第一版
（逐点瞬时速度）曾被实机评"非常难看"。速度推压力抓不到"书写意图"（中文的顿笔/回锋），
在小字号上还会牺牲笔画间的一致性——等宽更整齐是合理的审美结论。

按代价从小到大三条路：

1. **浅档先判（零代码，2 分钟）**：
   - `--simpressdepth 0.10` → `0.8×~1.2×`；
   - `--simpressdepth 0.05` → `0.9×~1.1×`。
   参照：Ink Canvas 第二版精调后的量级也是 `~0.7×~1.2×`；**我们当前默认 `0.6×~1.4×` 偏强**。
   若浅档仍不如等宽 → 审美结论：停，默认关。
2. **换单源：perfect-freehand 的 `simulatePressure`（MIT，可移植署名）**——为"好看"而生的模型
   （tldraw 在用）：
   - `sp = min(1, 距离 ÷ 笔宽)`：按笔宽归一化，设备/尺寸无关；
   - 目标 `rp = min(1, 1 − sp)`（慢→粗、快→细）；
   - 每点只向目标移动 `sp × 0.275`（**内建变化率限制**，防忽粗忽细）；
   - 起笔固定 `0.25`（防"胖开头"）；`streamline` 位置低通只用于**平滑测速**，不动渲染几何；
   - 另有**起收笔锥化（taper）**——"笔锋"的正路；但收笔锥化要在抬笔后动尾部
     （用户敏感"画完变形"，需单列开关）。
   按单源纪律做成**独立模式**，与 Xournal++ 档 A/B。
   其 taper 的准确语义（`getStrokeOutlinePoints.ts`）：
   - 按**距端点的路径长**算系数：`s = runningLength < taperLen ? ease(runningLength/taperLen) : 1`，
     终点同理；半径乘 `min(起点系数, 终点系数)`，下限 `MIN_RADIUS=0.01`；
   - 默认缓动：起点 `t(2−t)`、终点 `1−(1−t)³`；
   - `taper` 取值：`true` = 整条锥化（长度取 `max(size, totalLength)`）、数字 = 指定像素、false/缺省 = 关；
   - **活笔即可生效**：当前笔尖就是锥的末端，继续写会"长回去"，抬笔自然定型；
   - 配套的 `simulatePressure`（距离÷笔宽 → 目标 `1−sp`、每点移动 `sp×0.275`）自带变化率限制。
3. **停**：`--simpressure` 保留为实验档、默认关；「根据压感粗细」的 ON 语义暂不做模拟
   （ON = 真压感，OFF = 等宽，即现状）。

## 九、2026-10-05 追加：起收笔锥化 `--simtaper`（perfect-freehand 口径）

用户实机：`--simpressure --simpressdepth 0.10` 在正常宽度下"差不多"，要求融合"笔锋"再测。
已实现：

- **单源**：perfect-freehand `start/end taper`（MIT，Copyright (c) 2021 Steve Ruiz；
  已登记 `THIRD-PARTY-NOTICES.md`）。按上游公式：起点缓动 `t(2−t)`、终点缓动 `1−(1−t)³`；
  `t = 距端点路径长 ÷ 锥长`；半径乘两端较小的系数；终值压到我们压力的地板 0.05。
- **参数**：`--simtaper A[,B]`（画布像素；单个值 = 两端相同；0 = 关一端；默认关）。
- **可单用**：不开模拟压力时 = "等宽 ＋ 笔锋"（基础压力填 0.5 再乘锥化系数）；
- **可组合**：与 `--simpressure` 同开（组合档，两个来源，文档在此注明）。
- **活笔**：当前笔尖就是锥的末端（pf 原样，继续写会"长回去"）；抬笔自然定型。
- 真笔不动（`Eligible` 要求"没有真实压力"）。

验收：

- `--pressuretest` **35/35** 通过（新增 2 项：只开锥化时中段等宽、两端收细；
  组合档两端仍明显比中段细）；
- `--selftest 8 --simtaper 8,12`、`--selftest 8 --simpressure --simpressdepth 0.10 --simtaper 8,12`
  均 PASS；默认路径 PASS。

三档对比（用户测试用）：

```powershell
dotnet run --project src/InkTeach -c Release -- --nopressure                             # 纯等宽
dotnet run --project src/InkTeach -c Release -- --simtaper 8,12                         # 等宽＋笔锋
dotnet run --project src/InkTeach -c Release -- --simpressure --simpressdepth 0.10 --simtaper 8,12
```

看点：起收笔有没有"入锋 / 回锋"的笔感；活笔时那截"跟着笔尖走的锥"是否顺眼；
锥长 8/12 是否合适（可调 4~20）；"保守压力 ＋ 两端笔锋"会不会反而更像毛笔。

## 十、2026-10-05 追加：`--pfpressure`（perfect-freehand 口径，ClassIn 那种"甩尾收尖"）

用户目标（明确的两条）：

1. **等速写到末尾 → 宽度不变**；
2. **末尾甩速（快速甩出去）→ 线条变细**。

ClassIn（翼鸥教育）是闭源商业软件，拿不到代码；这个行为在开源界正是
**perfect-freehand 的 `simulatePressure`**（MIT）：

- `sp = min(1, 距离 ÷ 笔宽)`；目标 `rp = min(1, 1 − sp)`；
- `p = min(1, p + (rp − p) × (sp × 0.275))`，起笔 `p = 0.25`（防"胖开头"）；
- 等速 → 距离恒定 → 目标恒定 → 压力收敛到定值（**末尾不衰减**）；
- 末尾大步长 → `sp→1、rp→0`，每点掉 27.5% → **末尾明显收尖**；
- 距离用 streamline 低通后的位置算（`t = 0.15 + (1 − streamline) × 0.85`，**只影响测速**，
  不动渲染几何）；映射到我们压力域 `p_ours = 0.5 − thinning × (0.5 − p)`，
  与上游半径公式在 `size = 线宽` 时一致。

参数（默认值全部是上游默认）：

- `--pfpressure`：启用（默认关）；
- `--pfthinning 0.5`：压力→粗细强度（觉得整体偏细/偏粗就调它，0 = 只剩速度造成的掉压）；
- `--pfstreamline 0.5`：测速平滑（越大越贴原始点、越小越平滑）；
- 可再叠 `--simtaper A,B`（pf 的 taper，同一上游）——但**要"等速不变细"就不要开 taper**，
  因为 taper 是不看速度、固定让两端变细的。

验收：

- `--pressuretest` **37/37**（新增 2 项：等速末≈中且起笔偏细；甩尾末点明显低于中段）；
- 数：等速线 `首 0.375 / 中 0.582 / 末 0.599`（末≈中，不衰减）；
  同一条线末尾加两个"甩步"后 `末 0.433`（对比中段 0.582，明显变细）；
- `--selftest 8 --pfpressure`、`--selftest 8 --pfpressure --pfthinning 0.3`、默认路径均 PASS。

怎么试：

```powershell
dotnet run --project src/InkTeach -c Release -- --pfpressure                     # 默认 thinning 0.5
dotnet run --project src/InkTeach -c Release -- --pfpressure --pfthinning 0.3   # 整体更接近等宽
dotnet run --project src/InkTeach -c Release -- --pfpressure --pfthinning 0.8   # 甩尾更明显
dotnet run --project src/InkTeach -c Release -- --pfpressure --simtaper 0,12    # 可选：再加固定回锋
```

注意：pf 的粗细按"距离 ÷ 笔宽"归一化，**整体宽度会随速度比变化**——细笔 + 快写会整体偏细；
若觉得整体偏细，先调小 `--pfthinning`（或把 `--pfstreamline` 调大一点让测速更稳）。
Xournal++ 那档（`--simpressure`）保持原样，可 A/B 对照。

## 十一、2026-10-05 追加：`--flicktip`（只在末尾甩速时收尖）

用户澄清需求：**中段一律等宽**（不要"同一笔快慢不同就粗细不同"），
**只有末尾甩速时**才收尖。这排除了 `--pfpressure` / `--simpressure`（两者都是全程随速度变粗细）。

实现 = **perfect-freehand 的 end taper 形状/缓动（`1−(1−t)³`）+ 速度门控**：

- 末尾速度 = 最后至多 3 段的"总距离 ÷ 总时差"（px/ms；时差 ≤ 0 的段跳过）；
- 速度 < 门槛 → **完全不收**（等速/慢速写到末尾，宽度与中段一致）；
- 速度 ≥ 门槛 → 最后 `L` px 按 pf 尾锥收细（末端压到压力地板 0.05）；
- 中段压力恒为 0.5（不动），与 `--pfpressure`/`--simpressure` 互不叠加也不依赖；
- 活笔同样生效（写完一甩，尾巴立刻收；慢慢收笔就不会）。

参数：`--flicktip L[,vMin]`（默认关）——`L` 锥长（2~80px）、`vMin` 触发门槛（默认 0.5px/ms）；
`Eligible` 只认"没有真实压力"的笔迹（鼠标/触摸/关 Windows Ink 的笔），真笔不动。

**门控不是上游行为**：pf 的 taper 是固定长度、不看速度；ClassIn 闭源。这是按用户明确需求
在 pf 锥形之上加的独立组合档（按纪律记录在此）。

验收：`--pressuretest` **39/39**（新增 2 项）：
等速线 `中 0.500 / 末 0.500`（不收）；同一条线末尾加一个甩步 `中 0.500 / 末 0.050`（明显收细）。
`--selftest 8 --flicktip 14` PASS；默认路径 PASS。

怎么试：

```powershell
dotnet run --project src/InkTeach -c Release -- --flicktip 16          # 等宽 ＋ 末尾甩速收尖
dotnet run --project src/InkTeach -c Release -- --flicktip 24,0.35     # 更长、更容易触发
dotnet run --project src/InkTeach -c Release -- --flicktip 12,0.8      # 更短、需要更快地甩
```

看点：匀速写长横 → 中段和末尾一样粗；快写完最后一甩 → 尾巴收细；收笔放慢 → 不收。
若还是嫌甩尾不明显，加大 `L` 或减小 `vMin`。
