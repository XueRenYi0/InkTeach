# audit-steps.json 说明（给 agent 自己校准用）

这个文件描述"录视频时要做哪些动作"。`audit-ui.ps1` 会照着它移动鼠标、点击、拖拽，
同时用 ffmpeg 录下带真光标的视频。

## 坐标系

- 所有 `x` / `y` 都是**窗口内坐标**，原点在客户区左上角。
- 屏幕坐标 = 窗口 `left/top` + 这里的 `x/y`。窗口位置每次启动可能不同，所以只写相对坐标。
- 窗口尺寸和位置会打印在 `reports/audit-last.json` 的 `window` 字段里。

## 自校准流程

```
1. .\run.ps1                      启动应用
2. audit-ui.ps1 -Calibrate        生成 reports\calibrate\grid-*.png
3. 看那张图：网格 100px，标注 200px，红色线
4. 把目标控件的坐标填进本文件
5. audit-ui.ps1 -Steps scripts\audit-steps.json -Seconds 8
6. 看 reports\frames 有没有拍到目标控件；没拍到就回到第 3 步
```

不要凭记忆填坐标。每次界面改版、窗口大小变化后都要重新标定。

## 可用动作

| action | 参数 | 说明 |
|---|---|---|
| `move` | `x y [ms]` | 移动光标；`ms` 是移动后停留（默认 200） |
| `hover` | `x y [ms]` | 同 move，但默认停留 600ms，用于触发悬停态 |
| `click` | `x y` | 左键单击 |
| `dblclick` | `x y` | 左键双击 |
| `rightclick` | `x y` | 右键单击 |
| `drag` | `x y x2 y2 [ms]` | 从 `(x,y)` 拖到 `(x2,y2)`，16 步插值，默认 600ms |
| `wheel` | `delta` | 滚轮；负数向下，一格 120 |
| `key` | `keys` | SendKeys 语法，如 `^a`（Ctrl+A）、`{ESC}` |
| `wait` | `[ms]` | 纯等待，默认 500ms |

纯注释行写成 `{"_comment": "..."}`，脚本会跳过。

## 时间规则

- 所有动作的 `ms` 加起来，必须小于命令行的 `-Seconds`，否则视频会在动作结束前停。
- 建议留 1–2 秒余量：`-Seconds` = 动作总时长 + 2。
- 动画类检查（面板展开、toast）在动作后加 `wait`，否则抽帧抓不到中间态。

## 常见坑

1. **高 DPI**：脚本已声明 DPI 感知，坐标按物理像素算；如果系统缩放 150%，网格图上的数值就是实际像素。
2. **窗口被遮挡**：`gdigrab` 录的是屏幕区域，别的窗口盖上来就录进去了。录之前把无关窗口最小化。
3. **窗口位置变了**：坐标是相对的，一般不受影响；但如果窗口被移到负坐标或超出屏幕，录制区域会被截断。
4. **合成鼠标丢移动**：连续 `move` 太快时偶尔丢一次，关键动作前加 `wait`。
5. **录到隐私**：录制范围是整个窗口，弹窗、通知都会入镜。

## 给 agent 的检查清单

- [ ] 先跑 `-Check`，确认 ffmpeg 和窗口都在
- [ ] 跑 `-Calibrate`，拿到网格图再填坐标
- [ ] 动作总时长 < `-Seconds`
- [ ] 每个要审的交互后面有 `wait`，让动画能落在帧里
- [ ] 跑完看 `reports/audit-last.json` 的 `frameCount`，是 0 就说明录制失败
- [ ] 把帧交给 `eye` 时，附上"这一步预期看到什么"
