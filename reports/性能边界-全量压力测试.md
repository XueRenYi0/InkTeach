# 底层全量压力测试 · 性能边界（2026-09-13）

一台机器（2880×1800 @192DPI，Intel Iris Xe 核显），全部走**同一个可比的固定场景**。
目标机器是**4GB 内存的教室机**，所以内存一律看**提交大小**（工作集会被系统回收，
不反映真实占用）。

---

## 一、正确性（七套自检全过）

| 模式 | 验什么 |
|---|---|
| `--edittest` | 复制 / 删除 / 翻转 / 旋转的撤销语义 + 操作条命中 |
| `--handletest` | 手柄位置、命中、拖出来的变换矩阵 |
| `--transformtest` | 改变换不碰几何（几何版本号不变、撤销精确回原位） |
| `--savetest` | 保存/加载往返逐字段一致；坏数据明确失败 |
| `--shapetest` | 图形精确命中（轮廓中间是空的） |
| `--cameratest` | 相机只改一个数，对象数据不动 |
| `--scrollwrite` | 滚到哪儿都能写，内容留在那个画布位置 |
| `--erasertest` / `--selftest` | 橡皮正确性 / 渲染真的上屏 |

---

## 二、长跑：模拟一节课（60 秒 = 1153 轮 画→擦→撤销→翻页）

这是最接近真实使用的一项。

| 时间 | 提交 | 笔画数 | 最慢帧 |
|---|---|---|---|
| 0s | 92.1 MB | 19 | 1.71 ms |
| 15s | 111.9 MB | 19 | 9.30 ms |
| 30s | 114.9 MB | 21 | 9.30 ms |
| 45s | 114.9 MB | 20 | 10.78 ms |
| 60s | **115.1 MB** | 18 | 10.78 ms |

**结论：30 秒后就稳住了，不再随时间劣化**（这正是当年修掉两个内存泄漏之后
才有的性质）。最慢单帧 10.78 ms，远在 16ms 之内。

> 换算到 4GB 教室机：系统 + PPT 约吃 2.0~2.5GB，我们占 **115MB**，
> 余量很大。

---

## 三、绘制热路径（最关键的一条）

**一万笔画在屏幕上时，每帧绘制 1.3 ms，且不随笔画数增长。**

这是结构性的：内容层位图 + 脏区增量。所以"课上写着写着越来越卡"这件事
在我们这里不会发生——**内存优化换不来这一点，只有架构能**。

---

## 四、滚动（第一步：相机）

| 画布里的对象 | 滚动一步（整屏重画） | 判断 |
|---|---|---|
| 1000（一屏量级） | **2.8 ms** | 约 350fps，流畅 |
| 2000 | 10.6 ms | 尚可 |
| 5000 | 38.8 ms | 卡 |
| 10000 | 77.1 ms | 明显卡 |

**"保证一屏流畅"达成且余量很大**（一屏 1000 对象 2.8ms）。
累积量要靠第二步（滚动缓冲/分块），方案见计划文档第三十节。

滚下去能写已验证：在 0 / -1800 / -5400 三处各写一笔，都可见，
且各自留在自己的画布位置（700 / 2500 / 6100）。

---

## 五、选中与变换

| 画布里的对象 | 变换 20 个对象：内容层修补最长 |
|---|---|
| 1000 | **1.83 ms** |
| 10000 | 19.10 ms |

一万笔那 19ms 是**测试刻意选的散布全屏的对象**——代价是"重画它们占的面积"，
与架构无关。选聚在一起的一小撮会便宜得多。

---

## 六、指数复制（Ctrl+A + Ctrl+D 反复）

内存随对象数**线性**增长，约 **20 KB/对象**：

| 对象数 | 提交 | 每对象 |
|---|---|---|
| 1024 | 124 MB | 26.1 KB |
| 4096 | 180 MB | 20.6 KB |

到 **10 万对象会被护栏拒绝**（并写日志说明原因），而不是卡死。

---

## 七、一句话总结

| 场景 | 表现 |
|---|---|
| 一节课（长跑 1153 轮） | **115MB 稳住，最慢帧 10.8ms** |
| 一万笔在屏，持续书写 | **每帧 1.3ms，不随笔画数增长** |
| 一屏量级滚动 | **2.8ms/步** |
| 一屏量级选中变换 | **1.83ms/帧** |
| 拖动散布全屏的一批对象 | 19ms/帧（重画面积决定，架构无关） |
| 一万笔整屏滚动 | 77ms/步（需第二步的分块缓存） |
| 指数复制 | 线性增长，10 万对象被护栏拒绝 |
