# 产品面板的每帧代价（实测）

日期：2026-09-16　　命令：`InkTeach.exe --panelperf`

---

## 〇、为什么单开这份

设计阶段那句"界面每帧 0.5～1.5 毫秒"是**估**出来的（拿一块 160×60 的小界面按面积外推）。
而产品面板现在是 **636×82**，并且它待在**写字**这条最敏感的路径上——
教室机器比开发机慢，估的数不能当结论。这份记的是**实测**。

## 一、方法（先说清楚，不然数字没法比）

| 项 | 做法 |
|---|---|
| 内容 | 同一份：**200 笔**（每笔 40 个点，本来就是按屏幕铺开的） |
| 量什么 | 连续 `RenderAll()` 的墙钟时间 ÷ 帧数；每次渲染前强制 `_dirty = true`（不然"空闲不出帧"会把代价量成 0） |
| 三档 | 不挂界面（基准）／收起成一个球／展开＋色带张开（最贵的一档） |
| **取最小值** | 每档跑 **3 轮取最小**：这台机器上同时跑着向日葵远程控制（带虚拟显示器驱动）和几个吃 GPU/CPU 的客户端，同一档实测在 **1.1～3.0 毫秒**之间跳，平均值被"别人抢走的那几毫秒"抬得没法看。最小值＝最干净的那一轮 |

> 这条纪律和 `调研-折角掉色.md` 里那条"跨会话的数字不可比"是同一个道理：
> **先把机器状态说清楚，再谈数字**。

## 二、实测数字（本机：2880×1800 @192DPI，Intel 核显，**有背景负载**）

| 档 | 每帧 | 比基准多 |
|---|---|---|
| 不挂界面 | 1.50 ms | —— |
| 收起成一个球 | 2.08 ms | **+0.58 ms** |
| 展开 ＋ 色带张开 | 3.00 ms | **+1.50 ms** |

**归因**（把几块分别关掉再量，看钱花在哪）：

| 关掉 | 省 |
|---|---|
| 阴影（两层叠出来的近似） | 0.09～0.37 ms |
| 凹槽 ＋ 顶部内高光 | 0.03～0.16 ms |
| 色片的内高光与选中环 | 0.17～0.34 ms |
| 图标（13 个 Fluent 路径填充） | −0.12～0.32 ms |

结论：**钱主要不在填充面积上，而在"每帧几十次小绘制调用"本身**
（四块加起来只占 1 毫秒左右，而整块面板贵 1.5～2.6 毫秒）。

## 三、曾经试过、**已经回退**的一条路：静态底缓存

教科书解法是把静态底画进一张位图、每帧只贴一次（引擎里的性能面板就是这么干的：
4.3 ms → 0.05 ms）。我按这个改了，结果**整块面板直接变空白**——

**原因**：界面是在引擎的 `BeginDraw` **里面**被调用的，而缓存的刷新要"切换渲染目标 +
自己 BeginDraw/EndDraw"，Direct2D 不允许在绘制中途换目标。
（引擎自己的 `PrepareHud` 能这么干，是因为它挂在 `RenderFrame` 里、
**在 BeginDraw 之前**那一行。）

代价：**几何与命中测试的自检全绿**——那部分没坏，只有像素是空的。
这次是**出图**当场看出来的（`--panelshow` 出一张全白的图）。

**要做这条优化，先得在引擎里开一个口子**：`RenderFrame` 里、BeginDraw 之前，
给界面一次"离屏准备"的机会（和 `PrepareHud` 同一位置）。这是一次契约改动，
记在 [计划-底层对接界面.md](../计划-底层对接界面.md) §10.2 里，**没有偷着做**。

## 四、当前结论与待办

1. 面板的额外代价：收起 **+0.58 ms**、展开 **+1.50 ms**（红线也是 1.5）；
2. **这台机器量不准**（背景负载把基准从 1.1 抬到 3.0）——要找一台**空闲**的机器复测，
   复测命令就一条：`InkTeach.exe --panelperf`；
3. 真要把它压下去，顺序是：① 引擎开"绘制前准备"的口子 → ② 静态底缓存
   （预计能把展开态从 +1.5 压到 +0.2 上下）→ ③ 复测；
4. 在那之前**不要**动阴影层数：归因显示它只占 0.1～0.4 毫秒，
   砍它换不来什么，还会把观感砍掉（假面板的四种阴影叠法是有出图比过的）。
