# 性能面板重做（2026-09-14）

起因：面板"看不清"，而且里面的内存数与任务管理器对不上。

## 一、"看不清"的根因是字号没跟 DPI

老实现：写死 `1000×262` **物理**像素的面板 + `15f` 号字。而渲染时的变换只有平移、
没有缩放，所以 15 号字 = 15 物理像素——在这台 200% 缩放的屏上只有 **7.5 逻辑像素**高，
投影上糊成一团。放大框不解决问题，**字号必须乘 DPI**。

现在：面板 700×258 逻辑像素、字号 17 逻辑像素（按 DPI 生成并缓存），
框和文字一起放大，行距也放开。

## 二、顺手把面板自己的代价降了 80 倍

老实现每帧都用 DirectWrite 重排 7 行文字：**4.3 ms/帧**（比它显示的所有东西加起来还贵，
笔迹才 2 ms）。文字 4 Hz 才变一次，每帧重排纯属浪费。

改成：面板先画进一张**缓存位图**（DPI 一变或文字一变才重排），每帧只贴一次图。

| | 老 | 新 |
|---|---|---|
| 面板每帧代价 | 4.3 ms | **0.05 ms**（贴图）/ 0.9 ms×2~4 次每秒（重排） |
| 统计（取内存/CPU） | 2.1~4.3 ms | **0.03 ms** |
| 空闲整帧合计 | 5~7 ms | **1.1~1.3 ms** |

统计那一栏的大头是 `Process.GetCurrentProcess()+Refresh()`；改成
`GetProcessMemoryInfo` + `GetProcessTimes` 两个廉价调用后基本归零。

## 三、内存数为什么和任务管理器不一样（已对齐）

老面板报的是 **`WorkingSet64`（工作集，含共享页）**：112~126 MB。
任务管理器"内存"那一列报的是 **专用工作集**（私有页）：69~76 MB。
两个数都对，但口径不同，用户当然会问"为什么不一样"。

对齐过程（逐个验证过）：

| 取法 | explorer（静息进程） | 说明 |
|---|---|---|
| `GetProcessMemoryInfo(PROCESS_MEMORY_COUNTERS_EX2).PrivateWorkingSetSize` | 84.0 MB | **采用**：一次调用、文档化、Win11+ |
| PerfCounter `\Process(x)\Working Set - Private` | 84.0 MB | 一致 |
| `NtQuerySystemInformation.WorkingSetPrivateSize` | 84.0 MB | 任务管理器用的就是它，一致 |
| 自己逐页 `QueryWorkingSet` 数私有页 | 84.5~85 MB | 能用但波动大、要几百 KB 缓冲，弃用 |

（中途踩过一个坑：`QueryWorkingSetEx` 不是"给我全部页"，而是"我按地址问你"——
传全 0 缓冲区进去只会拿回 0 有效页；膨胀式扩容还一度把工作集吃到 2 GB。）

面板现在四个口径并列，并标明各自对应任务管理器的哪一列：

```
内存    69.9 MB（专用工作集 = 任务管理器的“内存”）
已提交  97.6 MB（=“提交大小”）   工作集 112.6 MB（含共享）
共享提交 57.9 MB   显存 86.8 MB   CPU 0.2 %
```

实测对照：面板 69.9 MB，同一时刻 `Get-Counter` 69.5~70.0 MB ✓。

## 四、其它改动

- 面板代价单独报："面板 0.89 ms/次 ×2/秒（摊到每帧 0.14 ms）"——4 Hz 重排这件事
  不该藏在一个平均值里。
- 帧率那行标注"（空闲不重绘）"：老面板只显示 3.9 fps，容易被读成"性能差"，
  其实是空闲时压根不渲染（这是设计，不是问题）。
- 键位提示更新成当前绑定（`6` 切粗细、`K` 键盘模式、`Y` 穿透方式）。
- **自检/基准模式下面板默认关闭**（`--hud` 可强制打开）：面板是个大黑框压在左上角，
  而 `--coordtest` / `--inputtest` / `--erasertest` / `--ghosttest` / `--tiletest` /
  `--appendtest` / `--passtest` / `--rotatetest` 的判据都是"数屏幕上的墨"。
  面板一放大就当场压到那些画面上，一次跑出 9 个假失败——这条记在这里，避免以后再踩。

## 五、这一步的自检情况（要如实说明）

| 模式 | 结果 |
|---|---|
| `--coordtest` / `--tiletest` / `--appendtest` / `--selftest` | PASS（面板关闭后恢复） |
| `--report` / `--memory` / `--longrun` / `--latbench` 等 | 跑完出数，内存与帧成本见上表 |
| 带**合成鼠标输入**的 8 条（inputtest / erasertest / ghosttest / passtest / rotatetest …） | 这次**跑不了**：系统当前拒绝注入指针——`SetCursorPos` 直接返回 False，说明本进程不在输入桌面上（锁屏 / 切换用户 / 远程会话都会这样）。证据：同一台机器 20 分钟前这些用例还全过。 |

结论：面板相关的改动本身是自洽的（渲染路径有像素级验证：面板截图与外部
PerfCounter 数字对得上）；带合成输入的那几条要等输入桌面恢复后再复跑一遍。
