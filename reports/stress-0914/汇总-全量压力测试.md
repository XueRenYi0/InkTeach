## 二、三个 FAIL 的定性

### 1. cameratest —— 真回归，而且能精确定位到提交

失败的那一条是"**墨到了偏移后的位置**"：相机偏移后屏幕上一像素洋红都没有
（原位置 0、新位置 0，滚回去又恢复 6720）。

**不是最近未提交改动的锅**，来回都验证过：

| 提交 | cameratest |
|---|---|
| f50fccc（09-13 那次全量报告的版本） | PASS |
| 968339f（滚动条第一步） | PASS |
| **d8e14ab（修"滚动后写不了字"）** | **FAIL** |
| 842cc11 / b861573（HEAD） | FAIL |

所以是 **d8e14ab** 带进来的——那一次改的正是脏矩形管线的坐标换算
（`CanvasRectToWindow` 接到文档来的矩形上），把相机自检这条路径一起改坏了。

**触发条件是窄的**：同一帧里"相机变了 + 整层内容被作废重画"。用户路径不受影响，
用外部进程逐帧量过（`tools/bench/Check-ScrollKeepsInk.ps1`，合成鼠标画一笔 + 真滚轮事件）：

| 动作 | 期望 | 实测 |
|---|---|---|
| 画一笔（宽 800） | — | x 500..1299，宽 800 ✓ |
| 滚轮往下 3 格 | 上移 432 px | 上移 432 px，宽度仍 800 ✓ |
| 滚轮往上滚回 | 回原位 | 偏差 0 px，宽度 800 ✓ |
| 滚动状态下清空、再写 | 新笔完整 | 宽 800，完整 ✓ |

（相机变了但**没有**整层作废时，走的是"只重合成不重画"那条路，那是好的；
`--coordtest` 12/12、`--scrollwrite` 8/8、`--wheeltest` 全过也都是这条。）

结论：**用户看得见的滚动是好的**，坏的是"相机 + 整层作废同一帧"这个组合。
现在产品里这个组合只有测试能构造（`SetBoardFromUi` 没有热键），但它是颗雷——
哪天给"白板开关"接上热键或界面，就会当场露出来。建议按 `CompositeTiles` +
`UpdateFrameDirty` 在"相机变了 + `_forceFullFrame`"同帧时的矩形换算去查。

### 2. cornertest —— 老问题，而且只在开了笔迹美化时才算数

"拐角 39%（2472） 水平段 56% 垂直段 59% → 拐角比直段少 31%"。
轮廓里那个外直角是有的（`(40.1, 0.7) → (40.1, -38.0)`），是栅格化/自交处被挖空。

在 f50fccc 上重跑，**一模一样**（39% / 56% / 59%），所以不是这次的滚动改动带出来的。
而且它只在装笔迹优化器时才有意义（该模式自动装）；**默认不装优化器**，
产品默认的等宽笔迹不受影响。

### 3. trailtest —— 预期内：合成输入是鼠标，不是笔

"按住不放时笔迹像素 0"。日志里写得很清楚：`设备=鼠标`。
委托墨迹轨迹只对 `PT_PEN` 生效，所以这条自检用合成鼠标永远过不了——
和 README 里"需要真笔确认一次"是同一件事（松手后 4943 像素，说明我们自己的笔画接管是好的）。

### 另外一条量不到的

latbench 的最后一节"上屏段"（Present 返回 → 屏幕变色）这次**没对上**：
"屏幕抓取可能被别的窗口挡住，或抓取本身失败"。前四段分场景数据是好的（见第三节）。
这一段依赖屏幕抓取，环境（多窗口/抓取时机）敏感，之前 f50fccc 那次是能量到的
（0.98 个刷新周期）。要量这一段建议在干净的桌面上重跑。

## 三、性能数据

### 绘制热路径（最关键的一条）

| 画布里笔画数 | 首帧全量重建 | 缓存层每帧记录 | **不缓存**每帧记录 | 上屏 |
|---|---|---|---|---|
| 0 | 1.1 ms | 1.00 ms | 0.57 ms | 3.00 ms |
| 1000 | 39.5 ms | 1.32 ms | 15.52 ms | 1.64 ms |
| 10000 | 274.4 ms | **1.96 ms** | **163.84 ms** | 5.01 ms |

**一万笔在屏，每帧 1.96 ms，且不随笔画数增长**（不缓存要 163.84 ms，差 84 倍）。
首帧全量重建那 274 ms 只在启动/清空时出现一次。

交互路径（一万笔画面上）：结束一笔增量更新 **0.28 ms/笔**；橡皮拖动一步 12.58 ms；
撤销一步 11.47 ms。命中测试 500 次：空间索引 4.1 ms vs 全表 60.8 ms（**15 倍**）。
激光笔叠在一万笔之上：约 1.9 ms/帧（各种画法差别在噪声内）。

### 长跑：一节课（60 秒 = 3386 轮 画→擦→撤销→翻页）

| 时间 | 提交 | 笔画数 | 最慢帧 |
|---|---|---|---|
| 0s | 101.7 MB | 19 | 2.59 ms |
| 15s | 131.7 MB | 0 | 4.91 ms |
| 30s | 136.7 MB | 77 | 4.91 ms |
| 45s | 137.1 MB | 133 | 4.91 ms |
| 60s | **136.7 MB** | 40 | **4.91 ms** |

30 秒之后完全平了，**不随时间劣化**；最慢单帧 4.91 ms（16.7 ms 预算的三成）。

### 连续书写（720 笔 / 63216 点，边写边把视图往下带）

记录耗时 均值 **1.36 ms**、最差 10.36 ms；提交 134 MB、工作集 153 MB、显存 94 MB；
分块光栅 0.72 ms；整屏连续重画 ×20 平均 1.64 ms；滚一屏（含贴图）1.6 ms，
墙钟 15.4 ms。撤销栈 200 步仍只持有引用、几何存活 0。

### 内存

| 场景 | 提交大小 |
|---|---|
| 空载（40 帧后强制回收） | **101.9 MB** |
| 讲一页 PPT（20 笔 / 100 笔） | 102.9 / 106.3 MB |
| 一节完整课程（500 笔） | 115.9 MB |
| 重度使用（2000 笔） | 143.2 MB |
| 压力测试（10000 笔） | 247.0 MB |

构成：.NET 运行时 + 程序集约 31 MB，Direct3D/2D/文字约 42 MB，屏幕尺寸合成缓冲约 26 MB。
一张与本屏同尺寸的离屏图层 = **+20.7 MB**。换算到 4GB 教室机：我们占 102 MB，
余量很大；一万笔那次 200+ MB 是极端值，且清空后 Direct2D 会留着复用（棘轮式）。

### 滚动

| 文档笔数 | 每格平均 | 最慢一格 | 一格光栅 | 判断 |
|---|---|---|---|---|
| 1000 | 1.59 ms | 2.33 ms | 1.32 ms | 不掉帧 |
| 5000 | 1.51 ms | 2.32 ms | 1.96 ms | 不掉帧 |
| 10000 | **2.15 ms** | 3.29 ms | 4.10 ms | 不掉帧 |

**滚一格的代价只与"新露出来的那一小条"有关，与文档总量无关。**

### 延时（合成输入，走真笔同一条 WM_POINTER 路径）

| 场景 | 合计中位 | 合计均值 | P90 | 最大 | >33.4 ms 的帧 |
|---|---|---|---|---|---|
| 空白页正常书写 | 2.81 ms | 7.55 | 17.57 | 20.19 | 0 / 142 |
| 空白页快速划线 | 2.75 ms | 7.04 | 17.07 | 24.09 | 0 / 125 |
| 密集页（已有 3000 笔） | 3.34 ms | 8.32 | 17.65 | 19.71 | 0 / 154 |

Present 内部阻塞均值 0.25 ms；12 秒长跑前后漂移 +0.75 ms（无劣化趋势）。
（"采样 → 收到消息"这一段在合成输入上只能算个下界：中位 0.05~0.06 ms。）

### 其它

- **选中与变换**：修补均 11.04 ms（1000 对象）/ 97.17 ms（10000，散布全屏）；每帧记录 11.42 / 16.15 ms。
- **指数复制**：8192 个对象时提交 209 MB，约 10.9 KB/对象；一次复制 8192 条被护栏拒绝（上限 5000），程序仍可响应。
- **内存 A/B（细分缓存开/关）**：私有 389 vs 389 MB、显存 331 vs 331 MB、每帧 1.87 vs 1.86 ms → **测不出来**，维持现状是对的。
- **分辨率**：图层内存 1920×1080 38.5 MB / 2560×1440 50.2 MB / 2880×1800 73.3 MB / 4K 80.7 MB；每次补丁 2.55 / 2.72 / 2.77 / 1.87 ms。
- **穿透**：四种实现里只有 Layered+Transparent 真的让下层窗口收到点击，与文档一致。
- **细笔覆盖率**：1.5 逻辑像素（3 物理像素）只有 0.36——细笔在 192DPI 下偏淡，与"填充带子会不会出洞"无关。

## 四、一句话结论

性能侧一切符合甚至好于上一版：**一万笔每帧 1.96 ms、滚动 2.15 ms/格、长跑 30 秒后完全平稳、
空闲 102 MB**，唯一"量不到"的是上屏段。功能侧 18/21 通过；两个 FAIL 是老问题
（直角拐角掉墨只在开美化时、委托轨迹要真笔），**一个新回归 `cameratest` 已定位到 d8e14ab**，
且已用外部逐帧像素证明用户看得见的滚动路径是好的。
