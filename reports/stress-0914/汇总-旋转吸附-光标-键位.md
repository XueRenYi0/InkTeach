## ① 旋转度数显示 + 吸附（90°）

**行为**

| 动作 | 结果 |
|---|---|
| 拖动旋转手柄 | 手柄外侧浮出度数标签（相对按下那一刻，正 = 顺时针） |
| 松手前离 90° 整数倍 ≤3° | **吸住**，标签变强调色（蓝底白字） |
| 按住 `Shift` | 硬网格 15°（覆盖任意角度，含精确 90°） |
| 按住 `Alt` | 完全自由（2° 就是 2°），用来转"不是整角"的角度 |
| 松手 | 标签消失；一次拖拽 = **一步撤销**，精确回原位 |

**实现**：`Selection.cs`（数学：`RotationDeltaDegrees` / `NormalizeDegrees` / `FormatDegrees`）、
`Engine.cs`（拖动中记录读数与"是否吸附"）、`Overlay.cs`（标签绘制 + 脏区）。
标签画在浮动层，**不进内容层**（性能红线）；按 DPI 生成字号；夹在可见画布内不会出屏。

**自检** `--rotatetest`：33 项全过。关键几项：

```
容差内：吸到 0°        PASS  转 2.0° → 0.0°（吸附）
普通角度：保持自由      PASS  转 43.0° → 43.0°（自由）
容差内：吸到 90°       PASS  转 88.0° → 90.0°（吸附）
容差外：保持自由（90 附近）PASS  转 95.0° → 95.0°（自由）
Shift：硬网格 15°      PASS  转 20.0° → 15.0°（吸附）
Alt：完全自由          PASS  转 2.0° → 2.0°（自由）
拖动 43°：读数与矩阵一致  PASS  读数 43.0°，矩阵量出 43.0°，轴心偏移 0.000px
吸住时标签上屏（强调色填充）PASS  7095 像素
一次拖拽 = 一步撤销      PASS  撤销后 M11=1.0000 M12=0.0000
```

像素级证据（外部截的图）：`rotate-label-90.bmp`（吸附态：蓝底白字 `90°`）、
`rotate-label-43.bmp`（自由态：白底蓝框 `43°`）。看外观：`--rotateshow 90|43`。

**顺手修掉一个隐藏 bug**：`Vortice.Mathematics.Rect` 的构造函数是
**(x, y, width, height)**，不是 (left, top, right, bottom)。性能面板的文字排版框一直按
后者写，靠"左对齐 + 框够大"没露馅；度数标签要居中排版，文字直接被排到屏幕外
（看起来像"字没画出来"）。两处都已改正。

## ② 光标统一（工具 × 粗细 × 设备）

**规则一句话**：鼠标没有笔尖 → 悬停和书写都自绘；手写笔的笔尖就是落点 → 落笔后不画；
触摸一律不画。

| 工具 | 落点反馈 | 尺寸 |
|---|---|---|
| 笔 | **双层圆环**（原来鼠标下只有系统十字） | 内圈 = 真实笔宽；外圈 = 最小可见尺寸（6 逻辑像素半径） |
| 荧光笔 | 宽度胶囊（半透明填充） | 高 = 荧光笔宽，宽 = 1.7×高 |
| 激光笔 | **实心红点**（原来什么都没有） | 半径 = 轨迹头部粗细，细激光有下限 |
| 橡皮 | 圆环 | 半径 = 橡皮半径 |

**同时修掉的 bug**：`Ctrl+Alt+6`（切粗细）以前只改**笔宽**，选了荧光笔按它毫无反应。
现在四种工具各有自己的档位表（笔 `1.5/3/6/10/16/24`、荧光笔 `8/18/32`、激光 `4/8/14`），
切的是**当前工具**那一档。激光笔也终于有了自己的宽度（以前借笔宽，而且轨迹粗细写死
"芯 5px + 发光 26px"——现在按激光宽度缩放，默认值和以前完全一样）。

**自检** `--cursortest`：46 项全过（原来 31 项）。新增的关键几项：

```
画笔 · 鼠标悬停（不再用系统十字）      PASS

鼠标书写中 · 笔环跟着走              PASS
鼠标书写中 · 胶囊跟着走              PASS
鼠标书写中 · 点跟着走                PASS
手写笔落笔后 · 不画（笔尖即落点）      PASS
笔 · 内圈跟着真实笔宽变              PASS  1.5 → 1.5px，24 → 24.0px
笔 · 细笔有外圈兜底（看得见落点）      PASS  真半径 1.5px，外圈 12.0px
笔 · 粗笔时内外圈合一                PASS  外圈 24.0px，真半径 24.0px
荧光笔 · 胶囊跟着荧光笔宽变           PASS  8 → 38px，32 → 66px
激光笔 · 点跟着激光宽变              PASS  19px → 36px
切粗细 · 激光改的是激光宽            PASS  激光 14 → 8，笔宽保持 24
切粗细 · 荧光笔改的是荧光笔宽         PASS  荧光笔 18 → 32，笔宽保持 24
```

看外观：`--cursorshow pen 3` / `pen 24` / `hl 18` / `laser 8`，
截图见 `cursor-pen-w3.bmp`（细笔：内圈小、外圈兜底）、`cursor-pen-w24.bmp`（粗笔：两圈合一）、

## ③ 键位模型（可配置 + 冲突可见 + 落盘）

新增 `src/InkEngine/KeyBindings.cs` + `Settings.cs`：

| 能力 | 说明 |
|---|---|
| 动作模型 | `KeyAction` 枚举 = 引擎的动作（不是界面的按钮） |
| 两档作用域 | `Global`（切换类，任何程序前台都生效）/ `Annotation`（编辑类，批注键盘模式下生效） |
| 键位表 | 31 条默认键位，`KeyChord` 支持解析/格式化 `Ctrl+Alt+P`、`Delete`、`Shift+Left` |
| 冲突检测 | 撞车**拒绝并说清是谁**；全局键没修饰键**拒绝**（会把正常打字抢走） |
| 落盘 | `%APPDATA%\InkTeach\settings.json`，**只写改动项**（以后改默认值不会顶掉用户设置） |
| 坏配置容错 | 文件坏了/键名写错 → 逐条警告 + 用默认值继续跑，绝不崩 |
| 注册失败可见 | 被别的程序占用时记进 `Keys.GlobalFailures` 并打印（以前只有一行没人看的日志） |

引擎里原来那串写死的 `(id, 'P', "穿透模式开关")` 已经删掉：全局热键和批注内快捷键
现在**走同一个 `RunAction` 入口**（避免"同一个动作两份实现、早晚不一致"）。
启动时打印整张键位表。

### 性能：不许退化，怎么验的

**关键认识**：这台机器在几小时内的"同一份代码"数字就会漂 20~30%（核显 + 平衡电源
方案），所以**只跟今天早上那份报告比是错的**。做了三重对照：

1. **同一会话、新旧代码交替跑**（旧代码 = HEAD 工作树，新代码 = 当前树）：

| 指标 | 旧（HEAD） | 新（当前） |
|---|---|---|
| 一万笔缓存每帧记录 | 10.91 / 11.22 ms | **2.38 / 2.45 ms** |
| 一万笔不缓存每帧记录 | 159.5 / 163.2 ms | 180.8 / 194.2 ms |
| 首帧全量重建 | 282.8 / 298.2 ms | 283.8 / 291.3 ms |
| 命中测试（空间索引） | 5.4 / 4.8 ms | 5.1 / 7.8 ms |

   （旧树是 HEAD，**不含你未提交的那批改动**，所以这一栏只能说明"新代码没有更慢"，
   不能直接当成性能对比。）

2. **三步之间互相比**（同一棵树，只差本次新增代码）：一万笔缓存每帧 2.33 / 2.46 / 2.53 ms，
   命中测试 6.4 / 3.9 / 6.1 ms，撤销 15.86 / 14.85 / 14.68 ms，长跑轮数 2451 / 2439 / 2431，
   内存 281.8 / 281.5 / 283.0 MB —— **都在噪声带里**。第③步（含鼠标落点环每帧都画）
   不比第①步慢，说明新增的每帧成本测不出来。
3. **故意挑一条我的代码碰不到的路径**（500 次命中查询，纯 CPU）看环境漂移：
   早上 4.1 ms → 现在 4.8~7.8 ms，**同一份代码漂了 20~90%**。

结论：**本次三项改动没有带来可测的性能退化**；内存、帧成本、长跑曲线都保持在
上次报告的水平。
