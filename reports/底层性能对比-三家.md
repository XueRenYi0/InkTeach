# 底层性能对比：原型（Direct2D）vs InkClass（WPF）vs Inkeys（C++）

测量日期 2026-09-13。同一台机器、同一块屏（2880×1800 @ 192 DPI，Intel Iris Xe 核显）。

| 被测对象 | 技术栈 | 性质 |
|---|---|---|
| **本原型** | C# + Direct2D + DirectComposition | 我们的 |
| **InkClass v6.6.3** | C# + .NET Framework 4.7.2 + WPF InkCanvas | 用户自己的产品（源自 Ink-Canvas） |
| **Inkeys 20260713a** | C++20（GPL v3，1167★） | 同类里主打"高性能画笔"的竞品 |

## 测量方法

- 同一套**合成鼠标手势**驱动三个程序：N 笔 × 每笔 40 个采样点，目标间隔 6 ms。
- 指标**全部从进程外部采集**（`Process.TotalProcessorTime`、性能计数器
  `GPU Engine(*)\Utilization Percentage` 的 3D 引擎、工作集/提交大小），
  不依赖被测程序内部埋点，所以对闭源程序同样有效。
- 每个程序都先用它自己的方式进入"可书写"状态，并**用截图确认红线真的画上去了**
  才采信数据（否则量到的是"没画"，不是"画得快"）。
- 三个程序都关掉各自的调试界面，量的都是渲染引擎本身。

## 结论

1. **内存原型大幅领先。** 空载 96 MB，比 WPF 版省 160 MB、比 Inkeys 省 336 MB。
   每写一笔的增长也是最小的。

2. **CPU 原型与 WPF 版接近，两者都远好于 Inkeys。**
   Inkeys 在书写时占用 **89%~96% 的一个 CPU 核心**，而 GPU 占用是 **0%**
   —— 说明它走的是**纯 CPU 软件渲染**（全屏分层窗口 + GDI 重绘）。
   这不是笔误：同样一笔，原型每个采样点花 2 ms，Inkeys 要 55~60 ms。

3. **Inkeys 在停止输入后仍有 14%~46% 的 CPU 占用**，说明它的消息队列已经积压、
   处理不完。实测输入速率也被拖慢到 48~52 点/秒（原型稳定 55）。
   对"上课连续写板书"这个场景，这是会直接影响手感的。

4. **GPU 上 WPF 版最省（2.3%~2.6%），原型 2.9% 紧随其后**，Inkeys 几乎不用 GPU。
   原型这一项是从 8.5% 优化下来的（见下）。

### 需要注意的边界

- Inkeys 的 `SuperDrawBeta2` 开关默认关闭；我开启后重测反而更差
  （162.6% 单核），所以**上面的数据是它的默认配置**，不是我们故意挑差的配置。
- Inkeys 空闲 CPU 波动较大（5.7%~15.1%），它有 PPT 监控等后台模块在跑；
  书写时的 CPU 里也包含这些模块的固定开销。但"书写 − 空闲"的差值仍然巨大。
- 三个程序的分辨率、DPI、字体渲染设置都不同，这属于产品差异而非测量误差。

## 本次对比中给原型做的优化

### 1. 脏区渲染 + 脏矩形上屏（GPU 8.5% → 2.9%）

原来每一帧都在做"全屏清屏 + 全屏贴图 + 全屏上屏"，一帧要动 518 万像素。
现在整条管线只处理真正变化的矩形：

- 用 `IDXGISwapChain1::Present1` 把脏矩形交给 DWM，让它跳过没变的区域；
- 连**合成**也限制在脏区内（实测这才是 8~9% GPU 的元凶，而不是上屏本身）。

实测脏区只有整屏的 **0.1%~1.0%**。

**双缓冲陷阱**：翻转模型下当前后缓冲里装的是**两帧前**的画面，所以脏区必须回溯
两帧的临时图元范围，否则快速移动的笔画/激光会留残影。这一点用对照实验验证过：
保留两帧回溯时逐像素差异 **0**，关掉回溯立刻变成 **616** 像素残影。

### 2. 空闲 CPU 5.2% → 0.0%

性能面板关掉之后，定时器仍然每秒触发 4 次重绘去刷新面板文字；
进程计数（`Process.Refresh()` + 拼字符串）一次约 3 ms，每秒跑 4 次。
现在面板关闭时不重绘、计数降到 1 秒 1 次。

## 对目标（低配电脑流畅上一节课）的评估

原型在核显机器上：空闲 **0% CPU / 0% GPU / 96 MB**；
连续书写时 **约 14% 单核 / 2.9% GPU**，且**与画面里已有多少笔无关**
（一万笔时每帧绘制开销仍是 0.6 ms）。

换算到典型教室机（i3-8100 / UHD 630 / 8 GB）：

- GPU：UHD 630 大约比 Iris Xe 慢 2~3 倍 → 约 **6~9%**，余量充足；
- CPU：4 核机器上约占全机 **3.5%**，无积压；
- 内存：空载 96 MB + 500 笔约 50 MB ≈ **150 MB**，8 GB 机器上无压力。

**结论：原型的能力已经足够支撑"低配电脑流畅上一节课"。**
继续优化的空间在 GPU（若换成 4K 屏，像素量翻倍）和长时间连续书写的内存增长。
